# 文档总览

## 1. 目录目的

本目录用于放置整个 `Docs` 的索引、总览和阅读路线。这里的文档不讨论单个模块细节，而是帮助读者快速找到应该先读什么、每份文档解决什么问题、各目录之间如何对应。

---

## 3. 当前目录结构说明

### 3.1 `01-当前架构`

这里存放当前 UI、模块边界、命令流、渲染边界等最直接的现状描述。

### 3.2 `02-变换与交互`

这里存放绘图交互、数据与渲染等交互和状态相关文档。

### 3.3 `03-渲染主链`

这里存放从文档到渲染数据、从渲染数据到视口呈现的主链路文档。

### 3.4 `04-测试与日志`

这里存放测试策略、日志策略与诊断相关文档。

### 3.5 `05-硬件与设备`

这里存放硬件抽象层（HAL）的框架设计、厂商适配器接入方法与各厂商接入现状。

- `硬件抽象层架构.md`：分层设计、跨 DLL ABI 约定、跨平台策略、MotionPlan IR、IO 与安全策略栈。
- `厂商适配器接入指南.md`：新增一个厂商要动哪些文件、按什么顺序做、提交前自检清单。
- `厂商接入现状.md`：六个厂商适配器的完成度、参数清单与**未实测项**（上机验证后直接改这份）。

### 3.6 根目录文档

根目录下的文档用于记录总纲、阶段总结、框架问题和大方向设计。

## 4. 文件命名规范

### 4.1 当前规范

现阶段建议：**文件名优先使用中文**，这样便于中文团队阅读，也能让文档语义更直观。

例如：

- `当前架构总览.md`
- `模块边界定义.md`
- `菜单架构定义.md`
- `左侧工具栏架构定义.md`

### 4.2 推荐规则

- 目录名可以保留编号前缀，例如 `01-当前架构`。
- 文件名尽量使用中文。
- 若需要英文名，建议只在文档内容中保留英文术语，不必依赖文件名。
- 新增文档优先保持“中文文件名 + 中文标题 + 英文术语括注”的风格。

---

## 5. UI 文档的统一原则

1. 所有 UI 入口都要定义职责边界。
2. 所有菜单和按钮都要对应命令 ID。
3. 所有可见文字都建议中英对照。
4. 所有工具栏都应说明与命令系统的关系。
5. 所有状态反馈都应说明来源和刷新机制。
