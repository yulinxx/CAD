# 右侧工具栏架构定义

## 1. 文档目标

本文档定义右侧工具栏的职责、内容边界、功能分类与架构设计。右侧工具栏通常承载属性编辑、工艺设置、对象管理和辅助面板入口，属于“参数与信息密集区”。

---

## 2. 右侧工具栏在整体框架中的位置

```text
选择图元 / 切换对象
    → 右侧工具栏显示对应属性
    → 用户修改参数
    → 文档事务 / 属性服务提交
    → 视口与状态栏同步刷新
```

右侧工具栏属于 `UI` 层，不保存业务真相，不直接替代文档模型，不直接修改图元底层内存。

---

## 3. 右侧工具栏的职责

右侧工具栏主要承担：

1. 显示当前选中对象的信息。
2. 提供几何属性编辑入口。
3. 提供工艺参数和加工参数配置入口。
4. 提供对象层、组、顺序等管理入口。
5. 提供属性面板和辅助设置的快速访问。

---

## 4. 右侧工具栏应承载的内容

### 4.1 对象属性

- 名称 Name
- 类型 Type
- 图层 Layer
- 颜色 Color
- 线型 Line Style
- 线宽 Line Width
- 是否锁定 Locked
- 是否可见 Visible
- 是否闭合 Closed
- 方向信息 Orientation

### 4.2 几何属性

按图元类型不同展示不同属性，例如：

- 直线：起点、终点、长度、角度
- 圆：圆心、半径
- 圆弧：圆心、半径、起始角、终止角、方向
- 多段线：顶点、闭合状态
- 样条：控制点、权重、节点向量

### 4.3 工艺属性

- 是否参与加工
- 加工层
- 切割/雕刻模式
- 功率
- 速度
- 频率
- 补偿方式
- 引线参数
- 微连参数
- 加工顺序

### 4.4 组织属性

- 群组
- 排序
- 选择状态
- 关联特征
- 绑定工艺模板

### 4.5 辅助面板入口

- 属性面板
- 工艺面板
- 图层面板
- 材料面板
- 诊断面板
- 预览面板

---

## 5. 右侧工具栏不应承载的内容

- 高频绘图按钮
- 主菜单级功能
- 临时鼠标工具切换
- 复杂的命令入口集合
- 纯显示类状态提示
- 直接的渲染细节

右侧工具栏的核心不是“启动动作”，而是“修改参数”。

---

## 6. 右侧工具栏的功能分类

建议划分为四类：

### 6.1 属性查看类

用于只读展示当前对象或当前场景的基础信息。

### 6.2 属性编辑类

用于编辑对象几何、显示和工艺参数。

### 6.3 组织管理类

用于图层、群组、排序和加工顺序管理。

### 6.4 面板入口类

用于切换复杂功能面板，而不是把所有控件堆在一个栏里。

---

## 7. 右侧工具栏与命令系统关系

右侧工具栏中的操作通常不是简单命令触发，而是“读取当前状态 → 编辑参数 → 提交事务”。

```text
Toolbar Property Edit
    → Property Service / Document Transaction
    → Update Entity / Feature / Process Data
    → Notify Scene Changed
```

### 7.1 设计要求

- 属性更改必须走统一提交入口。
- 不允许控件直接改图元内存结构。
- 属性编辑必须支持撤销重做。
- 右侧工具栏应在选择变化时自动刷新。
- 对不同图元类型应动态显示不同字段。

---

## 8. 右侧工具栏与框架设计

### 8.1 依赖约束

- 右侧工具栏依赖 `UI` 层和文档适配层。
- 右侧工具栏不得直接依赖几何算法内部实现。
- 右侧工具栏不得直接操作渲染层。
- 右侧工具栏不得作为业务事实源。

### 8.2 数据来源

右侧面板内容应来自：

- 当前选择集
- 当前文档对象
- 图层和工艺库
- 当前加工模式
- 当前工作台上下文

### 8.3 交互原则

- 展示应尽量与对象类型自动适配。
- 复杂属性应拆分成分组或页签。
- 多对象选择时应支持批量编辑。
- 不同层级的属性应有明确优先级。

---

## 9. 推荐右侧工具栏结构

### 9.1 基础信息区
- 对象名
- 类型
- ID
- 图层
- 可见性
- 锁定状态

### 9.2 几何属性区
- 坐标
- 尺寸
- 半径
- 角度
- 顶点列表
- 控制点列表

### 9.3 工艺参数区
- 加工方式
- 功率
- 速度
- 频率
- 补偿
- 引线
- 微连

### 9.4 管理区
- 群组
- 顺序
- 绑定工艺
- 绑定材料
- 绑定模板

### 9.5 高级面板入口区
- 属性面板
- 工艺面板
- 图层面板
- 诊断面板
- 预览面板

---

## 10. 当前框架下的实现建议

1. 由状态中心驱动当前选择变化。
2. 由文档事务层接收属性修改。
3. 右侧工具栏仅负责控件展示和参数收集。
4. 将复杂属性编辑拆成独立面板或弹窗。
5. 批量选择时使用统一属性合并规则。

---

## 11. 设计原则总结

右侧工具栏是“参数与信息中枢”，不是快速启动工具。它的价值在于帮助用户查看和编辑当前对象的细节，并把这些修改稳定地提交到文档和工艺体系中。对于大型激光软件，右侧工具栏应尽量围绕“对象属性”和“工艺属性”展开，而不是沦为杂项堆放区。
