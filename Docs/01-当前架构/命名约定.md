# 命名约定（新代码强制）

> 来源：《框架冗余与复杂度审查》§3.9 / P2-2.8。
> 生效范围：**新增代码必须遵守**；存量类不强制重命名，被实质修改时顺带对齐。
> 明确不做：全仓批量重命名（数千行 diff 掩盖语义变更，且破坏 `git blame`）。

## 1. 转发/扇出类后缀语义

本仓库历史上「把 A 转给 B」出现了 6 种后缀且语义混用。新代码按下表选词：

| 后缀 | 语义 | 判定问题 | 仓库内范例 |
|---|---|---|---|
| **Dispatcher** | 同步命令路由：commandId → 唯一处理入口，单点决策 | 「同一线程内一次调用直达目标吗？」 | `MenuDispatcher` |
| **Bus** | 事件扇出：post/subscribe，多订阅者，无返回值编排 | 「一发多收、收方互不知晓吗？」 | `OperationBus`、`SceneNotifier`（若在 UI 层应称 Bus） |
| **Bridge** | 工具箱边界适配：引擎/模型类型 ↔ Qt/UI 工具箱类型，双向胶水 | 「边界一侧是 QWidget/Qt 类型吗？」 | `QtLayerManagerBridge` |
| **Hub** | UI 动作聚合点：持有并批量刷新 QAction/菜单项生命周期 | 「管理的主体是 QAction 族吗？」 | `CommandActionHub` |
| **Coordinator** | 多路刷新/任务的时序权威：合并、排序、定时 | 「存在『谁先谁后/几帧一次』的裁决吗？」 | `SceneRefreshCoordinator` |
| **Adapter** | 单向层次翻译（非工具箱绑定），A 层类型 → B 层类型 | 「只做单向参数/类型转换吗？」 | `RenderXDeviceAdapter` |
| **Center / Registry / Service / Manager** | 见下节 | | |

## 2. 其余常见后缀

| 后缀 | 语义 |
|---|---|
| **Center** | 单一事实来源的状态仓 + 变更信号（如 `UiStateCenter`）。**禁止无界增长**：新增状态必须归入现有分组（见 `UiStateCenter.h` 的 4 组结构体），另立中心需架构评审。 |
| **Registry** | id → 条目/工厂 的纯查表；不含业务逻辑。查表超过 ~20 条应用哈希索引（参照 `CommandCatalog` 的 `CatalogIndex`）。 |
| **Service** | 领域能力的动词化门面（`TextEditService`、`SceneEditService`）；由组合根装配，不单身命周期于 UI 控件。 |
| **Manager** | 对一组对象拥有生命周期与变更权（`LayerManager`、`DocumentManager`）。与 Service 区别：Manager 有所有权，Service 无。 |

## 3. `I` 前缀

- **允许**：真正的可扩展接口（多个或将有多个实现，如 `IOperation`），或有意的 ABI 隔离层且注释声明该定位。
- **禁止**：单实现的迁移期临时接口、唯一实现的「隔离壳」改名时应去掉 `I` 或在类注释首行声明「单实现隔离层，非扩展点」。

## 4. 其它硬规则（历次改造沉淀）

1. **2D/3D 成对类型不合并**（`OperationBus` vs `OperationBus3D` 等）：DLL 边界有意隔离；共性进 `UI/Common/Command` 的 `*Base` 模板。详见各头文件的「为什么不合并」注释。
2. **同名不同类型必须消歧**：出现「两个同名但语义不同的类型」时，优先改名而不是合并（反例：曾有两个 `SceneChangeSet`，已改名 `SceneEditBatch`）。
3. **旧路径转发头不再新增**：迁移后旧路径头确认零引用即删；新代码一律 include 新路径。
