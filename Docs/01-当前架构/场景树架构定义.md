# 场景树架构定义

## 1. 文档目标

本文档描述 2D 工作台"场景"页（场景树 / Scene Tree Panel）的职责、功能、分层架构与实现方式。场景树用于浏览当前 2D 场景中的全部图元与群组、多选图元，并对多选执行显示/隐藏、锁定/解锁、删除等批量操作。

> 状态说明：本文对应已落地实现（2026-08-25）。涉及"数据/算法/UI 三层解耦""QTreeView + QAbstractItemModel 懒加载""百万级图元不卡""Shift/Ctrl 多选 + 右键批量操作"均已实现。
> 2026-08-25 变更：右键菜单启用态改为消费命令中枢快照（`setCommandState`），不再由面板自算，见 6.2 与 7。

---

## 2. 在整体框架中的位置

```text
引擎场景(SceneManager + LayerManager)
    → 算法层(SceneTreeBuilder2D) 生成紧凑拓扑 + 按行懒读元数据
    → 数据层(SceneTreeTopology2D / SceneTreeRow2D / SceneTreeRowMeta2D)
    → UI 层(SceneTreePanel2D: QTreeView + SceneTreeTableModel2D)
        ├─ 用户 Shift/Ctrl 多选 → selectionChanged → 引擎选择(selectMultiple)
        └─ 右键菜单批量操作 → 删除(可撤销) / 显示隐藏 / 锁定解锁 → 引擎写回
    → 绑定层(Workbench2D::setupSceneTree / refreshSceneTree) 组合根

命令 UI 状态（下行推送，与上述数据流反向）：
UiStateBridge2D → Workbench2D::refreshCommandUiState()
    → CommandActionHub::selectionContextChanged(snapshot)
    → Workbench2D::applySelectionContext()
    → SceneTreePanel2D::setCommandState(hasSelection, anyLocked)
```

场景树属于 `UI` 层。它**不保存业务真相**，**不直接修改图元内存**，只通过数据模型（`SceneTreeTopology2D`）与注入的提供者回调（`MetaProvider` / `ChildrenProvider`）访问算法层。

右键菜单的启用判定同样**不由面板决定**：面板只接收外部推入的 `hasSelection` / `anyLocked` 并据此灰显，判定规则的真值源是命令目录（`CommandCatalog`）与规则求值器（`Cmd::evaluateEnableRule`）。

---

## 3. 职责

1. 浏览当前 2D 场景的图元与群组层级。
2. 支持 Shift/Ctrl/框选多选，多选同步到引擎视口选择。
3. 右键菜单对多选图元执行：显示 / 隐藏、锁定 / 解锁、删除（可撤销）、全选、清空选择。启用条件由命令中枢快照推入，与顶部工具栏/视口右键菜单共用同一份规则（见 6.2）。
4. 双击名称内联重命名；勾选可见性列切换单个图元显隐。
5. 面向百万级图元不卡顿（懒加载 + 虚拟化渲染）。

---

## 4. 分层架构（UI / 算法 / 数据 解耦）

场景树按三层严格解耦，任一层可独立替换（面板可被删除/替换/定制，不影响数据与算法）。

### 4.1 数据层（Main，纯数据）

| 文件 | 说明 |
|---|---|
| `Main/Src/UI/Documents/SceneTreeModel2D.h` | 纯数据契约：`SceneTreeRow2D{id, isGroup}`、`SceneTreeRowMeta2D`、`SceneTreeTopology2D` |

数据层只定义紧凑结构与元数据，不依赖任何引擎类型或 Qt 控件，是算法层与 UI 层的唯一数据契约。**拓扑只存 id + 是否群组，元数据按行懒读**，因此 1M 图元也只产生 1M 个紧凑行条目，而非 1M 个控件节点。

### 4.2 算法层（Main，无 widget）

| 文件 | 说明 |
|---|---|
| `Main/Src/UI/Documents/SceneTreeBuilder2D.{h,cpp}` | 引擎访问的唯一入口：`buildTopology()`（O(N) 一次生成顶层索引）、`groupMembers()`（群组展开时懒取成员）、`rowMeta()`（O(1) 按行读名称/类型/图层/可见/锁定/选中）、`selectedIds()` |

算法层封装所有引擎细节（`Eg::SceneManager` / `LayerManager`），不依赖任何 widget。

### 4.3 UI 层（Main，可替换/移除）

| 文件 | 说明 |
|---|---|
| `Main/Src/UI/Widgets/UiSceneTreePanel2D.{cpp,h}` | `QTreeView` + 自写 `QAbstractItemModel`（`SceneTreeTableModel2D`）。实现 `canFetchMore/fetchMore`：群组展开时才懒加载成员；**绝不 `expandAll`**。对外暴露 `setCommandState(bool hasSelection, bool anyLocked)` 接收右键菜单启用态输入 —— **面板只渲染，不做状态判定** |

UI 面板只消费 `SceneTreeTopology2D`（数据）与 `MetaProvider` / `ChildrenProvider`（回调），不感知引擎。面板不存在或被替换都不影响数据与算法。

### 4.4 绑定层（组合根）

| 文件 | 说明 |
|---|---|
| `Main/Src/UI/Workbench/UiWorkbench.cpp` | `Workbench2D::setupSceneTree()`：探测面板（可缺失）→ 连接批量/选择信号 → 注入提供者；`refreshSceneTree()`：构建拓扑并推送；`syncSceneTreeSelection()`：选择变化同步高亮；`applySelectionContext()`：把命令中枢快照推给面板（`setCommandState`）与属性面板/状态栏 |
| `Main/Src/UI/Workbench/UiStateBridge2D.{h,cpp}` | 集中挂载 5 路状态变化触发源（选择 / 图层锁 / 场景变化 / 撤销栈 / 操作完成），统一收敛到 `Workbench2D::refreshCommandUiState()`。详见 `命令与状态流.md` 6.3 |

绑定层是唯一同时知道"面板是否存在"的地方，先探测 `sceneTreeDock()`（可为空）再绑定，保证 UI 可定制性。

## 5. 百万级性能设计

场景树从"数据驱动全量渲染"改为"**懒加载 + 虚拟化 + O(1) 定位**"：

| 关注点 | 方案 |
|---|---|
| 顶层大量图元 | 拓扑只存 `QVector<SceneTreeRow2D>` 紧凑索引；`QTreeView` 按可见区虚拟化渲染，不生成 1M 个控件节点 |
| 群组成员 | `QAbstractItemModel::canFetchMore/fetchMore`：仅当用户点击群组展开箭头时才懒取成员 |
| 展开 | **绝不 `expandAll`**；群组默认折叠，展开才加载 |
| 选中定位 | `id → 行号` 哈希（O(1)），不再全表 `findItems` 扫描 |
| 全选 | 用 `QItemSelection` 区间记录（O(1)），不逐行枚举 |
| 刷新 | 导入/撤销/操作完成后才重建拓扑；显示/锁定/重命名走轻量 `notifySceneChanged`，不重建拓扑 |

## 6. 交互与批量操作

### 6.1 多选

- 树默认 `ExtendedSelection`：支持 `Ctrl` 点选增删、`Shift` 范围多选、框选。
- 多选变化 → `selectionChanged(QStringList ids)` → 绑定层 `applySceneTreeSelection` → `ISelectionService::selectMultiple` 同步引擎；引擎选择变化 → `syncSceneTreeSelection` 回填高亮（带防回环抑制）。

### 6.2 右键菜单（对多选批量生效）

| 菜单项 | 启用条件 | 对应命令规则 | 信号 → 绑定层处理 |
|---|---|---|---|
| 显示 Show / 隐藏 Hide | 有选中 **且** 未锁定 | `RequiresUnlockedSelection` | `batchVisibilityRequested` → `setSceneTreeVisibility` |
| 锁定 Lock / 解锁 Unlock | 仅需有选中 | `RequiresSelection` | `batchLockRequested` → `setSceneTreeLock` |
| 删除 Delete | 有选中 **且** 未锁定 | `RequiresUnlockedSelection` | `deleteRequested` → `deleteSceneTreeSelection`（走 `SceneEditService::deleteEntities`，**可撤销**） |
| 全选 Select All / 清空 Clear | 恒可用 | `Always` | 面板内部（区间全选 / 清空） |

> **Lock / Unlock 必须只要求 `hasSelection`**。若也要求"未锁定"，锁定后将永远无法解锁 —— 这是该规则与 Delete 的关键差异。

启用判定的输入由 `SceneTreePanel2D::setCommandState(bool hasSelection, bool anyLocked)` 从外部推入，面板**不再自行遍历 selection model 计算 `hasSelection`**。这消除了历史上的规则漂移：面板自算时未考虑锁定，导致锁定图元在场景树右键仍可删除，而视口右键菜单已正确禁用。

`anyLocked` 来自 `CommandUiSnapshotBase::anyLocked()`，即实体锁与图层锁取或，与 `Cmd::evaluateEnableRule` 使用的是同一个判定。

### 6.3 单行操作

- 勾选"Vis"列：切换单个图元显隐（`visibilityToggled` → 引擎 `setVisible`）。
- 双击名称列：内联重命名（`renameRequested` → 引擎 `setName`）。

## 7. 触发时机

- `refreshSceneTree()`（重建拓扑）：视口/操作后（`operationCompleted`、`undoStateChanged`）、导入完成。
- `syncSceneTreeSelection()`（仅高亮）：视口选择变化。
- `setCommandState()`（右键菜单启用态）：由 `UiStateBridge2D` 的 5 路触发源统一驱动 —— 选择变化 / 图层锁变化 / **场景变化（含图元 `setLocked`）** / 撤销栈变化 / 操作完成。

> 第三类的必要性：图元级 `setLocked` 只发 `notifySceneChanged()`，不改变图元数量，因此 `onSceneTreeSceneChanged()` 不会重建树。若不单独订阅场景变化，锁定后右键菜单会停留在旧状态（历史 bug 本体）。

- **锁图标重绘**：`setCommandState()` 返回"锁定态是否翻转"，`applySelectionContext()` 在翻转时启动 150ms 去抖定时器排一次树重建。同一个计数守卫问题也影响锁图标本身 —— 图标由 `SceneTreeBuilder2D` 在重建时绘制，不补这一下，通过右键锁定后图标要等到下一次增删才出现。只在真的翻转时排重建，避免每次选择变化都做 O(N) 重建；代价是在锁定/未锁定图元之间来回切选择会多做几次重建。

## 8. 扩展建议

- 图层作为树顶层分组：在 `SceneTreeBuilder2D::buildTopology` 按 `LayerManager` 分组，数据层与 UI 层无需改动。
- 批量工艺操作（如批量填充/偏移/阵列）：在右键菜单或工具栏新增信号，绑定层复用既有批量 id 处理即可。
- 自定义/替换面板：面板仅依赖 `SceneTreeTopology2D` + 两个回调，可通过 `UiPanelRegistry` 注册工厂替换或移除，算法层零改动。
