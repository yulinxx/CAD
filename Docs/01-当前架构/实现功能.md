# 2D 功能开发路线图

> 这是给当前项目 2D 功能开发准备的执行路线图。
>
> 目标不是讲概念，而是把**后续怎么写代码、先改哪些文件、每一层负责什么、功能怎么逐步接入**说清楚。
>
> 你可以直接按本文档推进实现。

---

## 1. 路线图的总原则

当前 2D 功能开发，遵循下面四条原则：

1. **先打通主链，再扩功能**
   - 先把菜单 / 工具条 / 命令 / 文档 / 图元 / 渲染 / 刷新接通
   - 再做复杂绘图和编辑

2. **UI 只做入口，不做核心业务**
   - 菜单、工具条、视口负责触发和展示
   - 具体业务逻辑下沉到命令系统、文档层和图元层

3. **正式数据和临时状态分离**
   - 临时预览、采点、回退、取消不写进文档
   - 只有提交后才生成正式 `SyEntity`

4. **菜单和工具条统一命令语义**
   - 同一个功能必须有同一个 `OperationId`
   - 菜单、工具条、快捷键都要走同一个 `OperationBus`

## 3. 2D 功能总路线

建议按下面六个阶段做。

```text
阶段 1：入口统一
阶段 2：绘图基础
阶段 3：选择与编辑
阶段 4：刷新与撤销重做
阶段 5：复杂图元
阶段 6：体验收口
```

## 4. 阶段 1：入口统一

### 4.1 目标

把菜单、工具条、快捷键、命令系统统一成一条主链。

### 4.2 你要先做什么

#### A. 统一命令 ID
命令 ID 集中在以下位置维护：
- `UI/Common/Include/UI/Command/OperationId.h`
- `UI/2D/Src/Operation/CommandCatalog.cpp`

#### B. 统一菜单入口
在 `Main/Src/UI/Workbench/WorkbenchWindow.cpp` 中继续维护：
- `buildFileMenu()`
- `buildEditMenu()`
- `buildDrawMenu()`
- `buildModifyMenu()`
- `buildViewMenu()`

#### C. 统一工具条入口
工具条由 `Workbench2D` 挂载，不要在窗口骨架里塞业务按钮。

相关位置：
- `Main/Src/UI/Workbench/WorkbenchWindow.cpp`
- `Main/Src/UI/Workbench/WorkbenchWindow.h`
- `Main/Src/UI/Workbench/UiWorkbench.h`

#### D. 统一分发器接线
命令入口最终都应走：
- `OperationBus::run()` — 统一命令调度
- `UiInteractionDispatcher` — 鼠标 / 键盘事件转发
- `ToolManager::setActiveTool()` — 工具切换快速路径

### 4.3 这一步的验收标准

- 菜单点击有反应
- 工具条点击有反应
- 命令能进入
- 当前活动命令能识别
- 不再靠多个地方各自处理同一功能

## 5. 阶段 2：绘图基础

这一阶段先做最基础、最能验证主链的图元。

### 5.1 先做的功能顺序

1. 直线 `Line`
2. 多段线 `Polyline`
3. 圆 `Circle`
4. 圆弧 `Arc`
5. 多边形 `Polygon`

> 当前工具实现在 `UI/2D/Src/Ui/DrawTools/`，新工具继承 `ITool` / `BaseTool`，激活逻辑注册到 `OperationBus` / `ToolManager`。

---

### 5.2 直线 `Line`

#### 目标
- 鼠标两点确定一条线
- 预览实时跟随鼠标
- 确认后生成 `SyLine`
- 写入文档并刷新

#### 涉及文件
- `UI/2D/Src/Ui/DrawTools/LineTool.cpp`
- `UI/2D/Src/Ui/DrawTools/LineTool.h`
- `Engine/2D/Include/Engine2D/SyEntity/SyLine.h`
- `Engine/2D/Src/SyEntity/SyLine.cpp`
- `Main/Src/UI/Documents/SceneDocument2D.h`
- `Main/Src/UI/Documents/SceneDocument2D.cpp`

#### 命令设计建议
工具应提供：
- 起点采集
- 终点采集
- preview 更新
- commit
- cancel
- 退回选择模式

#### 关键技术点
- 统一坐标转换
- 统一屏幕坐标与文档坐标
- 预览线和正式线使用同一几何语义

---

### 5.3 多段线 `Polyline`

#### 目标
- 连续点击形成折线
- 双击 / Enter / 空格结束
- Backspace 回退最后一个点
- 生成 `SyLine` 的多点版本或专门折线模型

#### 涉及文件
- `UI/2D/Src/Ui/DrawTools/PolyLineTool.cpp`
- `UI/2D/Src/Ui/DrawTools/PolyLineTool.h`
- `Engine/2D/Include/Engine2D/SyEntity/SyLine.h`
- `Engine/2D/Src/SyEntity/SyLine.cpp`
- `Main/Src/UI/Documents/SceneDocument2D.h`

#### 关键技术点
- `SyLine::vPoints` 就是折线数据主体
- 预览状态不能写入正式文档
- `Backspace` 只删当前命令的临时输入，不做 undo

---

### 5.4 圆 `Circle`

#### 目标
- 第一次点击圆心
- 第二次点击半径点
- 生成 `SyCircle`
- 提交后刷新

#### 涉及文件
- `Engine/2D/Include/Engine2D/SyEntity/SyCircle.h`
- `Engine/2D/Src/SyEntity/SyCircle.cpp`
- `UI/2D/Src/Ui/DrawTools/CircleTool.cpp`
- `UI/2D/Src/Ui/DrawTools/CircleTool.h`

#### 关键技术点
- 半径计算要统一
- 预览和最终结果必须一致
- `basePoint` 应保持为圆心语义

---

### 5.5 圆弧 `Arc`

#### 目标
- 采集圆心、起点、终点或三点语义
- 生成 `SyArc`
- 角度单位统一为弧度

#### 涉及文件
- `Engine/2D/Include/Engine2D/SyEntity/SyArc.h`
- `Engine/2D/Src/SyEntity/SyArc.cpp`
- `UI/2D/Src/Ui/DrawTools/ArcTool.cpp`
- `UI/2D/Src/Ui/DrawTools/ArcTool.h`

#### 关键技术点
- 起止角归一化
- 弧方向保持一致
- 绘制后预览立即切换为正式图元

---

### 5.6 多边形 `Polygon`

#### 目标
- 生成规则多边形
- 支持边数调整
- `Ctrl + 滚轮` 调整参数
- 提交后生成 `SyPolygon`

#### 涉及文件
- `Engine/2D/Include/Engine2D/SyEntity/SyPolygon.h`
- `Engine/2D/Src/SyEntity/SyPolygon.cpp`
- `UI/2D/Src/Ui/DrawTools/PolygonTool.cpp`
- `UI/2D/Src/Ui/DrawTools/PolygonTool.h`

#### 关键技术点
- 它是规则多边形，不是任意闭合折线
- 边数、外接圆半径、中心点必须定义清楚
- 预览时要能实时显示边数变化

## 6. 阶段 3：选择与编辑

这一阶段开始把“画图”扩展到“改图”。

### 6.1 选择 `Select`

#### 目标
- 点选

- 取消选择

- `UI/2D/Src/Ui/DrawTools/SelectTool.cpp`
- `UI/2D/Src/Ui/DrawTools/SelectTool.h`
- `Main/Src/UI/Documents/SceneDocument2D.h`

#### 关键技术点
- selection 要和文档中的图元 ID 对应
- 不能把临时预览对象当作正式选择对象
- 选择变化后要刷新视口

### 6.2 删除 `Delete`

#### 目标
- 删除选中图元
- 支持撤销

#### 涉及文件
- `Main/Src/Composition/CoreOperationRegistry.cpp`
- `UI/2D/Include/UI2D/Operation/OperationBus.h`
- `Main/Src/UI/Documents/SceneDocument2D.h`
- `Engine/2D/Edit/SceneEditService.h`

#### 关键技术点
- 删除是文档变更，不是纯 UI 行为
- 删除后 selection 需要同步清理
- undo/redo 必须恢复删除前图元

### 6.3 移动 `Move`

#### 目标
- 选择对象后拖动移动
- 提交后写入新位置
- 支持撤销/重做

#### 涉及文件
- `Main/Src/Composition/CoreOperationRegistry.cpp`
- `UI/2D/Include/UI2D/Operation/OperationBus.h`
- `Main/Src/UI/Documents/SceneDocument2D.h`
- `Engine/2D/Include/Engine2D/SyEntity/SyEntity.h`

#### 关键技术点
- 使用图元快照或几何快照恢复
- 位移统一通过图元变换接口完成

### 6.4 旋转 `Rotate`

#### 目标
- 选择旋转中心
- 拖动生成旋转角度
- 提交后更新图元

#### 涉及文件
- `Main/Src/Composition/CoreOperationRegistry.cpp`
- `Main/Src/UI/Documents/SceneDocument2D.h`
- `Engine/2D/Include/Engine2D/SyEntity/SyEntity.h`

#### 关键技术点
- 旋转角度统一
- 旋转中心与默认中心逻辑要分开

### 6.5 复制 `Copy`

#### 目标
- 复制选中图元
- 生成新图元 ID
- 新图元默认选中

#### 涉及文件
- `Main/Src/Composition/CoreOperationRegistry.cpp`
- `Main/Src/UI/Documents/SceneDocument2D.h`

#### 关键技术点
- 复制不是原地修改，而是生成新对象
- undo/redo 时选中状态也要正确恢复

### 6.6 镜像 `Mirror`

#### 目标
- 选择镜像轴
- 对选中图元做镜像
- 支持撤销/重做

#### 涉及文件
- `Main/Src/Composition/CoreOperationRegistry.cpp`
- `Main/Src/UI/Documents/SceneDocument2D.h`
- `Engine/2D/Include/Engine2D/SyEntity/SyEntity.h`

#### 关键技术点
- 镜像后弧的方向、角度语义要正确处理
- 不要靠临时 UI 状态硬算结果

## 7. 阶段 4：刷新与撤销/重做

### 7.1 目标

让“提交后能看到结果”“撤销后回到之前状态”“重做后恢复”成为稳定能力。

### 7.2 核心文件
- `Engine/2D/Edit/SceneEditService.cpp`
- `Main/Src/UI/Documents/SceneDocument2D.h`
- `UI/2D/Src/Operation/OperationBus.cpp`
- `Main/Src/UI/Render/RenderViewport2D.cpp`
- `Main/Src/UI/Render/SceneRefreshCoordinator.cpp`

### 7.3 你要确保的事情

#### A. 命令提交后一定刷新
- 文档变更后触发刷新通知
- 视口按 `RefreshLevel`（Repaint / LightUpdate / FullRefresh）刷新

#### B. undo/redo 只针对正式提交结果
- 不处理鼠标移动中的临时状态
- 不处理还没提交的预览态

#### C. selection 同步恢复
- 撤销回去后 selection 应恢复合理状态
- 重做后也要正确恢复

## 9. 阶段 6：体验收口

这一阶段是把交互体验变顺、变一致。

### 9.1 键鼠语义统一

建议统一成：
- `Backspace`：回退当前命令最后一步输入
- `Esc`：取消当前命令
- `Enter` / `Space`：确认当前命令
- `双击`：结束多点工具
- `右键`：取消或结束当前命令

### 9.2 相关文件
- `Main/Src/UI/Render/RenderViewport2D.cpp`
- `Main/Src/UI/Render/ViewportInputRouter.cpp`
- `UI/2D/Src/Ui/DrawTools/*.cpp`
- `Main/Src/UI/Interaction/UiInteractionDispatcher.h`

### 9.3 体验收口要检查的点
- 键盘行为是否统一
- 不同命令的结束语义是否一致
- 取消后是否回到选择工具
- 预览是否即时清理
- 状态栏是否同步

## 10. 推荐的具体开发顺序

如果你现在真的开始写代码，推荐下面这个顺序。

### 第 1 步：把命令入口统一

先确保：
- 菜单项可点
- 工具条按钮可点
- 都进同一个命令系统
- 不再靠旧分支抢事件

### 第 2 步：做直线和多段线

这是最适合验证主链的功能。

### 第 3 步：做选择和删除

这是验证 selection 和文档刷新最好的功能。

### 第 4 步：做圆和圆弧

这是验证几何图元和预览一致性的功能。

### 第 5 步：做移动、旋转、复制、镜像

这是验证编辑链、快照、undo/redo 的功能。

### 第 6 步：再做多边形、Bezier、NURBS、SmartLine

这些功能更复杂，适合放在主链稳定后实现。

## 12. 你写代码时可以直接照着检查的清单

### 12.1 新增一个绘图功能前
- [ ] OperationId 定义了吗
- [ ] 菜单入口有了吗
- [ ] 工具条入口有了吗（`Workbench2D` 挂载）
- [ ] 工具类有了吗（`UI/2D/Src/Ui/DrawTools/`）
- [ ] 操作注册了吗（`ApplicationCompositionRoot` 或 `CoreOperationRegistry`）
- [ ] 对应图元类有了吗
- [ ] 文档写入接口有了吗
- [ ] 预览策略有了吗
- [ ] undo/redo 方案有了吗

### 12.2 新增一个编辑功能前
- [ ] selection 机制可用吗（`ViewportSelector` / `SceneEditService`）
- [ ] 变换接口可用吗
- [ ] 快照或恢复方式明确吗
- [ ] 取消和提交语义明确吗

### 12.3 新增一个图元前
- [ ] 它的语义单一吗

## 14. 最后给你的执行建议

如果你要真正开始做，不要试图一下子把所有 2D 功能都做完。

最稳的方式是：

1. 先统一入口
2. 再做线和多段线
3. 再做选择和删除
4. 再做圆和圆弧
5. 再做移动旋转复制镜像
6. 最后做复杂曲线

这样你每一步都能看到结果，也最容易定位问题。

## 15. 结论

这份路线图的核心意思是：

- `UI` 负责入口
- `OperationBus` + 工具负责流程
- `SceneDocument2D` 负责正式数据
- `SyEntity` 负责图元本体
- `Renderx` / `SanYiRender` 负责显示
- `Undo/Redo` 负责恢复正式结果

你后续就按这条线写代码，整个 2D 系统会越来越稳。
