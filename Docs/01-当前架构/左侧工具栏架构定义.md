# 左侧工具栏架构定义

## 1. 文档目标

本文档定义左侧工具栏的职责、内容边界、功能分类与架构设计。左侧工具栏通常承载高频绘图与基础建模入口，应尽量保持“创建型”“绘制型”“开始操作型”的特征。

---

## 2. 左侧工具栏在整体框架中的位置

```text
用户点击左侧工具栏
    → 工具状态切换
    → 命令系统激活
    → 视口开始捕获输入
    → 创建几何 / 进入交互式绘图流程
```

左侧工具栏属于 `UI` 层入口，不直接创建图元，不直接操纵文档对象，不直接实现几何算法。

---

## 3. 左侧工具栏的职责

左侧工具栏的主要职责是：

1. 提供高频绘图入口。
2. 提供快速创建基础图元的操作按钮。
3. 驱动当前绘图工具的启用与切换。
4. 维持与视口交互状态的一致性。
5. 与命令系统共享统一命令 ID。

---

## 4. 左侧工具栏应承载的内容

左侧工具栏建议优先承载以下内容：

- 选择工具 Select
- 直线 Line
- 圆 Circle
- 圆弧 Arc
- 多段线 Polyline
- 多边形 Polygon
- 矩形 Rectangle
- 椭圆 Ellipse
- 样条 Spline
- 点 Point
- 基础辅助绘图入口 Basic Drawing Tools

如果项目中存在更专业的加工几何创建工具，也可以放置在这里，但原则仍然是：**高频、创建型、面向绘图过程**。

---

## 5. 左侧工具栏不应承载的内容

- 低频系统设置
- 文件打开保存
- 复杂参数对话框入口
- 工艺库管理
- 仿真控制
- 设备连接
- 状态提示类信息
- 纯显示切换项

这些内容应分别放在菜单、右侧工具栏、顶部工具栏或状态栏。

---

## 6. 左侧工具栏的功能分类

建议分成三类：

### 6.1 基础选择类

用于切换交互模式，例如：

- 选择
- 框选
- 点选
- 平移辅助

### 6.2 几何创建类

用于新建基础图元，例如：

- 线
- 圆
- 圆弧
- 多段线
- 多边形
- 矩形
- 椭圆
- 样条

### 6.3 辅助绘图类

用于绘图过程中的辅助功能，例如：

- 正交
- 捕捉
- 极轴辅助
- 辅助网格
- 临时约束

---

## 7. 左侧工具栏与命令系统关系

左侧工具栏的按钮点击后应只做一件事：激活一个命令或工具模式。

```text
Toolbar Button
    → Command ID / Tool ID
    → Command Dispatcher / OperationBus
    → Tool State / Interaction State
    → Viewport Input Handling
```

### 7.1 设计要求

- 每个按钮必须有稳定命令 ID。
- 工具栏按钮不得直接创建图元。
- 工具栏状态必须与当前工具状态同步。
- 工具栏应支持高亮当前工具。
- 工具栏应支持禁用不可用动作。

---

## 8. 左侧工具栏与框架设计

### 8.1 依赖约束

- 左侧工具栏依赖 `UI` 公共层、状态中心和命令系统。
- 左侧工具栏不得依赖 `Engine` 具体算法实现。
- 左侧工具栏不得直接操作场景和渲染后端。

### 8.2 数据来源

按钮可用性和当前状态应来自：

- 当前工具状态
- 当前文档类型
- 当前视图模式
- 当前是否正在绘图
- 当前是否存在选择集

### 8.3 交互原则

- 高点击频率动作放在左侧工具栏。
- 工具切换应尽量单击完成。
- 工具栏按钮名称应短、明确、可识别。
- 图标优先于长文本，必要时提供文字提示。

## 10. 当前框架下的实现建议

结合现有架构，左侧工具栏应通过以下方式构建：

1. 由 `Main` 或工作台初始化。
2. 按工具类别组织按钮组。
3. 通过命令分发器激活工具状态。
4. 通过状态中心同步选中状态。
5. 通过视口反馈当前交互阶段。

## 11. 当前实际架构（2026-07-28 更新）

### 11.1 工具系统架构

当前绘图功能采用 **ToolManager + ITool** 架构，而非 IInteractionDispatcher 命令系统：

```text
左侧工具栏按钮
    → OperationBus::run(Tool_XXX)
    → LambdaOperation（在 registerPendingToolOperations 中注册）
    → viewport->setActiveTool(toolName)
    → ToolManager::setActiveTool(toolName)
    → 对应 ITool 实现的 onMousePress/onMouseMove/onMouseRelease
    → emitEntity() → SceneEditService::addEntityFromPointer()
    → SceneManager → 渲染刷新
```

### 11.2 已注册工具清单

在 `ToolInitializer::registerAllTools()` 中注册的工具：

| OperationId | 工具名称 | 实现类 | 状态 |
|---|---|---|---|
| Tool_Select | SelectTool | SelectTool | ✅ |
| Tool_Point | PointTool | PointTool | ✅ |
| Tool_Line | LineTool | LineTool | ✅ |
| Tool_Polyline | PolyLineTool | PolyLineTool | ✅ |
| Tool_Polygon | PolygonTool | PolygonTool | ✅ |
| Tool_Bezier2 | Bezier2Tool | Bezier2Tool | ✅ |
| Tool_Bezier | BezierTool | BezierTool | ✅ |
| Tool_Spline | SplineTool | SplineTool | ✅ |
| Tool_Nurbs | NurbsTool | NurbsTool | ✅ |
| Tool_SmartLine | SmartLineTool | SmartLineTool | ✅ |
| Tool_Circle | CircleTool | CircleTool | ✅ |
| Tool_Arc | ArcTool | ArcTool | ✅ |
| Tool_Ellipse | EllipseTool | EllipseTool | ✅ |
| Tool_Rectangle | RectangleTool | RectangleTool | ✅ |
| Tool_Triangle | TriangleTool | TriangleTool | ✅ |
| Tool_Text | TextInputTool | TextInputTool | ✅ |
| Tool_Bitmap | BitmapInputTool | BitmapInputTool | ✅ |
| Tool_QRCode | QRCodeInputTool | QRCodeInputTool | ✅ |

### 11.3 工具名称映射规则

在 `ApplicationCompositionRoot.cpp` 的 `toolNameFromOperationId()` 中维护 OperationId → 工具名称的映射：

- 映射名称必须与 `ToolInitializer::registerAllTools()` 中注册的名称完全一致
- 对话框类工具使用 `XxxInputTool` 命名（如 TextInputTool、BitmapInputTool、QRCodeInputTool）
- 绘图类工具使用 `XxxTool` 命名（如 PointTool、LineTool、CircleTool）

### 11.4 事件处理优先级

在 `RenderViewport2D::mousePressEvent()` 中，事件处理优先级为：

1. **中键**：平移模式
2. **左键 + 平移模式**：平移
3. **左键 + IInteractionDispatcher 有活动命令**：转发到 dispatcher（当前为空实现）
4. **左键 + ToolManager 有活动工具**：转发到 ITool 实现
5. **左键 + Selector**：选择

**注意**：当前实际工作的路径是第 4 条（ToolManager 路径），IInteractionDispatcher 为未来预留。

---

## 12. 设计原则总结

左侧工具栏是“绘图入口层”，不是“业务层”。它应稳定、快速、明确，服务于高频创建动作。对于大型激光软件，左侧工具栏的目标不是多，而是准：只放最常用、最接近图元创建的一组动作。
