# 序列化架构定义

> **文档状态**：✅ 已对齐代码（2026-08-26）
> **适用版本**：统一 NativeWriter + 导入侧中立 IR（IrPublisher/IrProjector）重构后
> **维护者**：架构组


---

## 1. 概述

序列化模块负责 CAD 文档的持久化存储，支持 2D (.sy) 和 3D (.syx) 原生格式，以及 DXF/SVG/PLT/STEP 等交换格式。

核心设计原则：
- **2D/3D 统一**：通过 `FileFormat` 参数区分行为，消除代码重复
- **DLL 安全**：公共 API 使用 POD 类型，不暴露 STL 容器
- **可扩展**：新增格式只需实现 `IFileWriter`/`IFileParser` 并注册

## 3. 核心组件

### 3.1 SySerializer（文件格式核心）

**位置**：`FileIO/FileIO/Src/SySerializer.cpp`
**职责**：文档与二进制文件的双向转换

文件格式结构：
```
┌───────────────┬──────────────┬──────────────┬──────────────┐
│ Magic (4B)    │ Version (4B) │ Flags (4B)   │ DataLen (4B) │  ← 16 字节文件头
├───────────────┴──────────────┴──────────────┴──────────────┤
│ Protobuf 序列化数据 (可选加密)                              │
├────────────────────────────────────────────────────────────┤
│ CRC32 校验 (4B)                                           │  ← 文件尾
└────────────────────────────────────────────────────────────┘
```

魔数选择：
- `.sy` 文件 → `"SYPB"` (SY ProtoBinary)
- `.syx` 文件 → `"SXPB"` (SYX ProtoBinary)

关键接口：
```cpp
// 格式感知的保存（推荐）
SerializeResult saveToFile(const char* filePath, const SyDocument& doc,
    bool encrypt, FileFormat fmt, ...);

// 向后兼容（默认 2D）
SerializeResult saveToFile(const char* filePath, const SyDocument& doc,
    bool encrypt, ...);
```

### 3.2 NativeWriter/NativeParser（统一 2D/3D）

**位置**：`FileIO/FileIO/Src/Writers/NativeWriter.cpp`, `FileIO/FileIO/Src/Parsers/NativeParser.cpp`

通过构造参数 `FileFormat` 区分行为：
```cpp
// 2D 写入器
NativeWriter writer(FileFormat::Native);      // → magic "SYPB", ext ".sy"

// 3D 写入器
NativeWriter writer(FileFormat::Native3D);    // → magic "SXPB", ext ".syx"
```

两种路径：
1. **ILegacyWriter::write()** — 兼容旧路径，仅处理 2D 图元
2. **writeDocument()** — 推荐路径，支持 2D + 3D 混合文档

### 3.3 SyDocument / SyDocument3D（文档数据模型）

**位置**：`FileIO/Include/FileIO/SyDocument.h`, `SyDocument3D.h`

PIMPL 设计，跨 DLL 安全：
- `SyDocument` — 2D 图元 + 图层 + 硬件信息 + 元数据
- `SyDocument3D` — 3D 网格图元（独立类，避免 Engine2D 依赖 Engine3D）

### 3.4 MetadataFiller（元数据填充工具）

**位置**：`FileIO/FileIO/Src/Internal/MetadataFiller.h`

纯函数式接口，集中处理：
- 软件名称/版本
- 时间戳（ISO 8601）
- 操作系统信息
- 设备序列号、电脑用户名（环境溯源）

### 3.5 导入侧中立 IR（IrPublisher / IrProjector / IrTransform）

**位置**：`FileIO/FileIO/Src/Internal/IrProjector.h|.cpp`、`IrTransform.h|.cpp`
**对外契约**：`FileIO/FileIO/Include/FileIO/FioTypes.h`
**转换层**：`Engine/3D/Src/Import/FioEntityConverter.cpp`（`Eg::FioEntityConverter`）

导入侧不向外暴露任何 Engine 类型：解析器统一产出 `Fio::FioParseResult`（纯 POD），
由 `Eg::FioEntityConverter` 翻译成 `SyEntity` / `SyMeshEntity`。三个组件各司其职：

- **`IrPublisher`** —— `thread_local` 缓冲区的**唯一所有者**。`threadLocal()` 取本线程实例，
  `reset()` 清空，`entities()/layers()/groups()/blob()` 追加，`publish(sourceFormat, sourceUnit)`
  产出 `FioParseResult`。解析器**不得**自建 `thread_local` 缓冲区
  （以前各解析器各建一套，导致 extensionBlob 布局漂移）。
- **`IrProjector::project(ParseData&, sourceFormat)`** —— 解析期结构 → IR 的唯一投影点：
  图层 / 群组 id 稠密重编号（1-based，0 保留为哨兵）、父引用重映射、
  缺失父级降级为顶层并告警、成环打断并告警、几何按类型投影，复杂数据进 `extensionBlob`。
- **`IrTransform`（`IrXform` + `transformEntity`）** —— 2D 仿射变换的唯一实现。
  被 DXF `INSERT` 展开（含阵列/嵌套）、镜像复用；相似变换下圆/圆弧保形，
  `det() < 0` 时圆弧起止角互换，非等比缩放退化为椭圆。

**转换层为什么在 Engine3D**：它要同时构造 Engine2D 的十几种图元与 Engine3D 的
`SyMeshEntity`，而依赖方向是 Engine3D → Engine2D，Engine3D 是唯一能同时看到两侧的层级。
放在 `Main` 时 UI3D 用不到，这正是 `Engine/3D` 里曾经存在第二套 `StlLoader`/`ObjLoader`
的根因；下移后那两个类已删除，UI3D 的 OBJ/STL 导入也走 FileIO。
注意 Engine3D 只**包含** FileIO 的公开头（`FioTypes.h`，纯 POD 无导出符号），
**不链接** FileIO —— FileIO 反过来链接 Engine2D/Engine3D，链接就成环。

**内存契约（跨 DLL 关键约束）**：`entities / layers / groups / extensionBlob.data` 均为
借用指针，指向 FileIO 内部 `thread_local` 缓冲区——只读、不可释放、有效期仅到
「同一线程下一次解析」为止，不可跨线程保存。读取 `extensionBlob` 前必须校验
`extensionDataOffset + extensionDataSize <= extensionBlob.size`
（落地实现：`FioEntityConverter::extensionRangeValid()`）。

**图层 / 颜色 / 群组 / 位图四条通道**：

| 通道 | IR 载体 | 消费者 |
|------|---------|--------|
| 图层 | `layers[]` + `EntityInfo::layerSourceId` | `ImportService::restoreImportedLayers` |
| 实体色 | `EntityInfo::color`（0xAARRGGBB，0=未指定） | 转换层按覆盖色应用 |
| 群组 | `groups[]` + `EntityInfo::groupSourceId` | `ImportService::restoreImportedGroups` → `Eg::GroupManager` |
| 位图 | `EntityType::Image` + `imageWidth/Height` + extensionBlob | `FioEntityConverter` |

群组成员关系**只单向记录**：实体记 `groupSourceId`，`IrGroupInfo` 只记 `parentSourceId`，
不存成员列表——与 `layerSourceId` 同构、双向存储不一致时无裁决依据、少一处越界校验点。

格式级细节（各格式依赖库、实体覆盖、已知缺口）见 `FileIO/README.md`。

## 4. 2D/3D 文件对应关系

| 格式 | 扩展名 | 魔数 | 写入器 | 读取器 | 说明 |
|------|--------|------|--------|--------|------|
| Native | `.sy` | SYPB | NativeWriter(Native) | NativeParser(Native) | 2D 原生格式 |
| Native3D | `.syx` | SXPB | NativeWriter(Native3D) | NativeParser(Native3D) | 3D 原生格式 |
| DXF | `.dxf` | — | DxfWriter | DxfParser | AutoCAD 交换格式 |
| SVG | `.svg` `.svgz` | — | SvgWriter | SvgParser | 矢量图形（svgz 需 zlib） |
| PLT | `.plt` `.hpgl` | — | PltWriter | PltParser | HPGL 绘图仪 |
| IGES | `.igs` `.iges` | — | UgWriter | UgParser | Siemens NX / UG |
| STEP | `.stp/.step` | — | StepExportWriter | StepParser | ISO-10303 3D |
| PDF | `.pdf` | — | PdfExportWriter | PdfParser | 经 pdftocairo 转 SVG 后解析 |
| AI | `.ai` | — | — | AiParser | pdftocairo / Ghostscript 两条路 |
| OBJ | `.obj` | — | ObjExportWriter | ObjParser | Wavefront 3D |
| STL | `.stl` | — | — | StlParser | 立体光刻 3D，ASCII/二进制自动识别 |
| BMP/PNG | `.bmp` `.png` | — | — | —（无 parser） | 只在 FormatRegistry 登记扩展名；解码走 `Fio::loadImageToRgba` |

> **写入器归属**：`FileWriterFactory::initDefaults()` 只注册 DXF / SVG / PLT / UG /
> Native / Native3D 六种；表中 `StepExportWriter` / `PdfExportWriter` / `ObjExportWriter`
> 是 `Main/Src/Export/Writers/` 下的 Main 侧写出器，不在 FileIO DLL 内。

## 5. 序列化流程

### 5.1 保存流程 (File_Save)

```
用户点击保存
    │
    ▼
FileOperationRegistry::doExport(filePath)
    │
    ▼
ExportService::exportFile(filePath)
    │
    ├─ collectAllEntities()  ← 2D 图元
    │
    ▼
ExportDispatcher::dispatch(context, entities)
    │
    ├─ detectFormat(filePath)  ← 根据扩展名检测格式
    │
    ▼
NativeExportWriter::write(context, entities)
    │
    ├─ FileIOManager::exportFile(path, format, entities)
    │
    ▼
FileWriterFactory::createWriter(format)
    │
    ├─ NativeWriter(format)  ← 根据格式创建对应写入器
    │
    ▼
NativeWriter::write(filePath, entities)
    │
    ├─ MetadataFiller::fillMetadata(doc, softwareName, version)
    ├─ doc.addEntity(entity->clone())
    │
    ▼
SySerializer::saveToFile(filePath, doc, encrypt, format)
    │
    ├─ serializeToProto(doc, protoData)
    │   └─ SyEntitySerializer::serializeEntity(entity, protoEntity)
    │
    ├─ 选择魔数 (SYPB / SXPB)
    ├─ 计算 CRC32
    └─ 写入文件
```

### 5.2 加载流程 (File_Open)

原生格式（.sy/.syx）与交换格式（DXF/SVG/PLT/OBJ/STL/…）走的是**同一条链路**，
差别只在解析器内部：

```
用户打开文件
    │
    ▼
FileOperationRegistry::doOpenFile(filePath)
    │
    ▼
ImportService::importWithContext(context, opts)
    │
    ├─ Phase 1: FormatRegistry::detectFormat(filePath)
    │
    ├─ Phase 2: ImportDispatcher::dispatch(context, entities)
    │           └─ IImportReader → ImportReaderBase::readViaIR(context, format, out, collectLayers)
    │               ├─ FileParserFactory::createParser(format)
    │               ├─ IFileParser::parseToIR(path)              ← FileIO DLL 内
    │               │   ├─ 格式专属解析 → ParseData
    │               │   ├─ IrProjector::project(...)  ← id 稠密化 / 缺父降级 / 成环打断
    │               │   └─ IrPublisher::publish(...)  → FioParseResult（借用 POD）
    │               ├─ Eg::FioEntityConverter::convertAll(ir, &entityLayerMap, &entityGroupMap)
    │               │   └─ 逐实体校验 extensionBlob 范围后建 SyEntity
    │               └─ 填 ImportResult::importedLayers / importedGroups / entity*Map
    │
    ├─ Phase 3: buildDocument（加入场景后再还原结构）
    │           ├─ restoreImportedLayers(...)  → LayerManager（按名 → 按色 → 新建）
    │           └─ restoreImportedGroups(...)  → GroupManager（父子重建 + wouldCreateCycle 兜底）
    ├─ Phase 4: refreshDisplay（视口/树/属性）
    └─ Phase 5: writeBackState（最近文件/状态栏）
```

原生格式在 Phase 2 内部额外经过
`SySerializer::loadFromFile`（魔数 + 版本 + CRC32 校验 + 可选解密 → protobuf 反序列化）。

**顺序约束**：图层与群组的还原必须在图元加入场景之后进行——`entityGroupMap` 的键是
运行时 `EntityId`，只有入场景后才能用 `SceneManager::findEntityById` 反查到实体。

## 7. 当前架构决策摘要

当前保持的设计决策（不含历史时间线）：

1. **统一 NativeWriter / NativeParser**：2D / 3D 共用一套写入器与解析器，通过 `FileFormat` 参数区分行为（Native → SYPB / .sy；Native3D → SXPB / .syx）。
2. **SySerializer 带 format 参数**：序列化门面显式接收目标格式，保证魔数写入正确。
3. **MetadataFiller 集中元数据**：跨平台系统信息获取逻辑统一管理。
4. **SyDocument PIMPL**：避免 STL 类型跨越 DLL 边界。
5. **IFileWriter 内部化**：write()/parse() 收敛到 FileIO 内部接口，公共 ABI 只暴露稳定形态。
6. **导入侧只走中立 IR**：解析器统一产出 `FioParseResult`（纯 POD），Engine 类型不跨 DLL 边界；
   `FioTypes.h` 内不引入 `std::` 容器与虚函数，这是 FileIO 可独立编译、可被其它软件复用的前提。
7. **IR 缓冲区单一所有者**：`IrPublisher` 是唯一的 `thread_local` 缓冲区持有者，
   `IrProjector` 是唯一的投影点。解析器自建缓冲区会导致 extensionBlob 布局漂移与
   id 规范化缺失，一律禁止。
8. **转换层落在 Engine3D**：`Eg::FioEntityConverter` 需要同时构造 Engine2D 图元与
   `SyMeshEntity`，Engine3D 是唯一能同时看到两侧的层级；Engine3D 只包含 FileIO 的
   POD 头、不链接 FileIO（否则与 FileIO→Engine 成环）。
9. **2D/3D 导入链路同构**：`FormatRegistry → FileParserFactory → parseToIR → IR → 转换层`，
   3D 只是产出 `EntityType::Mesh3D`；Main 侧所有 reader 都收敛到 `readViaIR` 一行，
   UI3D 的 OBJ/STL 也走同一条链路（原 `Engine/3D` 的 StlLoader/ObjLoader 已删除）。
10. **群组成员关系单向记录**：实体记 `groupSourceId`，群组只记 `parentSourceId`，
    与 `layerSourceId` 同构；畸形结构（缺父/成环）由 IR 侧降级并告警，消费侧再兜底一次。
11. **导出侧仍直接吃 SyEntity**：`Writers/` 靠 `dynamic_cast` 分派图元子类，
    这是已知技术债（FileIO 因此仍依赖 Engine2D/Engine3D）。切到 IR 后依赖闭包可缩到
    `Utility + Log`，分期计划见 `FileIO/README.md` §11。


> 新增决策时追加到本节即可，不保留阶段时间线。
