# 当前架构总览

> 本文只描述当前工作树中已确认的生产主路径，以及后续仍需继续收口的方向，不保留阶段性历史记录。

---

## 1. 系统分层架构

```text
SanYiCAD.exe
├── UI 层
│   ├── UICommon
│   ├── UI2D
│   └── UI3D
├── 核心层
│   ├── EngineCommon
│   ├── Engine2D
│   ├── Engine3D
│   ├── EnginePersistence
│   └── FileIO
├── 渲染层
│   └── Renderx / RenderX
└── 基础设施层
    ├── Utility
    ├── Log
    ├── CrashHandler
    └── Licensing
```

## 3. 当前边界

### 3.1 渲染边界

当前生产渲染统一由 `Renderx` / `RenderX` 承担。

### 3.2 2D 边界

2D 生产路径为：

```text
SceneDocument2D → SceneManager → RenderSceneBuilder (GeometryStore + DrawList) → RenderWidget → Renderx / RenderX
```

### 3.3 3D 边界

3D 生产路径以 `Workbench3D`、`Viewport3D`、`ViewportRendererFactory`（原 `Renderer3DFactory`，2026-09-12 更名）、`RenderWidget3DAdapter`、`RenderWidget3D`、`IRenderer3D` 组成当前链路，核心几何提交走 `Mesh3DBuilder`（`GeometryStore` + `DrawList`）对接 `Renderx`。

### 3.4 命令边界

命令统一由 `OperationBus` 调度，菜单、工具栏、快捷键共享同一命令语义。操作注册按职责拆分为四个子注册器：`EditOperationRegistry`（编辑）、`ViewOperationRegistry`（视图）、`AlgorithmOperationRegistry`（算法）、`HelpOperationRegistry`（帮助），由 `CoreOperationRegistry` 外观类统一调度。**`OperationRouting::setOperationBus()` 已移除，`dispatch()` 签名改为 `dispatch(MenuActionId, OperationBus*, ...)`，所有调用方显式传递 bus 实例。**

---

## 4. 当前约束

1. 核心层不依赖 UI。
2. 渲染层不依赖 UI 和业务真相。
3. UI 只保留入口、交互和状态同步。
4. C ABI 对外契约只暴露句柄、POD、错误码和版本约束。
5. 旧模块名只作为“已替换/已删除”的说明，不再扩展成新主线。

---

## 5. 当前需要继续收口的方向

- 继续统一 ABI 风格和错误码风格
- 继续压缩 UI 与实现细节之间的耦合
- 继续清理文档中的旧术语、旧路径和旧模块名
- 继续把历史分析文档改写成当前现状 + 后续计划
- **2D/3D 命令体系分裂**：两套 `OperationId` / `CommandCatalog` / `CommandActionHub` / `OperationBus`，约 15 个同名命令重复注册（详见下方 §8）
- **SceneRefreshCoordinator 上帝类**：承担脏图元收集、合并渲染批次、16ms 节流、3D 增量与全量刷新协调等多重职责，需后续拆分为独立调度器

## 6. 主要调用链

### 6.1 菜单命令 → Engine 调用链

```text
JSON 菜单配置（base.json）
→ UiConfigLoader 加载 + extends 继承合并
→ UiLayoutBuilder 按配置构建 QMenu/QToolBar
→ CommandActionHub 绑定 QAction::triggered → OperationBus::run(commandId)
→ CommandCatalog::operationForCommandId 查找 handler（2D: CommandCatalog，3D: CommandCatalog3D）
→ handler->begin(commandId)（同步 UiStateCenter 状态）
→ handler->activate()（进入命令生命周期）
→ 用户事件 → handler 内部操作 SceneEditService / SceneEditService3D
→ SceneEditService 修改 SceneManager → notifySceneChanged()
→ SceneRefreshCoordinator / SceneRefreshCoordinator3D 接收变更
```

**注意**：2D 和 3D 各有一套独立的 `CommandCatalog`、`OperationBus`、`CommandActionHub`，命令注册互不共享。`WorkbenchBase::isCommandRegistered()` 已改为直接静态查询命令目录（2D: `CommandCatalog::operationForCommandId`，3D: `CommandCatalog3D`），不再委托给未实例化的分发对象。

**2D 写入口约束**：`SceneEditService` 是 UI/Main 生产代码**唯一**的场景写入口。`Eg::SceneManager` 的实体增删接口（`addEntity(s)` / `deleteEntity(ies)` / `insert(extract|replace)*`）已降为 private，只对 `SceneEditService` 与 `Engine2D` 内部/测试使用的 `Eg::SceneWriteGateway` 开放。生产代码引用网关会被 `CMake/SceneWriteSurface.cmake` 在 configure 阶段拒绝。3D 侧尚未做同等收敛。

### 6.2 撤销 / 重做调用链

```text
用户触发 Ctrl+Z / Ctrl+Y / 菜单按钮
→ CommandActionHub → OperationBus::run(Edit_Undo / Edit_Redo)
→ LambdaOperation → ctx.undoManager->undo() / redo()
→ UndoRedoManager 弹出栈顶命令 → cmd->undo() / redo()
→ 命令内部与 SceneManager 交换状态（EntitySnapshotsCommand 零克隆交换）
→ QtUndoRedoBridge 发出 sigCanUndoChanged / sigCanRedoChanged
→ CommandActionHub::refreshCommandUiState() → 菜单/工具栏按钮灰显更新
```

**约束**：所有 UndoCommand 必须实现完整的 `redo()` 方法，确保撤销/重做闭环。跨撤销/重做持有的 `SyEntity*` 指针会失效，必须缓存 id 而不是指针（见 [`撤销重做机制.md`](../02-变换与交互/撤销重做机制.md) §3.4）。

### 6.3 渲染刷新调用链（7 层跨 3 模块）

```text
Engine 变更（SceneEditService / SceneEditService3D）
  ↓ notifySceneChanged() / recordChange()
SceneRefreshCoordinator（UI 层）— 脏图元记账 + 16ms 节流
  ↓ 定时器到期 → requestRefresh()
RenderSceneBuilder（UI 层）— 从 SceneManager 提取几何、组织 DrawList
  ↓ upsertEntities() 增删改常驻几何仓条目
PersistentGeometryStore（RenderBridge 层）— 2D/3D 共用的几何存储与绘制命令管理
  ↓ GeometryManager::allocBlock() / upsertDrawItem()
RenderBridge（RenderBridge 层）— 常驻几何仓生命周期、绘制列表 upsert、覆盖层容器
  ↓ submitSceneFromDataSource() / addRenderEntity()（需 makeCurrent 保证 GL 上下文）
Renderx / RenderX（渲染层）— renderSubmitGeometry() → renderFrame() → GPU 执行
  ↓
屏幕刷新
```

**关键特性**：
- 帧合并机制：`QueuedConnection | UniqueConnection` 保证每帧最多一次 `update()`
- 增量渲染：3D 已完成阶段 3（按脏 ID 增量同步），FullRefresh 退为兜底
- 实体显隐已纳入刷新链（VisibilityChanged 变更日志）；实体锁定不进刷新链（纯元数据）

## 8. 2D/3D 命令体系分裂现状

**当前状态**：2D 和 3D 各有一套独立的命令体系，约 15 个同名命令重复注册：

| 分裂项 | 2D | 3D |
|--------|----|----|
| 命令目录 | `UI/2D/Src/Operation/CommandCatalog.cpp` | `UI/3D/.../CommandCatalog3D.cpp` |
| 运行时总线 | `OperationBus`（UI/2D） | 3D 侧同名或独立总线 |
| UI 动作中心 | `CommandActionHub`（2D） | 3D 独立实例 |
| 命令 ID 枚举 | `EditOperationId` | 3D 侧独立枚举 |
| 实现方式 | `EditOperationRegistry` + `ViewOperationRegistry` + `AlgorithmOperationRegistry` + `HelpOperationRegistry` | 3D 侧同类注册器 |

**已收口的部分**：
- 工具栏数据驱动：`base.json` 的 `toolbars` 数组（4 条），2D Default 上下文 + 3D 三条工具栏已走 JSON 装配
- `skippedByBuilder` 机制：避免 Workbench 自构建与 JSON 自动构建冲突
- `WorkbenchBase::isCommandRegistered()` 已改为直接静态查询命令目录，不再依赖未实例化的分发对象

**仍硬编码的部分**：2D 非 Default 上下文（TextEditing 等 5 个）、MoreViews 工具栏；`RightToolBar` 2D/3D 同名不同义；2D 状态栏信息区被隐藏；3D 工具栏 reparent 双生命周期。

## 9. 全局常量定义

### 9.1 版本信息

版本定义在 `Main/Src/Common/VersionInfo.h.in`（CMake 模板），由构建系统生成 `Main/VersionInfo.h`：

| 宏/函数 | 值 | 说明 |
|---------|-----|------|
| `APP_NAME` | "SanYiCAD" | 应用名称 |
| `APP_VERSION` | "1.0.0" | 应用版本 |
| `VERSION_MAJOR` | 1 | 主版本号 |
| `VERSION_MINOR` | 0 | 次版本号 |
| `VERSION_PATCH` | 0 | 补丁版本号 |
| `APP_ORGANIZATION_NAME` | "SanYi" | 组织名称 |
| `APP_ORGANIZATION_DOMAIN` | "sanyi-cad.com" | 组织域名 |

**访问接口：**
- `MainApp::appName()` - 应用名称
- `MainApp::appVersion()` - 应用版本字符串
- `MainApp::versionMajor()` / `versionMinor()` / `versionPatch()` - 版本号分量
- `MainApp::organizationName()` - 组织名称
- `QCoreApplication::applicationVersion()` - Qt 应用版本
