## 3. 关键架构边界

### 3.1 ABI 安全边界（C API Facade）

以下模块提供 **纯 C ABI**，供外部（插件、Python、其他语言）安全调用：

| 模块 | C API 头文件 | 句柄风格 | 错误码 |
|------|-------------|----------|--------|
| Log | `SyLogger.h` | 全局单例 | 无 |
| Engine | `EngineAPI.h` | 无 | `int` |
| Nesting | `NestingDLL.h` | `NestingJobHandle`（`void*`） | `NestingResultCode` |
| Vision | `VisionDLL.h` | `VisionImageHandle` 等 | `VisionResultCode` |
| GeoModelCore | `GeoModelDLL.h` | `GeoModelHandle` | `GeoModelResultCode` |
| Engraving | `EngravingCAPI.h` | `EngravingVolumeHandle`（类型安全） | `EngravingResultCode` |
| SanYiRender | `render/render.h` | `RenderDevice*`（不透明结构体） | 无 |

**统一规范参考**：`Docs/DLL标准.md`

### 3.2 内部 C++ 协作边界

- **Engine2D/3D ↔ SanYiRender**：通过 `SceneManager`、`SceneDocument`、`RenderWidget`、`SceneGeometrySinkAdapter`、`RenderWidget3D` 等纯 C++ 接口协作
- **UI2D/3D ↔ SanYiRender**：UI 层通过 `Renderx` 的 C API 驱动渲染设备，2D 使用 `RenderWidget` + `SceneGeometrySinkAdapter`，3D 使用 `RenderWidget3D` / `RenderWidget3DAdapter`
- **FileIO ↔ Engine**：通过 `EnginePersistence` 序列化协议交换数据
- **菜单/工具栏 ↔ 命令执行层**：菜单和工具栏都只保存“命令入口”，不直接实现业务逻辑，统一转发到 `OperationBus`、工作台命令分发器或主题/语言服务

### 3.3 渲染架构分层（当前对齐）

当前渲染链路以 **Renderx / SanYiRender** 为唯一统一后端。


### 3.4 菜单与工具栏的逻辑关系

菜单与工具栏在架构上是两种不同的 UI 呈现，但它们通常调用同一批业务功能：

- **菜单**更适合承载层级化、发现性强、说明文字更完整的入口
- **工具栏**更适合承载高频、一步直达、需要图标快速识别的入口
- **二者的共同点**是：都只保存“命令入口”，不重复实现业务逻辑
- **二者的差异**是：菜单更偏组织结构，工具栏更偏快捷操作

因此，**菜单、工具栏、快捷键是同一功能的三个入口层**，它们共享同一执行逻辑，只是展示形态不同。切换工作台时，三者都应按当前工作台的配置和状态重新同步，避免残留与混淆。

## 4. 数据流向总览

### 4.1 2D 编辑 → 渲染流

```text
用户交互 (Main/Src/UI/Render/RenderViewport2D)
    → ToolManager / OperationBus
    → SceneEditService (文档事务 + Undo/Redo)
    → SceneDocument2D (图元增删改)
    → sigSceneChanged()
    → RenderViewport2D::updateSceneRender()
        ├─→ RefreshLevel::LightUpdate → 增量提交 (addRenderEntity/modifyRenderEntity/removeRenderEntity)
        └─→ RefreshLevel::FullRefresh → RenderWidget::submitSceneFromDataSource()
            ├─→ renderBeginScene()
            ├─→ SceneManager::gatherGeometry(sink)
            └─→ renderEndScene()
    → paintGL() → renderFrame()
        ├─→ world2D.update()
        ├─→ world2D.queryVisible()
        ├─→ batchQueue.submit()/render()
        └─→ overlayQueue.render()
    → 屏幕呈现
```

### 4.2 3D 场景 → 渲染流

```text
用户交互 (UiViewport3D / Workbench3D)
    → RenderWidget3DAdapter
    → RenderWidget3D
    → SceneDocument3D / SceneManager3D
    → SanYiRender / OpenGL 渲染链
    → 屏幕呈现
```

> `SimpleRenderer3D`、`Renderer3DFactory` 等实现仍可能存在于代码库中，主要用于兼容、测试或辅助路径；当前文档不将其描述为唯一生产链路。

### 4.3 文档 → 渲染数据流

详见 `Docs/03-渲染主链/document-to-renderdata-flow.md`。

```text
Document / Scene
    → Selection / 状态
    → Render Data (批次、高亮、预览)
    → GPU Renderer
    → Viewport
    → Screen
```

## 6. 当前已知技术债

| 项 | 模块 | 影响 | 优先级 | 计划 |
|----|------|------|--------|------|
| 句柄风格不统一 | Nesting / Vision / GeoModelCore / Engraving | 跨模块调用易错 | P1 | 统一为不透明结构体指针 |

## 7. 命令系统架构（当前实现）

### 7.1 命令系统现状

当前命令系统采用纯 `OperationBus` + `LambdaOperation` 模式，由三个注册表分层管理：

| 注册表 | 职责 | 文件 |
|--------|------|------|
| `CoreOperationRegistry` | 编辑、算法、视图等核心操作 | `Main/Src/Composition/CoreOperationRegistry.cpp` |
| `FileOperationRegistry` | 文件打开/保存/导入/导出 | `Main/Src/Composition/FileOperationRegistry.cpp` |
| `PendingOperationRegistry` | 未接入操作占位（当前为空） | `Main/Src/Composition/PendingOperationRegistry.cpp` |

组合根 `ApplicationCompositionRoot` 通过 `registerAllOperations()` 统一调用三个注册表。

### 7.2 命令执行路径

```text
用户操作 (按钮/菜单/快捷键)
    │
    ▼
OperationBus::run(opId) → 统一命令调度
    │
    └─→ LambdaOperation / ParamLambdaOperation
            └─→ 捕获服务引用，直接调用对应 Service
```

所有命令统一注册为 `LambdaOperation`，不经过中间适配层。交互式命令生命周期由 `IInteractionDispatcher` 管理。

### 7.3 撤销/重做机制

Undo/Redo 统一由 `UndoRedoManager` 管理，通过 `SceneEditService` 内部调用 `executeCommand()`。

| 命令类型 | Undo 策略 | Redo 策略 |
|----------|-----------|-----------|
| 创建命令 | `AddEntitiesCommand::undo()` 移除图元 | `AddEntitiesCommand::redo()` 恢复图元 |
| 删除命令 | `DeleteEntitiesCommand::undo()` 恢复图元 | `DeleteEntitiesCommand::redo()` 移除图元 |
| 变换命令 | `EntitySnapshotsCommand::undo()` 恢复快照 | `EntitySnapshotsCommand::redo()` 应用快照 |

### 7.4 EntitySnapshot 结构

```cpp
struct EntitySnapshot
{
    QString id;
    int type;
    QPointF basePoint;
    QVector<QPointF> points;
    double radius;
    double startAngle;
    double endAngle;
    bool closed;
    bool ccw;
};
```

### 7.5 历史说明

原 `UiCommandHandler.cpp`（约 2700 行）已拆分为多个独立文件，后进一步重构为纯 `LambdaOperation` 注册模式。旧的 `ICommandHandler` 接口、`CommandHandlerAdapter`、`UiCommandDispatcher` 均已删除，命令不再经过中间适配层。
