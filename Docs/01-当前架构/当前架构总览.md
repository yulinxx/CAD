## 3. 关键架构边界

### 3.1 ABI 安全边界（C API Facade）
以下模块提供 **纯 C ABI**，供外部（插件、Python、其他语言）安全调用：

| 模块 | C API 头文件 | 句柄风格 | 错误码 |
|------|-------------|----------|--------|
| Log | `SyLogger.h` | 全局单例 | 无 |
| Engine | `EngineAPI.h` | 无 | `int` |
| Nesting | `NestingDLL.h` | `NestingJobHandle` (void*) | `NestingResultCode` |
| Vision | `VisionDLL.h` | `VisionImageHandle` 等 | `VisionResultCode` |
| GeoModelCore | `GeoModelDLL.h` | `GeoModelHandle` | `GeoModelResultCode` |
| Engraving | `EngravingCAPI.h` | `void*` | `int` |
| SanYiRender | `sanyi_render.h` | `SanyiRenderContext*` (不透明结构体) | 无 |
| RenderNext | `CAPI.h` | `RNWorldImpl*` (不透明结构体) | 无 |

**统一规范参考**：`Docs/DLL标准.md`

### 3.2 内部 C++ 协作边界
- **Engine2D/3D ↔ Render2D/3D**：通过 `RenderTypes`、`RenderContext`、`SceneCompiler` 等纯 C++ 接口协作
- **UI2D/3D ↔ RenderCompat**：静态链接，RenderWidget 提供 OpenGL 渲染控件
- **FileIO ↔ Engine**：通过 `EnginePersistence` 序列化协议交换数据
- **菜单/工具栏 ↔ 命令执行层**：菜单和工具栏都不直接实现业务逻辑，只保存“命令入口”；点击后统一转发到 `OperationBus`、工作台命令分发器或主题/语言服务。这样相同功能可以同时暴露为菜单项、工具栏按钮或快捷键，但业务只维护一份。
### 3.3 渲染架构分层（2026-08-02 代码对齐）

2D 生产路径已确认使用 **Renderx**（`SanYiRender.dll`），通过 `RenderWidget`、`ISceneGeometrySink` 和 `ISceneDataSource` 与数据层连接。

### 3.4 菜单与工具栏的逻辑关系

菜单与工具栏在架构上是两种不同的 UI 呈现，但它们通常调用同一批业务功能：

- **菜单**更适合承载层级化、发现性强、说明文字更完整的入口
- **工具栏**更适合承载高频、一步直达、需要图标快速识别的入口
- **二者的共同点**是：都只保存“命令入口”，不重复实现业务逻辑
- **二者的差异**是：菜单更偏组织结构，工具栏更偏快捷操作

为了避免重复实现，相同功能应抽象成统一命令标识或统一回调：

- 菜单项点击后调用命令分发器 / `OperationBus` / 主题服务 / 语言服务
- 工具栏按钮点击后也调用同一套命令入口
- 快捷键同样复用同一命令标识

因此，**菜单、工具栏、快捷键是同一功能的三个入口层**，它们共享同一执行逻辑，只是展示形态不同。切换工作台时，三者都应按当前工作台的配置和状态重新同步，避免残留与混淆。

3D 当前代码同时包含 `RenderWidget3DAdapter`、`RenderWidget3D`、`UiViewport3D` 和 `SimpleRenderer3D` 等实现。当前不将它们统称为单一已完全收口的生产路径；需要按实际构建目标和运行时工厂进一步确认每条路径的生产/兼容/测试属性。

```
┌─────────────────────────────────────────────────────────────┐
│  UI/Viewport 层 (Qt 依赖)                                    │
│  RenderViewport2D — 2D 视口（RenderWidget + Renderx）       │
│  Viewport3D — 3D 视口                                        │
└──────────────────────────────┬──────────────────────────────┘
                               │ ISceneDataSource 接口
┌──────────────────────────────▼──────────────────────────────┐
│  适配层 (RenderCompat)                                       │
│  RenderWidget — 渲染控件，封装 OpenGL 上下文和 Renderx 设备   │
│  SceneGeometrySinkAdapter — 接口调用 → C API 转换             │
└──────────────────────────────┬──────────────────────────────┘
                               │ C API
┌──────────────────────────────▼──────────────────────────────┐
│  渲染层 (Renderx / SanYiRender.dll)                          │
```

## 4. 数据流向总览

### 4.1 2D 编辑 → 渲染流（2026-07-16 更新）

```
用户交互 (RenderViewport2D)
    → ToolManager / OperationBus
    → SceneEditServiceAdapter (文档事务)
    → SceneDocument2D (图元增删改)
    → sigSceneChanged()
    → RenderViewport2D::updateSceneRender()
    → RenderWidget::submitSceneFromDataSource()
        ├─→ renderBeginScene()     // 清除旧图元
        ├─→ SceneManager::gatherGeometry(sink)  // 遍历图元推送几何
        └─→ renderEndScene()
    → paintGL() → renderFrame()
        ├─→ world2D.update()       // 脏图元 → GPU 顶点池
        ├─→ world2D.queryVisible() // 四叉树剔除
        ├─→ batchQueue.submit()/render()  // 批次绘制
        └─→ overlayQueue.render()  // 叠加层
    → 屏幕呈现
```

### 4.2 3D 场景 → 渲染流
```
用户交互 (Viewport3D)
    → Workbench3D / UiViewport3D
    → RenderWidget3DAdapter
    → RenderWidget3D
    → SceneManager3D / ISceneDataSource
    → Renderx / OpenGL 渲染链
    → 屏幕呈现
```

> `SceneBuilder3D`、`SimpleRenderer3D` 和 `RenderCoreRenderer` 仍可能存在于代码库或兼容路径中，但不能在未确认运行时工厂和构建目标前作为唯一 3D 生产调用链描述。

### 4.3 文档 → 渲染数据流（详见 `Docs/03-渲染主链/document-to-renderdata-flow.md`）
```
Document / Scene
    → Selection / 状态
    → Render Data (批次、高亮、预览)
    → GPU Renderer
    → Viewport
    → Screen
```

## 5. 核心设计原则

| 原则 | 说明 | 实施状态 |
|------|------|----------|
| **核心纯化** | Engine、Utility 等核心层零 Qt 依赖 | ✅ 已完成 |

## 6. 当前已知技术债

| 项 | 模块 | 影响 | 优先级 | 计划 |
|----|------|------|--------|------|
| 句柄风格不统一 | Nesting/Vision/GeoModel/Engraving | 跨模块调用易错 | P1 | 统一为不透明结构体指针 |
| 错误码不统一 | 各 C API 模块 | 客户端需针对每模块单独处理 | P1 | 统一为 `SanyiResult` |
| 缺少版本查询 | 大部分 C API | 无法运行时检测兼容性 | P1 | 每 facade 增加 `Xxx_GetVersion()` |
| PyBindCore 直接绑定 C++ | SanYiPyBindCore | 跨编译器/CRT 风险 | P2 | 增加 C facade 中间层 |
| GeoModelCore 压制 4251 警告 | GeoModelCore | 掩盖潜在 STL 跨边界 | P0 | 已修复 STL 导出，需移除压制 |
| 缺少架构文档目录 | Docs/01-当前架构/ | 新人上手困难 | P0 | **已完成** |

## 7. 命令系统架构（2026-07-11 更新）

### 7.1 命令处理器拆分

原 `UiCommandHandler.cpp`（约 2700 行）已拆分为多个独立文件：

| 文件 | 职责 |
|------|------|

| `CommandGeometry.h/cpp` | 几何变换辅助函数（rotatePoint、mirrorPoint） |

### 7.2 EntitySnapshot 结构

```cpp
struct EntitySnapshot
{
    QString id;           // 图元 ID
    int type;             // 图元类型
    QPointF basePoint;    // 基点
    QVector<QPointF> points;  // 顶点列表
    double radius;        // 半径（圆/弧）
    double startAngle;    // 起始角度（弧）
    double endAngle;      // 终止角度（弧）
    bool closed;          // 是否闭合（多边形）
    bool ccw;             // 逆时针方向（多边形缠绕顺序）
};
```

### 7.3 IUndoStack 刷新回调

```cpp
class IUndoStack
{
public:
    using RefreshCallback = std::function<void()>;
    virtual void setRefreshCallback(RefreshCallback callback) = 0;
    // ... 其他接口
};
```

`DefaultUndoStack` 在 `push()`、`undo()`、`redo()` 时会调用 `notifyRefresh()` 触发视图刷新，支持增量刷新和防重入保护。
