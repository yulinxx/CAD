# 数据库架构

## 概述

SanYiCAD 使用 SQLite（基于 SQLiteCpp 封装）作为本地持久化存储，主要存储以下数据：
- 用户设置（分组键值对，支持 string/int/bool/double 类型）
- 最近文件列表
- 工作区布局快照
- 图层信息
- 文档元数据
- 对话框界面状态（v5 新增）

> **相关全局定义**：版本号、路径等全局常量见 [当前架构总览](./当前架构总览.md) 第 6 节。

## 数据库文件位置

| 平台 | 路径 |
|------|------|
| macOS | `~/Library/Application Support/SanYiCAD/data/cad_database.sqlite` |
| Windows | `C:/Users/<user>/AppData/Local/SanYiCAD/data/cad_database.sqlite` |
| Linux | `~/.local/share/SanYiCAD/data/cad_database.sqlite` |

数据库文件在首次使用时自动创建，使用默认配置。

## Schema 版本管理

当前版本：**v5**（定义于 `DatabaseBootstrapper.cpp` 中的 `kSchemaVersion`）

| 版本 | 变更内容 |
|------|----------|
| v1 | 初始表结构（settings, recent_files, workspace_snapshots, layers, documents） |
| v2 | 新增 documents 表（文档元数据） |
| v3 | layers 表新增 fill 列（填充图层标志，色块填充） |
| v4 | layers 表新增 fill_color 列（填充色，色块填充） |
| v5 | 新增 dialog_states 表（对话框状态持久化）；为常用查询字段创建索引 |

版本号存储于 `app_meta` 表的 `schema_version` 键中，应用启动时由 `DatabaseBootstrapper::ensureSchema()` 自动执行迁移。

## 核心表结构

### 1. settings - 用户设置

通用分组键值对存储，支持任意类型设置。

| 列名 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 自增主键 |
| group_name | TEXT | 设置分组（如 `ui`, `viewport`, `file`） |
| key | TEXT | 设置键名 |
| value | TEXT | 设置值（字符串形式存储） |
| data_type | TEXT | 值类型标记（`string`/`int`/`bool`/`double`） |
| updated_at | TEXT | 最近更新时间（ISO 8601） |

**唯一约束**：`UNIQUE(group_name, key)`

### 2. recent_files - 最近文件

| 列名 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 自增主键 |
| file_path | TEXT | 文件完整路径（唯一约束） |
| title | TEXT | 文件标题 |
| format | TEXT | 文件格式（如 DXF, PLT, SVG） |
| last_opened_at | TEXT | 最后打开时间（ISO 8601） |

**唯一约束**：`UNIQUE(file_path)`

### 3. workspace_snapshots - 工作区布局快照

| 列名 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 自增主键 |
| workbench_id | TEXT | 工作台标识（如 `2D`, `3D`） |
| geometry | TEXT | QWidget::saveGeometry() 的 Base64 编码 |
| window_state | TEXT | QWidget::saveState() 的 Base64 编码 |
| updated_at | TEXT | 最近更新时间（ISO 8601） |

**唯一约束**：`UNIQUE(workbench_id)`

### 4. layers - 图层信息

| 列名 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 自增主键 |
| document_id | TEXT | 所属文档 ID |
| layer_id | INTEGER | 图层运行时 ID（LayerManager::createLayer 返回） |
| name | TEXT | 图层名称 |
| color | TEXT | 图层颜色（hex 格式，如 `#FF0000`） |
| visible | INTEGER | 可见性（0=隐藏, 1=可见） |
| locked | INTEGER | 锁定状态（0=解锁, 1=锁定） |
| fill | INTEGER | 填充图层标志（0=普通, 1=填充） |
| fill_color | TEXT | 填充色（hex 格式，色块填充使用） |
| layer_type | INTEGER | 图层类型（0=矢量 VECTOR, 1=位图 BITMAP） |
| order_index | INTEGER | 图层排序序号 |
| updated_at | TEXT | 最近更新时间（ISO 8601） |

### 5. documents - 文档元数据

| 列名 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 自增主键 |
| file_path | TEXT | 文件完整路径（唯一约束） |
| title | TEXT | 文档标题 |
| format | TEXT | 文件格式（如 DXF, SVG, SY） |
| entity_count | INTEGER | 文件中图元数量 |
| file_size | TEXT | 文件大小（格式化字符串） |
| last_opened_at | TEXT | 最后打开时间（ISO 8601） |
| last_saved_at | TEXT | 最后保存时间（ISO 8601） |
| created_at | TEXT | 创建时间（ISO 8601） |

**唯一约束**：`UNIQUE(file_path)`

### 6. dialog_states - 对话框界面状态（v5 新增）

| 列名 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 自增主键 |
| dialog_key | TEXT | 对话框唯一标识（如 `LayerEditDialog`） |
| document_id | TEXT | 关联文档 ID（空表示全局状态） |
| state_json | TEXT | 对话框状态的 JSON 序列化字符串 |
| created_at | TEXT | 创建时间（ISO 8601） |
| updated_at | TEXT | 最近更新时间（ISO 8601） |

**唯一约束**：`UNIQUE(dialog_key, document_id)`

### 7. app_meta - 应用元数据

| 列名 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 自增主键 |
| key | TEXT | 键名（唯一约束） |
| value | TEXT | 值 |
| updated_at | TEXT | 更新时间（ISO 8601） |

**重要键：**
- `schema_version`: 数据库 schema 版本号（整数）
- `app_version`: 应用版本号（字符串，如 "1.0.0"）

**版本控制策略：**
- `schema_version`: 当数据库表结构变化时递增
- `app_version`: 当应用版本变化时记录（来自 `MainApp::appVersion()`）
- 版本不匹配时：清除业务数据（recent_files, workspace_snapshots, layers, documents），保留 meta 表

**版本统一管理：**
- 版本号定义在 `Main/VersionInfo.h.in`（CMake 模板），通过 CMake 配置生成
- 运行时通过 `MainApp::appVersion()` 获取
- Qt 应用版本通过 `QCoreApplication::setApplicationVersion()` 设置
- UI 模块通过 `QCoreApplication::applicationVersion()` 读取

## 数据库索引

v5 版本引入了索引优化，提升常用查询的性能：

| 索引名 | 表 | 字段 | 用途 |
|--------|------|------|------|
| `idx_layers_document_id` | layers | document_id | 按文档查询图层 |
| `idx_layers_doc_layer` | layers | document_id, layer_id | 按文档+图层ID查询 |
| `idx_recent_files_opened_at` | recent_files | last_opened_at DESC | 按时间排序最近文件 |
| `idx_dialog_states_doc_id` | dialog_states | document_id | 按文档查询对话框状态 |
| `idx_dialog_states_key` | dialog_states | dialog_key | 按对话框标识查询 |

索引通过 `DatabaseBootstrapper::createIndices()` 创建，使用 `CREATE INDEX IF NOT EXISTS` 保证幂等性。

### 核心类说明

#### Eg::Database

SQLite 底层封装，特点：
- 基于 SQLiteCpp 库
- 语句缓存：LRU 策略，最多缓存 128 条 prepared statement
- 线程安全：`std::recursive_mutex` 保护所有操作
- WAL 模式：`PRAGMA journal_mode=WAL`
- 外键约束：`PRAGMA foreign_keys=ON`
- 忙等待超时：`PRAGMA busy_timeout=5000`
- RAII 事务：`Database::Transaction` 析构时自动回滚
- 所有错误通过 `lastError()` 传递，不抛异常

```cpp
// 典型用法
Eg::Database db;
db.open("path/to/database.sqlite");

// 通用 CRUD
std::map<std::string, std::string> values;
values["key"] = "setting_name";
values["value"] = "42";
db.insert("settings", values);

// 查询
auto rows = db.query("SELECT * FROM settings WHERE key = ?", {"setting_name"});

// 事务
Eg::Database::Transaction txn(db);
db.execute("INSERT INTO ...");
txn.commit();  // 析构时若未 commit 则自动 rollback
```

#### UI::IDatabase

跨 DLL 的 C 风格 ABI 接口：
- 纯虚接口，无 Qt 依赖
- 使用 POD 类型（`KvPair`、`const char*`）避免 STL 跨 DLL 问题
- 回调模式处理查询结果
- `DatabaseWrapper` 是其具体实现

#### SqliteRepositoryBase

仓储基类，提供：
- 统一的数据库引用 `m_database`
- 错误状态管理 `m_lastError`
- 辅助方法 `fail(tag, message)` 和 `setError(tag, message)`

#### PersistenceService

持久化服务，统一管理：
- 数据库连接和 Schema 初始化
- 所有仓储对象的创建和生命周期
- 仓储访问器：`recentFiles()`, `layers()`, `settings()`, `documents()`, `dialogStates()`

#### LayerPersistenceBridge

图层持久化桥接器：
- 实现 `ILayerManagerObserver` 接口
- 监听图层运行态变更（新增/删除/属性修改/顺序调整）
- 单向同步：运行态 → 数据库（运行态 → DB）
- 通过 `attach()`/`detach()` 控制监听生命周期

### Repository 模式

每个表对应一个 Repository 类，继承自 `SqliteRepositoryBase`：

| 仓储 | 表 | 主要方法 |
|------|------|----------|
| `RecentFileRepository` | recent_files | `loadAll()`, `saveAll()`, `append()`, `remove()` |
| `WorkspaceSnapshotRepository` | workspace_snapshots | `load()`, `save()`, `remove()` |
| `LayerRepository` | layers | `loadByDocument()`, `save()`, `remove()`, `rename()`, `updateVisibility()` 等 |
| `SettingsRepository` | settings | `loadValue()`, `saveValue()`, `removeValue()`, `loadGroup()` |
| `DocumentRepository` | documents | `loadAll()`, `loadByPath()`, `save()`, `remove()` |
| `DialogStateRepository` | dialog_states | `save()`, `load()`, `loadByDocument()`, `loadAll()`, `remove()`, `removeByDocument()` |

### 数据模型

每个 Repository 对应一个 Record 结构体（POD），定义于 `Persistence/Models/` 目录：

| 模型 | 文件 | 说明 |
|------|------|------|
| `RecentFileRecord` | RecentFileRecord.h | 最近文件记录 |
| `WorkspaceSnapshotRecord` | WorkspaceSnapshotRecord.h | 工作区布局快照 |
| `LayerRecord` | LayerRecord.h | 图层记录 |
| `SettingRecord` | SettingRecord.h | 设置记录 |
| `DocumentRecord` | DocumentRecord.h | 文档元数据记录 |
| `DialogStateRecord` | DialogStateRecord.h | 对话框状态记录 |

## 使用示例

### 通过 PersistenceService 访问

```cpp
// 获取持久化服务实例（通过 UiServices 注入）
PersistenceService* persistence = services.persistenceService;

// 最近文件操作
auto* recentFiles = persistence->recentFiles();
recentFiles->append(record);

// 图层操作
auto* layers = persistence->layers();
auto layerList = layers->loadByDocument(documentId);
layers->save(layerRecord);

// 设置读写
auto* settings = persistence->settings();
std::string theme = settings->loadValue("ui", "theme", "light");
settings->saveValue("ui", "theme", "dark");

// 对话框状态保存（v5 新增）
auto* dialogStates = persistence->dialogStates();
DialogStateRecord state;
state.dialogKey = "LayerEditDialog";
state.documentId = docId;
state.stateJson = R"({"expanded":true,"tab":2})";
dialogStates->save(state);
```

### 图层持久化同步

```cpp
// LayerPersistenceBridge 自动将图层变更同步到数据库
// 在文档打开时创建 bridge 并 attach
auto bridge = std::make_unique<LayerPersistenceBridge>(layerManager, layerRepository);
bridge->setDocumentId(documentId);
bridge->attach();

// 之后所有图层操作（新增/删除/属性修改）会自动写入数据库
// 文档关闭时 detach
bridge->detach();
```

## 设计原则

### 1. 单一数据库文件

所有持久化数据存储在同一个 SQLite 文件中：
- 避免数据分散
- 简化备份和迁移
- 保证数据一致性

### 2. Schema 版本管理与自动迁移

- `DatabaseBootstrapper` 负责创建和升级表结构
- 使用 `kSchemaVersion` 追踪当前版本
- 逐版本递增迁移，保证幂等性
- 版本不匹配时清除业务数据重建

### 3. 错误容忍

数据库错误处理原则：
- 数据库初始化失败不阻塞应用启动
- 使用默认值作为降级策略
- 记录错误日志但不抛异常
- `lastError()` 返回最近一次操作的错误信息

### 4. 线程安全

- `Eg::Database` 使用 `std::recursive_mutex` 保护所有操作
- WAL 模式支持并发读写
- `Database::Transaction` RAII 管理事务生命周期

### 5. 接口安全

- 参数使用 `?` 占位符防止 SQL 注入
- 仓储层封装 SQL，UI 不直接拼接
- RAII 管理资源（事务、连接）

## 扩展指南

### 添加新表

1. 在 `DatabaseBootstrapper::createBusinessTables()` 中添加建表 DDL：

```cpp
std::string sql = R"(
    CREATE TABLE IF NOT EXISTS my_table (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        name TEXT NOT NULL,
        value INTEGER DEFAULT 0,
        created_at TEXT DEFAULT (datetime('now'))
    )
)";
m_database.execute(sql);
```

2. 如果是新版本，更新 `kSchemaVersion` 并在 `runMigrations()` 中添加迁移分支

3. 在 `createIndices()` 中添加常用查询字段的索引

4. 新建 Model 结构体（`Persistence/Models/MyRecord.h`）

5. 新建 Repository 类（继承 `SqliteRepositoryBase`）

6. 在 `PersistenceService` 中添加仓储成员和访问器

### 添加新设置

通过 `SettingsRepository` 直接读写：

```cpp
// 保存
persistence->settings()->saveValue("ui", "new_setting", "value");

// 读取
std::string val = persistence->settings()->loadValue("ui", "new_setting", "default");
```

## 常见问题

### Q: 数据库文件在哪里？
A: 见上文「数据库文件位置」

### Q: 如何重置所有设置？
A: 删除数据库文件后重新启动，应用会使用默认设置创建新数据库

### Q: 设置不生效？
A:
1. 确认保存成功（检查返回值）
2. 确认数据库路径正确
3. 检查日志输出中的错误信息
4. 尝试重启应用

### Q: 数据库损坏怎么办？
A:
1. 备份现有数据库文件
2. 删除损坏的数据库
3. 重新启动应用（会自动创建新数据库）

### Q: 如何保存对话框界面状态？
A: 使用 `DialogStateRepository`，将对话框状态序列化为 JSON 字符串存储：

```cpp
// 保存
DialogStateRecord rec;
rec.dialogKey = "MyDialog";
rec.stateJson = R"({"width":800,"selectedTab":1})";
persistence->dialogStates()->save(rec);

// 加载
auto rec = persistence->dialogStates()->load("MyDialog");
if (!rec.stateJson.empty()) {
    QJsonDocument doc = QJsonDocument::fromJson(QByteArray::fromStdString(rec.stateJson));
    // 恢复对话框状态...
}
```
