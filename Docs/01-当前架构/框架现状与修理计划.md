# 框架现状与修理计划

本文是当前开发主文档，只保留当前状态、当前问题和后续计划，不保留历史阶段记录。

---

## 1. 当前状态

### 1.1 总判断

框架已经完成主要收口，当前重点不再是回顾阶段过程，而是继续把剩余边界收紧，并保持文档与代码同步。

### 1.2 当前稳定项

- 主渲染路径统一到 `Renderx` / `RenderX`（`renderx.h` 是唯一公共 ABI 头）
- 场景事实源以 `SceneManager` 为准
- `SyEntity` 多态模型 + Protobuf 是主干
- `Camera2D` 和 `ViewportSelector` 已从视口中拆出
- `FileOperationRegistry` 和 `CoreOperationRegistry` 已从组合根中抽离（后者进一步拆分为 Edit/View/Algorithm/Help 四个子注册器）
- 增量渲染接口存在，刷新语义统一
- 3D 工具、菜单、状态栏和渲染适配层具备生产链路
- **UI→Engine 依赖收口**：UI 只经 `UiEngineAccess` 门面访问 Engine；方向由 `CMake/CheckDependencies.cmake` 在 configure 阶段强制
- **UI 服务依赖分组化**：消费者取 `UiServiceGroups.h` 的聚焦分组或具体接口，不再传递 `UiServices` 聚合；`UiWorkbench::initialize` 收 `WorkbenchServices`
- **布局/菜单构建接口化**：`ILayoutBuilder`（工具栏/Dock/状态栏）与 `IMenuBuilder`（菜单/快捷键）为消费接口，`UiLayoutBuilder` 为唯一实现；布局配置经 `ILayoutConfig` 消费
- **场景统一入口 `ISceneContext` 已落地**：2D/3D 共享 `ISceneManager + ISceneDataSource + ISceneChangeStream` 组合接口，`SceneDocument2D::sceneContext()` 替代直接暴露 `Eg::SceneManager*`，UI 层主要消费者已迁移
- 渲染后端开关统一为 `SANYI_DEFAULT_RENDER_BACKEND`（派生 `SY_ENABLE_METAL_VIEWPORT`）
- 根工程支持 `BUILD_UI_DIMENSION=2D|3D|BOTH` 维度门控
- C ABI 版本查询由 `CMake/CheckCApi.cmake` 在 configure 阶段校验
- Engine 组与 UI 组均可独立配置 / 构建 / 测试
- **P0 全部完成**：3D 双文档模型已合并、EntityToVertices 缓存已移除、UICommon→Engine2D 依赖已通过内联前向声明解耦、2D 离散化已合并、Tessellator2D 已落地、RenderWidget3DAdapter 空方法已清理、OperationRouting 去单例、DialogParameterBase 导出宏修复
- **UICommon→Engine2D 依赖已解耦**：UICommon 通过内联前向声明访问 Engine2D 类型，不再直接链接 Engine2D，`Engine2DTypes.h` 已废弃
- **3D 双文档模型已合并**：`SceneDocument3D` 与 `SceneDocument3DAdapter` 已合并为单一文档入口，`removeEntity()`/`clear()` 路由经 `SceneEditService3D`
- **EntityToVertices 缓存已移除**：缓存整块删除，`entityToVertices` 退回纯函数
- **OperationRouting 去单例**：移除 `setOperationBus()`，`dispatch()` 签名改为显式传递 `OperationBus*`
- **DialogParameterBase 导出修复**：宏中添加 `UICOMMON_API` 确保 DLL 导出 `toAlgorithmParams()`/`fromAlgorithmParams()`
- **性能基准已常态化（2026-09-24）**：`Tools/PerfBenchmark`（数据层 22 项）+ `Tools/RenderBenchmark`（渲染帧路径 8 项，挂 Null 后端、无 GPU 依赖）两个可无人值守复现的基准，结果按轮次标记追加 `Docs/performance-audit/*.csv`；配套集成回归 `SceneEditIntegrationTests`（10 例）纳入 ctest
- **数据层已无 P0（2026-09-24）**：变换类撤销改为零克隆状态交换（+ `SnapshotScope` 处理算法内部增删图元）、容器类型桶位置索引化、RTree 批量装载与分裂算法调整。实测：批量移动 10 万图元 2993 → 1129 ms、撤销重做 3078 → 1197 ms、百万图元入场景 11015 → 1626 ms
- **渲染端有了 CPU 侧基线并落地一项优化（2026-09-24）**：全场景视野下 100 万图元 95 → 64 ms/帧（draw call 仅 5 个，瓶颈是逐条遍历与合批）；新增「视野 ⊇ 索引包围盒并集」的剔除捷径，去掉全图视野下注定被丢弃的网格收集
- **10 万图元（常态规模）经实测已全部达标**：一次移动 1 万图元 38 ms、撤销/重做各约 44 ms、全场景视野帧路径 CPU 侧 3.5 ms、全选 1.2 ms。详见《性能审查报告》

### 1.3 当前风险项

- `RenderWidget3DAdapter` 的桥接职责仍需继续收紧，避免长出业务逻辑
- 尚未落地的边界接口：`IEntityFactory`、`IUiModule` —— 在出现真实实现者/消费者前不新增，避免死抽象
- **`ISceneContext` 已落地作为 UI 统一场景入口**：`SceneDocument2D::sceneContext()` 替代原 `editService()->sceneManager()` 暴露，UI 层（RenderViewport2D、ViewportInputRouter、TransformDialogAdapter、RightToolBar、BaseEditor、EntityEditManager、ViewportSelector、GridSnapManager、SceneRefreshCoordinator、SceneAccessAdapter 等）已迁移完成
- 部分 C ABI 错误码尚无 `<Module>_StatusText`，待出现消费者时再补
- 仅 3D 构建不受支持：Main 硬依赖 UI2D（无桩回退）
- 文档中仍可能残留旧模块名、旧路径
- **端到端真实帧率仍无数据（2026-09-24）**：两个基准都只覆盖 CPU 侧（渲染基准不含 GPU 执行/呈现，也不含应用侧每帧的场景→顶点转换）。"百万图元在真实视口里到底多少帧"需要真实视口埋点才能回答。应用内已有刷新耗时监视器（`Log/SyPerfCounter.h` 的 `FrameTimer`，经 `SceneRefreshCoordinator::setPerfMonitorEnabled` 开启），但**生产路径没有调用点**——要用得先接一个开关
- **百万级（极端场景）仍明显迟钝**：百万图元入场景 1628 ms 且在主线程（界面会顿一下）、全选移动 10 万图元 537 ms、撤销 615 ms、全图视野帧路径 CPU 侧 64 ms。这些是当前架构下的已知上限，不是缺陷

## 2. 当前工作重点

1. 继续收紧 `RenderWidget3DAdapter` 的桥接边界。
2. 保持 UI→Engine 只经 `UiEngineAccess`、UI 服务只经分组/接口访问；新增依赖须过方向门禁。
3. 统一各 facade 的版本查询与错误码风格（按需补 `_StatusText`）。
4. 保持渲染主路径只剩 `Renderx` / `RenderX`。
5. 保持文档与代码同步，且只写现状与计划。

## 3. 当前需要继续做的事

- 收紧 `RenderWidget3DAdapter` 的桥接边界
- 在有真实需求时落地 `IEntityFactory` / `IUiModule` 等边界接口（接口 + 实现者 + 消费者一起）
- 按需补齐各 C ABI 的 `<Module>_StatusText`
- 清理文档中残留的旧模块名与旧路径
- **属性面板解耦**：定义 `IPropertySink` + `PropertyEmitter` 模式，复用 `EntityGeometryEmitter` 成功经验，消除 UI 层对具体图元类型的 `dynamic_cast`
- **UiServices 核心字段下沉**：`document2D`/`sceneEditService`/`layerManager`/`selectionService` 等 16 个具体类型字段逐字段改为构造参数或聚焦分组注入
- **绘图工具预览图元解耦**：用 `SyEntityOwnPtr` + 基类接口替代成员变量持有 `SyPolygon`/`SyLine`/`SyArc`
- **3D 增量渲染路径**：实现 `IncrementalVertexSink::emitTriangleSoup`，补齐 3D 场景增量刷新能力
- **真实视口的端到端帧率与拖动延迟埋点**（性能工作唯一还没覆盖的一环）：把 `FrameTimer` 接一个可用开关，并补"输入到画面更新"的拖动延迟测量
- **性能后续候选（按实测影响排序，仅在确有需要时做）**：渲染端图元级 LOD（`Docs/03-渲染主链/百万级矢量剔除-空间索引设计.md` §14.8）、DrawList 增量排序、数据层空间索引的精确性契约（脏集 + 延迟更新）。注意同文件 §14.1 / §14.5 / §14.9 已记录三处**实测无效或收益有限、不要重试**的做法
