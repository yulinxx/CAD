# 框架问题分析

本文只保留当前仍然存在的框架问题、已确认的收口方向和后续计划，不保留历史时间线。

---

## 1. 当前结论

当前框架已经进入稳定收口阶段，主要生产路径已经明确：

- 渲染统一到 `Renderx` / `RenderX`
- 2D 视图以 `RenderViewport2D`、`RenderWidget`、`SceneGeometrySinkAdapter` 为主
- 3D 视图以 `Workbench3D`、`Viewport3D`、`Renderer3DFactory`、`RenderWidget3DAdapter` 为主
- 命令统一通过 `OperationBus` 调度
- 文档与场景的事实源仍应保持单一

---

## 2. 当前仍需关注的问题

### 2.1 3D 适配层仍需继续收口

`RenderWidget3DAdapter`、`RenderWidget3D` 属于当前链路，应继续收紧适配器职责，不让它演化成并行主框架。

> 2026-08-26 更新：`SimpleRenderer3D` 已删除。3D 现在只有一条渲染链
> （`Renderer3DFactory` → `RenderWidget3DAdapter` → `RenderWidget3D`），
> 「并行主框架」这个风险在渲染层已经消除。

### 2.2 视图层与业务层仍需继续分离

UI 层只保留入口、交互和状态同步，不应继续扩展成业务编排层。

### 2.3 ABI 规则仍需继续统一

跨 DLL 对外边界继续坚持：

- POD 优先
- 句柄优先
- 错误码明确
- 版本查询补齐

---

## 3. 当前稳定项

- `SceneManager` 仍是当前场景事实源
- `SceneEditService` 已成为文档编辑的统一入口
- `RenderViewport2D` 的刷新职责已拆分
- `FileOperationRegistry` 和 `CoreOperationRegistry` 已从组合根抽离
- `Renderx` 是当前唯一生产渲染路径

---

2. 继续统一 2D / 3D 的交互语义。
3. 继续压缩兼容层边界。
4. 继续统一对外 ABI 风格。
