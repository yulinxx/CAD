# 模块边界定义

## 概述

本文档定义各模块之间的边界、依赖关系和通信协议，确保模块间职责清晰、耦合度低。

## 2. 模块边界详细定义

### 2.1 UICommon

**职责**：UI 公共基础设施

| 边界 | 规则 |
|------|------|
| **依赖** | Utility, Log, Qt |
| **不依赖** | Engine2D, Engine3D, SanYiRender |
| **对外提供** | 主题、布局、状态中心、服务注册、公共枚举 |
| **禁止** | 业务逻辑、渲染实现、具体工具定义 |

**关键文件**：
- `UI/Common/Include/UI/Command/OperationId.h` — 公共操作枚举
- `UI/Common/Include/UI/Command/OperationBusBase.h` — 公共操作总线基类
- `UI/Common/Include/UI/Command/OperationTypes.h` — 公共操作类型

---

### 2.2 UI2D

**职责**：2D 绘图界面和交互。当前 2D 生产路径收口到 `Renderx`（`SanYiRender.dll`）+ `RenderWidget`，`Viewport2D` 仅保留历史兼容语义，不再扩展生产逻辑。

| 边界 | 规则 |
|------|------|
| **依赖** | UICommon, Engine2D, SanYiRender, Qt |
| **不依赖** | Engine3D, UI3D |
| **对外提供** | 2D 视口、工具系统、命令系统、文档视图 |
| **禁止** | 3D 业务逻辑、跨模块状态管理 |

**关键文件**：
- `Main/Src/UI/Render/RenderViewport2D.h` — 2D 视口宿主
- `UI/2D/Include/RenderWidget.h` — 渲染控件
- `UI/2D/Include/Render/SceneGeometrySinkAdapter.h` — 几何适配器
- `UI/2D/Src/Ui/ViewWidget/ViewWidget.h` — 2D 视图控件
- `UI/2D/Src/Ui/DrawTools/ToolManager.h` — 工具管理器
- `UI/2D/Src/Operation/OperationBus.h` — 操作总线

---

### 2.3 UI3D

**职责**：3D 场景界面和交互

| 边界 | 规则 |
|------|------|
| **依赖** | UICommon, Engine3D, SanYiRender, Qt |
| **不依赖** | Engine2D, UI2D |
| **对外提供** | 3D 视口、场景树、属性面板、相机控制 |
| **禁止** | 2D 业务逻辑、跨模块状态管理 |

**关键文件**：
- `Main/Src/UI/Render/UiViewport3D.h` — 3D 视口
- `Main/Src/UI/Render/RenderWidget3DAdapter.h` — 3D 渲染控件适配器
- `UI/3D/Include/UI3D/Render3D/RenderWidget3D.h` — 3D 渲染控件接口

---

### 2.4 Engine2D

**职责**：2D 几何引擎

| 边界 | 规则 |
|------|------|
| **依赖** | Utility, Log |
| **不依赖** | Qt, UI2D |
| **对外提供** | 实体、拓扑、布尔运算、约束求解 |
| **禁止** | UI 逻辑、渲染逻辑 |

---

### 2.5 Engine3D

**职责**：3D 几何引擎

| 边界 | 规则 |
|------|------|
| **依赖** | Utility, Log, GeoModelCore |
| **不依赖** | Qt, UI3D |
| **对外提供** | BRep、网格、布尔、投影 |
| **禁止** | UI 逻辑、渲染逻辑 |

---

### 2.6 Renderx（SanYiRender）

**职责**：2D/3D 统一渲染管线、Shader、OpenGL/Vulkan/Metal 后端。当前生产库目标名为 `SanYiRender`，源码位于 `Renderx/`。

| 边界 | 规则 |
|------|------|
| **依赖** | 仅系统库（OpenGL / Vulkan / Metal） |
| **不依赖** | Qt, Engine, UI |
| **对外提供** | 纯 C ABI（`render/render.h`：`renderCreateDevice`, `renderSubmitGeometry`, `renderFrame` 等） |
| **禁止** | 业务逻辑、文档操作 |

**关键文件**：
- `Renderx/include/render/render.h` — C API 入口（`RenderDevice*` 句柄）
- `Renderx/include/render/render_types.h` — 渲染公共类型（POD 结构体）

## 3. 跨模块通信协议

### 3.1 UI → Engine

通过 **构造函数注入** 模式：
```cpp
// UI2D 通过 OperationContext 获取 Engine2D 服务
Eg::SceneManager* sm = ctx.sceneManager;
```

### 3.2 UI → Render

通过 **RenderWidget** 直接调用：
```cpp
// UI 通过 RenderWidget 与渲染层通信
renderWidget->setPreviewPoints(points, count);
renderWidget->setControlLines(lines, count);
```
2D 文档几何则通过 `SceneGeometrySinkAdapter` 转换为 `Renderx` C API 调用。

### 3.3 Engine → Render

通过 **`ISceneDataSource` / `ISceneGeometrySink` 接口 + Renderx C API**：
```cpp
// SceneManager（数据层）实现 ISceneDataSource
// SceneGeometrySinkAdapter（适配层）实现 ISceneGeometrySink，调用 Renderx C API
dataSource->gatherGeometry(sink);  // 遍历图元推送几何到渲染层
```

### 3.4 2D ↔ 3D

通过 **UICommon 公共枚举**：
```cpp
// 共享操作 ID 和操作来源定义
using OperationId = Cmd::OperationId;
using OperationSource = Cmd::OperationSource;
```

## 4. 禁止的依赖关系

| 源模块 | 目标模块 | 原因 |
|--------|----------|------|
| Engine2D | UI2D | 核心不依赖 UI |
| Engine3D | UI3D | 核心不依赖 UI |
| Renderx | Qt | 渲染核心零 Qt 依赖 |
| UI2D | UI3D | 保持 2D/3D 独立 |
| Engine2D | Engine3D | 保持 2D/3D 独立 |

## 5. ABI 安全边界

以下模块提供 **纯 C ABI**：

| 模块 | C API 头文件 | 句柄风格 |
|------|-------------|----------|
| Log | `SyLogger.h` | 全局单例 |
| Engine | `EngineAPI.h` | 无 |
| Nesting | `NestingDLL.h` | `NestingJobHandle` |
| Vision | `VisionDLL.h` | `VisionImageHandle` |
| GeoModelCore | `GeoModelDLL.h` | `GeoModelHandle` |
| Engraving | `EngravingCAPI.h` | `EngravingVolumeHandle`（类型安全） |
| SanYiRender | `render/render.h` | `RenderDevice*` (不透明结构体) |

## 7. 命令系统架构（2026-08-17 更新）

当前命令系统采用纯 `OperationBus` + `LambdaOperation` 模式，由三个注册表分层管理：

| 注册表 | 职责 | 文件 |
|--------|------|------|
| `CoreOperationRegistry` | 编辑、算法、视图等核心操作 | `Main/Src/Composition/CoreOperationRegistry.cpp` |
| `FileOperationRegistry` | 文件打开/保存/导入/导出 | `Main/Src/Composition/FileOperationRegistry.cpp` |
| `PendingOperationRegistry` | 未接入操作占位（当前为空） | `Main/Src/Composition/PendingOperationRegistry.cpp` |

组合根 `ApplicationCompositionRoot` 通过 `registerAllOperations()` 统一调用三个注册表。

### 7.1 命令执行路径

```text
用户操作 (按钮/菜单/快捷键)
    │
    ▼
OperationBus::run(opId) → 统一命令调度
    │
    └─→ LambdaOperation / ParamLambdaOperation
            └─→ 捕获服务引用，直接调用对应 Service
```

所有命令统一注册为 `LambdaOperation`，不经过中间适配层。`ICommandHandler`、`CommandHandlerAdapter`、`UiCommandDispatcher` 均已删除。

### 7.2 撤销/重做机制

Undo/Redo 统一由 `UndoRedoManager` 管理，通过 `SceneEditService` 内部调用 `executeCommand()`。

### 7.3 EntitySnapshot 结构

```cpp
struct EntitySnapshot
{
    QString id;           // 图元 ID
    int type;             // 图元类型
    QPointF basePoint;    // 基点
    QVector<QPointF> points;  // 顶点列表
    double radius;        // 半径（圆/弧）
    double startAngle;    // 起始角度（弧）
    double endAngle;      // 终止角度（弧）
    bool closed;          // 是否闭合（多边形）
    bool ccw;             // 逆时针方向（多边形缠绕顺序）
};
```
