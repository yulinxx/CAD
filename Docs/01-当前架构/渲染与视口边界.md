# 渲染与视口边界

## 概述

本文档结合当前代码框架，说明 `Main`、`UI`、`Engine`、`Render`、`Docs` 之间的职责边界，以及 2D / 3D 视口、菜单、工具条、命令系统、文档、实体和渲染层的关系。

本文档的目的不是抽象出一个理想架构，而是明确：**现在这套框架里每一层到底负责什么，现有 UI 该怎么用，后续该往哪里收口。**

## 2. 边界定义

### 2.0 结合现有框架先说明一句

当前框架里，`UI` 不是核心本体，`Engine` 不是界面，`Render` 不是业务，`Docs` 不是临时交互。

更准确地说：

- `Main` 负责把应用组织起来
- `UI` 负责给用户入口和交互
- `Engine` 负责图元与通用能力
- `Render` 负责显示
- `Docs` / `FileIO` 负责保存和加载

后续如果你继续做 2D 功能，绝大多数功能都应该沿着这个方向落位。

### 2.1 渲染核心层（Renderx 架构）

**职责**：定义渲染语义和接口，接收几何原语并执行 GPU 绘制

| 边界 | 规则 |
|------|------|
| **依赖** | 仅系统库（OpenGL）、无 Qt 依赖 |
| **不依赖** | Qt, UI, Engine |
| **对外提供** | C API（renderCreateDevice, renderEmit*, renderFrame 等） |
| **禁止** | UI 逻辑、业务逻辑、平台依赖 |

**关键接口**：

```cpp
// C API — 几何原语推送接口（render_c_api.cpp）
RENDER_API void renderEmitPolyline(RenderDevice* dev, const float* pts, uint32_t count, bool closed);
RENDER_API void renderEmitCircle(RenderDevice* dev, float cx, float cy, float radius);
RENDER_API void renderEmitArc(RenderDevice* dev, float cx, float cy, float radius,
                               float startAngle, float endAngle);
RENDER_API void renderEmitEllipse(RenderDevice* dev, float cx, float cy,
                                   float rx, float ry, float rotation,
                                   float startAngle, float endAngle, bool fullEllipse);

// C API — 场景控制接口
RENDER_API void renderBeginScene(RenderDevice* dev);
RENDER_API void renderEndScene(RenderDevice* dev);
RENDER_API void renderFrame(RenderDevice* dev);
```

### 2.2 Qt 适配层（RenderCompat）

**职责**：桥接 UI 和 Renderx 渲染核心

| 边界 | 规则 |
|------|------|
| **依赖** | UICommon, Renderx (SanYiRender.dll) |
| **不依赖** | 业务状态与文档实现细节 |
| **对外提供** | RenderWidget（渲染控件）、SceneGeometrySinkAdapter（适配器） |
| **禁止** | 业务逻辑、文档操作、状态管理 |

**关键类**：

```cpp
// RenderWidget — 渲染控件（封装 OpenGL 上下文和 Renderx 设备）
class RenderWidget : public QOpenGLWidget, protected QOpenGLFunctions
{
public:
    void submitSceneFromDataSource(ISceneDataSource* dataSource);
    // 内部调用 renderBeginScene → gatherGeometry → renderEndScene → update()
};

// SceneGeometrySinkAdapter — ISceneGeometrySink 实现
class SceneGeometrySinkAdapter : public ISceneGeometrySink
{
public:
    explicit SceneGeometrySinkAdapter(RenderDevice* dev);
    void emitPolyline(...) override { renderEmitPolyline(...); }
    void emitCircle(...) override   { renderEmitCircle(...); }
    // 将接口调用转换为 C API 调用
};
```

### 2.3 UI/Viewport 层

**职责**：用户交互和窗口管理。当前唯一生产路径为 `Render/2D/` + `RenderWidget`（OpenGL）；`Viewport2D` 保留为历史兼容实现并已标记 `deprecated`。

| 边界 | 规则 |
|------|------|
| **依赖** | Qt, UICommon |
| **不依赖** | RenderCore 内部实现 |
| **对外提供** | 事件入口、尺寸变化、重绘触发 |
| **禁止** | 直接拼 render frame、直接操作后端对象、直接处理 selection 真相 |

#### 2.3.1 `UI/2D` 在当前框架中的位置

`UI/2D` 是 2D 功能的前端入口集合，核心职责如下：
- 菜单入口
- 工具条入口
- 视口事件入口
- 命令触发入口
- 交互反馈入口

它不应该承担：
- 图元本体定义
- 文档事实维护
- 渲染编译
- 业务规则分发

#### 2.3.2 `UI/2D` 以后怎么用

以后 `UI/2D` 仍然会用，而且会持续使用，但使用方式会变得更单一：
- 只保留入口与交互
- 不再写核心业务
- 不再复制一套实体逻辑
- 不再让视口兼任命令调度中心

也就是说，它会一直存在，但会越来越像“前端壳层”，而不是“业务核心层”。

#### 2.3.3 菜单的用途与去向

**当前用途**
- 提供主窗口级入口
- 承载 File / Edit / Draw / Modify / View 等命令入口
- 和工具条共享同一套命令语义

**以后去向**
- 保留
- 继续作为统一入口之一
- 只触发命令，不直接实现业务
- 所有功能尽量保证菜单和工具条是一一对应或语义对应

#### 2.3.4 工具条的用途与去向

**当前用途**
- 提供高频操作入口
- 左侧偏绘图与选择
- 顶部偏修改与视图

**以后去向**
- 保留
- 继续作为高频入口
- 与菜单共用命令 ID
- 不直接操作文档或实体，只触发命令

#### 2.3.5 视口的用途与去向

**当前用途**
- 接收鼠标、键盘、滚轮输入
- 显示预览
- 显示正式结果
- 触发刷新

**以后去向**
- 保留
- 只做显示和事件转发
- 不做业务编排
- 不直接控制图元生命周期

#### 2.3.6 当前框架下的建议流向

```text
菜单 / 工具条 / 快捷键
→ UI/2D
→ 命令系统
→ 文档 / 场景
→ Engine 的 SyEntity
→ Render
→ 视口显示
```

### 2.4 UI 现有组成与未来去向

这一节专门对照你现在的框架里最常接触的 UI 组成，说明它们“现在是什么、以后怎么用”。

#### 2.4.1 `UI/2D`

**当前用途**
- 提供 2D 绘图的菜单、工具条、视口和交互入口
- 处理鼠标、键盘、快捷键、工具切换
- 将用户输入转成命令与绘图状态
- 为预览、提交、取消、选择、编辑提供前端入口

**以后去向**
- 继续保留，作为 2D 前端交互层
- 逐步收口旧分支与重复逻辑
- 不承担图元本体、文档事实和渲染核心职责
- 只保留“入口 + 交互 + 反馈”职责

#### 2.4.2 菜单

**当前用途**
- 作为主窗口级功能入口
- 承载 File / Edit / Draw / Modify / View 等统一入口
- 为工具栏提供同名或同义命令入口，避免按钮孤岛

**以后去向**
- 保留为主入口之一
- 与工具条共享同一套命令 ID
- 不直接执行业务逻辑，只触发命令调度
- 新增功能时优先同步菜单与工具条，避免只接一处

#### 2.4.3 工具条

**当前用途**
- 提供高频操作入口
- 左侧偏绘图与选择，顶部偏修改与视图
- 让用户快速进入当前工具或图元操作

**以后去向**
- 保留为高频入口
- 与菜单共享命令语义
- 不保存业务状态，不处理图元事实
- 仅负责按钮触发、状态展示、工具切换提示

#### 2.4.4 视口中的 UI 控件

**当前用途**
- 接收用户输入
- 显示预览和最终结果
- 触发重绘
- 配合选择、高亮、拖拽、框选等交互

**以后去向**
- 保留为交互容器
- 视口只做显示和事件转发，不做核心业务编排
- 复杂逻辑应交给命令系统、文档层和渲染层

#### 2.4.5 现有框架中的整体关系

```text
菜单 / 工具条 / 视口事件
→ UI/2D
→ 命令调度
→ 文档 / 场景
→ SyEntity
→ 渲染层
→ 视口显示
```

这意味着 `UI/2D` 不会被废弃，但会被定位为**前端入口层**；真正的图元、几何、状态与渲染事实，会逐步沉到更下层。

## 3. 通信协议

### 3.1 UI → 渲染请求

```cpp
// ViewWidget 发送渲染请求
renderCoreRenderer->render();

// 事件转发
renderCoreRenderer->handleEvent(uiEvent);

// 尺寸变化
renderCoreRenderer->resize({width, height});
```

### 3.2 渲染 → UI 更新

```cpp
// 渲染完成后通知 UI
void onRenderCompleted();

// selection 变化通知
void onSelectionChanged(const Selection& selection);
```

### 3.3 类型转换

| Qt 类型 | 核心类型 | 转换位置 |
|---------|----------|----------|
| `QString` | `std::string` | UiRenderCore |

| `QPointF` | `RenderPointF` | UiRenderCore |
| `QRectF` | `RenderRectF` | UiRenderCore |
| `QMouseEvent` | `MouseEvent` | UiRenderCore |

## 4. 数据流（2026-07-16 更新）

### 4.1 文档 → 渲染数据（当前实际流程）

```
SceneManager (ISceneDataSource)
    │
    │  gatherGeometry(sink)
    ▼
SceneGeometrySinkAdapter (ISceneGeometrySink)
    │
    │  C API 调用
    ▼
Renderx (SanYiRender.dll)
    │
    ├─→ renderEmitPolyline → tessellatePolyline → RenderWorld::addEntity()
    ├─→ renderEmitCircle   → tessellateCircle   → RenderWorld::addEntity()
    ├─→ renderEmitArc      → tessellateArc      → RenderWorld::addEntity()
    └─→ renderEmitEllipse  → tessellateEllipse  → RenderWorld::addEntity()
    │
    ▼
RenderWorld（SlotMap + 顶点池 + 四叉树）
```

### 4.2 RenderWorld → GPU（每帧渲染）

```
renderFrame()
    │
    ├─→ world2D.update()           // 脏实体顶点 → GPU 顶点池
    ├─→ world2D.queryVisible()     // 四叉树视锥剔除
    ├─→ sceneEnv.render()          // 网格背景
    ├─→ batchQueue.submit()        // 按 PrimitiveType 排序组装批次
    ├─→ batchQueue.render()        // 间接绘制
    ├─→ overlayQueue.render()      // 叠加层（仅脏时上传 GPU）
    └─→ meshManager.render()       // 仅在有 3D 实例时
    │
    ▼
GPU 绘制 → 屏幕呈现
```

### 4.3 UI → 渲染刷新

```
用户操作
    │
    ▼
ToolManager / OperationBus
    │
    ▼
SceneEditServiceAdapter
    │
    ▼
SceneDocument2D::applyChange()
    │
    ▼
sigSceneChanged()
    │
    ▼
RenderViewport2D::updateSceneRender()
    │
    ▼
RenderWidget::submitSceneFromDataSource()
    │
    ├─→ renderBeginScene()    // 清除旧实体
    ├─→ gatherGeometry()      // 推送新几何原语
    ├─→ renderEndScene()
    └─→ update()              // 触发 paintGL → renderFrame()
    │
    ▼
视口显示
```

## 5. 边界检查清单

### 修改渲染层时检查
- [ ] 是否引入了 Qt 依赖？
- [ ] 是否跨越了核心抽象边界？
- [ ] 是否修改了公共接口？

### 修改视口层时检查
- [ ] 是否直接操作了渲染后端？
- [ ] 是否直接拼了 render frame？
- [ ] 是否正确使用了适配层？

### 修改适配层时检查
- [ ] 是否增加了不必要的业务逻辑？
- [ ] 是否正确处理了类型转换？
- [ ] 是否保持了接口的稳定性？

## 6. 禁止的操作

| 操作 | 原因 |
|------|------|
| 视口直接拼 render frame | 破坏分层，难以维护 |
| 视口直接操作后端对象 | 破坏封装，难以替换后端 |
| 视口直接处理 selection 真相 | 数据一致性问题 |
| 渲染层直接操作 UI 对象 | 核心不依赖 UI |
| 渲染层直接修改文档 | 职责不清 |

## 7. 渲染管线增强（2026-07-11 更新）

### 7.1 RenderCoreRenderer 错误处理增强

**文件**：`RenderCoreRenderer.cpp`

**增强内容**：
- ✅ 空文档保护：编译前检查文档是否为空
- ✅ 无效视口尺寸检查：避免零尺寸渲染
- ✅ 异常捕获与恢复：编译异常时记录日志并恢复状态
- ✅ 渲染状态日志：记录编译开始/完成、帧统计、性能数据

### 7.2 渲染流程优化

**文件**：`DefaultSceneCompiler.cpp`、`SceneTraverser.cpp`

**优化内容**：
- ✅ 公共编译模板函数：`compileGeneric()`、`compileIncrementalGeneric()` 消除重复代码
- ✅ 统一缓存策略：减少重复编译
- ✅ 增量编译支持：只更新脏实体对应的批次

### 7.3 日志覆盖增强

| 模块 | 日志级别 | 覆盖范围 |
|------|----------|----------|
| RenderCoreRenderer | INFO/WARN/ERROR | 编译开始/完成、渲染状态、错误处理 |
| SceneCompiler | INFO | 编译过程、实体统计、批次信息 |
| SceneTraverser | DEBUG/INFO | 场景遍历、实体访问 |
