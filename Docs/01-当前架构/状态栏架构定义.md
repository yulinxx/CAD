# 状态栏架构定义

## 1. 文档目标

本文档定义状态栏的职责、内容边界、功能分类与架构设计。状态栏用于显示当前上下文、即时反馈、提示信息和轻量状态，不承担业务操作本身。

---

## 2. 状态栏在整体框架中的位置

```text
用户操作 / 系统事件 / 命令状态变化
    → 状态中心 / 文档状态 / 视图状态
    → 状态栏刷新
    → 用户看到即时反馈
```

状态栏属于 UI 层的反馈区域，不存储业务真相，不直接参与命令执行。

---

## 3. 状态栏的职责

状态栏主要承担：

1. 显示当前上下文信息。
2. 显示命令执行反馈。
3. 显示选择状态、坐标和尺寸信息。
4. 显示加工状态和仿真状态。
5. 显示系统提示、警告和轻量错误信息。

---

## 4. 状态栏应承载的内容

### 4.1 视图状态

- 鼠标坐标 Cursor Position
- 当前缩放比例 Zoom Level
- 当前视图模式 View Mode
- 当前视口尺寸 Viewport Size
- 当前单位 Unit

### 4.2 选择状态

- 当前选中数量
- 当前对象类型
- 当前选择模式
- 当前框选状态

### 4.3 命令状态

- 当前工具名
- 当前命令阶段
- 下一步操作提示
- 临时输入提示

### 4.4 加工状态

- 当前工艺模式
- 预览进度
- 仿真状态
- 输出状态
- 设备连接状态（如适用）

### 4.5 系统提示

- 成功信息
- 警告信息
- 错误信息
- 诊断信息

---

## 5. 状态栏不应承载的内容

- 长文本说明
- 复杂交互控件
- 主要命令按钮
- 大型配置面板
- 业务逻辑入口

状态栏应保持轻量，避免成为第二个工具栏。

---

## 6. 状态栏的功能分类

建议划分为五类：

### 6.1 光标与坐标区

显示鼠标位置、捕捉点、距离和角度。

### 6.2 选择摘要区

显示当前选择集规模和对象概况。

### 6.3 命令提示区

显示当前命令名称和下一步输入提示。

### 6.4 加工反馈区

显示仿真、输出、设备连接和执行状态。

### 6.5 通知消息区

显示短时成功、失败、警告和信息消息。

---

## 7. 状态栏与命令系统关系

状态栏是命令系统的反馈面，不是命令入口。

```text
Command / Tool / Document Event
    → State Center
    → Status Bar
```

### 7.1 设计要求

- 状态栏消息必须短。
- 状态栏更新应及时但不能闪烁过度。
- 状态栏要支持命令阶段提示。
- 状态栏应能区分普通提示和错误提示。
- 状态栏状态不应与文档事实混淆。

### 7.2 常见信号来源

- 鼠标移动
- 捕捉点变化
- 工具切换
- 命令开始 / 结束
- 选择变化
- 文件加载 / 保存
- 仿真开始 / 结束
- 设备连接 / 报警

---

## 8. 状态栏与框架设计

### 8.1 依赖约束

- 状态栏依赖状态中心和 UI 公共服务。
- 状态栏不得依赖几何核心实现。
- 状态栏不得直接修改文档和场景。
- 状态栏不得承担复杂逻辑。

### 8.2 设计原则

- 显示为主，交互为辅。
- 信息尽量短、稳定、可读。
- 关键状态优先显示在固定位置。
- 颜色、图标和文本要有一致语义。

---

## 9. 推荐状态栏结构

### 9.1 左侧：命令提示区
- 当前工具
- 当前阶段
- 下一步提示

### 9.2 中间：选择与坐标区
- 鼠标坐标
- 捕捉点
- 选择数量
- 距离 / 角度

### 9.3 右侧：系统与加工状态区
- 保存状态
- 加工状态
- 仿真状态
- 设备状态
- 错误 / 警告图标

---

## 10. 当前框架下的实现建议

1. 由状态中心统一发布状态变化。
2. 状态栏只订阅变化，不直接推导业务。
3. 鼠标坐标和命令提示应优先刷新。
4. 系统消息建议支持自动超时清除。
5. 错误信息应保留到用户显式确认或下一次操作。

---

## 11. StatusBarBase 架构设计（2D/3D 统一）

### 11.1 类层次结构

```text
StatusBarBase (UI/Common)          -- 抽象基类，定义公共接口
├── StatusBar (UI/2D)              -- 2D 模式状态栏：坐标/选择(含宽高)/消息/状态
└── StatusBar3D (UI/3D)            -- 3D 模式状态栏：坐标/选择/模型/消息/状态
```

### 11.2 职责划分

| 层级 | 职责 | 管理者 |
|------|------|--------|
| **框架级** | `workbenchLabel`（WB/Doc/Cmd/Layer/View/Dirty）+ `busyLabel`（Busy/Idle） | WorkbenchWindow 始终持有 |
| **工作台级** | 坐标/选择/消息/状态（由 StatusBarBase 子类封装） | 各 Workbench 在 attachToWindow 时创建 |

### 11.3 挂载/卸载机制

```text
WorkbenchWindow::mountStatusBar(StatusBarBase*)
    → 将 StatusBarBase widget 添加到 QStatusBar
    → 旧 widget 自动卸载

WorkbenchWindow::unmountStatusBar()
    → 从 QStatusBar 移除当前 StatusBarBase widget
    → 不 delete（生命周期由创建它的 Workbench 负责）
```

### 11.4 工作台切换流程

```text
Workbench2D::attachToWindow()
    → 创建 StatusBar 实例
    → window.mountStatusBar(statusBar2D)
    → 连接 viewport positionCallback → statusBar2D->setPositionText()

Workbench3D::attachToWindow()
    → 创建 StatusBar3D 实例
    → window.mountStatusBar(statusBar3D)
    → 连接 renderWidget sigCursorWorldPosition → statusBar3D->setPositionText()
    → 连接 renderWidget sigSelectionChanged → statusBar3D->setSelectionInfo()

clearWorkbenchContent()
    → window.unmountStatusBar()  // 移除旧 widget，不删除
    → 保留 workbenchLabel/busyLabel
```

### 11.5 设计优势

1. **封装清晰**：每个模式的状态栏由独立类管理，2D/3D 互不干扰
2. **生命周期明确**：Workbench 拥有 StatusBar，切换时销毁旧的、创建新的
3. **框架级标签稳定**：workbenchLabel/busyLabel 不随工作台切换而销毁
4. **信号直连**：3D 光标/选择信号直接连接到 StatusBar3D，无中间层

### 11.6 框架级槽位配置化（2026-08-25 起）

状态栏被拆成**两个互不干扰的层**：

- **工作台级内容**（坐标 / 选择 / 消息 / 工具提示）—— 仍由 `StatusBarBase` 子类
  （`StatusBar` / `StatusBar3D`）实现，经 `mountStatusBar` / `unmountStatusBar` 挂载。
  这部分是高频信号驱动的，不配置化。
- **框架级槽位**（客户标识、授权状态等跨工作台恒定的指示器）—— 由客户 JSON 的
  `statusBar.items[]` 声明，`WorkbenchLayoutManager::buildStatusBar()` 构建。

```text
WorkbenchLayoutManager::buildStatusBar()
    → m_panelState.statusBar = m_parent->statusBar()   // 容器始终存在
    → ensureConfigLoaded()（失败则 SY_WARN，跳过槽位，不影响工作台级状态栏）
    → clearStatusBarSlots()                            // 先回收上一轮，防止切换时堆积
    → UiLayoutBuilder::buildStatusBar(config->statusBar, m_activeWorkbenchId)
    → builder.builtStatusBarSlots() 存入 m_statusBarSlots（QPointer，防悬垂）
```

JSON 示例与字段语义（`align` / `stretch` / `feature` / `workbenches`）见
《UI定制.md》§3.11。两个必须记住的点：

- `align: "permanent"` → `QStatusBar::addPermanentWidget`，**不会被 `showMessage()` 的
  临时消息覆盖**；`align: "left"` → `addWidget`，会被覆盖。常驻指示器必须用 `permanent`。
- 槽位控件由 `UiPanelRegistry` 工厂创建，`widgetType` 必须已在
  `registerBuiltinUiPanels()` 注册（与 Dock 面板共用同一个注册表）。

> 新增一个客户专属指示器的完整步骤：
> 1. 写好 `QWidget` 子类；
> 2. `registerBuiltinUiPanels()` 里 `registerPanel("MyIndicator", ...)`；
> 3. 客户 JSON 的 `statusBar.items[]` 加一项，`align` 选 `permanent`；
> 4. （可选）加 `feature` 字段做授权控制。
>
> 全程不改 `StatusBarBase` 及其子类。


---

## 12. 设计原则总结

状态栏是“轻量反馈层”，其作用是让用户知道当前发生了什么、当前该做什么以及系统目前处于什么状态。对于大型激光软件，状态栏应尽量做到信息准确、响应及时、内容简洁，并与命令系统、视口和文档状态严格同步。
