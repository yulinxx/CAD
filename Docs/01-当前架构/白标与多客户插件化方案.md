# 白标与多客户插件化方案

> 状态：设计已确认，按本文分阶段落地（2026-10）。
> 关联文档：`01-当前架构/UI定制.md`（配置字段与运行期语义）、`01-当前架构/授权等级与功能分级设计.md`、`01-当前架构/UI分层与职责边界.md`。
> 本文解决三个缺口：**品牌层（Brand）**、**面板插件化（Panel Plugin）**、**打包流水线（Packaging）**，并给出客户代码独立仓库的组织方式。

---

## 1. 结论

现有「菜单 / 布局 / 功能授权」级多客户定制已经可用，问题不在配置模型，而在交付边界：

| 能力 | 现状 | 目标 |
| --- | --- | --- |
| 换产品名 / 公司 / 版权 / 图标 / 启动图 / 默认主题 | 硬编码在 C++（`WorkbenchWindow.cpp:148`、`AboutDialog.cpp`、`CADApplicationRuntime.cpp:29`） | 由 `brand.json` 驱动，零重编 |
| 客户新增 Dock / 面板 / 状态栏部件 | 必须改 `UiBuiltinPanels.cpp` 重编主程序 | 客户插件 DLL 注册 |
| 客户配置下发 | 只能编进 `configs.qrc`，缺文件直接 `FATAL_ERROR`（`Main/CMakeLists.txt:137-155`） | exe 旁 `configs/<id>.json` 外置加载 |
| 换客户 | 重编 + 人工替换资源 | `client.id` + 脚本一键出包 |
| 客户代码隔离 | 全部堆在主仓库 | 每客户独立仓库，以 git submodule 挂入 `Clients/<id>` |

判定标准（验收时逐条勾）：

1. 只改外部文件（`client.id`、`configs/`、`branding/`、`plugins/clients/`）即可完成一个客户的白标交付，不重新编译主程序。
2. 主程序在没有插件、没有外部配置时行为与今天完全一致（内置 `san_yi` 回落）。
3. 任一客户配置/品牌错误只影响该客户启动，并在日志与自检中给出明确错误。
4. 客户插件 ABI 与主程序锁定，插件加载失败不阻止主程序启动。

非目标（本阶段不做）：

- 不实现 JSON 的「删除/隐藏」减法语义；客户配置仍以「覆盖 + 追加」表达，需要隐藏的项由插件或授权层裁剪。
- 不实现运行期切换客户（切换 = 换 `client.id` 后重启）。
- 不实现 Linux/macOS 安装包；Windows 目录包 + zip 为一等交付物。

## 2. 现状与差距（代码证据）

### 2.1 已有能力

- 客户配置：`Main/Src/UI/ClientConfig/`，`UiClientContext` / `UiConfigLoader` / `UiConfigurationManager` / `UiLayoutBuilder` / `UiPanelRegistry` / `UiFeatureGate` / `UiConfigSelfCheck`。`base.json` 176 个 action、15 个子菜单，`ClientConfigTests.cpp` 33 个契约测试。
- 客户 ID 来源：`setClientIdOverride` > `SANYI_CLIENT_ID` > `QSettings "Client/Id"` > `san_yi`（`UiClientContext.cpp:32-57`）。
- 面板工厂：`PanelFactory = std::function<QWidget*(QWidget*)>`，内置 `SceneTreePanel`、`PropertiesPanel`、`ClientIndicator`、`LicenseIndicator`、`Spacer`、`MessageLabel`（`UiBuiltinPanels.cpp:27-85`）。
- 插件脚手架：`UI/Common/Include/UI/Plugin/ICommandPlugin.h`、`CommandPluginRegistry`、`CommandPluginPathHelper`，但仅 3D 接线（`OperationSetup3D.cpp:67-68`）。
- 主题：`ThemeManager` 6 套 QSS，`SettingsService` 持久化。
- 图标：`IconHelper::resolveIconResource` 支持 flavor 覆盖，`setUserIconDirectory`（`IconHelper.cpp:284`）已实现但全仓库无调用。

### 2.2 关键缺口

1. **配置不可外置**：`UiClientContext.cpp:85` 只拼 `:/configs/%1.json`；`Main/CMakeLists.txt:137-155` 要求磁盘 JSON 必须登记进 qrc，否则配置失败。
2. **品牌不可配置**：应用名/组织名来自编译期 `VersionInfo.h`；窗口图标、窗口标题、About 版权、组件标题均为常量。`themeStyle` 字段被解析（`UiConfigLoader.cpp:289-291`）但无消费者；`SANYI_DEFAULT_CLIENT_ID`（`Main/CMakeLists.txt:275`）无代码读取；文档中的 `--client=xxx` 未实现。
3. **面板不可扩展**：新增面板必须修改 `UiBuiltinPanels.cpp`；插件接口没有面板注册能力，且 `ICommandPlugin` 的 sink 是空标记类。
4. **无打包链路**：主 CMake 无 `install()`，无安装器/zip 脚本，无客户矩阵 CI。
5. **基线风险**：所有客户 `extends base.json`，改基线影响全部客户；合并无减法语义，也没有「全客户加载 + 快照」测试。

## 3. 目标架构

```text
<AppDir>/
  SanYiCAD.exe
  client.id                      # 纯文本，唯一部署真源
  configs/
    base.json                    # 基线（与内置 :/configs/base.json 同源）
    <clientId>.json              # 客户 UI 配置
  branding/
    <clientId>/
      brand.json
      app.ico  logo.svg  splash.png  icons/...
  plugins/
    clients/
      <clientId>/
        ClientUi.dll
  <Qt runtime dlls...>
```

加载顺序（不变式）：

```text
argv --client / SANYI_CLIENT_ID / client.id / QSettings / san_yi
        │
        ▼
UiBrandManager.loadForProcess()      # 纯 std::filesystem + QJson，先于 QApplication
        │ 设置 org/app 名、QCoreApplication 属性
        ▼
QApplication
        │
        ▼
UiClientContext                      # 配置路径：用户目录 → AppDir/configs → :/configs
        │
        ▼
UiClientPluginHost.loadForClient()   # 只加载 plugins/clients/<active> 与 SANYI_CLIENT_PLUGIN_DIR
        │
        ▼
AppBootstrapper → UiConfigurationManager → UiLayoutBuilder
        │
        ▼
registerBuiltinUiPanels()            # 内置面板 + 插件面板（两个 registry 都覆盖）
```

## 4. 品牌层设计

### 4.1 `brand.json` 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `clientId` | string | 必填，与目录名一致；不一致时以目录名为准并告警 |
| `productName` | string | 产品名，窗口标题默认值、About 标题、`applicationName` |
| `companyName` | string | 公司名，`organizationName`、About 版权主体 |
| `appId` | string | 组织/数据目录隔离用，默认 `companyName + productName`（去空格） |
| `organizationDomain` | string | `QCoreApplication::setOrganizationDomain` |
| `version` | string | 覆盖 `applicationVersion`，空则用编译期版本 |
| `windowTitle` | string | 覆盖主窗口标题，空则用 `productName` |
| `tagline` | string | 一句话描述（About 副标题） |
| `copyright` | string | 版权行，空则用 `Copyright (C) <year> <companyName>` |
| `website` | string | About 链接 |
| `supportEmail` | string | About 支持邮箱 |
| `aboutText` | string | 追加到 About 的纯文本段落 |
| `appIcon` | string | 相对 `branding/<id>/` 或 `:/` 资源；窗口/任务栏图标 |
| `logo` | string | 主界面 Logo（预留给后续接线） |
| `aboutLogo` | string | About 顶部 Logo |
| `splash` | string | 启动图；空则不显示 |
| `splashDurationMs` | int | 启动图最短展示时间，默认 800 |
| `iconDirectory` | string | `IconHelper::setUserIconDirectory` 的目录 |
| `theme` | string | `light/dark/blue/slate/high_contrast/system`，仅在用户未保存主题时生效 |
| `styleSheet` | string | 品牌附加 QSS（相对路径），叠加在主题之后 |

`brand.json` 本身不参与 `UiConfig` 的 `extends` 合并，按目录整体覆盖。

### 4.2 查找顺序

1. `SANYI_BRAND_DIR`（开发/自动化测试，指向含 `brand.json` 的目录）
2. `<AppDir>/branding/<clientId>/brand.json`
3. `:/brand/<clientId>/brand.json`
4. `:/brand/default/brand.json`
5. 内置默认值（= 当前 SanYi CAD 行为）

资源字段解析：绝对路径/`:/` 原样；相对路径先找品牌目录，再找 `:/brand/<id>/`，最后 `:/brand/default/`。

### 4.3 应用点

| 应用点 | 位置 | 说明 |
| --- | --- | --- |
| org/app 名、版本、域名 | `UiBrandManager::applyApplicationIdentity()` | 必须在 `AppPathManager::buildAppPaths()` 之前，保证数据目录按客户隔离 |
| `QCoreApplication` 属性 | 同上 | `brand.productName/companyName/copyright/website/aboutText/aboutLogo`，供 UICommon 读取 |
| 窗口图标 | `CADApplicationRuntime` 构造 | `appIcon` → `QApplication::setWindowIcon` |
| 窗口标题 | `WorkbenchWindow`（构造 + `retranslateUi`） | `UiBrandManager::windowTitle()` |
| About 标题/副标题/版权/网站 | `UI/Common/Src/Dlg/AboutDialog.cpp` | 通过新增 `UI/BrandInfo.h` 读 qApp 属性，UICommon 不依赖 Main |
| 默认主题 | `CADApplicationRuntime` 启动早期 | `ThemeManager::setTheme(brand.theme)`；`SettingsService::getTheme` 默认改为「当前主题」，已保存值仍优先 |
| 图标目录 | `CADApplicationRuntime` 启动早期 | `IconHelper::setUserIconDirectory(brand.iconDirectory)` |
| 品牌 QSS | 同上 | `ThemeManager::setBrandStyleSheet(...)`，每次切主题后重新追加 |
| 启动图 | `CADApplicationRuntime::run()` | `QSplashScreen`，在 bootstrap 完成后关闭，最短展示 `splashDurationMs` |

### 4.4 已知限制

- **Windows exe 图标与文件版本信息无法运行期修改**。白标交付由打包脚本生成带图标的快捷方式，并使用 `rcedit`（可选）在 CI 中对 exe 拷贝写入 `ProductName/CompanyName/Icon`；主仓库不引入该依赖。
- 品牌改名会改变 `QSettings` 的 `organization/application` 键空间（`appId` 决定），但 `AppPathManager` 的日志/crash/config 目录仍固定为 `SanYiCAD`（历史兼容，本次不改）。同一台机器切换客户等于切换设置身份，这是有意为之；升级时由打包脚本固定 `appId` 防止漂移。
- 中文品牌名写入 JSON 必须 UTF-8；源码新增文件统一 UTF-8（MSVC 已开 `/utf-8`）。

## 5. 面板与命令插件化

### 5.1 接口（Main 侧，不修改 UICommon 的既有命令接口）

新文件 `Main/Src/UI/ClientConfig/IClientUiPlugin.h`：

```cpp
class UiPanelRegisterSink
{
public:
    virtual ~UiPanelRegisterSink() = default;
    virtual void registerPanel(const QString& id,
                               std::function<QWidget*(QWidget*)> factory) = 0;
};

class IClientUiPlugin
{
public:
    virtual ~IClientUiPlugin() = default;
    virtual QString id() const = 0;
    virtual QString clientId() const = 0;          // 空 = 所有客户
    virtual void registerPanels(UiPanelRegisterSink& sink) {}
};

extern "C" IClientUiPlugin* createClientUiPlugin();
extern "C" void destroyClientUiPlugin(IClientUiPlugin*);
```

- 插件只依赖 Qt Widgets 与 C++ 标准库，不链接主 exe；sink 由宿主传入，虚表跨 DLL 使用。
- 插件若同时导出 `createCommandPlugin`，宿主复用同一个 `QLibrary` 句柄注册到现有 `CommandPluginRegistry`，避免同一 DLL 被加载两次、产生两份单例。
- 面板布局仍由客户 JSON 的 `panels` 段引用插件注册的 id；未引用的面板不实例化。

### 5.2 目录与加载

```text
<AppDir>/plugins/clients/<clientId>/*.dll
$SANYI_CLIENT_PLUGIN_DIR/*.dll        # 开发/调试，优先级最高
```

- `UiClientPluginHost::loadForClient(clientId)` 在 `CADApplicationRuntime::run()` 中、`AppBootstrapper` 创建前调用（早于 `UiConfigurationManager` 首次访问）。
- 只加载与 `clientId` 匹配（或 `clientId()` 为空）的插件；加载失败记 `SY_ERROR` 并继续。
- 句柄常驻，不卸载（Qt 插件卸载会破坏已创建的 QWidget 元对象）。
- `UiBuiltinPanels.cpp` 末尾对传入 registry 调用 `UiClientPluginHost::applyPanels(registry)`，因此 `WorkbenchMenuManager` 与 `WorkbenchLayoutManager` 两处 registry 都能拿到插件面板。

### 5.3 2D 命令插件

现有 `CommandPluginPathHelper` 与 `CommandPluginRegistry` 只在 3D 使用。本阶段：

- 客户插件走新的 `plugins/clients/<id>` 目录，2D/3D 都可注册**面板**；
- 2D 的**命令/目录项**仍走 L2（编入主程序）或后续给 2D 增加 `ICatalogRegisterSink` 实现，不在本次范围；
- 3D 的 `applyAll` 会消费客户插件导出的命令（若存在），因为一个进程只服务一个客户。

### 5.4 ABI 约束

- 插件与主程序必须同一编译器（MSVC 工具集）、同一 Qt 版本、同一运行库（`/MD`）、同一架构（x64）。
- 发布时在 `plugins/clients/<id>/abi.txt` 写 `qt=6.x.y msvc=19.4x arch=x64`，宿主发现不匹配时拒绝加载并提示。
- 接口只允许新增纯虚函数（带默认实现）或在末尾追加；禁止改既有签名。每次破坏性变更提升 `SANYI_CLIENT_PLUGIN_ABI` 并在 `NewClient.ps1` 模板中断言。

## 6. 外部配置与 `client.id`

### 6.1 客户 ID 解析（最终顺序）

1. `--client=<id>` / `--client <id>`（新增，`CADApplicationEntry` 解析）
2. `SANYI_CLIENT_ID`
3. `<AppDir>/client.id`（首行，去 BOM/空白；打包脚本写入）
4. `QSettings "Client/Id"`（兼容旧安装）
5. `san_yi`

### 6.2 配置查找

`UiClientContext::configResourcePath()` 改为按序探测：

1. `AppPathManager::configDir()/ui/<id>.json`（每用户覆盖，运维热修）
2. `<AppDir>/configs/<id>.json`（交付包）
3. `:/configs/<id>.json`（内置）
4. 都缺失 → `:/configs/san_yi.json`（现有 Fallback 行为保留）

父配置（`extends`）解析失败时，新增回退：若父 id 在内置 `:/configs/<name>.json` 存在则用之，否则报错。这样交付包只需放客户 JSON + `base.json`，不会因为相对路径失效而整体回落。

### 6.3 缓存与自检

- `UiConfigurationManager` 仍按进程缓存；`client.id` 变化必须重启。
- `UiConfigSelfCheck` 增加品牌段检查：`productName` 非空、`theme` 合法、引用的资源存在、插件目录存在但未加载时给出提示。
- 打包脚本在出包前跑同一套 JSON 解析，失败即中止。

## 7. 客户代码仓库策略

### 7.1 方案对比

| 方案 | 隔离性 | 主程序重编 | 发布风险 | 结论 |
| --- | --- | --- | --- | --- |
| A. 全放主仓库 `Clients/<id>/`（同仓分支） | 差 | 每次客户改动都要全量构建 | 高 | 仅适合 2-3 个试点 |
| B. 每客户独立仓库，编成插件 DLL，submodule 挂入 | 好 | 只有插件重编 | 低 | **推荐** |
| C. 每客户独立仓库，整包 fork 主程序 | 最好 | 各自全量 | 维护成本最高 | 仅当客户要求源码隔离/私有协议 |

采用 **B**，保留升级到 C 的出口：客户仓库只依赖公开 SDK 头（`Main/Src/UI/ClientConfig/IClientUiPlugin.h`）与 UICommon/UI2D 导入库，不 include 主程序私有实现。

### 7.2 仓库布局

```text
Clients/
  _template/                 # 脚手架，不参与构建
  <clientId>/                # 独立 git 仓库 / submodule
    CMakeLists.txt
    src/ClientPlugin.cpp
    src/ClientPanels.h/.cpp
    configs/<clientId>.json
    branding/<clientId>/brand.json + assets
    README.md
CMakeLists.txt               # 根仓库聚合（SANYI_BUILD_CLIENT_PLUGINS）
```

接入命令（在客户仓库创建后由管理员执行一次）：

```powershell
git submodule add <repo-url> Clients/<clientId>
git submodule update --init --recursive
```

### 7.3 分支与发布

- 客户仓库 `main` 只放该客户内容；`core-sdk` 标签记录适配的主程序版本（`SANYI_CORE_VERSION`）。
- 主程序升级后，插件按 SDK 版本重编；`PackageClient.ps1 -ClientId x` 校验 `abi.txt` 与 `client.id`。
- 客户配置/品牌属于客户仓库，主仓库只保留 `san_yi/client_a/client_b` 三个示例用于回归测试。

## 8. 打包流水线

### 8.1 交付目录

```text
dist/<clientId>/
  SanYiCAD.exe
  client.id
  configs/{base.json,<clientId>.json}
  branding/<clientId>/*
  plugins/clients/<clientId>/*.dll
  <Qt runtime + platforms/ + styles/ ...>
```

### 8.2 脚本

| 脚本 | 职责 |
| --- | --- |
| `Tools/NewClient.ps1 -ClientId acme -ProductName "AcmeCut"` | 从 `Clients/_template` 生成客户目录；替换占位符；打印 `git init` / submodule 命令 |
| `Tools/PackageClient.ps1 -ClientId acme -BuildDir build/bin_Qt6/Release` | 校验配置/品牌/ABI；拷贝运行目录；写 `client.id`；生成 zip；可选生成带图标快捷方式 |
| `Tools/VerifyClient.ps1 -ClientId acme`（后续） | 跑 `UiConfigSelfCheck` 的离线版：JSON schema、引用完整性、资源存在性 |

脚本要求：

- 全部使用 `-LiteralPath` 与 UTF-8（无 BOM）写 `client.id`；
- 失败时非零退出并输出中文原因；
- 不修改主仓库工作区，只读 `Clients/` 与构建输出。

### 8.3 CI

新增 `client-matrix` job（手动触发）：

1. 枚举 `Clients/*/configs/*.json`；
2. 对每个客户执行 `MainTests --gtest_filter=ClientConfig*:BrandConfig*`，环境变量设 `SANYI_CLIENT_ID`；
3. 构建对应插件并运行 `PackageClient.ps1 -NoZip` 做冒烟；
4. 任一步失败阻断发布。

## 10. 风险与回滚

- **配置路径变化导致旧包失效**：保留 qrc 路径为第 3 顺位；`san_yi` 回落不变。
- **品牌改名导致设置丢失**：`appId` 默认由品牌生成，首次升级由脚本固定；文档中明确「换客户 = 新身份」。
- **插件崩溃**：加载在 bootstrap 之前，异常用 `try/catch` 包裹并记录；面板工厂异常只影响该面板，`UiLayoutBuilder` 已有失败降级。
- **ABI 漂移**：`abi.txt` + 编译期 `SANYI_CLIENT_PLUGIN_ABI` 双重校验；不匹配拒绝加载。
- **回滚**：删除 `client.id` 与外部目录即回到内置 `san_yi`；代码开关 `SANYI_BUILD_CLIENT_PLUGINS=OFF` 可完全关闭插件聚合。
