# 设置系统架构

本文档描述 CAD 软件中设置系统的架构设计，涵盖设计理念、核心领域模型、数据流、扩展性设计。

---

## 1. 设计背景与目标

### 1.1 解决的问题

- **设置分散**: 各类设置散落在代码各处，缺乏统一管理
- **耦合严重**: UI 与业务逻辑直接耦合，切换 UI 框架成本高昂
- **扩展困难**: 新增设置项需要修改多处代码
- **状态混乱**: 内存设置与持久化状态不同步
- **无法回溯**: 缺少设置变更历史，无法撤销

### 1.2 设计目标

| 目标 | 描述 |
|------|------|
| **分层解耦** | UI 层、业务层、持久化层完全分离 |
| **类型安全** | 设置项有明确类型，编译期检查 |
| **可观测性** | 设置变更可监听，支持响应式更新 |
| **可回溯** | 支持设置变更历史，支持撤销/重做 |
| **可扩展** | 插件可声明自己的设置项 |
| **可验证** | 支持设置项的约束和校验规则 |

## 3. 核心领域模型

### 3.1 设置项元数据 (SettingsItem)

```cpp
struct SettingsItem {
    QString key;                    // 唯一键标识 (如 "canvas.background.color")
    SettingType type;               // 类型: Bool/Int/Float/Double/String/Enum
    QVariant defaultValue;         // 默认值
    QString displayName;            // 显示名称 (用于 UI)
    QString description;            // 描述信息
    std::function<bool(const QVariant&)> validator;  // 校验函数
    std::function<void(const QVariant&)> onChanged;  // 变更回调
};
```

### 3.2 设置域 (SettingsDomain)

```cpp
class SettingsDomain {
public:
    virtual QString domainName() const = 0;
    virtual std::vector<SettingsItem> getAllItems() const = 0;

    // 运行时操作
    virtual QVariant getValue(const QString& key) const = 0;
    virtual void setValue(const QString& key, const QVariant& value) = 0;
    virtual void resetToDefaults() = 0;

    // 变更通知
    virtual void subscribe(const QString& key, std::function<void(const QVariant&)> callback) = 0;
    virtual void unsubscribe(const QString& key, std::function<void(const QVariant&)> callback) = 0;
};
```

### 3.3 设置域分类

| 域 | 说明 | 典型设置项 |
|----|------|------------|
| `common` | 公共设置 | 语言、主题、字体、单位 |
| `canvas` | 画布设置 | 背景色、网格显示、原点 |
| `grid` | 网格设置 | 间距、颜色、样式 |
| `snap` | 捕捉设置 | 捕捉模式、捕捉半径 |
| `ruler` | 标尺设置 | 可见性、刻度单位 |
| `selection` | 选择设置 | 虚线动画、选择颜色 |
| `machine` | 机器设置 | 激光功率、速度、焦距 |
| `view3d` | 3D 视图 | FOV、Fog、抗锯齿 |
| `camera3d` | 3D 相机 | 移动速度、旋转灵敏度 |

## 4. 数据流动

### 4.1 设置读取流程

```
启动应用
    │
    ▼
SettingsService::init()
    │
    ├── 加载注册表 (从 DLL/插件扫描 SettingsDomain 实现)
    │
    ├── 从数据库恢复设置值
    │   └── ISettingsRepository::load(domainName) → SettingsGroup
    │
    └── 通知订阅者
        └── SettingsContext::applySettings(group)
            │
            ├── 字体设置 → QApplication::setFont()
            ├── 主题设置 → ThemeManager::setTheme()
            ├── 视图设置 → Viewport::applySettings()
            └── 捕捉设置 → SnapEngine::applySettings()
```

### 4.2 设置修改流程

```
用户修改设置 (UI 控件)
    │
    ▼
ISettingsTab::onControlChanged()
    │
    ├── 收集到临时 SettingsTable
    │
    ├── 实时预览 (可选)
    │   └── emit previewRequest(settingsTable)
    │
    └── 用户点击"确定"
        │
        ▼
SettingsDialogBase::slotAccept()
    │
    ├── validateBeforeAccept() → 校验输入
    │
    ├── 记录到历史栈 (可选)
    │   └── SettingsHistory::push(change)
    │
    ├── 原子性持久化
    │   └── ISettingsRepository::save(domain, settings)
    │
    └── 应用到运行时
        └── SettingsContext::applySettings(settings)
            │
            ├── 通知相关组件
            │   └── domain.getNotifier(key).notify(newValue)
            │
            └── 发送变更信号
                └── emit settingsChanged(domain, key, newValue)
```

### 4.3 变更通知机制

```cpp
// 设置域内部使用信号-槽或回调
class CanvasDomain : public SettingsDomain {
    void setValue(const QString& key, const QVariant& value) override {
        // 1. 更新内部值
        m_values[key] = value;

        // 2. 触发验证器
        if (auto it = m_validators.find(key); it != m_validators.end()) {
            Q_ASSERT(it->second(value));  // 校验失败抛异常
        }

        // 3. 通知订阅者
        if (auto it = m_subscribers.find(key); it != m_subscribers.end()) {
            for (auto& callback : it->second) {
                callback(value);  // 同步调用
            }
        }

        // 4. 标记脏状态
        m_isDirty = true;
    }

    // 订阅者容器: key -> vector<callback>
    std::unordered_map<QString, std::vector<std::function<void(const QVariant&)>>> m_subscribers;
};
```

## 5. 关键设计决策

### 5.1 为什么使用"域"而非"表驱动"

| 设计 | 优点 | 缺点 |
|------|------|------|
| 表驱动 (key-value) | 简单、灵活 | 无类型安全、无验证、无法表达关系 |
| **领域模型 (Domain)** | **类型安全、可验证、可组合** | 初期开发成本略高 |

**决策**: 采用领域模型 + 键值对混合模式
- 元数据 (item) 使用代码声明 → 编译期检查
- 运行时值使用键值对 → 灵活持久化

### 5.2 为什么不直接用 Qt 属性系统

Qt 属性系统适合对象级设置，但存在以下问题：
- 难以跨对象共享和同步
- 缺乏统一的变更历史
- 与持久化层耦合紧密

**决策**: 自建设置系统，通过 `SettingsContext` 与 Qt 控件解耦

### 5.3 批量更新优化

问题：连续修改多个设置项时，每次修改都触发通知和持久化，性能低下。

解决：引入 `SettingsBatch`

```cpp
// 使用示例
SettingsBatch batch(settingsDomain);
batch.setValue("grid.visible", false);
batch.setValue("grid.spacing", 10.0);
batch.setValue("snap.enabled", true);
batch.commit();  // 一次性持久化，只触发一次通知
```

## 6. 扩展性设计

### 6.1 添加新设置域

```cpp
// 1. 声明领域
class MyPluginDomain : public SettingsDomain {
    QString domainName() const override { return "myplugin"; }

    std::vector<SettingsItem> getAllItems() const override {
        return {
            {"myplugin.option1", SettingType::Bool, false, "Option 1"},
            {"myplugin.option2", SettingType::Int, 100, "Option 2"},
        };
    }
};

// 2. 注册领域
SettingsService::registerDomain(std::make_unique<MyPluginDomain>());
```

### 6.2 动态设置项 (运行时声明)

```cpp
// 插件可动态注册设置项
settingsDomain->registerItem({
    .key = "plugin.dynamic.setting",
    .type = SettingType::String,
    .defaultValue = "default",
    .displayName = "Dynamic Setting",
    .validator = [](const QVariant& v) { return !v.toString().isEmpty(); }
});
```

## 10. 设计原则总结

1. **领域驱动**: 以设置"域"为中心，而非 UI 对话框
2. **声明式定义**: 设置项元数据在代码中声明，类型安全
3. **响应式通知**: 变更自动传播，订阅者无需轮询
4. **可观测性**: 完整的历史记录，支持审计和回滚
5. **接口隔离**: 各层通过接口通信，便于替换实现
6. **插件友好**: 开放注册机制，支持动态扩展
