# 顶部工具栏架构定义

## 1. 文档目标

本文档定义顶部工具栏的职责、内容边界、功能分类与架构设计。顶部工具栏通常承载视图控制、全局快捷入口、加工预览和常用系统操作，应兼顾高频访问与全局可见性。

---

## 2. 顶部工具栏在整体框架中的位置

```text
用户点击顶部工具栏
    → 全局视图 / 系统命令
    → 命令系统
    → 视图、布局、预览、全局功能执行
    → 状态栏 / 视口刷新
```

顶部工具栏属于应用级 UI 控件，通常靠近窗口顶部，服务于全局动作而不是绘图过程本身。

---

## 3. 顶部工具栏的职责

顶部工具栏主要承担：

1. 提供视图控制入口。
2. 提供全局常用操作入口。
3. 提供当前工作模式的快速切换。
4. 提供加工预览、仿真、输出等全局动作入口。
5. 与菜单保持功能对应，但以更高频、更便捷的形式呈现。

---

## 5. 顶部工具栏不应承载的内容

- 大量图元创建按钮
- 细粒度属性编辑
- 局部对象管理
- 复杂面板内容
- 专属于某个工具的瞬时状态

这些内容应分别交给左侧工具栏、右侧工具栏、菜单或面板。

---

## 6. 顶部工具栏的功能分类

建议分成五类：

### 6.1 视图控制类

用于缩放、平移、复位和视图方向控制。

### 6.2 全局文件类

用于新建、打开、保存、导出等高频文件动作。

### 6.3 工具模式类

用于在选择、绘图、编辑、预览之间切换。

### 6.4 加工快捷类

用于路径分析、仿真和输出等工艺相关动作。

### 6.5 状态切换类

用于显示或切换当前全局模式。

## 7. 顶部工具栏与命令系统关系

顶部工具栏应统一通过命令系统执行，不应有独立行为分支。

```text
Top Toolbar Action
    → Command ID
    → Command Dispatcher / OperationBus
    → View / Document / Process Service
```

构建期（决定按钮是哪个 QAction）与触发期（决定执行哪个操作）是两条不同的链路：

```text
构建期：ToolBarContext 注册的 actionId（如 edit.align_left）
    → CommandCatalog::menuIdForCommandId()
    → CommandActionHub::editAction() / toggleEditAction() / toolAction()
    → TopToolBar 直接复用中枢托管的同一个 QAction

触发期：QAction::triggered
    → CommandCatalog::operationForCommandId()
    → OperationBus::run(OperationId, ...)
```

### 7.1 设计要求

- 顶部工具栏和菜单应共享同一命令集合。
- 顶部工具栏动作应尽量一键完成。
- 工具栏状态应与当前文档和视图状态同步。
- 视图控制类命令应支持重复点击和连续操作。
- **`ToolBarAction::actionId` 必须使用命令目录的小写点分 id**（`edit.align_left`、`edit.delete`），不得使用 `Edit_AlignLeft` 这类 Pascal_Underscore 写法。前者能被 `menuIdForCommandId()` 解析并复用中枢 QAction；后者解析落空后会退化为 `createUnmanagedAction()` 新建的非托管 QAction，启用态从此固定为配置里的静态值。
- 工具栏内部不得维护第二张 `actionId → MenuActionId` 映射表。解析职责唯一归属 `CommandCatalog`。

### 7.2 状态同步

顶部工具栏的按钮状态来自两类来源。

视图/模式类（工具栏自身或视图服务驱动）：

- 当前视图缩放状态
- 当前工作模式
- 当前加工状态
- 当前文档状态
- 当前是否正在播放预览或仿真

命令启用态类（由命令中枢的 `CommandUiSnapshot` 统一驱动，工具栏不做任何判定）：

- 是否有选中图元（`hasSelection`）
- 选中数量（`selectionCount`，对齐类命令要求 ≥ 2）
- 锁定态：图层锁 `anyLockedLayer` 或图元锁 `anyLockedEntity`
- 剪贴板是否非空（`hasClipboard`）
- 撤销/重做栈状态（`canUndo` / `canRedo`）

刷新由 `UiStateBridge2D` 集中挂载触发源（选择变化、图层变化、撤销栈变化、操作完成、`SceneMonitor::sceneChanged`），统一走 `Workbench2D::refreshCommandUiState()` → `CommandActionHub::refreshActionStates(snapshot)`。工具栏侧无需订阅任何信号。

## 8. 顶部工具栏与框架设计

### 8.1 依赖约束

- 顶部工具栏依赖 UI 公共服务、视图控制服务和命令系统。
- 不应直接依赖几何核心实现。
- 不应直接修改文档数据。
- 不应直接操作渲染后端。

### 8.2 设计原则

- 高频全局动作优先放顶部。
- 顶部工具栏应保持简洁，避免过度拥挤。
- 重要系统状态应可视化，但不应占满空间。
- 常用命令优先暴露图标与快捷键。

## 10. 当前实现状态

1. 顶部工具栏由主工作台统一创建（`Workbench2D::createToolbars()`），内容由 `ToolBarContextManager` 按上下文提供。
2. 通过命令总线统一触发动作。
3. 顶部工具栏复用菜单命令 ID —— `actionId` 即命令目录 id，经 `CommandCatalog::menuIdForCommandId()` 解析后直接取回 `CommandActionHub` 托管的同一个 QAction（`TopToolBar::resolveHubAction()`），与菜单/右键菜单共享同一实例。
4. 状态变化后按钮启用态自动更新：触发源由 `UiStateBridge2D::install()` 集中挂载，`Workbench2D::refreshCommandUiState()` 是唯一刷新入口，`Cmd::setActionEnabled()` 是唯一 `setEnabled` 出口。
5. 无选择、选择数量不足、目标被锁定、剪贴板为空、撤销栈为空时对应动作自动禁用，规则声明在 `CommandCatalog` 条目的 `enableRule` 上，工具栏不参与判定。

菜单栏走的是另一条路：菜单项是配置化构建（`UiLayoutBuilder`）出来的独立 QAction，中枢刷新触达不到，改由 `WorkbenchMenuManager::refreshCommandStates(snapshot)` 按同一份快照与同一份目录规则外挂刷新。顶部工具栏与菜单栏因此启用态一致，但实现机制不同：工具栏复用 Hub 的 QAction，菜单栏是外挂刷新器。


---

## 11. 设计原则总结

顶部工具栏是“全局高频入口层”，用于承载视图控制、常用系统功能和加工快捷动作。它的目标不是复杂，而是让用户在不打开菜单的情况下快速完成最常见的全局操作。
