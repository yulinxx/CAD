# 图元选择与菜单/工具栏联动机制

## 1. 概述

本文档描述 2D 工作台中，当用户选择（或取消选择）图元时，菜单栏和顶部工具栏的按钮启用状态如何实时联动的技术架构与实现流程。

---

## 2. 核心概念

### 2.1 命令中枢 (CommandActionHub)

`CommandActionHub` 是整个 UI 命令系统的核心枢纽，负责：
- 托管所有命令的 QAction（菜单项、工具栏按钮）
- 维护命令启用状态的单一事实来源 (`CommandUiSnapshot`)
- 处理命令分发（点击后执行什么操作）

### 2.2 命令 UI 快照 (CommandUiSnapshot)

`CommandUiSnapshot` 是选择状态的单一事实来源，包含：

```cpp
struct CommandUiSnapshotBase
{
    bool hasSelection{ false };      // 是否有选中图元
    int selectionCount{ 0 };         // 选中的图元数量
    bool hasClipboard{ false };       // 剪贴板是否有内容
    bool canUndo{ false };           // 撤销栈是否可撤销
    bool canRedo{ false };           // 重做栈是否可重做

    // 锁定维度
    bool anyLockedLayer{ false };    // 选中的图元是否位于锁定图层
    bool anyLockedEntity{ false };   // 选中的图元本身是否被锁定
    bool anyEditable{ false };       // 是否有可编辑的图元
    bool anyHidden{ false };         // 是否有隐藏的图元

    // 类型直方图（用于工具栏上下文切换）
    uint32_t typeMask{ 0 };

    // 辅助方法
    bool anyLocked() const { return anyLockedLayer || anyLockedEntity; }
};
```

### 2.3 命令目录 (CommandCatalog)

`CommandCatalog` 定义了所有命令的元数据，包括：
- 命令 ID（如 `edit.delete`、`edit.mirror_horizontal`）
- 启用规则（`CmdCond` 位掩码，命令目录里写 `Cmd::RequiresXxx`）

```cpp
// UI/Common/Include/UI/Command/CommandEnableRule.h
// 启用规则 = 一组原子条件按位组合；命令目录用 `|` 组合即表示"全部满足才启用"
enum class CmdCond : uint32_t
{
    None = 0,                 // 无条件（等价于 Always）
    Selection = 1u << 0,      // 有选中（>=1）
    MultiSelection = 1u << 1, // 选中数量 >= 2
    Clipboard = 1u << 2,      // 剪贴板有内容
    Undo = 1u << 3,           // 可撤销
    Redo = 1u << 4,           // 可重做
    Unlocked = 1u << 5,       // 选中中无任何锁定（图元锁或图层锁）
    Editable = 1u << 6,       // 选中中至少一个是可编辑（未锁）
    Visible = 1u << 7,        // 选中中无任何隐藏
    MeshTarget = 1u << 8,     // 存在网格目标（3D）
    ReliefPath = 1u << 9,     // 存在浮雕刀路（3D）
    Never = 1u << 31,         // 永不可用
};

namespace Cmd
{
    // 常用组合常量，命令目录直接引用，语义自解释
    constexpr CmdCond Always = CmdCond::None;
    constexpr CmdCond RequiresSelection = CmdCond::Selection;
    constexpr CmdCond RequiresUnlockedSelection = CmdCond::Selection | CmdCond::Unlocked;
    constexpr CmdCond RequiresUnlockedMultiSelection = CmdCond::MultiSelection | CmdCond::Unlocked;
    constexpr CmdCond RequiresVisibleSelection = CmdCond::Selection | CmdCond::Visible;
    constexpr CmdCond RequiresUnlockedVisibleSelection =
        CmdCond::Selection | CmdCond::Unlocked | CmdCond::Visible;
    // ...
}
```

## 4. 关键代码路径

### 4.1 状态提供器注入

在 `Workbench2D::createToolbars()` 中：

```cpp
// 1. 注入选择上下文提供器
m_commandHub->setSelectionContextProvider([selectionService = m_services.selectionService,
                                         layerManager = m_services.layerManager,
                                         sceneEditService = m_services.sceneEditService]() -> SelectionContext {
    // 遍历选中图元，计算 selectionCount / anyLockedLayer / anyLockedEntity / anyHidden
    SelectionContext result;
    // ...
    result.hasSelection = result.selectionCount > 0;
    result.groupEnabled = result.hasSelection && !(result.anyLockedLayer || result.anyLockedEntity || result.anyHidden);
    return result;
});

// 2. 注入撤销/重做状态提供器
m_commandHub->setUndoRedoProvider([undoManager = m_services.undoManager]() -> UndoRedoState {
    UndoRedoState state;
    if (undoManager) {
        state.canUndo = undoManager->canUndo();
        state.canRedo = undoManager->canRedo();
    }
    return state;
});

// 3. 注入剪贴板状态提供器
m_commandHub->setClipboardProvider([clipboard = m_services.clipboard]() -> bool {
    return clipboard && clipboard->hasContent();
});
```

### 4.2 按钮创建与 commandId 设置

`createEditAction()` 必须设置 `commandId` 属性，否则 `applySnapshotToAction()` 会跳过该按钮：

```cpp
QAction* CommandActionHub::createEditAction(const CommandEntry2D& entry)
{
    QAction* action = new QAction(parentWidget);
    action->setText(...);
    action->setData(static_cast<int>(entry.menuId));

    // 关键：必须设置 commandId 属性！
    if (entry.shortcutId)
    {
        const QString commandId = QString::fromUtf8(entry.shortcutId);
        action->setProperty("commandId", commandId);
        action->setObjectName(commandId);
    }
    // 如果 shortcutId 为空，从 menuId 派生
    else
    {
        const QString menuIdName = QMetaEnum::fromType<UI::MenuActionId>().valueToKey(static_cast<int>(entry.menuId));
        if (menuIdName.startsWith("Edit_"))
        {
            QString base = menuIdName.mid(5);
            base[0] = base[0].toLower();
            commandId = "edit." + base;
        }
    }
    // ...
}
```

### 4.3 启用规则判断

`applySnapshotToAction()` 中的规则判断：

```cpp
void CommandActionHub::applySnapshotToAction(QAction* action, const CommandUiSnapshot& snapshot)
{
    // 从 commandId 反查目录条目
    const QString commandId = action->property("commandId").toString();
    const UI::MenuActionId menuId = CommandCatalog::menuIdForCommandId(commandId);
    const CommandEntry2D* entry = CommandCatalog::findByMenuId(menuId);

    // 启用规则统一走内核求值：2D / 3D 同一条路径 Cmd::satisfy
    if (entry->enableRule == Cmd::Always)
    {
        return;  // 恒可用命令不写 enabled，避免与全局置灰互相打架
    }
    Cmd::setActionEnabled(action, Cmd::satisfy(entry->enableRule, snapshot));
}
```

原先这里还有两条针对 `CommandEnable2D::RequiresVisibleSelection` / `RequiresVisibleMultiSelection`（私有值 100/101）的特判分支，各自手算 `hasSelection && !anyLocked && !anyHidden`。这两条已删除：规则迁移到 `CmdCond` 后，「选中 + 未锁定 + 未隐藏」就是 `Selection | Unlocked | Visible` 三个 bit（对应 `Cmd::RequiresUnlockedVisibleSelection` / `Cmd::RequiresUnlockedVisibleMultiSelection`），`Cmd::satisfy` 已统一覆盖，特判没有存在理由。

## 5. 刷新触发源

所有 UI 刷新都通过 `UiStateBridge2D::install()` 统一挂载：

| 触发源 | 信号 | 刷新动作 |
|--------|------|----------|
| 用户选择图元 | `RenderViewport2D::selectionChanged` | 刷新所有按钮 |
| 锁定/解锁图层 | `QtLayerManagerBridge::sigLayerChanged` | 刷新锁定相关按钮 |
| 撤销/重做 | `OperationBus::undoStateChanged` | 刷新撤销/重做按钮 |
| 操作完成 | `OperationBus::operationCompleted` | 刷新所有按钮 |
| 场景变化 | `SceneMonitor::sceneChanged` | 刷新所有按钮 |

## 6. 架构设计要点

### 6.1 单一事实来源

整个 UI 状态管理的核心是 `CommandUiSnapshot`：
- 所有状态信息（hasSelection、canUndo、canRedo 等）都从快照获取
- 快照由状态提供器（Provider）捕获，而非直接从场景读取
- 这种设计使得状态计算逻辑集中，便于维护和测试

### 6.2 命令目录驱动

`CommandCatalog` 是元数据的集中定义点：
- 每个命令的启用规则在此统一定义
- 新增命令只需在目录中添加条目，无需修改刷新逻辑
- enableRule 枚举扩展性好，可根据需求添加新规则

### 6.3 统一连接层

`UiStateBridge2D` 作为桥接层：
- 将分散的信号源（selectionChanged、sigLayerChanged、undoStateChanged 等）统一管理
- 避免各 UI 组件各自监听信号导致的重复和遗漏
- 刷新请求统一流向 `Workbench2D::refreshCommandUiState()`

### 6.4 属性驱动查找

工具栏按钮通过 `commandId` 属性查找对应的 QAction：
- 菜单和工具栏的按钮在逻辑上视为一体
- 点击菜单项和点击工具栏按钮执行相同的命令
- 这种设计简化了菜单/工具栏同步问题

## 8. 测试建议

1. **无选择时**：所有需要选择的命令（Delete/Mirror/Copy/Align/Group）应该灰
2. **单选时**：Delete/Mirror/Copy 可用，Align 需要多选所以灰
3. **多选时**：所有编辑命令都可用
4. **选中锁定图层图元时**：相关命令变灰
5. **选中隐藏图元时**：相关命令变灰（RequiresVisibleSelection 规则）
6. **撤销栈非空时**：撤销按钮变亮
7. **重做栈非空时**：重做按钮变亮
8. **剪贴板有内容时**：粘贴按钮变亮
