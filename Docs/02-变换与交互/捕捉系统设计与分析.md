## 2. 捕捉标记形状系统

### 2.1 设计动机

原系统中所有捕捉类型都渲染为同一个绿色圆圈，用户无法区分当前捕捉到的是端点、节点、交点还是网格点。新的标记形状系统为每种捕捉类型提供**唯一的形状 + 独立的颜色**，使捕捉状态一目了然。

### 2.2 标记形状与颜色映射

每种捕捉类型对应一个**互不重复**的形状（旧实现里 `Midpoint`/`Nearest` 都是圆、`Quadrant`/`Polar` 都是三角，现已拆开）：

| 捕捉类型 | 形状 | 颜色 | 说明 |
|----------|------|------|------|
| `Snap_Endpoint` | ■ 方形 | 红色 (1,0,0) | 线段/圆弧/曲线的端点 |
| `Snap_Midpoint` | ▲ 三角 | 蓝色 (0,0.7,1) | 线段中点、圆弧中点 |
| `Snap_Center` | + 十字 | 橙色 (1,0.5,0) | 圆/圆弧的中心 |
| `Snap_Node` | ◇ 菱形 | 紫色 (0.8,0,0.8) | 样条/折线的内部控制点 |
| `Snap_Quadrant` | ⬡ 六边形 | 绿色 (0,0.8,0) | 圆/椭圆的0°/90°/180°/270°点 |
| `Snap_Intersection` | ✕ X形 | 品红 (1,0,1) | 两图元交点 |
| `Snap_Perpendicular` | ⊥ 直角 | 青色 (0,1,1) | 图元上最近的垂足 |
| `Snap_Tangent` | ⌒ 弧线 | 黄橙色 (1,0.6,0) | 圆/圆弧的切点 |
| `Snap_Nearest` | ○ 圆形 | 浅蓝 (0.5,0.5,1) | 图元上距离最近的点 |
| `Snap_Grid` | · 点 | 灰色 (0.6,0.6,0.6) | 网格点 |
| `Snap_Polar` | ⧗ 沙漏 | 浅绿 (0,0.9,0.3) | 极轴追踪点 |
| `Snap_StartPoint` | ★ 星形 | 深红 (1,0.2,0.2) | 绘制起点闭合捕捉 |

### 2.3 尺寸与绘制

- **尺寸基准**：`kSnapIndicatorRadiusPx = 16`（`RenderBridge/Include/RenderBridge/ScreenConstantMetrics.h`），
  单位是**逻辑像素/点**；所有形状以它为半径基准按固定系数缩放（0.22 ~ 0.78）。
  `RenderBridge::OverlayScene` 在送入 `WorldPinned` 前乘 `devicePixelRatio`（见
  `RenderBridge::OverlayScene::setDevicePixelRatio`），因此 Retina / 非 Retina 上屏幕视觉尺寸一致，
  不会出现「Retina 上只有一半大」的问题。
- **屏幕定尺寸**：整个指示器走 `RenderSpace::WorldPinned`，只锚定世界位置，
  尺寸恒定，不随视图缩放变化。
- **无底衬**：只画彩色形状本身，不加白色圆盘底。捕捉命中时鼠标指针会被隐藏
  （见 §2.4），标记不会被指针遮挡，也就无需底衬来提升可辨性。
- 绘制批次：彩色形状一笔 `Lines` 命令。

### 2.4 命中后隐藏鼠标指针

捕捉命中后标记已经画在捕捉点上，鼠标指针再压上去会挡住它。因此：

- `RenderViewport2D::applySnap()` 算出 `didSnap` 后，经 `UI::CursorManager::setHidden()`
  在命中时隐藏指针、未命中恢复当前工具光标；
- 平移时不隐藏（手型必须可见）；快速移动跳过捕捉时也会恢复。

光标系统（角色语义、皮肤适配、替换方式）见 `光标系统.md`。

### 2.5 形状渲染实现

每个形状都在屏幕空间中以像素定尺寸渲染（`RenderSpace::WorldPinned`），不随视图缩放变化：

- **方形**：4个顶点组成的闭合正方形轮廓
- **圆形**：20段线段组成的圆（最近点）
- **十字**：水平+垂直两条线（圆心）
- **菱形**：4个顶点组成的菱形
- **X形**：两条对角线
- **三角形**：等边三角形朝上
- **弧形**：0°到135°的圆弧
- **直角**：L形折线
- **点**：约3像素的小圆点
- **星形**：5角星（外圆+内圆交替）
- **六边形**：6段线段组成的闭合六边形（尖朝上）
- **沙漏**：上下两条边 + 两条交叉对角线（领结形）

| 文件 | 职责 |

## 3. 框架设计问题分析

### 3.1 已解决的问题

#### 问题 11（已解决）: `SnapResult` 信息丢失 → 捕捉类型可视化

原 `SnapResult` 只返回最佳候选点的位置。现在：
- `SnapEngine::SnapResult::snapType` 已存在，完整返回捕捉类型
- `GridSnapManager::snap()` 返回 `SnapOutput`（位置 + 类型），不再丢失类型信息
- `RenderViewport2D::applySnap()` 将 `snapType` 传播到渲染层
- `RenderBridge::OverlayScene` 根据类型渲染不同形状标记

#### 问题 1（已解决）: 重复的 SnapFlag 定义 → `RenderTypes.h` 统一引用

`Engine2D/Interaction/SnapEngine.h` 中的 `SnapFlag` 通过 `RenderTypes.h` 的包含链被渲染层直接引用。不再有重复定义。

### 3.2 待改进的问题（低风险，后续优化）

| # | 问题 | 现状 | 建议 |
|---|------|------|------|
| 1 | 重复 SnapFlag 定义 | 已在渲染层统一引用 | 提取到独立 `SnapTypes.h`，`GridSnapManager` 和 `SnapEngine` 都使用 |
| 2 | `SnapEngine` 重复持有设置 | `GridSnapManager` 和 `SnapEngine` 各有 `m_drawingStartPoint`/`m_tempEntitiesProvider` | 将设置收敛到 `GridSnapManager`，`SnapEngine` 只负责计算 |

| 5 | `snapToGrid` 逻辑重复 | `GridSnapManager` 和 `SnapEngine` 各自实现 | `GridSnapManager::snapToGrid` 委托给 `SnapEngine::snapToGrid` |

### 4.4 优先级与选择逻辑

```text
候选点来源          优先级值    说明
────────────────────────────────────────────
图元捕捉点           100       端点/中点/圆心/节点/象限/交点/垂足/切点/最近点
临时图元捕捉点       100       绘制中的预览图元
起点捕捉             100       闭合形状回起点
网格捕捉              50       网格点
极轴追踪              30       极轴投影点

选择规则：
1. 按 priority 降序（高优先级优先）
2. 同 priority 按 distSq 升序（距离近的优先）
3. 只有 distSq <= radiusSq 的候选点才参与选择
4. 最终取 min_element 的结果作为唯一 SnapResult
```

### 4.5 正交模式流程

正交模式是独立于捕捉系统的约束，在捕捉**之后**施加：

```text
BaseTool::onMouseMove(worldPos, event) [final]
    │
    ├── applySnap(worldPos) → 已吸附到最近图元/网格/起点
    │
    ├── wantsPointerConstraint() ? applyOrthoConstraint(pos) : pos
    │       └── m_gridSnapManager->isOrthoEnabled() || m_shiftOrthoOverride
    │               │
    │               ├── true → snapToOrtho(point, constraintAnchor())
    │               │       ├── |delta.x| > |delta.y| → 锁定 X 轴（水平）
    │               │       └── |delta.x| <= |delta.y| → 锁定 Y 轴（垂直）
    │               │
    │               └── false → 返回原坐标
    │
    └── setCurrentMousePos(pos) → 工具更新预览
```

Shift 键可临时启用正交（无论全局正交开关状态）。

## 5. 捕捉的使用方法

### 5.1 配置捕捉参数

通过 `GridSnapManager` 的 setter 接口配置：

```cpp
// 获取 GridSnapManager（通常由 RenderViewport2D 持有）
GridSnapManager* gsm = renderViewport2D->gridSnapManager();

// 启用/禁用捕捉
gsm->setSnapEnabled(true);

// 设置捕捉模式（位或组合）
gsm->setSnapModes(SnapMode_Endpoint | SnapMode_Midpoint | SnapMode_Center);

// 设置捕捉半径（像素单位）
gsm->setSnapRadius(10.0);

// 视图缩放：1 像素对应的世界单位数（视口在缩放/平移时同步），
// 捕捉计算时按该比例把像素半径换算为世界半径，保证屏幕捕捉范围恒定
gsm->setPixelToWorldScale(renderWidget->pixelToWorldScale());

// 设置网格间距
gsm->setGridSpacing(10.0);

// 启用极轴追踪
gsm->setPolarTrackingEnabled(true);
gsm->setPolarAngleStep(15.0);  // 度

// 启用正交模式
gsm->setOrthoEnabled(true);
```

### 5.2 获取捕捉结果

`GridSnapManager::snap()` 现在返回 `SnapOutput`，包含捕捉位置和类型：

```cpp
auto output = gsm->snap(worldPos);
if (output.snapType != SnapEngine::Snap_None)
{
    // 捕捉成功
    // output.pos → 捕捉后的坐标
    // output.snapType → 捕捉类型（用于显示不同标记）
}
```

### 5.3 工具集成

在 `ToolContext` 中注入 `GridSnapManager`：

```cpp
ToolContext ctx;
ctx.gridSnapManager = gsm;
toolManager->initializeTools(ctx);
```

工具基类 `BaseTool` 通过 `m_gridSnapManager` 自动获得：

- **绘制起点**：`setDrawingStartPoint()` 在工具激活时同步
- **临时图元**：`setTemporaryEntitiesProvider()` 在 `onActivate()` 时安装 lambda
- **正交约束**：`applyOrthoConstraint()` 在 `onMouseMove` 中自动施加

### 5.4 自定义捕捉提供者

通过 `TemporaryEntitiesProvider` 注入进行中绘制的临时图元：

```cpp
gsm->setTemporaryEntitiesProvider([this]() -> std::vector<const Eg::SyEntity*> {
    std::vector<const Eg::SyEntity*> result;
    for (const auto& e : m_previewEntities) {
        if (e) result.push_back(e.get());
    }
    return result;
});
```

**注意**：不要将"当前鼠标点"包含在临时图元中，否则终点捕捉会吸附到自己身上。

### 5.5 空间查询优化

通过 `setSpatialQueryCallback` 接入场景的 R-Tree：

```cpp
gsm->setSpatialQueryCallback([scene = sceneManager](const Ut::BBox2d& box) {
    return scene->queryByBox(box, /*containedOnly=*/false);
});
```

未设置时 `SnapEngine` 自动回退到全量遍历 `sceneManager->getAllEntities()`。

### 5.6 观察者模式

```cpp
class MyObserver : public IGridSnapManagerObserver {
    void onSettingsChanged() override { ... }
    void onGridVisibilityChanged(bool bVisible) override { ... }
};

IGridSnapManagerObserver* obs = new MyObserver();
gsm->addObserver(obs);
// ...
gsm->removeObserver(obs);
```

`QtGridSnapManagerBridge` 是 Qt 层面的具体实现，将 C++ 观察者回调转发为 Qt signals。

## 6. 捕捉方式方法总结

### 6.1 捕捉类型分类

| 类别 | 捕捉类型 | 原理 | 触发条件 |
|------|----------|------|----------|
| **图元几何捕捉** | Endpoint | 提取图元顶点（含多边形顶点） | 鼠标在半径内 |
| | Midpoint | 线段/圆弧中点计算 | 鼠标在半径内 |
| | Center | 圆/圆弧/多边形圆心 | 鼠标在半径内 |
| | Node | 样条/折线/多边形控制点或顶点 | 鼠标在半径内 |
| | Quadrant | 圆/椭圆轴向端点 | 鼠标在半径内 |
| | Intersection | 两图元交点计算 | 鼠标在半径内 |
| | Perpendicular | 图元上最近垂足 | 鼠标在半径内 |
| | Tangent | 从鼠标到圆/圆弧的切线 | 鼠标在半径内 |
| | Nearest | 图元上距离最近的点 | 鼠标在半径内 |
| **网格/极轴捕捉** | Grid | 坐标四舍五入到网格间距 | flags 含 Snap_Grid 且 spacing > 0 |
| | Polar | 角度归一化到极轴步长 | flags 含 Snap_Polar 且 angle > 0 |
| | StartPoint | 捕捉到绘制起点 | flags 含 Snap_StartPoint 且起点有效 |

### 6.2 捕捉算法关键逻辑

**网格捕捉**：
```cpp
x_snap = round(x / spacing) * spacing
y_snap = round(y / spacing) * spacing
```

**极轴追踪**：
```cpp
1. 计算鼠标相对于基点的角度 angleDeg
2. 归一化到 [0, 360)
3. snappedDeg = round(angleDeg / angleStepDeg) * angleStepDeg
4. snappedPos = basePoint + dist * (cos(snappedRad), sin(snappedRad))
```

**正交约束**：
```cpp
if |delta.x| > |delta.y| → (point.x, basePoint.y)  // 水平锁定
else                      → (basePoint.x, point.y)  // 垂直锁定
```

**交点捕捉**：
- 使用 `Geo2DParallel::intersectionPointsAllPairs()` 对所有候选图元对计算交点
- 交点无距离过滤（由 `SnapEngine` 统一过滤）

### 6.3 优化策略

1. **空间查询**：通过 R-Tree 只查询捕捉半径内的图元，避免全量遍历
2. **平方距离比较**：所有距离判断使用 `distSq` 避免 `sqrt` 开销
3. **候选点预分配**：`candidates.reserve(128)` 减少动态分配
4. **标志位过滤**：通过 `flags & Snap_Endpoint` 等位运算提前跳过不相关的提取逻辑
5. **条件提取**：仅在 `flags` 对应位为真时才调用对应的 `extract*Points` 方法

### 6.4 性能优化记录 (2024-09)

#### 6.4.1 包围盒预过滤

**问题**：鼠标移动时，每次调用 `findSnap` 都会对候选图元提取捕捉点，但大量图元的捕捉点可能离鼠标很远，提取是纯浪费。

**解决方案**：在 `processEntitySnapPoints` 开头添加包围盒预过滤：

```cpp
// 计算包围盒到鼠标点的最小距离的平方
const auto bbox = entity->getBbox();
double distX = 0.0, distY = 0.0;
if (worldPos.x() < bbox.minPt.x())
    distX = bbox.minPt.x() - worldPos.x();
else if (worldPos.x() > bbox.maxPt.x())
    distX = worldPos.x() - bbox.maxPt.x();
if (worldPos.y() < bbox.minPt.y())
    distY = bbox.minPt.y() - worldPos.y();
else if (worldPos.y() > bbox.maxPt.y())
    distY = worldPos.y() - bbox.maxPt.y();
const double closestDistSq = distX * distX + distY * distY;
if (closestDistSq > radiusSq) {
    return;  // 包围盒离鼠标太远，跳过提取捕捉点
}
```

**效果**：对于不在捕捉范围内的图元，直接跳过昂贵的捕捉点提取。

#### 6.4.2 交点计算优化

**问题**：交点捕捉使用 `intersectionPointsAllPairs`，复杂度 O(n²)。当候选图元很多时（如1717个），需要计算 147 万对交点，极慢。

**解决方案**：
1. 使用更小的查询半径（`snapRadius * 0.5`）进行空间查询
2. 额外进行包围盒距离过滤

```cpp
const double intersectionQueryRadius = snapRadius * 0.5;
// 使用小半径查询图元，再做包围盒过滤
```

**效果**：大幅减少传入 `intersectionPointsAllPairs` 的图元数量。

#### 6.4.3 快速移动跳过捕捉

**问题**：鼠标快速移动时，捕捉结果对用户无意义，但仍然进行昂贵的捕捉计算。

**解决方案**：在 `RenderViewport2D::applySnap` 中添加移动距离检测：

```cpp
static constexpr double kFastMoveSnapThresholdPx = 50.0;  // 像素单位
// 阈值同样以像素衡量，先换算成世界单位再比较，避免缩放时误判
const double thresholdWorld = kFastMoveSnapThresholdPx * pixelToWorldScale;
const double dx = worldPos.x() - m_lastSnapMousePos.x();
const double dy = worldPos.y() - m_lastSnapMousePos.y();
if (dx*dx + dy*dy > thresholdWorld * thresholdWorld) {
    // 快速移动，跳过捕捉
    return worldPos;
}
```

**效果**：鼠标快速移动时完全不执行捕捉计算。
