# 数据与渲染

## 1. 目标

本文件描述绘图交互与渲染联动的当前链路，重点是把文档数据稳定送到渲染层显示。

---

## 2. 当前总流程

```text
工具按钮
→ OperationBus
→ 绘图 / 编辑命令
→ 文档 / 场景数据变化
→ selection / preview 同步
→ SceneDocument2D
→ RenderViewport2D::updateSceneRender()
→ RenderWidget::submitSceneFromDataSource()
→ SceneManager::gatherGeometry(sink)
→ SceneGeometrySinkAdapter → C API
→ Renderx / SanYiRender
→ renderFrame()
→ 视口显示
```

当前链路的核心事实源是：

- `SceneDocument2D`：保存图元事实
- `SceneEditService`：执行编辑和撤销入口
- `RenderViewport2D`：把文档状态送到渲染层

---

## 3. 当前实施顺序

### 第 1 步：命令进入正确入口

当前按钮和快捷键应先进入 `OperationBus`，再路由到具体命令。

### 第 2 步：命令切换到正确绘图模式

命令进入后，工具状态应切换到对应模式，避免绘图和编辑状态相互干扰。

### 第 3 步：生成预览数据

预览只应作为临时状态存在，不应污染正式文档。

### 第 4 步：提交到文档 / 场景

提交后才生成正式图元事实，取消应恢复原状态。

### 第 5 步：文档变化触发渲染刷新

文档变化后应通过适配层通知视口刷新。

### 第 6 步：整理 render data

渲染层应把图元、选择、高亮、预览和批次信息统一整理为中间数据。

### 第 7 步：传给渲染入口

适配层只做转换和转发，不做业务编排。

### 第 8 步：后端绘制并显示

后端负责真正绘制，视口负责显示结果。

---

## 4. 当前检查点

每一步都建议检查三类内容：

- 编译是否通过
- 相关测试是否通过
- 日志是否符合预期

---

## 5. 当前注意事项

- 预览状态不应直接写入最终文档
- 视口不应承担命令中心职责
- 渲染数据应尽量保持中间层语义
- selection 和 preview 需要和正式图元分层处理
