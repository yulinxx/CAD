# 文字绘制与编辑

本文描述当前 2D 文字从**输入**到**再编辑**的完整链路、职责边界与已知约束。只写当前状态，不保留历史修复记录。

---

## 1. 两条链路，一个数据结构

文字功能由两条独立链路组成，中间靠**顶层群组名承载的元数据**衔接：

```text
链路 A（输入 / 首次生成）
左侧工具栏 / Ctrl+T
→ OperationBus (Tool_Text)
→ TextInputTool（模态对话框）
→ TextProcessor
→ TextConverter（FreeType 取字形轮廓）
→ SceneManager / GroupManager（建 Text > Char > SySmartLine 群组）
→ 群组名写入 TextMeta

链路 B（再编辑）
双击文字 / TextEditTool 激活后单击
→ TextEditTool（会话 / 光标 / 键盘 / IME）
→ TextEditService（模型 → 布局 → 增量重建）
→ TextConverter（按字符取轮廓，带 glyph 缓存）
→ SceneManager / GroupManager（替换群组内容）
→ 群组名回写 TextMeta
```

两条链路都不直接改文档事实，最终落点都是 `SceneManager` / `GroupManager`；撤销都经 `SceneEditService` / `UndoManager`。

---

## 2. 文字的场景数据结构

```text
Text 群组   name = "Text|SY_TXT:v1:<base64 JSON>"     ← 顶层，承载可编辑元数据
├── Char 群组   name = "Char"                          ← 一个字符一个
│   ├── SySmartLine（字形第 1 条闭合轮廓）
│   ├── SySmartLine（字形第 2 条闭合轮廓，如 "口" 的内框）
│   └── ...
└── Char 群组 ...
```

- 图元所有权在 `SceneManager`，群组关系在 `GroupManager`，两者都随文件持久化。
- 每条轮廓是 `SySmartLine`，内部段为 `SyLine` / `SyBezier2` / `SyBezier`（对应 FreeType 的 line / conic / cubic 分解）。
- **群组名是唯一的元数据通道**：`Eg::SyEntity` 没有属性袋，而群组名会持久化，所以文字内容 / 字体 / 字号 / 逐字符样式全部编码进顶层群组名。

### 2.1 TextMeta 编解码

`UI/2D/Src/Option/TextEdit/TextMetaCodec.cpp`

- 格式：`"Text|" + "SY_TXT:" + "v1" + base64(compact JSON)`
- `TextMetaCodec::encodeToGroupName` / `decodeFromGroupName` 是唯一出入口
- `isTextGroupName`：是否文字群组（含旧数据的纯 `"Text"`）
- `isEditableTextGroupName`：是否带可解析元数据 —— **旧数据（纯 `"Text"`）只能选中/变换，不能进编辑**

`TextMeta`（`TextMeta.h`）内容：整段文字 `text`、原点 `origin`、对齐 `alignment`、以及**逐字符**的 `styles`（字体族 / 字号 / 粗 / 斜 / 下划线），因此同一段文字支持混合字体。

## 3. 链路 A：输入与首次生成

### 3.1 TextInputTool

`UI/2D/Src/UI/DrawTools/TextInputTool.cpp`，继承 `DialogTool`。

1. `TextInputDlg` 收集 `TextDlgParameters`（文字内容 + 字体参数）
2. 空内容直接告警返回
3. 当前绘图色写入 `inputTextParam.color`
4. 参数存入 `TextInputSettingsStore`，供"粘贴外部文字为矢量"复用
5. 调 `TextProcessor::addTextToScene`

### 3.2 TextProcessor

`UI/2D/Src/Option/TextProcessor.cpp`

- `getFontFilePath(QFont)` → 经 `FontManager::getFontInfo` 解析字体文件；**解析结果会额外校验文件存在性**（`FontInfo::isValid()` 只判非空），无效则返回空串交给回退链
- `inputParam.fontFallback = FontFallbackChain::defaultChain()` —— 主字体缺 CJK 字形时补齐
- `doConvertByCharacter` 拿到按字符分组的轮廓
- 按 `Char` 群组逐字符建组，再挂到顶层 `Text` 空群组下
  - 顶层必须走 `GroupManager::createGroup("Text")` 的**无实体重载**：传空实体列表的那个重载返回 `nullptr`
- 最后 `TextMetaCodec::encodeToGroupName` 写回顶层群组名
- 有 `SceneEditService` 时，"加图元 + 建群组"整体作为单步撤销（`createGroupStateCommand`，before/after 群组状态快照）

`addTextToSceneCentered` 是同一实现的居中变体：先以原点转换，再按总包围盒中心整体平移。

### 3.3 TextConverter

`Engine/2D/Src/Text/TextConverter.cpp`

- `doConvert`：整段 → 一批 `SySmartLine`
- `doConvertByCharacter`：按字符分组 → `CharSmartLines`
- FreeType `FT_Outline_Decompose` 逐轮廓回调（moveTo / lineTo / conicTo / cubicTo）转成 `TextPathSegment`，再由 `fromContour` 组装 `SySmartLine`
- 斜体是**剪切变换**（`dItalicSkew`），不是另找斜体面
- 下划线由 `createUnderline` 生成实心矩形轮廓，优先用字体原生 `underline_position` / `underline_thickness`，并按 `descender` 下压避免压字；粗细有下限（激光加工不能退化成细线）

## 4. 字体解析

解析顺序（`TextConverter.cpp` 的 `loadFont`）：

1. **显式文件路径**：`param.strFontFilePath` 非空 → 校验存在后直接用
2. **FontManager 缓存查表**（跨平台主路径）
3. **平台原生兜底**：Windows 注册表 / Linux fontconfig / macOS CoreText
4. 仅当**未指定族名**时才允许兜底到系统默认字体 —— 指定了族名却解析失败会返回失败，由上层走回退链

### 4.1 FontManager

`Engine/Common/Src/Text/FontManager.cpp`

- 扫描各平台字体目录，为每个 face 建多套键：裸族名、紧凑族名（去空格/连字符/小写）、族名+样式名、PostScript 名、name-table 各条目
- **裸族名键必须指向常规面**：粗体/斜体变体不得覆盖常规条目，否则 `"Arial"` 会解析到 Arial Italic
- 查表顺序：粗+斜 → 粗 → 斜 → 常规；精确命中失败后进紧凑索引，最后做"族名前缀 + 纯样式后缀"的模糊匹配（`isPrefixWithStyleOnly` 拦住 `arial` 误配 `arialhebrew`）
- 结果缓存到 `~/.sanyi/font_cache.dat`（Windows 为 `%APPDATA%\SanYi`）

### 4.2 回退链

`FontFallbackChain::defaultChain()`（`Engine/Common/Src/Text/FontParameters.cpp`）= 拉丁族 + 平台 CJK 族。`TextConverter` 会：

- 主字体无效时，把第一个可用的回退字体**提升为主字体**
- 逐码点查字形：主字体没有该码点时，按顺序在已加载的回退 face 里找

### 4.3 macOS 注意事项

- `sizeof(wchar_t) == 4`。CoreText 的 `CFStringCreateWithCharacters` 要 16 位 `UniChar`，**不能把 `std::wstring` 缓冲 `reinterpret_cast` 成 `UniChar*`** —— 那会让 CoreText 读到 `"P\0i\0n\0..."` 这样的半截乱码串，任何字体名都匹配失败。转换统一走 `utf8ToUniChars`（返回 `std::vector<UniChar>`，BMP 外码点编成代理对）。
- CoreText 对不存在的族名返回 NULL URL（不做静默替换），所以"空路径"就等于"系统没装这个字体"，回退链的遍历语义可以依赖这一点。
- 现代 macOS 的部分中日韩字体**不在** `/System/Library/Fonts` 等经典目录下，而在
  `/System/Library/AssetsV2/com_apple_MobileAsset_Font*/<hash>.asset/AssetData/`。
  `FontManager` 的 `__APPLE__` 分支会逐个登记这些 `AssetData` 目录（`scanDirectory`
  非递归，只加 AssetsV2 根目录无效）。PingFang 就靠这条路径解析。
- **同一字体家族在系统里可能有两份，格式不同。** PingFang 为例：
  - `/System/Library/PrivateFrameworks/FontServices.framework/Resources/Reserved/PingFangUI.ttc`
    —— CoreText 返回的这份，字形表是 Apple 私有的 `hvgl` + `cidg`，**没有 glyf / CFF / CFF2**，
    FreeType 无驱动可用，`FT_New_Face` 直接失败。
  - `…/AssetsV2/…/AssetData/PingFang.ttc` —— 传统 `CFF ` 版本，FreeType 正常读取。

  因此平台兜底给出的路径不能只查 `exists()`：`TextConverter` 的 `canFreeTypeOpen()`
  会真的试开一次，打不开就判该族名不可用、让回退链继续走，而不是交出去到
  `doConvert` 里才 "open face failed"（那时已无退路，整段文字转换失败）。
  CoreText 与 fontconfig 两条兜底都接了这个判据。
- 回退链里的 `Noto Sans` / `DejaVu Sans` / `Liberation Sans` 在 macOS 上恒不存在，每次都会白跑一轮查找。

### 4.4 下拉框只列引擎能用的字体

`QFontComboBox` 列的是 Qt 字体数据库的全量家族（macOS 走 CoreText、Windows 走
DirectWrite、Linux 走 fontconfig），而取矢量轮廓统一用 FreeType。两者能力不对等时，
用户会选到"列表里有、引擎画不出来"的字体，然后被静默回退 —— 界面显示 PingFang SC，
画出来是 Arial。

`Eg::FontManager::availableFamilies()` 给出可用性真源：只有被 FreeType 成功打开过的
face 才会进这个集合，所以判据天然跨平台，不需要为每个平台写特例。

`EngineFontFilter`（`UI/2D/Src/Option/EngineFontFilter.h`）把它接到 UI：

- `TextFontToolBar` 与 `TextInputDlg` 构造下拉框后各调一次 `installOn`
- `installOn` 挂 model 的 `rowsInserted` / `modelReset`，在下拉框被重新填充后自动再过滤。
  必须挂 model 而不是某个具体 `QEvent`：Qt6 已移除 `fontDatabaseChanged` 信号
  （`QFontComboBox` 只留了 `protected bool event()`），重新填充走哪条内部路径不保证稳定，
  但一定经过它自己的 model。重过滤排到事件队列里做，不在填充过程中途插手；一轮填充的
  多次插入会合并成一次
- `TextFontToolBar::refreshFromTool` 额外传 `strKeepFamily` —— 已有文字可能用的是
  本机不可用的字体（换机器打开、系统升级换了字体格式），删掉它会让下拉框显示成
  另一个字体，等于谎报当前文字的字体。保留项记在下拉框的动态属性上，自动重过滤
  会沿用；`applyTo` 也会把被此前调用删掉的保留项补回来，因此可以安全反复调用
- 家族名比较走紧凑键（小写、去空格/连字符/下划线/点），与 `Eg::FontUtil::compactFamilyKey` 同规则
- 两条 fail-open 安全阀：可用集合为空、或过滤后一项不剩，都完全不过滤

## 5. 链路 B：再编辑



### 5.1 进入编辑

`UI/2D/Src/UI/DrawTools/TextEditTool.cpp`

两个入口，都要求群组名可解析（`isEditableTextGroupName`）且图层未锁定：

- `tryEnterEditAt(worldPos)`：`TextEditTool` 激活后单击命中文字 → 光标落在点击位置
- `tryEnterEditFromSelection()`：双击已选中的文字 → 光标落在文末

进入后 `TextEditService::beginSession` 会抓一份 `TextGroupSnapshot` 作为 before 快照。

### 5.2 会话内的三层

- **TextEditTool**：会话状态、光标 `m_cursor` / 锚点 `m_anchor`、鼠标拖选、键盘、IME
- **TextEditService**：`TextMeta` → 布局 → 场景增量重建。持有 glyph 缓存（键为"字符 + 样式"），按 slot 复用已生成的轮廓，只对变化的槽位重建
- **TextEditOverlay**：光标竖线与选区高亮，走覆盖层通道，不进场景
- **TextLayoutCalculator**：纯计算 —— 光标命中 `hitTestIndex`、光标框 `caretBBox`、逐行选区框 `selectionRects`、行首行尾 `lineStartSlot` / `lineEndSlot`、跨行移动 `slotAtXOnLine`

### 5.3 交互语义

- 编辑态点击文字**内部** → 定位光标并开始拖选；点击**外部** → 提交并退出到 `SelectTool`
- 编辑态右键 = 提交退出（与点空白一致）
- `onDeactivate` 兜底提交；`cancel()`（应用级取消）恢复 before 快照
- IME：`onInputMethodEvent` 处理组字（preedit）与上屏（commit）。上屏后部分平台还会逐字符补派同 `text()` 的按键事件，靠 `m_imeCommitRemaining` 做**前缀匹配**消费，避免重复输入

### 5.4 键盘删除的三级分流

⌫ / ⌦ 是**应用级快捷键**（`Qt::ApplicationShortcut`，注册在 `UiWorkbench`），按键在送达视口 widget 之前就被快捷键系统消费。因此工具的 `onKeyPress` 里那两个分支拿不到事件，判定必须由快捷键回调主动向下问：

```text
UiWorkbench::deleteSelectedShapes(forward)
  1. editingText()                              → Qt 文本控件（QLineEdit/QTextEdit）内，放行不拦
  2. viewport->handleTextDeleteRequest(forward)  → 画布上有文字光标，走字符级删除
  3. viewport->handleStepBackRequest()           → 绘图中，回退一个落点
  4. OperationBus::run(Edit_Delete)              → 删除选中图元
```

- ⌫ 绑 `forward=false`（删选区 / 光标**前**一个字符），⌦ 绑 `forward=true`（删选区 / 光标**后**一个字符）
- 非文本编辑态两个键都删选中图元 —— macOS 上 ⌫ 发 `Key_Backspace`、`Key_Delete` 要按 Fn+⌫，只绑后者等于让 Mac 用户没法用最顺手的键
- 第 2、3 跳经 `ITool::deleteTextAtCursor(bool)` / `ITool::stepBackDrawing()` 下探；编辑态判据在工具自己手里（`TextEditTool` 查 `m_editing`），路由层不认识具体工具类型

> ⚠️ **单一所有者约束**：`edit.delete` 的键序列只能有一个 `ApplicationShortcut` 持有者。菜单配置（`base.json`）里给 `edit.delete` 再写一个 `"shortcut": "Delete"` 会与 `UiWorkbench` 的 `QShortcut` 撞成两个接收者，Qt 判 ambiguous 后**两边都不触发**，表现就是"按删除键没反应"。`UiLayoutBuilder::buildShortcuts` 的 `m_menuShortcutKeys` 守卫只拦配置 shortcuts 节，拦不到裸建的 `QShortcut`。

其余按键（在 `TextEditTool::onKeyPress` 内，走视口正常键盘路由）：可打印字符插入、`←/→`（`Ctrl` 按词、`Shift` 扩选）、`↑/↓` 跨行、`Home/End` 行首行尾。

### 5.5 提交与撤销

`TextEditService::commit`

1. 用最终 `TextMeta` 做一次完整 `rebuild`
2. 内容与 `m_original` 相同 → **不压撤销栈**直接返回
3. 抓 after 快照，`createReplaceTextGroupCommand(before, after, "Edit Text")` 压入一条命令

一次编辑会话 = 一条撤销记录。用群组感知的专用命令，因为通用的 Add/Delete/Snapshot 命令只恢复图元、不恢复群组结构。

## 6. 选中与高亮

文字在场景里就是普通群组，选中走 `SelectTool` + `SelectionGizmo` 通用路径：

- 选择框 / 缩放手柄 / 旋转手柄经 `RenderOverlayUpdate` 提交
- 选中轮廓（流水虚线）经 `ViewRenderCoordinator::setSelectionOutlines` 直写，由 `SelectionOutlineBuilder` 离散为带累积弧长的折线

**`SelectionGizmo::hitTest` 的 Body（整体平移）判据只认真几何命中，不认包围盒内部。** 这条对文字尤其关键：多行文字的包围盒是个大矩形，字形之间绝大部分是空白。若判据写成 `bbox.contains(pos) || hitsSelectedGeometry(pos)`，左边会短路掉右边，点包围盒内任何空白处都被判成"要拖动当前选中项"，`SelectionGizmo::onMousePress` 返回 true，`SelectTool::onMousePress` 立即 return，重新拾取的分支走不到 —— 表现为"旧高亮框不消失、新的也选不上"。

### 6.1 编辑态内的选区高亮：逐行分块，单一通道

编辑态的字符级选区（半透明蓝块）由 `TextEditOverlay::update` 提交，走 `OverlayState::selectionHighlightQuads` —— **一条**通道，装 N 个四边形（每 4 个顶点一块）。

形状由 `TextLayoutCalculator::selectionRects` 决定：按 `layout.lineOfSlot` 把选中槽位分组，**每个视觉行各自求并集**，得到「首行从起点到行尾、中间行整行、末行从行首到终点」的常规文本选区形状。换行间隙槽位的包围盒是无效的（见 `TextEditService::baseCharBoxes`），扫描时跳过，不会在行尾拖出一条到行首的空条。

有整体变换时每块矩形的 4 顶点各自过 `Mat3d`，映射成平行四边形随文字旋转；没有变换就是轴对齐矩形 —— 矩形只是四边形的特例，不需要单独的通道。

两条设计约束都来自实际缺陷：

- **不能用单个并集包围盒。** 从第 N 行中段选到第 N+1 行中段，并集是一个横跨两行满宽的大矩形，两行未选中的部分会一起被涂色。
- **不能有两条并列的持久通道。** 曾经是 `filledSelectionBox`（轴对齐）+ `filledSelectionQuad`（带变换）并列，业务层只写生效的那条，另一条留着上一帧的残影：在带变换的文字块里选一小段再点别处，选区塌缩后只清了 box 通道，quad 高亮就永远挂在屏幕上。现在空列表即清除，`update()` 无条件写一次，天然对称。

## 7. 已知约束

- **旧数据不可编辑**：群组名为纯 `"Text"` 的历史文字没有元数据，只能选中/变换/删除。
- **`nFontFaceIndex` 在链路 A 中被丢弃**：`TextProcessor` 只把路径传给 `InputTextParam`，`nFontFaceIndex` 硬编码 0；`TextConverter` 对主字体也不读 `info.nFaceIndex`，而是用 `findFaceIndex` 按族名重新猜。对 `.ttc` 字体集合（Helvetica.ttc、Hiragino Sans GB.ttc）拿到的可能不是选中的那个 face，且 `findFaceIndex` 不看 `bBold` / `bItalic`。
- **字体缓存（`~/.sanyi/font_cache.dat`，Windows 为 `%APPDATA%\SanYi`）落盘不完整**：`saveCacheFile` 写两段 —— `m_mapCompactIndex` 与 `#FAMILIES` 之后的可用家族名。**样式键 / PostScript 名 / name-table 条目仍不落盘**，`setFontScanned` 命中缓存后直接返回不再扫描，于是首次运行（全扫描）与后续运行（读缓存）的**粗体/斜体**匹配精度不同。缓存也没有失效条件（无目录 mtime、无 OS 版本），装新字体或升级系统不会自动重扫 —— 只能靠改版本号强制作废（当前 v3；搜索路径集合变更时必须递增，否则改动在已有缓存的机器上不生效）。
- **`TextMeta::styles` 与 Char 群组的索引基准不同**：`styles` 按 `QString::size()`（UTF-16 码元，含换行）填充，Char 群组按实际渲染字形计数。当前全字符同样式时看不出问题，一旦逐字符样式落地、或遇到代理对（emoji）会错位。
- **快捷键设置页**：`edit.delete` 的窗口级 `QShortcut` 未登记进 `UiShortcutRegistry`，设置页里该行当前键显示为空，用户改不了。
