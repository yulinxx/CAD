# 文字绘制与编辑

本文描述当前 2D 文字从**输入**到**再编辑**的完整链路：使用方式、分层设计与取舍理由、处理流程、职责边界与已知约束。只写当前状态，不保留历史修复记录。

- 第 0 章：怎么用（面向使用者与联调）
- 第 1–4 章：数据结构与链路 A（首次生成、字体解析）
- 第 5 章：链路 B（再编辑）—— 分层、流程、键位、撤销
- 第 6–9 章：选中高亮、约束、测试、文件索引

## 0. 使用方式

### 0.1 新建文字

1. 左侧工具栏「文字」或 `Ctrl/⌘+T` → 弹出 `TextInputDlg`
2. 填内容与字体参数（字体族 / 字号 / 粗斜下划线）；下拉框里只会出现**引擎真能取到轮廓**的字体（见 4.4）
3. 填位置 X/Y，并选**锚点**决定 X/Y 指的是文字的哪个点：
   - 水平：起笔点 / 墨迹左 / 墨迹中 / 墨迹右
   - 垂直：基线 / 墨迹下 / 墨迹中 / 墨迹上
   - 默认「墨迹左 + 墨迹下」= **图形左下角**，符合按材料边缘定位的习惯
4. 确定 → 文字以矢量轮廓落进场景，成为一个 `Text` 群组

关于锚点的两点：

- 锚点按**墨迹包围盒**算，不是文本框。`" A"` 的左边界是 A 的墨迹而非空格起点；`"abc"` 与 `"Abg"` 同 Y 时可见高度不同但下边界齐平。
- 「起笔点 / 基线」两档无法用包围盒表达（是排版语义），保留它们是为了把多段文字对齐到同一起笔列或同一条基线。带下伸部的字（g / y / p、下划线）会伸到基线以下，所以基线不等于可见下边界。

文字进场景后就是普通几何：可选中、平移、旋转、缩放、删除，与其他图元无差别。

### 0.2 再编辑已有文字

两条入口，效果相同（都进入同一个编辑会话）：

- **双击**画布上的文字（`SelectTool` 交接）→ 光标落在文末
- 激活「文字编辑」工具后**单击**文字 → 光标落在点击处的字符间隙

进入编辑态后画布上出现闪烁竖线光标，顶部出现字体工具栏（回显光标处的字体/字号/样式）。

### 0.4 代码里怎么用

工具栏 / 宿主与文字编辑交互只经 `TextEditTool` 的公开面：

```cpp
tool->isEditing();                        // 是否在编辑会话中
tool->currentFontStyle();                 // 工具栏回显（选区首字符 / 插入样式）
tool->applyFontFamily("PingFang SC");     // 改字体（作用域见上）
tool->applyFontSize(24.0);
tool->toggleStyle(true, false, false);    // 切粗体
tool->setFontStateChangedCallback([]{ /* 光标/选区/样式变了，刷新回显 */ });
```

不要直接碰 `TextEditService` 或 `TextMeta` —— 会话状态与刷新时机都在工具手里。

## 1. 两条链路，一个数据结构

文字功能由两条独立链路组成，中间靠**顶层群组名承载的元数据**衔接：

```text
链路 A（输入 / 首次生成）
左侧工具栏 / Ctrl+T
→ OperationBus (Tool_Text)
→ TextInputTool（模态对话框）
→ TextProcessor
→ TextConverter（FreeType 取字形轮廓）
→ SceneManager / GroupManager（建 Text > Char > SySmartLine 群组）
→ 群组名写入 TextMeta

链路 B（再编辑）
双击文字 / TextEditTool 激活后单击
→ TextEditTool（事件 → 意图 → 刷新）
→ TextEditBuffer（改模型）
→ TextEditService（模型 → 布局 → 增量重建 → 提交/撤销）
→ TextConverter（按字符取轮廓，带 glyph 缓存）
→ SceneManager / GroupManager（替换群组内容）
→ 群组名回写 TextMeta
```

两条链路都不直接改文档事实，最终落点都是 `SceneManager` / `GroupManager`；撤销都经 `SceneEditService` / `UndoManager`。

## 2. 文字的场景数据结构

```text
Text 群组   name = "Text|SY_TXT:v1:<base64 JSON>"     ← 顶层，承载可编辑元数据
├── Char 群组   name = "Char"                          ← 一个字符一个
│   ├── SySmartLine（字形第 1 条闭合轮廓）
│   ├── SySmartLine（字形第 2 条闭合轮廓，如 "口" 的内框）
│   └── ...
└── Char 群组 ...
```

- 图元所有权在 `SceneManager`，群组关系在 `GroupManager`，两者都随文件持久化。
- 每条轮廓是 `SySmartLine`，内部段为 `SyLine` / `SyBezier2` / `SyBezier`（对应 FreeType 的 line / conic / cubic 分解）。
- **群组名是唯一的元数据通道**：`Eg::SyEntity` 没有属性袋，而群组名会持久化，所以文字内容 / 字体 / 字号 / 逐字符样式全部编码进顶层群组名。

### 2.1 TextMeta 编解码

`UI/2D/Src/Option/TextEdit/TextMetaCodec.cpp`

- 格式：`"Text|" + "SY_TXT:" + "v1" + base64(compact JSON)`
- `TextMetaCodec::encodeToGroupName` / `decodeFromGroupName` 是唯一出入口
- `isTextGroupName`：是否文字群组（含旧数据的纯 `"Text"`）
- `isEditableTextGroupName`：是否带可解析元数据 —— **旧数据（纯 `"Text"`）只能选中/变换，不能进编辑**

`TextMeta`（`TextMeta.h`）内容：整段文字 `text`、原点 `origin`、对齐 `alignment`、以及**逐字符**的 `styles`（字体族 / 字号 / 粗 / 斜 / 下划线），因此同一段文字支持混合字体。

## 3. 链路 A：输入与首次生成

### 3.1 TextInputTool

`UI/2D/Src/UI/DrawTools/TextInputTool.cpp`，继承 `DialogTool`。

1. `TextInputDlg` 收集 `TextDlgParameters`（文字内容 + 字体参数）
2. 空内容直接告警返回
3. 当前绘图色写入 `inputTextParam.color`
4. 参数存入 `TextInputSettingsStore`，供"粘贴外部文字为矢量"复用
5. 调 `TextProcessor::addTextToScene`

### 3.2 TextProcessor

`UI/2D/Src/Option/TextProcessor.cpp`

- `getFontFilePath(QFont)` → 经 `FontManager::getFontInfo` 解析字体文件；**解析结果会额外校验文件存在性**（`FontInfo::isValid()` 只判非空），无效则返回空串交给回退链
- `inputParam.fontFallback = FontFallbackChain::defaultChain()` —— 主字体缺 CJK 字形时补齐
- `doConvertByCharacter` 拿到按字符分组的轮廓
- **按锚点整体平移**（见下）
- 按 `Char` 群组逐字符建组，再挂到顶层 `Text` 空群组下
  - 顶层必须走 `GroupManager::createGroup("Text")` 的**无实体重载**：传空实体列表的那个重载返回 `nullptr`
- 最后 `TextMetaCodec::encodeToGroupName` 写回顶层群组名
- 有 `SceneEditService` 时，"加图元 + 建群组"整体作为单步撤销（`createGroupStateCommand`，before/after 群组状态快照）

**定位只有一条路**（`TextAnchor.h` / `addTextToSceneImpl`）：

```text
1. 一律以 pos=(0,0)、nAlignment=0 转换   ← 笔从原点起，"自然空间"
2. offset = 目标点 - anchor.pointIn(墨迹包围盒)
3. 整体平移 offset，且 meta.origin = offset
```

第 3 步的两件事**必须同时做**。因为笔从原点起，`offset` 恰好就是新的起笔点，所以 origin 换算是精确的而不是估计。

> ⚠️ 只平移几何而不同步 `origin`，再进编辑时 `TextLayoutBuilder` 会从旧 origin 重排，差值被 `TextBlockTransform` 当成「整体变换」吸收 —— 一段从未被旋转/缩放过的文字被判成带变换，选区高亮走四边形路径，而那个变换是假的。这正是 alignment 曾经的 bug：转换器内部按 advance 宽度平移了几何，而那个宽度只存在于 Engine 内部，上层拿不到，所以 origin 无从同步。

因此**水平对齐不再由 `nAlignment` 承担**，改由 `TextAnchorH` 按墨迹包围盒定位。与旧的 advance 宽度差一个左右侧边距，换来 origin 精确，且 `"AB   "` 居中时不把尾随空格算进去。`TextMeta::alignment` 降级为描述性字段。

`addTextToSceneCentered`（粘贴外部文字）是 `inkCenter()` 锚点的薄封装，定位点走同一个 `pos` 通道，没有第二套"目标位置"参数。

### 3.3 TextConverter

`Engine/2D/Src/Text/TextConverter.cpp`

- `doConvert`：整段 → 一批 `SySmartLine`
- `doConvertByCharacter`：按字符分组 → `CharSmartLines`
- FreeType `FT_Outline_Decompose` 逐轮廓回调（moveTo / lineTo / conicTo / cubicTo）转成 `TextPathSegment`，再由 `fromContour` 组装 `SySmartLine`
- 斜体是**剪切变换**（`dItalicSkew`），不是另找斜体面
- 下划线由 `createUnderline` 生成实心矩形轮廓，优先用字体原生 `underline_position` / `underline_thickness`，并按 `descender` 下压避免压字；粗细有下限（激光加工不能退化成细线）

## 4. 字体解析

解析顺序（`TextConverter.cpp` 的 `loadFont`）：

1. **显式文件路径**：`param.strFontFilePath` 非空 → 校验存在后直接用
2. **FontManager 缓存查表**（跨平台主路径）
3. **平台原生兜底**：Windows 注册表 / Linux fontconfig / macOS CoreText
4. 仅当**未指定族名**时才允许兜底到系统默认字体 —— 指定了族名却解析失败会返回失败，由上层走回退链

### 4.1 FontManager

`Engine/Common/Src/Text/FontManager.cpp`

- 扫描各平台字体目录，为每个 face 建多套键：裸族名、紧凑族名（去空格/连字符/小写）、族名+样式名、PostScript 名、name-table 各条目
- **裸族名键必须指向常规面**：粗体/斜体变体不得覆盖常规条目，否则 `"Arial"` 会解析到 Arial Italic
- 查表顺序：粗+斜 → 粗 → 斜 → 常规；精确命中失败后进紧凑索引，最后做"族名前缀 + 纯样式后缀"的模糊匹配（`isPrefixWithStyleOnly` 拦住 `arial` 误配 `arialhebrew`）
- 结果缓存到 `~/.sanyi/font_cache.dat`（Windows 为 `%APPDATA%\SanYi`）

### 4.2 回退链

`FontFallbackChain::defaultChain()`（`Engine/Common/Src/Text/FontParameters.cpp`）= 拉丁族 + 平台 CJK 族。`TextConverter` 会：

- 主字体无效时，把第一个可用的回退字体**提升为主字体**
- 逐码点查字形：主字体没有该码点时，按顺序在已加载的回退 face 里找

### 4.3 macOS 注意事项

- `sizeof(wchar_t) == 4`。CoreText 的 `CFStringCreateWithCharacters` 要 16 位 `UniChar`，**不能把 `std::wstring` 缓冲 `reinterpret_cast` 成 `UniChar*`** —— 那会让 CoreText 读到 `"P\0i\0n\0..."` 这样的半截乱码串，任何字体名都匹配失败。转换统一走 `utf8ToUniChars`（返回 `std::vector<UniChar>`，BMP 外码点编成代理对）。
- CoreText 对不存在的族名返回 NULL URL（不做静默替换），所以"空路径"就等于"系统没装这个字体"，回退链的遍历语义可以依赖这一点。
- 现代 macOS 的部分中日韩字体**不在** `/System/Library/Fonts` 等经典目录下，而在
  `/System/Library/AssetsV2/com_apple_MobileAsset_Font*/<hash>.asset/AssetData/`。
  `FontManager` 的 `__APPLE__` 分支会逐个登记这些 `AssetData` 目录（`scanDirectory`
  非递归，只加 AssetsV2 根目录无效）。PingFang 就靠这条路径解析。
- **同一字体家族在系统里可能有两份，格式不同。** PingFang 为例：
  - `/System/Library/PrivateFrameworks/FontServices.framework/Resources/Reserved/PingFangUI.ttc`
    —— CoreText 返回的这份，字形表是 Apple 私有的 `hvgl` + `cidg`，**没有 glyf / CFF / CFF2**，
    FreeType 无驱动可用，`FT_New_Face` 直接失败。
  - `…/AssetsV2/…/AssetData/PingFang.ttc` —— 传统 `CFF ` 版本，FreeType 正常读取。

  因此平台兜底给出的路径不能只查 `exists()`：`TextConverter` 的 `canFreeTypeOpen()`
  会真的试开一次，打不开就判该族名不可用、让回退链继续走，而不是交出去到
  `doConvert` 里才 "open face failed"（那时已无退路，整段文字转换失败）。
  CoreText 与 fontconfig 两条兜底都接了这个判据。
- 回退链里的 `Noto Sans` / `DejaVu Sans` / `Liberation Sans` 在 macOS 上恒不存在，每次都会白跑一轮查找。

### 4.4 下拉框只列引擎能用的字体

`QFontComboBox` 列的是 Qt 字体数据库的全量家族（macOS 走 CoreText、Windows 走
DirectWrite、Linux 走 fontconfig），而取矢量轮廓统一用 FreeType。两者能力不对等时，
用户会选到"列表里有、引擎画不出来"的字体，然后被静默回退 —— 界面显示 PingFang SC，
画出来是 Arial。

`Eg::FontManager::availableFamilies()` 给出可用性真源：只有被 FreeType 成功打开过的
face 才会进这个集合，所以判据天然跨平台，不需要为每个平台写特例。

`EngineFontFilter`（`UI/2D/Src/Option/EngineFontFilter.h`）把它接到 UI：

- `TextFontToolBar` 与 `TextInputDlg` 构造下拉框后各调一次 `installOn`
- `installOn` 挂 model 的 `rowsInserted` / `modelReset`，在下拉框被重新填充后自动再过滤。
  必须挂 model 而不是某个具体 `QEvent`：Qt6 已移除 `fontDatabaseChanged` 信号
  （`QFontComboBox` 只留了 `protected bool event()`），重新填充走哪条内部路径不保证稳定，
  但一定经过它自己的 model。重过滤排到事件队列里做，不在填充过程中途插手；一轮填充的
  多次插入会合并成一次
- `TextFontToolBar::refreshFromTool` 额外传 `strKeepFamily` —— 已有文字可能用的是
  本机不可用的字体（换机器打开、系统升级换了字体格式），删掉它会让下拉框显示成
  另一个字体，等于谎报当前文字的字体。保留项记在下拉框的动态属性上，自动重过滤
  会沿用；`applyTo` 也会把被此前调用删掉的保留项补回来，因此可以安全反复调用
- 家族名比较走紧凑键（小写、去空格/连字符/下划线/点），与 `Eg::FontUtil::compactFamilyKey` 同规则
- 两条 fail-open 安全阀：可用集合为空、或过滤后一项不剩，都完全不过滤

## 5. 链路 B：再编辑

### 5.1 分层与依赖方向

编辑侧分两类：**一条主干**（事件 → 模型 → 场景）+ **三个纯计算协作者**。依赖**严格单向朝下**，越靠下越纯：

```text
TextEditTool          事件 → 意图 → 刷新（Qt 事件、会话生命周期、平台键位差异）
      ↓
TextEditOverlay       渲染侧：光标细条 + 选区高亮两条覆盖层通道
      ↓
TextEditService       场景侧：群组识别 / 元数据载入 / 几何重建 / 会话与撤销
      ↓        ↘ 协作者（都不碰场景，可独立单测）
      ↓          TextGlyphSource      字体解析 + 字形轮廓 + 两级缓存
      ↓          TextLayoutBuilder    模型 → 布局数据 + 字形序列
      ↓          TextBlockTransform   反推文字块整体变换（仿射/相似最小二乘）
      ↓
TextLayoutCalculator  纯算法：槽位 ↔ 坐标、命中测试、逐行选区矩形
      ↓
TextEditBuffer        纯模型：TextMeta + 光标/锚点 + 全部编辑原子操作
      ↓
TextMeta              纯数据：文字内容 + 逐字符样式 + 原点/对齐
```

各层职责与"不做什么"：

- **`TextMeta`** —— 只有数据，会被 base64 编进群组名持久化，所以**加字段等于改文件格式**。
- **`TextEditBuffer`** —— 一段可编辑文字的全部可变状态与作用其上的原子操作。没有场景、没有 Qt 控件、没有渲染、没有剪贴板；布局由调用方按值传入。因此**可以脱离视口单测**。
- **`TextLayoutCalculator`** —— 静态函数集合，输入布局数据输出坐标/槽位/矩形，不持状态。
- **`TextGlyphSource`** —— 「一个字符长什么样」：族名+样式 → 字体文件（缓存），字符+样式 → 推进宽 + 基空间轮廓（缓存）。缓存里的轮廓一律位于原点，位置由 `instantiate` 平移决定。
- **`TextLayoutBuilder`** —— 「字符摆在哪里」：走一遍笔位置，产出 `TextLayoutData` 与 `TextGlyphRun`（逐字符字形键 + 键到槽位的映射）。字形度量向 `TextGlyphSource` 索取，自己不碰字体。
- **`TextBlockTransform`** —— 「这块文字被怎么变换过」：基准几何 ↔ 场景几何点对应，最小二乘解仿射/相似矩阵。
- **`TextEditService`** —— 唯一碰场景的一层：识别文字群组、解码元数据、编排上面三个协作者、增量替换群组内容、抓快照压撤销命令。它**不再持有任何模型算法、字体细节或矩阵求解**。
- **`TextEditOverlay`** —— 只推两条覆盖层通道，不进场景、不参与持久化。
- **`TextEditTool`** —— 把 Qt 事件翻译成编辑意图、管会话生死、决定每次改动之后刷什么。**不含任何模型算法**。

### 5.2 设计思路：三条硬约束

这套分层不是自然长成的，是三条约束逼出来的。

**（1）模型算法必须只有一份，且必须能单测。**
删字符要处理代理对、按词删要处理标点退化、反缩进要按行首算槽位修正 —— 这些逻辑原先散在 `TextEditTool` 里，与"重建几何 / 刷新覆盖层 / 通知工具栏"逐行交织：每个函数既改模型又管刷新，既没法单测也没法复用；`TextEditService` 里还平行存在一份样式区间操作，同一份数学两个入口。现在全部收进 `TextEditBuffer`，服务层的样式函数删除，工具层只调用不实现。

**（2）刷新粒度必须由返回值机械地决定，不靠人记。**
`TextEditBuffer` 的返回值是契约：

- 返回 `bool` 的是**改文本或样式**的操作 —— `true` 表示模型变了，**几何必须重建**
- 返回 `void` 的只动光标/选区 —— 几何不变，**只需重推覆盖层**

工具层把这条契约收口成唯一一个函数，任何编辑意图都从这里出去：

```cpp
void TextEditTool::afterEdit(bool modelChanged)
{
    if (modelChanged) { rebuildGeometry(); }
    updateOverlay();
}
```

于是"改了模型忘了重建"和"重建了光标没跟上"这两类 bug 在结构上消失了。反过来，光标闪烁走的是更细的 `TextEditOverlay::refreshCaret()`（只重推光标通道），因为 `baseCharBoxes()` 按值返回全文字符包围盒，几千字每 530ms 拷一遍纯属浪费。

**（3）入口必须窄。**
- 进入编辑只有一个函数 `startSession(group, hitWorldPos, reason)`：两条来路（画布点击 / 选中集交接）的差异压缩成 `std::optional<Ut::Vec2d>` 一个参数 —— 有值就把光标放在命中处，没值就放文末。以前两条路各自复制一遍"锁定检查 → 载入 → 清选择 → 放光标 → 刷覆盖层"，改一处漏一处。
- 键盘只有一个入口，内部按语义**四路分派**，每个分支只管一类事、都返回"是否已消费"：

```cpp
bool TextEditTool::onKeyPress(QKeyEvent* event)
{
    if (!m_editing || !event) return false;
    if (consumedByIme(event)) return true;
    const KeyMods mods = modsOf(event);
    return handlePrintableKey(event)            // 可打印字符
        || handleTextMutationKey(event, mods)   // 改文本：删除 / Tab / Enter
        || handleCaretMoveKey(event, mods)      // 只动光标：方向键 / Home / End
        || handleCommandKey(event, mods);       // ⌘ 组合：剪贴板 / 样式 / 全选 / 退出
}
```
- 平台键位差异**只分叉一次**，收在 `KeyMods` 里（`modsOf()`），下游分支不再出现 `#ifdef`。

**（4）易错的并行数组，用类型绑起来。**
换行符不产生字形因此不产生「字形键」，但**会**产生槽位；代理对占 2 个槽位却只有 1 个键。于是「键索引」与「槽位索引」不是同一套下标 —— 拿键索引去查 `boundariesX`，在多行文字里会整体错位。这两个数组必须成对交付、成对使用，所以它们被绑成一个类型：

```cpp
struct TextGlyphRun
{
    std::vector<std::string> keys;  // 逐字符字形键（换行符不产生键）
    std::vector<int> slotIndices;   // 键 → 字符起点槽位（与 keys 平行等长）
};
```

以前这两个数组作为两个 out 参数在四个函数之间穿，注释里反复写"必须用映射定位"。现在约束落在类型上。

### 5.3 关键概念：槽位（slot）

光标落在**字符之间**，取值 `[0, length()]`。槽位是贯穿全链路的坐标系：

- 与 `TextLayoutData` 的 `boundariesX` / `cursorYs` / `slotFontSizes` / `lineOfSlot` 下标**一一对应**，`slotCount() == text.size() + 1`
- 选区是半开区间 `[min(cursor,anchor), max(cursor,anchor))`
- 索引基准是 **UTF-16 码元**（与 `QString::size()` 一致，含换行符）

代理对（emoji）占 2 个码元但只产生 1 个字形，`computeCharLayout` 为此补出**零宽**中间槽位（X 取字形起点），以维持"槽位与 UTF-16 码元严格 1:1"这条不变量。命中测试天然不会选中零宽槽。

### 5.4 处理流程

**流程 1：进入编辑**

```text
双击（SelectTool 交接）→ tryEnterEditFromSelection(reason)
单击（编辑工具激活）  → tryEnterEditAt(worldPos)
        ↓ 两条都汇入
startSession(group, hitWorldPos, reason)
  1. TextEditService::isLayerLocked        图层锁定 → 失败，reason = "图层已锁定"
  2. TextEditService::beginSession(meta)   抓 before 快照（TextGroupSnapshot）
                                           + 解码元数据（无/损坏 → 失败并带具体原因）
                                           + 检测文字块整体变换（旋转/缩放/平移）
  3. 清场景选择                              编辑态不叠加图元级选中框
  4. m_buffer.reset(meta, meta.length())   模型入座，光标先放文末
  5. hitWorldPos ? setCursor(slotAt(pos), false) : 保持文末
  6. updateOverlay()                        推光标 + 选区，启动闪烁
```

**流程 2：一次编辑（以输入一个字符为例）**

```text
QKeyEvent → onKeyPress → handlePrintableKey
  → insertText(text)
      → m_buffer.insert(text)              纯模型：替换选区 → 插字符 → 补样式 → 移光标
      → afterEdit(/*modelChanged=*/true)
           → rebuildGeometry()
                → TextEditService::rebuild(m_buffer.meta(), err)
                     1. TextLayoutBuilder   算布局 + 逐字符字形序列（顺带填字形缓存）
                     2. diff 键序列 vs 上一轮基线（m_prevGlyphKeys / m_prevGlyphPos）
                     3. applyIncrementalRebuild
                          未变字符 → 只重定位；变更槽位 → 替换/新增/删除 Char 群组
                          结构不匹配 → 回退全量重建
                     4. 群组名回写新 TextMeta
                （失败则回滚会话，避免场景与模型不一致）
           → updateOverlay()                重推光标 + 选区，复位闪烁相位，通知工具栏
```

只动光标的按键（方向键等）走同一条路，但 `afterEdit(false)` —— 跳过整个重建段。

**流程 3：提交退出**

```text
⌘Enter / Esc / 点击文字外 / 右键 / onDeactivate 兜底
  → finishSession(commitChange = true)
      → TextEditService::commit(finalMeta, err)
           1. 用最终 TextMeta 做一次完整 rebuild
           2. 与 m_original 相同 → 不压撤销栈，直接返回
           3. 抓 after 快照
           4. createReplaceTextGroupCommand(before, after, "Edit Text") 压入**一条**命令
      → clearOverlay()（擦覆盖层 + 停闪）
      → endSessionAndSwitchToSelect()
```

`cancel()`（应用级取消）走另一支：`TextEditService::cancel()` 直接恢复 before 快照，不压栈。

### 5.5 性能：两级缓存 + 增量重建

编辑态每敲一个键都要重建几何，全量跑字体管线会卡。`TextEditService` 内有三处优化：

- **字形缓存**（`TextGlyphSource`）：键 = 字符 + 样式 + 字体文件 + face（`keyOf`），值 = 基空间轮廓（位于原点）+ 有效推进宽。会话内复用，`instantiate` 只做克隆 + 平移。容量上限 5000，超限整体清空。
- **字体解析缓存**（`TextGlyphSource`）：键 = 族名 + 字号 + 粗 + 斜，值 = 字体文件路径 + face 索引，避免重复走 `FontManager` 查表。
- **增量重建** `applyIncrementalRebuild`：与上一轮基线 diff（公共前缀 + 公共后缀），未变字符的场景图元**只重定位不重建**，只对变更槽位替换/新增/删除 `Char` 群组。结构不匹配时安全回退到全量重建。

`TextGlyphRun::slotIndices` 是绕不开的一环：换行符产生**无键槽位**，键索引与槽位索引并非一一对应，定位字符槽位必须用这个映射（见 5.2 第 4 条）。

### 5.6 交互语义细节

- 编辑态点击文字**内部** → 定位光标并开始拖选；点击**外部** → 提交并退出到 `SelectTool`
- 编辑态右键 = 提交退出（与点空白一致）
- `wantsPointerConstraint()` 返回 false：文字编辑不构造几何，光标要落在字符上，被正交/吸附拉一下就选错字
- **IME**：`onInputMethodEvent` 处理组字（preedit）与上屏（commit）。组字期间 `m_imeActive` 屏蔽按键路径；上屏后部分平台还会逐字符补派同 `text()` 的按键事件，靠 `m_imeCommitRemaining` 做**前缀匹配**消费，避免重复输入。撤掉 preedit 也走窄接口（`setCursor` 两次 + `deleteSelection()`），不另开一条"按区间删除"的路。

**鼠标选择**：单击定位并开始拖选；**双击选词**；**三击选行**；`Shift`+单击保留锚点扩选。

- 三击：Qt **不派发**三击事件，序列是 `Press/Release/DoubleClick/Release/Press`。判据是「第三次 `Press` 与上一次 `DoubleClick` 的间隔 ≤ `QApplication::doubleClickInterval()`」，时间取 `QMouseEvent::timestamp()` 而非墙上时钟。
- 选词跨度**不复用** `prev/nextWordBoundary`：那两个是**移动**语义（先跳空白再跳词字符），拿来选词的话点在空白上会选中前一个词。`selectWordAt` 按「点击处所属的同类字符连续段」取跨度（空白 / 字母数字含 CJK / 其余标点三类），且不跨行。
- 双击曾经是 `selectAll()`。全选留给 `⌘A`。

**光标闪烁**：`kCaretBlinkMs`（530ms）半周期，只在编辑会话内运行。相位翻转只调 `TextEditOverlay::refreshCaret()`（理由见 5.2），也不通知工具栏。任何光标移动/输入都经 `updateOverlay()` → `resetCaretBlink()` 把相位按回「亮」并重新计时，正在打字的位置不会闪没。停闪与「擦掉光标」绑在 `clearOverlay()` 里：定时器还在跑的话，下一次 timeout 会把光标重新推回 preview 通道，退出编辑后画布上留一根鬼影竖线。

**拖选越过视口边缘自动平移**：`m_autoPanTimer`（16ms）在拖选期间运行，指针进入距边缘 `kAutoPanMarginPx`（24px）的带内就按越界深度平移（`kAutoPanGain` 比例，单帧上限 `kAutoPanMaxStepPx`）。平移能力由 `ToolContext::panViewByPixels` 注入（宿主未提供时该功能静默禁用）：`RenderViewport2D` 传入的闭包做 DPR 换算后落到 `ViewportInputRouter::panViewByPhysicalPixels` → `ViewportNavigation2D::panByPixels`。

> ⚠️ `panByPixels` 刻意不走 `beginPan/updatePan`：那条路会覆盖 `m_lastMousePos`，把用户真实拖拽平移的锚点冲掉；也不置 `m_panning`，否则随后的 `MouseRelease` 会被当成平移收尾吃掉。
>
> ⚠️ 平移之后指针没动，但脚下的世界点变了。工具拿不到 `widgetToWorld`，`updateAutoPan()` 自己按平移量反向修正 `m_dragWorld`。注意 `pixelToWorld` 是「一个**物理**像素多少世界单位」（取的是后备缓冲尺寸），而越界量是逻辑像素，要先乘 DPR。

### 5.7 键位实现中的坑

**修饰键平台分叉**（收在 `KeyMods::modsOf` 里）：**Qt 在 macOS 上把 ⌘ 映射成 `Qt::ControlModifier`、把物理 Control 映射成 `Qt::MetaModifier`**。所以：

- `cmd`（快捷键前缀）两平台用同一份判断
- **按词**在 mac 上是 `⌥`（`AltModifier`），其他平台是 `Ctrl`。曾经统一绑 `ControlModifier`，mac 上表现为「⌘← 按词跳」，而系统级约定 ⌘← 是行首 —— 两个都错（mac 笔记本没有独立 Home/End）

**Tab / Enter**：`Key_Tab` 和 `Key_Return` 的 `event->text()` 分别是 `\t` 和 `\r`，`QChar::isPrint()` 都为 false，走不到可打印分支，必须在 switch 里显式接管。而且**必须 return true**：一旦不接受事件，`QWidget::event` 就拿 Tab 去做 `focusNextPrevChild()`，编辑态的焦点直接被移出画布。`Key_Tab` 里还留了一支 `shift` 判断 —— Qt 通常把 Shift+Tab 归一成 `Key_Backtab`，但个别平台/输入法仍报 `Key_Tab` + `ShiftModifier`，漏了这支反缩进会变成再插一级缩进。

**软制表符**：`Tab` 插 4 个空格，**不插 `\t` 本身**。布局层对没有字形的字符统一回退到名义空格宽（`TextGlyphSource::blankAdvance`，即 `advance <= 0` 的分支），一个 `\t` 只推进一个空格宽，看着就是敲了个空格；真正的制表位对齐要往 `TextMeta` 加 tab stop 字段，而 `TextMeta` 是持久化进群组名的，等于改文件格式。软制表符零成本复用现有槽位/命中/增量重建。

`Shift+Tab` → `unindent()`，删掉**本行行首**最多 4 个空格。与 Tab 刻意不对称：Tab 在光标处插，反缩进按行首算 —— 光标停在行中间时也要能退掉一级缩进。行首没有缩进就静默返回 false，**不退化成删前一个字符**。槽位修正规则：行首之前的槽位在更早的行上不动，行首之后的整条尾巴左移 `count` 但不越过行首。

**换行与退出**：`Enter` 插入 `\n`；`⌘Enter` 与 `Esc` 提交退出。曾经 `Enter` 无条件结束会话，于是编辑态里加不了行 —— 而布局层从一开始就处理 `\n`，多行文字只能靠输入对话框粘贴进来。

**空格必须归工具**：视口的空格在空闲态是导航语义（按住拖动临时平移，单击释放重置视图），过去只按 `ITool::isDrawingActive()` 分流 —— 文字编辑不算「绘制中」，于是空格进了平移分支，编辑里怎么敲都插不进一个空格。判据补成 `isDrawingActive() || isTextInputActive()`（`TextEditTool` 返回 `m_editing`），`ViewportInputRouter::handleKeyPress` 直接把事件派发给工具。

> ⚠️ 光靠释放分支救不回来：`handleKeyRelease` 里合成的那次 `Key_Space` 按下**不带 `text()`**，`TextEditTool` 的可打印字符分支拿到的是空串；而且指针只要在按住期间动过一下（触控板单指移动也算）就置 `m_spacePanned`，连合成事件都不会发。

### 5.8 应用级快捷键与「向下问」阶梯

⌫ / ⌦ / ⌘Z 是**应用级快捷键**（`Qt::ApplicationShortcut`），按键在送达视口 widget 之前就被快捷键系统消费，工具的 `onKeyPress` 里那些分支拿不到事件。判定必须由快捷键回调主动向下问 —— 而且**编辑态判据留在工具自己手里**，路由层不认识具体工具类型。

删除键的三级分流：

```text
UiWorkbench::deleteSelectedShapes(forward)
  1. editingText()                              → Qt 文本控件（QLineEdit/QTextEdit）内，放行不拦
  2. viewport->handleTextDeleteRequest(forward)  → 画布上有文字光标，走字符级删除
  3. viewport->handleStepBackRequest()           → 绘图中，回退一个落点
  4. OperationBus::run(Edit_Delete)              → 删除选中图元
```

- ⌫ 绑 `forward=false`（删选区 / 光标**前**一个字符），⌦ 绑 `forward=true`（删选区 / 光标**后**一个字符）
- 非文本编辑态两个键都删选中图元 —— macOS 上 ⌫ 发 `Key_Backspace`、`Key_Delete` 要按 Fn+⌫，只绑后者等于让 Mac 用户没法用最顺手的键
- 第 2、3 跳分别经 `ITool::deleteTextAtCursor(bool)` / `ITool::stepBackDrawing()` 下探

这套「阶梯」在 `ITool` 上共三个虚函数，语义一致：`deleteTextAtCursor` / `stepBackDrawing` / `undoTextEdit`，外加一个纯判据 `isTextInputActive()` 供路由层分流空格。

> ⚠️ **单一所有者约束**：`edit.delete` 的键序列只能有一个 `ApplicationShortcut` 持有者。菜单配置（`base.json`）里给 `edit.delete` 再写一个 `"shortcut": "Delete"` 会与 `UiWorkbench` 的 `QShortcut` 撞成两个接收者，Qt 判 ambiguous 后**两边都不触发**，表现就是"按删除键没反应"。`UiLayoutBuilder::buildShortcuts` 的 `m_menuShortcutKeys` 守卫只拦配置 shortcuts 节，拦不到裸建的 `QShortcut`。

**按词删除**走的是另一条路：`⌥⌫` / `⌥⌦`（非 mac `Ctrl+⌫` / `Ctrl+⌦`）带修饰键，不会被无修饰的应用级删除快捷键截走，所以这一支能在 `onKeyPress` 里正常收到事件。光标正停在标点上时词边界函数原地不动，此时**退化成删一个字符**，否则这个键看着像坏了。边界还要避开代理对中间（低位代理不是合法边界，向外扩一格），切一半会留下孤立代理。

### 5.9 撤销：单一粒度，⌘Z 在编辑态被吃掉

一整个编辑会话在全局 Undo 栈上只是**一条** `ReplaceTextGroupCommand`。会话中按 `⌘Z` 若直落全局栈，退掉的是**进入编辑之前**的那个操作 —— 用户看到的是「文字还在改，画布上别的东西却变了」。所以编辑态把这个键**吃掉且不做事**，提交退出后按一次整段回退本次编辑：

```text
OperationBus::run(Edit_Undo)                     // 菜单 / ⌘Z 的应用级快捷键
  1. viewport->handleTextUndoRequest(false)      // 编辑态 → 返回 true，到此为止（不做任何事）
  2. undoManager->undo()                         // 非编辑态 → 全局栈，退掉整条 "Edit Text"
```

- 分级实现：`CoreOperationRegistry` 的 `Edit_Undo` / `Edit_Redo` lambda 先问 `ViewportActionHub::viewport()`，下探经 `ITool::undoTextEdit(bool redo)`
- `TextEditTool::undoTextEdit` 就是 `return m_editing;` —— 编辑中算已消费，退出后交回全局栈
- 视口自己的 `⌘Z` / `Ctrl+Y` 按键分支同样只 `return true`，兜住按键真送到视口的情况
- 用群组感知的专用命令，因为通用的 Add/Delete/Snapshot 命令只恢复图元、不恢复群组结构
- **不做会话内快照栈**：曾经实现过一版（`EditSnapshot` + 打字串合并），能退掉「刚敲的几个字」，但和「一次会话 = 一条 Undo」这个既有契约叠在一起，用户很难分清手里这一次 ⌘Z 会退到哪个粒度。改回单一粒度：编辑中要退字用 `⌫`，整段不要了就提交后 ⌘Z

> ⚠️ IME 组字期间的 preedit 变更不构成撤销单元（组字过程本身是可回退的），撤销以上屏后的文本为准。

## 6. 选中与高亮

文字在场景里就是普通群组，选中走 `SelectTool` + `SelectionGizmo` 通用路径：

- 选择框 / 缩放手柄 / 旋转手柄经 `RenderOverlayUpdate` 提交
- 选中轮廓（流水虚线）经 `ViewRenderCoordinator::setSelectionOutlines` 直写，由 `SelectionOutlineBuilder` 离散为带累积弧长的折线

**`SelectionGizmo::hitTest` 的 Body（整体平移）判据只认真几何命中，不认包围盒内部。** 这条对文字尤其关键：多行文字的包围盒是个大矩形，字形之间绝大部分是空白。若判据写成 `bbox.contains(pos) || hitsSelectedGeometry(pos)`，左边会短路掉右边，点包围盒内任何空白处都被判成"要拖动当前选中项"，`SelectionGizmo::onMousePress` 返回 true，`SelectTool::onMousePress` 立即 return，重新拾取的分支走不到 —— 表现为"旧高亮框不消失、新的也选不上"。

### 6.1 编辑态内的选区高亮：逐行分块，单一通道

编辑态的字符级选区（半透明蓝块）由 `TextEditOverlay::update` 提交，走 `OverlayState::selectionHighlightQuads` —— **一条**通道，装 N 个四边形（每 4 个顶点一块）。

形状由 `TextLayoutCalculator::selectionRects` 决定：按 `layout.lineOfSlot` 把选中槽位分组，**每个视觉行各自求并集**，得到「首行从起点到行尾、中间行整行、末行从行首到终点」的常规文本选区形状。换行间隙槽位的包围盒是无效的（见 `TextEditService::baseCharBoxes`），扫描时跳过，不会在行尾拖出一条到行首的空条。

有整体变换时每块矩形的 4 顶点各自过 `Mat3d`，映射成平行四边形随文字旋转；没有变换就是轴对齐矩形 —— 矩形只是四边形的特例，不需要单独的通道。

两条设计约束都来自实际缺陷：

- **不能用单个并集包围盒。** 从第 N 行中段选到第 N+1 行中段，并集是一个横跨两行满宽的大矩形，两行未选中的部分会一起被涂色。
- **不能有两条并列的持久通道。** 曾经是 `filledSelectionBox`（轴对齐）+ `filledSelectionQuad`（带变换）并列，业务层只写生效的那条，另一条留着上一帧的残影：在带变换的文字块里选一小段再点别处，选区塌缩后只清了 box 通道，quad 高亮就永远挂在屏幕上。现在空列表即清除，`update()` 无条件写一次，天然对称。

## 7. 已知约束

- **旧数据不可编辑**：群组名为纯 `"Text"` 的历史文字没有元数据，只能选中/变换/删除。双击这类文字时状态栏给出具体原因（`beginSession` 的 `err` 一路带到 `onActivate`），不再是「双击了什么都没发生」—— 通用提示「Click or double-click text to start editing」只在选中集里根本没有文字群组时才出。
- **`TextMeta::styles` 与 Char 群组的索引基准不同**：`styles` 按 `QString::size()`（UTF-16 码元，含换行）填充，Char 群组按实际渲染字形计数。代理对（emoji）占 2 个码元只产生 1 个字形，`TextLayoutBuilder` 为此补出**零宽**中间槽位（X 取字形起点），保证槽位与 UTF-16 码元严格 1:1、`boundariesX.size() == text.size() + 1`；命中测试天然不会选中零宽槽。曾经只 push 一次，槽位整体错位一格且 `boundariesX.at(n)` 直接越界（`QVector::at` 在 release 下不做边界检查）。
- **`nFontFaceIndex` 在链路 A 中被丢弃**：`TextProcessor` 只把路径传给 `InputTextParam`，`nFontFaceIndex` 硬编码 0；`TextConverter` 对主字体也不读 `info.nFaceIndex`，而是用 `findFaceIndex` 按族名重新猜。对 `.ttc` 字体集合（Helvetica.ttc、Hiragino Sans GB.ttc）拿到的可能不是选中的那个 face，且 `findFaceIndex` 不看 `bBold` / `bItalic`。
- **字体缓存（`~/.sanyi/font_cache.dat`，Windows 为 `%APPDATA%\SanYi`）落盘不完整**：`saveCacheFile` 写两段 —— `m_mapCompactIndex` 与 `#FAMILIES` 之后的可用家族名。**样式键 / PostScript 名 / name-table 条目仍不落盘**，`setFontScanned` 命中缓存后直接返回不再扫描，于是首次运行（全扫描）与后续运行（读缓存）的**粗体/斜体**匹配精度不同。缓存也没有失效条件（无目录 mtime、无 OS 版本），装新字体或升级系统不会自动重扫 —— 只能靠改版本号强制作废（当前 v3；搜索路径集合变更时必须递增，否则改动在已有缓存的机器上不生效）。
- **真制表位不支持**：`Tab` 是 4 个空格的软制表符，理由见 5.7。
- **单字符文字的整体变换检测失效**：`TextBlockTransform::detect` 的单字符降档分支要求 `worldBoxes.size() == n`，但调用方传的 `charBoxes()` 长度是**槽位数**（`n + 1`），所以这个分支永远进不去。后果：单个字符被旋转/缩放后再进编辑，变换不会被复现。多字符不受影响（走仿射/相似求解）。本轮未修。
- **会话内无细粒度撤销**：编辑中 ⌘Z 不做事，理由见 5.9。
- **快捷键设置页**：`edit.delete` 的窗口级 `QShortcut` 未登记进 `UiShortcutRegistry`，设置页里该行当前键显示为空，用户改不了。
- **`TextEditService` 只保留场景侧编排**（约 750 行，原 1300）：字形/字体、布局构建、变换求解已分别拆到 `TextGlyphSource` / `TextLayoutBuilder` / `TextBlockTransform`。剩下的会话 + 增量重建仍是这一层最长的一段，但两者共享基线状态（`m_prevGlyphKeys` / `m_prevGlyphPos`），再拆需要先把基线做成独立对象。
