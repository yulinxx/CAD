# 绘图与交互

本文只描述当前可用的 2D 绘图交互链路、职责边界和后续收口方向，不保留历史修复记录。

---

## 1. 当前目标

2D 绘图交互当前的目标很明确：

- 工具能稳定触发
- 预览能稳定显示
- 提交和取消能稳定工作
- selection 能和文档保持一致
- 撤销 / 重做能稳定回放
- 视口只做宿主和刷新，不承担业务编排

---

## 2. 当前主链

当前 2D 绘图交互推荐按下面理解：

```text
工具按钮 / 快捷键 / 右键菜单
→ OperationBus
→ UiInteractionDispatcher
→ 具体绘图命令 / 工具状态机
→ SceneEditService
→ SceneDocument2D
→ RenderViewport2D
→ SceneRefreshCoordinator
→ RenderWidget
→ Renderx / RenderX
→ 视口显示
```

这个链路里，真正的事实源只有两个：

- `SceneDocument2D`：文档和图元事实
- `SceneEditService`：编辑与撤销入口

---

## 3. 当前职责划分

### 3.1 工具层

工具层负责：

- 接收鼠标、键盘、滚轮事件
- 管理临时预览状态
- 决定当前输入阶段
- 在合适时机提交或取消

工具层不负责：

- 直接修改文档事实
- 直接操作渲染内部状态
- 兼任命令总线

#### 3.1.1 指针位置的约束收口

指针坐标从路由器到工具，只有一条路：

```text
ViewportInputRouter::applySnap（图元/网格/起点吸附）
  → BaseTool::onMouseMove【final】
        wantsPointerConstraint() ? applyOrthoConstraint(pos) : pos
        → setCurrentMousePos(pos)
        → onPointerMoved(event)   ← 子类唯一的业务钩子
```

三条硬约定：

- **`onMouseMove` 是 `final`，子类不得覆写**，只能覆写 `onPointerMoved(QMouseEvent*)`。
- **`onPointerMoved` 不接收坐标**，位置一律从 `getCurrentMousePos()` 取。参数里刻意不给
  `worldPos`，是为了让「拿到未约束的原始坐标」在语法上不可达。
- 不构造几何的工具（`SelectTool`、`TextEditTool`）覆写
  `wantsPointerConstraint()` 返回 `false`：约束的语义是「让正在构造的几何对齐」，
  施加到框选矩形或文字光标定位上只会让它们错位。

之所以要 `final`：曾经有 7 个工具（PolyLine / Polygon / Spline / Nurbs / Bezier /
Bezier2 / SmartLine）各自覆写 `onMouseMove` 且不回调基类，于是**正交约束在这些工具上
全部静默失效**，而它们各自实现的 `constraintAnchor()` 成了永不执行的死代码。缺陷不在
某一个工具里，在「可以绕开」这件事本身 —— 收口之后，下一个新工具也没有绕开的入口。

#### 3.1.2 工具基类的两条骨架（2026-08-28 收口）

19 个绘图工具按「输入形状」分成两类，各有一个基类；两类都只收口机制，不碰图元语义。

```text
ITool
  └── BaseTool                      事件分发 / 预览 / 确认取消 / 回退 的统一入口
        ├── TwoPointDrawTool        一次点击定锚点，二次点击提交
        │     Line / Rectangle / Circle / Ellipse / Triangle
        └── StagedDrawTool<Stage>   多个有名字的输入阶段
              Arc / Polygon / Spline / Nurbs / Bezier / Bezier2 / SmartLine
```

- `TwoPointDrawTool`：子类只写三个钩子 —— `buildPreview()` 画什么、
  `isShapeValid()` 多大算合法、`emitShape()` 造哪个图元。状态迁移、锚点、
  取消/确认语义、提交后的 `resetState() + clearPreview()` 全在基类。
  收口前这五个工具是同一份代码的五份拷贝，已抄出两处走形（`EllipseTool::cancel()`
  少了 `isDrawing()` 卫哨、`onActivate()` 里基类调用与 `resetState()` 的顺序各家不一）。

- `StagedDrawTool<Stage>`：阶段枚举由子类给出（**必须含 `Idle`**，表示未在绘制），
  基类持有阶段，`setStage()` 是唯一写入口，且它同时同步 `ToolState`：

  ```cpp
  void setStage(StageEnum s)
  {
      m_stage = s;
      setToolState(s == StageEnum::Idle ? ToolState::Idle : ToolState::Drawing);
  }
  ```

  收口前这两行在 5 个工具里各写一份。它们必须成对：只要有一处只改了阶段字段而漏了
  `setToolState`，`isDrawing()` 就与实际阶段脱节 —— 表现是预览还在跟手，但
  Esc / 删除 / 空格确认全部失效。`ArcTool` 当时正处在这个边缘（`m_subState` 有三处
  裸赋值，靠「反正已经是 Drawing 了」侥幸正确）。

  枚举写在类外（`ArcStage`、`SplineStage`……），类内用 `using Stage = ArcStage;`
  保留旧名字。原因是 C++ 的硬限制：`class ArcTool : StagedDrawTool<ArcTool::SubState>`
  在实例化基类时 `ArcTool` 还不完整，嵌套枚举此时不可见。

`doubleClickForConfirm()` 同期收进 `BaseTool`：原先 9 个工具各写一份
`canConfirm() ? confirm() : false`，其中 `SmartLineTool` 漏了 `canConfirm()` 卫哨
（因其 `confirm()` 自己又查了一遍才没出事）。这类「凑巧等价」正是要消掉的东西。

### 3.2 命令层

命令层负责：

- 接收来自菜单、工具栏、快捷键的入口
- 调度操作
- 维护工具切换和编辑入口的一致性

当前代码里，命令注册和执行仍以 `OperationBus` 为主，UI 配置构建层保留 `IUiCommandDispatcher` 抽象，用来把菜单/工具栏动作绑定到当前命令目录；这里的抽象只服务于 UI 构建与测试，不作为业务总线的第二入口。

#### 3.2.1 工具切换与勾选态同步（2026-08-26 收口）

工具切换是双向的：入口负责"派发切换"，视口负责"回写当前是谁"。

```text
派发（入口 → 工具）
左侧绘图按钮 / Draw 菜单项 / 右键菜单 / 快捷键
→ 同一个 commandId（tool.select / tool.line …）
→ OperationBus::run(Tool_XXX, {}, source)
→ LambdaOperation（registerPendingToolOperations 注册）
→ findActiveViewport2D() → ToolManager::setActiveTool(toolName)

回写（工具 → UI 高亮）
RenderViewport2D::activeToolChanged(toolName)      // Esc 回 SelectTool、工具用完自动返回
→ CommandActionHub::setActiveToolAction(toolName)
→ toolAction(toolName)->setChecked(true)
→ QActionGroup（exclusive）自动取消上一个
→ 左侧按钮跟着变高亮（QToolButton::setDefaultAction 的副产品）
```

要点：

- 左侧绘图面板 `DrawToolBarWidget` 是纯展示层，按钮通过 `setDefaultAction` 挂中枢的工具 QAction，
  自己不记 `activeTool`、不持 `OperationBus`（详见《菜单工具栏交互.md》3.1.1）。
  勾选态因此只有一个事实源：中枢内部的 `QActionGroup`。
- **`setActiveToolAction` 里不能用 `QSignalBlocker`。** `QActionGroup` 的互斥依赖
  `QAction::changed` 生效，屏蔽信号会让上一个动作保持勾选，界面上出现两个按钮同时高亮；
  而 `setChecked()` 本身不发 `triggered`，不会回环派发命令，本来就不需要屏蔽。
- 配置驱动的 Draw 菜单项是 `UiLayoutBuilder` 自建的**不可勾选**普通 QAction，与中枢的工具
  QAction 是两个对象：共用同一条派发链，但不参与高亮。高亮只体现在左侧工具栏，这是设计现状。


### 3.3 文档层

文档层负责：

- 保存图元事实
- 保存选择状态
- 保存脏标记
- 保存提交后的正式数据

文档层不应该保存临时绘图过程中的中间状态。

### 3.4 视口层

视口层负责：

- 显示预览与正式结果
- 接收输入事件
- 触发刷新
- 与渲染适配层协作

视口层不应该承担命令编排中心职责。

#### 3.4.1 覆盖层：写入与重绘必须成对

预览线、控制线、十字准星、吸附指示器、选择框/手柄都是**覆盖层**，走
`ViewRenderCoordinator`。协调器只把几何请求累积进 `OverlayState`，真正翻译成
`Render::RT::DrawCommand` 发生在视口的渲染帧里（`flushOverlay`）。

因此约定：**每个覆盖层写入口自己在末尾请求一帧重绘**（`ViewRenderCoordinator::requestRepaint()`）。
绘制过程中没有任何别的重绘来源 —— 视口不在 `mouseMoveEvent` 里重绘，流水虚线定时器
只在有选中轮廓时才跑 —— 只写状态不请求帧，表现就是「预览完全看不见」。

这一对由协调器内部保证，不允许下放给调用方各自记得补 `update()`：漏一个就是一次静默回归。
唯一的例外是 `setOverlayFrameParams()`，它由视口在帧内调用，绝不能再触发重绘。

#### 3.4.2 预览的三条颜色通道

绘制预览由三类内容组成，颜色语义各不相同，混成一个「drawingColor」就会互相牵连：

- **预览几何**（`previewPoints`）→ 当前**图层色**，与提交后的图元同色，所见即所得
- **辅助线**（`controlLines`：切线手柄、十字准星、控制多边形）→ **固定绿**，
  不跟图层色。跟着图层色变，在绿色图层上辅助线会直接消失，而它恰恰是绘制过程中
  最需要看清的东西
- **控制点**（`pointMarkers`）→ 屏幕定尺寸方块（绿填充 + 白描边），视图缩放时大小不变，
  尺寸常量在 `Render::ScreenMetrics::kDrawControlPointSizePx`

唯一提交入口是 `BaseTool::updatePreview(points, controlLines, controlPoints)`。
各工具**不要**自己拼 `Render::RenderOverlayUpdate` —— 曲线类工具曾经各拼一份，
结果辅助线颜色被 `drawingColor` 顶掉、控制点根本没人画。

## 4. 2D 绘图与 `SyEntity` 的关系

2D 绘图的终点仍然是 `SyEntity`。

推荐理解方式：

```text
用户操作
→ 绘图工具
→ 临时预览状态
→ 生成 / 更新 SyEntity
→ SceneDocument2D
→ RenderViewport2D
→ RenderWidget
→ Renderx
```

### 4.1 图元 ID

当前实现里，ID 生成已经区分：

- 持久 ID：真正进入场景时使用
- 临时 ID：预览 / 中间过程使用

这样可以避免预览过程消耗持久 ID，也能让正式落地图元保持连续编号。

#### 临时作用域必须成对（2026-08-26 已修）

临时 ID 由 `Eg::EntityIdGenerator` 的作用域计数控制：
`ToolManager::setActiveTool` 激活工具时 `pushTransientScope()`，切到另一个工具时
先 `popTransientScope()` 再 push。

漏洞在于**销毁路径**：2D / 3D 工作台切换走的是「直接销毁 `ToolManager`」，不经过
"换到另一个工具"，于是最后那次 push 永远没人配对。作用域深度是 `thread_local` 且
只增不减 —— 残留之后，该线程上后续**每个新建图元都拿到负数临时 ID**。

修法：`~ToolManager()` 在 `m_activeTool` 非空时补一次 `popTransientScope()`。
**只 pop，不调 `onDeactivate()`** —— 析构时 `RenderWidget`、场景服务可能已经先走了，
让工具再去碰它们等于在析构顺序上赌运气。


### 4.2 闭合语义：`LineLoop` 不进渲染 ABI

闭合图元（多边形、矩形、整圆、整椭圆、`bClosed` 的折线）在应用层用
`PrimitiveType::LineLoop` 表达意图，但**这个拓扑不允许流到渲染 DLL**：
Metal / Vulkan 都没有原生 LineLoop，Runtime 会把它静默降级成 LineStrip，
闭合边就此丢掉 —— 表现是「画完少最后一条边，一选中虚线又是闭合的」
（选中轮廓走 `SelectionOutlineBuilder`，那条路自己把首点补到了末尾）。

收口点是 `RenderSceneBuilder::addPiece()`：遇到 `LineLoop` 就把首顶点补到末尾，
按 `LineStrip` 提交。增量路径（`upsertEntity`，顶点来自 `EntityToVertices`）与
全量路径（`ISceneGeometrySink::emit*`）都经过这里，因此两条路对「闭合」的
理解不会再漂移。

预览侧同理：工具在 `updatePreview()` 里就把首顶点补到末尾（预览走覆盖层的
`previewPoints`，展开成 LineList 相邻点对）。

### 4.3 点图元：唯一「尺寸只能用像素表达」的实体

`SyPoint` 在世界空间里没有大小，一个物理像素的点既看不见也点不中。因此它是唯一
一个**实体几何本身就是屏幕定尺寸**的图元：

```text
emitPoint / 单点折线 → PrimitiveType::PointList → RT 拓扑 Points
                     → DrawCommand::pointSize = ScreenMetrics::kEntityPointSizePx
                     → 顶点着色器写 gl_PointSize（world_point_p3c*.vert）
                     → 片段着色器按单位圆 discard（point_p3c*.frag）→ **实心圆**
```

两个必须记住的点：

- **`pointSize` 必须由 `addPiece()` 填**。不填就落到 `rxSession` 的兜底 `1.0f`，
  也就是一个像素 —— 这正是「画了点却什么都看不见」的原因，而且它不会报任何错。
- **尺寸不能用顶点几何表达**。用世界坐标撑出一个小方块/小圆，缩放时点会跟着变大变小；
  `gl_PointSize` 是像素量，缩放时才恒定。GL 后端为此在设备创建时开了
  `GL_PROGRAM_POINT_SIZE`（不开的话 shader 里写的 `gl_PointSize` 被静默忽略）。

这与覆盖层控制点（`pointMarkers` 走 `WorldPinned` + 像素偏移展开成方块）是**两套**
机制：覆盖层标记要描边、要方形，用几何展开；点图元要圆形实心，用 point sprite。

### 4.4 撤销 / 重做

撤销和重做不应由绘图工具自己直接承担，而应通过：

- `SceneEditService`
- `UndoRedoManager`
- `SceneUndoCommands`

来完成。

### 4.5 选中后的移动 / 缩放 / 旋转

三种变换共用同一条链路，没有单独的「移动工具」也没有「移动手柄」：

```
RenderWidget → ViewportInputRouter → SelectTool → SelectionGizmo
  ├─ hitTest：先旋转手柄 → 再 8 个缩放手柄 → 最后才判图元本体
  ├─ 本体命中 = HandleKind::Body（名字里有 Handle，但它不是手柄）
  ├─ onMousePress  → m_interactionBeginFn  → InteractiveEditSession::begin（存 before 快照）
  ├─ onMouseMove   → computeTransform(kind) → m_transformFn → SyEntity::transform(Mat3d)
  └─ onMouseRelease→ 动过才 commit("Transform")，没动过 cancel（不留空记录）
```

要点：

- **`HandleKind::Body` 的判据只能是真几何命中**，不能是 `bbox.contains`。包围盒内的空白
  区不属于图元；曾经写成 `bbox.contains(pos) || hitsSelectedGeometry(pos)`，左边短路掉
  右边，导致「选中一个图元后点它包围盒里的空白处，旧高亮不消失、新的也选不上」。多行
  文字把这个缺陷放大到必现。
- 判据落在 `Geo2DQuery::hitTest()`：①到轮廓距离 ≤ `dPick`，或②图元闭合且点在内部。
  所以**新图元类型要能被拖动，必须让 `Geo2DPath::decompose/toPolyline/isClosedContour`
  和 `Geo2DQuery::isClosed/locatePoint` 都认识它**，五处缺一处就会出现「能选中边、
  拖不动内部」或「只有手柄可用」这类局部失效。位图（`SyImage`）和色块（`SyFillRegion`）
  就是这样漏过去的。
- 撤销由 `InteractiveEditSession` → `SceneEditService::commitInteractive` →
  `EntitySnapshotsCommand` 承担，记录的是**前后两组完整实体克隆**而不是变换矩阵
  （一次拖拽是 N 个增量矩阵的连乘，且 `SyText::transform` 并非纯线性）。
  `allowMerge=false`，所以连续两次拖拽是两条独立记录；方向键 `nudgeSelected` 相反，
  用 `allowMerge=true` 把连按合并成一条。
- 位图的像素数据在快照里是深拷贝的裸字节，撤销一次位图变换要存两份完整像素。正确但吃内存。

回归测试：`Main/Src/UI/Test/ToolSelectionSyncRegressionTests.cpp` 的
`GizmoBodyDragRegressionTest`，覆盖直线本体拖动、位图内部拖动、拖动的撤销/重做、
角点缩放的撤销。这条链路此前只有 `EntitySnapshotsCommand` 的单元测试，
Gizmo 到撤销栈之间没有任何覆盖。

## 5. 当前键鼠约定

目前推荐的交互约定是：

- `Ctrl + 滚轮`：调整参数类工具的绘图参数
- `Enter` / `空格`：确认当前绘制
- `Backspace` / `Delete`：回退当前临时输入
- `右键` / `Esc`：取消当前绘制或退出工具

原则很简单：

- `Backspace` 不是 `Undo`
- `Esc` 不是 `Redo`
- 已提交图元的回退只能走撤销栈

### 5.1 滚轮：先给工具，再给导航

`ViewportInputRouter::handleWheel()` 的顺序是固定的：**活动工具 → 视图导航**。

```text
tool->onWheel(worldPos, event) == true  → 事件被工具吃掉，导航不参与
否则                                    → m_navigation.handleWheel(event)
```

导航层的 `classifyWheel()` 对「无滚动阶段」的滚轮一律判缩放，它不看修饰键，
所以 `Ctrl + 滚轮` 若不先问工具就会被当成缩放。参数类工具（如 `PolygonTool`
调边数）自己判 `Qt::ControlModifier`：带 Ctrl 才消费，不带 Ctrl 返回 `false`
把普通滚轮让回缩放。

### 5.2 空格 / 回车的确认语义

「以当前鼠标点为最后点，若能构成图元则确认」是绘图态的语义，与空闲态的导航语义
分层：

```text
绘图中（tool->isDrawingActive()）→ keyPress 里**立即**派发给工具确认
空闲态                            → 按住拖动 = 临时平移；单独按下再释放 = 原有重置/确认
```

绘图态必须在 `keyPress` 就派发，不能进「按住空格」的临时平移态：
`handleMouseMove` 里「空格按住 + 任意移动」即置 `m_spacePanned = true`（触控板
单指移动也算），手放在鼠标上按空格几乎必然产生一次移动事件，于是释放时的确认会
被判成导航而丢掉 —— 表现就是「绘制中按空格没反应」。

对称地，`handleKeyRelease` 合成确认前必须先看 `wasHeld`（`m_spaceHeld` 的旧值）：
绘图态那条路不置 `m_spaceHeld`，若不加这个前置条件就会**确认两次**。

`Enter` 走 `handleKeyPressDispatch` 的既有分支（有活动交互命令时 `submit()`），
与空格的绘图态确认等价。

### 5.3 Delete / Backspace 的分级语义

```text
绘制中（tool->isDrawingActive()）→ 回退一个已确定的落点（stepBackDrawing）
否则                              → 经 OperationBus 跑 Edit_Delete，删除选中图元
```

样条 / NURBS / 多段线这类要点多次的图元，点错一个点不该被迫整条重画。这一级**不是**
主 Undo 栈：只回退当前正在构造的图元的输入点，已提交的图元一个都不动。

来路与 Esc 完全同构，且更硬：Delete / Backspace 是工作台注册的
`Qt::ApplicationShortcut`，按键在送达视口 widget 之前就被快捷键系统消费掉，
`BaseTool::onKeyPress` 里的回退分支在绘图态**从来没被走到过**。因此快捷键回调必须
先问一次视口（`RenderViewport2D::handleStepBackRequest()`），消费掉就到此为止。

分层只有一处实现：

- 判据与派发：`ViewportInputRouter::handleStepBackRequest()`
- 工具协议：`ITool::stepBackDrawing()`，`BaseTool` 把它接到已有的
  `canStepBack()` / `stepBack()` 上 —— 各工具只实现那一对，不必关心按键从哪条路进来

### 5.4 Esc 的分级语义

Esc 按「从内到外」逐级退出，一次按键只退一级：

```text
1) 活动工具正在绘制  → 丢弃当前正在构造的图元，**留在当前绘图工具**（可以接着画下一个）
2) 绘图工具已空闲    → 退回选择工具（经 OperationBus 的 Tool_Select，工具栏高亮跟着回写）
3) 已在选择工具      → 清空选中集
```

实现上只有一份：`ViewportInputRouter::handleEscapeRequest()`（前两级）+ 工作台的
清空选择（第三级）。

要点：**Esc 的实际来路是工作台的窗口级 `QShortcut`，不是视口的 `keyPressEvent`。**
macOS 下 `QOpenGLWidget` 不会自动获焦，且选择可能来自场景树面板而非画布，所以
Delete / Ctrl+A / Esc 一律注册成窗口级快捷键；而 Qt 的快捷键在键事件送达聚焦控件
**之前**就消费掉了 —— 视口的输入路由根本拿不到这次 `KeyPress`。因此快捷键回调必须
先问一次视口（`RenderViewport2D::handleEscapeRequest()`），视口消费掉就到此为止，
不能顺手再清一次选择，否则「画到一半按 Esc」会连用户之前的选中集一起清掉。

### 5.5 方向键：选中时 nudge 图元，未选中时平移视图

在 2D 视口中，方向键的行为与选中状态关联：

- **有选中图元**：方向键微调（nudge）选中图元位置
- **无选中图元**：方向键平移视图

修饰键控制步长：
- `Shift + 方向键`：大步长（10.0 世界单位）
- `Ctrl + 方向键`：小步长（0.1 世界单位）
- 默认：1.0 世界单位

实现位于 `SelectTool::handleArrowKeys()`，通过 `ToolContext::panViewByPixels` 回调实现视图平移。

### 5.6 3D 视口方向键 nudge 轴向约束

在 3D 视口中，方向键在移动/旋转/缩放模式下均可操作选中图元（与 Blender G/R+S+axis 语义一致）：

#### 移动模式（Q 或 W 键）

- **方向键**：激活 nudge 移动
- **方向键后按 X/Y/Z**：切换轴向约束
  - X → 仅 X 轴移动
  - Y → 仅 Y 轴移动
  - Z → 仅 Z 轴移动
- **无轴向约束时**：XY 平面移动（默认）
- **选中变化时**：自动重置为 XY 平面

#### 旋转模式（E 键）

- **方向键**：绕当前轴向旋转
- **方向键后按 X/Y/Z**：切换旋转轴
  - X → 绕 X 轴旋转（上下键）
  - Y → 绕 Y 轴旋转（上下键）
  - Z → 绕 Z 轴旋转（左右键）
- **无轴向约束时**：绕 Z 轴旋转（默认，左右键控制）

#### 缩放模式（R 键）

- **方向键**：均匀缩放
- **方向键后按 X/Y/Z**：可扩展为轴向缩放（暂为均匀缩放）
- **无轴向约束时**：均匀缩放（默认）

修饰键控制步长（与 2D 一致）：
- `Shift + 方向键`：大步长（10.0）
- `Ctrl + 方向键`：小步长（0.1）
- 默认：1.0

## 6. 3D 视口交互约定

3D 视口（`RenderWidget3D`）的导航交互独立于 2D，不走 `ViewportInputRouter`，直接在 widget 事件回调里实现。

### 6.1 交互设备与操作映射

| 操作 | 鼠标 | 触摸板 (Mac) | 触摸板 (Windows) | 键盘 |
|------|-------|---------------|-----------------|------|
| 旋转 | 中键拖动 | Option + 双指拖动 | Alt + 双指拖动 | — |
| 平移(相机) | 右键拖动 | 双指拖动 | 双指拖动 | 方向键(无选中) |
| 移动(图形) | — | — | — | 方向键(有选中) |
| 缩放 | 滚轮 | 双指捏合 (pinch) | Ctrl + 双指拖动 | +/- |
| 重置视图 | — | — | — | Home |

#### 实现要点

- **触摸板检测**：用 `QWheelEvent::phase()` 区分 `ScrollStarted/Updated`（触摸板）vs `NoScrollPhase`（鼠标滚轮）
- **像素滚动优先**：`pixelDelta()` 比 `angleDelta()` 更平滑，用于触摸板
- **修饰键优先级**：`Alt` > `Shift` > `Ctrl`：Alt/Shift 用于旋转，Ctrl 用于缩放，剩下纯双指才是平移
- **右键平移的 macOS 兼容性**：macOS 上 `QContextMenuEvent` 在 `mousePress` 时就送达（旧实现用这个事件判定弹菜单，导致平移失效），改为在 `mouseRelease` 时根据拖动距离裁决：拖过阈值算平移，没拖过弹菜单

### 6.2 代码位置与流程

```text
RenderWidget3D
├── mousePressEvent      → MMB=旋转, RMB=平移开始, LMB=选择/框选
├── mouseMoveEvent      → 旋转/平移实时更新
├── mouseReleaseEvent   → 右键：拖过阈值→平移完成，未拖→弹菜单
├── wheelEvent         → 触摸板手势解析（平移/缩放/旋转）
└── keyPressEvent     → 方向键平移, +/-缩放, Home重置
```

### 6.3 键位约定

- **旋转**：中键拖动（鼠标）、Option/Alt + 双指拖动（触摸板）
- **平移**：右键拖动（鼠标）、双指拖动（触摸板）、方向键
- **缩放**：滚轮（鼠标）、双指捏合/Ctrl+双指（触摸板）、+/- 键
- **重置**：Home 键

### 6.4 状态栏提示

`RenderWidget3D::navigationStatusHint()` 返回的提示必须与实现保持一致：

```
Mouse: MMB=Rotate RMB=Pan Wheel=Zoom LMB=Select | 
Trackpad: 2-finger=Pan Pinch=Zoom Alt+drag=Rotate | 
Keys: Arrows=Pan +/-=Zoom Home=FitAll
```

## 7. 当前需要继续收口的点

1. 继续减少工具层里的临时分支。
2. 继续让选择、编辑、刷新各自只做一件事。
3. 继续统一 2D / 3D 的入口语义。
4. 继续让文档事实只保留在文档层。
5. 继续让渲染层只做绘制，不做业务编排。
6. **「吸附到正在构造的图元」只接通了一半。** `BaseTool::onActivate()` 已经向
   `GridSnapManager::setTemporaryEntitiesProvider()` 装好了读取端，读的是
   `m_previewEntities`；但**没有任何工具调用 `setPreviewEntities()`**，容器恒为空，
   于是这条吸附通道永远拿不到数据。
   不要顺手补上：预览图元里通常含有「当前鼠标点」，直接喂进去会让终点吸附到自己身上。
   要接就得同时定义「哪些预览子几何可被吸附」（一般是已落定的段，不含跟手那一段），
   属于吸附专项，不属于工具骨架重构。

## 8. 未来设计方向

如果后续继续优化，建议沿着这几个方向推进：

- 交互状态完全收敛到工具状态机
- 预览态与提交态彻底分离
- 菜单、工具栏、快捷键共用同一命令目录
- 2D / 3D 使用同一套命令命名风格
- 对外只暴露稳定的入口，不让旧桥接层继续膨胀
