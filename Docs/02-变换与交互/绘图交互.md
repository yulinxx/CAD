# 绘图与交互

本文只描述当前可用的 2D 绘图交互链路、职责边界和后续收口方向，不保留历史修复记录。

---

## 1. 当前目标

2D 绘图交互当前的目标很明确：

- 工具能稳定触发
- 预览能稳定显示
- 提交和取消能稳定工作
- selection 能和文档保持一致
- 撤销 / 重做能稳定回放
- 视口只做宿主和刷新，不承担业务编排

---

## 2. 当前主链

当前 2D 绘图交互推荐按下面理解：

```text
工具按钮 / 快捷键 / 右键菜单
→ OperationBus
→ UiInteractionDispatcher
→ 具体绘图命令 / 工具状态机
→ SceneEditService
→ SceneDocument2D
→ RenderViewport2D
→ ViewportSelector / SceneRefreshCoordinator
→ RenderWidget
→ Renderx / SanYiRender
→ 视口显示
```

这个链路里，真正的事实源只有两个：

- `SceneDocument2D`：文档和图元事实
- `SceneEditService`：编辑与撤销入口

---

## 3. 当前职责划分

### 3.1 工具层

工具层负责：

- 接收鼠标、键盘、滚轮事件
- 管理临时预览状态
- 决定当前输入阶段
- 在合适时机提交或取消

工具层不负责：

- 直接修改文档事实
- 直接操作渲染内部状态
- 兼任命令总线

### 3.2 命令层

命令层负责：

- 接收来自菜单、工具栏、快捷键的入口
- 调度操作
- 维护工具切换和编辑入口的一致性

当前代码里，命令注册和执行仍以 `OperationBus` 为主，UI 配置构建层保留 `IUiCommandDispatcher` 抽象，用来把菜单/工具栏动作绑定到当前命令目录；这里的抽象只服务于 UI 构建与测试，不作为业务总线的第二入口。

### 3.3 文档层

文档层负责：

- 保存图元事实
- 保存选择状态
- 保存脏标记
- 保存提交后的正式数据

文档层不应该保存临时绘图过程中的中间状态。

### 3.4 视口层

视口层负责：

- 显示预览与正式结果
- 接收输入事件
- 触发刷新
- 与渲染适配层协作

视口层不应该承担命令编排中心职责。

---

## 4. 2D 绘图与 `SyEntity` 的关系

2D 绘图的终点仍然是 `SyEntity`。

推荐理解方式：

```text
用户操作
→ 绘图工具
→ 临时预览状态
→ 生成 / 更新 SyEntity
→ SceneDocument2D
→ RenderViewport2D
→ RenderWidget
→ Renderx
```

### 4.1 图元 ID

当前实现里，ID 生成已经区分：

- 持久 ID：真正进入场景时使用
- 临时 ID：预览 / 中间过程使用

这样可以避免预览过程消耗持久 ID，也能让正式落地图元保持连续编号。

### 4.2 撤销 / 重做

撤销和重做不应由绘图工具自己直接承担，而应通过：

- `SceneEditService`
- `UndoRedoManager`
- `SceneUndoCommands`

来完成。

---

## 5. 当前键鼠约定

目前推荐的交互约定是：

- `Ctrl + 滚轮`：调整参数类工具的绘图参数
- `Enter` / `空格`：确认当前绘制
- `Backspace` / `Delete`：回退当前临时输入
- `右键` / `Esc`：取消当前绘制或退出工具

原则很简单：

- `Backspace` 不是 `Undo`
- `Esc` 不是 `Redo`
- 已提交图元的回退只能走撤销栈

---

## 6. 当前需要继续收口的点

1. 继续减少工具层里的临时分支。
2. 继续让选择、编辑、刷新各自只做一件事。
3. 继续统一 2D / 3D 的入口语义。
4. 继续让文档事实只保留在文档层。
5. 继续让渲染层只做绘制，不做业务编排。

---

## 7. 未来设计方向

如果后续继续优化，建议沿着这几个方向推进：

- 交互状态完全收敛到工具状态机
- 预览态与提交态彻底分离
- 菜单、工具栏、快捷键共用同一命令目录
- 2D / 3D 使用同一套命令命名风格
- 对外只暴露稳定的入口，不让旧桥接层继续膨胀
