# 菜单工具栏交互文档

## 1. 当前架构

当前菜单和工具栏都围绕统一命令目录展开：

- 2D 使用 `CommandCatalog`
- 3D 使用 `CommandCatalog3D`
- UI 构建层通过 `WorkbenchMenuManager`、`MenuManager3D`、`UiLayoutBuilder` 等组件组装动作
- 动作最终统一进入 `OperationBus`

---

## 2. 命令分发主链路

```text
QAction::triggered
→ 菜单/工具栏回调
→ CommandCatalog::operationForCommandId()
→ OperationBus::run(OperationId, params, source)
→ OperationRegistry::get(OperationId)
→ IOperation::execute(ctx, request)
```

菜单和工具栏的差异主要在展示层，最终执行路径应尽量一致。

---

## 3. 当前菜单分工

### 3.1 2D

2D 菜单当前以 `WorkbenchMenuManager` 为主，负责文件、编辑、视图、帮助以及绘图和算法入口的组装。

### 3.2 3D

3D 菜单由 `MenuManager3D` 自理，和 2D 的菜单刷新路径分开。

### 3.3 UI 构建层

`UiLayoutBuilder` 负责把配置化布局构建成菜单、工具栏和 Dock；`IUiCommandDispatcher` 只作为构建层抽象存在。

---

## 4. 当前需要保持一致的点

- 菜单和工具栏都应尽量走同一命令目录
- 菜单点击和工具栏点击都应记录统一日志
- 命令字符串命名应保持小写下划线风格
- 2D / 3D 菜单不要混用不同的路由方式

---

## 5. 当前收口方向

1. 继续减少硬编码菜单项。
2. 继续让菜单和工具栏共享命令目录。
3. 继续把 UI 构建层和业务执行层分开。
4. 继续让 2D/3D 菜单各自只处理自己的工作台。
