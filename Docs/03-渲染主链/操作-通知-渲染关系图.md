# 3D 场景操作与通知/树重建/渲染更新关系图

> 记录在 `UiWorkbench.cpp` 各项 3D 操作中，场景通知、树重建、Render 更新三者的触发关系。
> 标注了修复前（→旧）和修复后（→新）的路径对比。
>
> 图例：
> - 🔴 = 高频/性能问题（修复前）
> - 🟢 = 低频/已优化（修复后）
> - ⚪ = 无影响
> - `structureRevision` 推进 = 📈 | 不推进 = ➡️

## 2. 各操作详细路径（修复后）

### 2.1 框选 / Ctrl+A（Selection）

| 环节 | 修复后路径 | 说明 |
|------|-----------|------|
| 场景通知 | ✅ 无 | `selectMany` 只通知 SelectionManager，不触发 `notifySceneChanged` |
| 树重建 | ✅ 无 | `structureRevision` 不变 → `refreshSceneTree3DIfNeeded()` early return |
| Render 更新 | 🟢 `requestSceneUpdate()` → 调度器节流 | 每帧最多一次 `update()`，不设 `m_meshDirty` |
| `m_meshDirty` | ⚪ 不设置 | 选中变更不修改几何，不触发 `gatherGeometry()` |

```
selectByRect / selectByRay / selectMany
  → SelectionManager::commitSelectionChanged()
    → RenderWidget3D::onSelectionChanged 回调
      → requestSceneUpdate()  [调度器 QueuedConnection 节流]
        → 16ms 定时器到期 → update() → paintGL → 渲染选中高亮
```

### 2.2 批量删除（Delete）

| 环节 | 修复后路径 | 说明 |
|------|-----------|------|
| 场景通知 | 🟢 1 次 `notifySceneChanged()` | `deleteEntities()` 内部只发一次 |
| 树重建 | 🟢 `refreshSceneTree3DIfNeeded()`（防抖 150ms） | `structureRevision` 📈 推进，防抖后一次重建 |
| Render 更新 | 🟢 `markSceneDirty()` → 调度器节流 | `m_meshDirty = true` + `requestLightRefresh()` |
| `m_meshDirty` | 🟢 设置但 `syncMeshGeometryIncremental` 有空集保护 | 即使 dirtyIds 为空也跳过 `gatherGeometry()` |

```
deleteSceneTreeSelection3D(ids)
  → SceneManager3D::deleteEntities(targets, count)
    → detach() 一趟压缩 O(N) + ++structureRevision
    → notifyEntitiesRemoved(removedPtrs)  [批量语义，1次]
    → notifySceneChanged()               [1次]
  → markDataChanged()
    → notifySceneChanged() [触发 SceneMonitor → refreshSceneTree3DIfNeeded()]
  → refreshSceneTree3DIfNeeded()
    → structureRevision 📈 变化 → 启动150ms防抖定时器
      → 定时器到期 → refreshSceneTree3D() [一次完整树重建]
  → markSceneDirty()
    → m_meshDirty = true + requestLightRefresh()
      → paintGL → syncMeshGeometryIncremental(dirtyIds, deletedIds)
        → gatherGeometry() [仅删除的图元需从常驻列表移除]
```

### 2.3 批量隐藏/显示（Visibility Batch）

| 环节 | 修复后路径 | 说明 |
|------|-----------|------|
| 变更记录 | 🟢 每个图元 1 条 `recordChange(VisibilityChanged)` | 由 `setVisible` 回调产生（2026-09-18 新增） |
| 场景通知 | 🟢 1 次 `markDataChanged()` | 只在有变更时调用一次 |
| 树重建 | 🟢 `m_sceneTree3DRefreshTimer->start()`（防抖 150ms） | 多次调用只触发一次重建 |
| Render 更新 | 🟢 调度器节流 + `LightUpdate` 增量 | 可见性翻转走增量路径，不再全量重建 |
| `m_meshDirty` | ⚪ 不设置 | 可见性变更不修改几何 |

```
setSceneTreeVisibility3D(ids, visible)
  → for each id: mesh->setVisible(visible)
      → 可见性回调 → recordChange(id, VisibilityChanged)   [2026-09-18 新增]
  → markDataChanged()
    → notifySceneChanged() [触发 SceneMonitor → refreshSceneTree3DIfNeeded()]
      → structureRevision ➡️ 不变 → early return（不重建！）
  → m_sceneTree3DRefreshTimer->start() [启动150ms防抖]
    → 定时器到期 → refreshSceneTree3D() [一次完整树重建]
  → SceneRefreshCoordinator3D → LightUpdate
    → paintGL → syncMeshGeometryIncremental(dirtyIds, deletedIds)
      → Mesh3DBuilder::setEntityVisible [不重传顶点]
```

> 注：2026-09-18 前 `setVisible` 不产生 `VisibilityChanged`，渲染侧只能全量重建；
> 现在经回调进入变更流，走 `LightUpdate` 增量路径。

**修复前：**
```
setSceneTreeVisibility3D(ids, visible)
  → for each id: mesh->setVisible(visible)
  → markDataChanged() → notifySceneChanged()
  → refreshSceneTree3D()  [🔴 立即完整重建，无防抖]
```

### 2.4 逐个隐藏/显示（Visibility Single）

| 环节 | 修复后路径 | 说明 |
|------|-----------|------|
| 变更记录 | 🟢 每个翻转的图元 1 条 `VisibilityChanged` | `setVisible` 回调 |
| 场景通知 | 🟢 1 次 `markDataChanged()` | 每个实体都调，但只发一次通知 |
| 树重建 | 🟢 `m_sceneTree3DRefreshTimer->start()` | 多个 `toggleEntityVisibility3D` 共享同一个防抖定时器 |
| Render 更新 | 🟢 调度器节流 + 增量 | 同上 |
| `m_meshDirty` | ⚪ 不设置 | 可见性变更不修改几何 |

```
toggleEntityVisibility3D(id, visible)
  → mesh->setVisible(visible)
      → 可见性回调 → recordChange(id, VisibilityChanged)
  → markDataChanged() → notifySceneChanged()
  → m_sceneTree3DRefreshTimer->start() [150ms防抖]
    → 定时器到期 → refreshSceneTree3D() [一次完整树重建]
```

**修复前：**
```
toggleEntityVisibility3D(id, visible)
  → mesh->setVisible(visible)
  → markDataChanged()
  → refreshSceneTree3D()  [🔴 每个实体都完整重建！N个实体=N次重建]
```

### 2.5 锁定/解锁（Lock，2026-09-20 重构）

| 环节 | 修复后路径 | 说明 |
|------|-----------|------|
| 变更记录 | 🟢 每个翻转图元 1 条 `recordChange(LockChanged)` | 由 `setLocked` 回调产生 |
| 场景通知 | ⚪ **无** | 锁定是纯元数据，不影响渲染，不调 `notifySceneChanged()` |
| 树重建 | ⚪ **无** | 锁定态当前不在树中可视化，无需刷新 |
| Render 更新 | ⚪ **无** | 不设置 `m_meshDirty`，不触发视口刷新 |
| 命令状态 | 🟢 `refreshCommandUiState()` | Lock/Unlock 菜单灰显依赖 `anyLocked` |

```
setSceneTreeLock(ids: QVector<qint64>, locked)
  → scene->setEntitiesLocked(ids, locked)   [批量，内部经回调 recordChange(LockChanged)]
  → refreshCommandUiState()                  [更新 Lock/Unlock 菜单灰显]
  [不 notifySceneChanged / 不 markDataChanged / 不重建树]
```

> 旧路径的三重浪费：① `QStringList` 传 N 个字符串 ID 并逐个解析；② 为纯元数据变更
> 触发一次 `notifySceneChanged()`；③ 为刷新一个并不存在的锁图标做 O(N) 全量树重建。

### 2.6 改名（Rename）

| 环节 | 修复后路径 | 说明 |
|------|-----------|------|
| 场景通知 | 🟢 1 次 `markDataChanged()` | 同上模式 |
| 树重建 | 🟢 `m_sceneTree3DRefreshTimer->start()` | 防抖 150ms |
| Render 更新 | 🟢 调度器节流 | 同上 |
| `m_meshDirty` | ⚪ 不设置 | 改名不修改几何 |

```
renameEntity3D(id, newName)
  → mesh->setName(utf8)
  → markDataChanged() → notifySceneChanged()
  → m_sceneTree3DRefreshTimer->start() [150ms防抖]
    → 定时器到期 → refreshSceneTree3D() [一次完整树重建]
```

### 2.7 拖动变换（Gizmo Transform）

| 环节 | 修复后路径 | 说明 |
|------|-----------|------|
| 场景通知 | 🟢 `markSceneDirty()` → 调度器节流 | `m_meshDirty = true` + `requestLightRefresh()` |
| 树重建 | ⚪ 无 | `structureRevision` 不变 |
| Render 更新 | 🟢 `requestLightRefresh()` 节流 | 每帧一次 `update()` |
| `m_meshDirty` | 🟢 设置但 `gatherGeometry` 通过 contentHash 跳过未变图元 | 仅重传变化图元的顶点 |

```
Gizmo::setTransformRequest(entities, mat)
  → SceneEditService3D::transformEntities()
    → EntityTransform::applyMatrixToIds() [矩阵合并一次]
    → updateEntityBoundsNoNotify() [一次索引同步]
    → pushExecutedSnapshotCommand()
      → notifySceneChanged() [1次]
  → markSceneDirty()
    → m_meshDirty = true + requestLightRefresh()
      → paintGL → syncMeshGeometryIncremental(dirtyIds, deletedIds)
        → Mesh3DBuilder::beginRebuild/endRebuild
          → contentHash 跳过未变图元 → 仅重传变化顶点
```

### 2.8 方向键 Nudge（KeyPress）

| 环节 | 修复后路径 | 说明 |
|------|-----------|------|
| 场景通知 | 🟢 `markSceneDirty()` | `m_meshDirty = true` |
| 树重建 | ⚪ 无 | `structureRevision` 不变 |
| Render 更新 | 🟢 `markSceneDirty()` 内部已触发 | 移除了冗余 `update()` |
| `m_meshDirty` | 🟢 设置但 contentHash 优化 | 仅重传变化图元 |

```
keyPressEvent(Qt::Key_Up) [Nudge]
  → SelectionManager3D::nudgeSelected()
    → EntityTransform::moveByIds() [矩阵合并一次]
    → notifySceneChanged() [1次]
  → markSceneDirty() [m_meshDirty=true + requestLightRefresh]
    [移除了冗余 update() — markSceneDirty 已触发调度器]
```

## 3. 性能问题矩阵（修复后）

| 操作 | 场景通知次数 | 树重建次数 | Render update | `gatherGeometry()` |
|------|-------------|-----------|---------------|-------------------|
| 框选 N 个图元 | 0 | 0 | 1 次（节流） | ❌ 不调用 |
| 批量删除 N 个 | 1 | 1 次（防抖） | 1 次（节流） | 仅删除的图元 |
| 批量隐藏 N 个 | 1 | 1 次（防抖） | 1 次（节流） | ❌ 不调用 |
| 逐个隐藏 N 个 | N | 1 次（共享防抖） | 1 次（节流） | ❌ 不调用 |
| 批量锁定 N 个 | 1 | 1 次（防抖） | 1 次（节流） | ❌ 不调用 |
| 拖动变换 N 个 | 1 | 0 | 1 次（节流） | 仅变化图元 |
| 方向键 Nudge | 1 | 0 | 1 次（节流） | 仅变化图元 |
| 改名 N 个 | 1 | 1 次（防抖） | 1 次（节流） | ❌ 不调用 |

```

  │                  │      ──→ QueuedConnection                  │
  │                  │             │                               │
  │                  │             ▼                               │
  │                  │      ┌──────────────┐                     │
  │                  │      │ 16ms 定时器   │                     │
  │                  │      │ (SceneRefresh)│                     │

  │                  │      └──────────────┘                     │
```

## 6. 已知遗留问题

- [x] ~~`SceneTreeBuilder3D::build()` 仍然是 O(N) 全量遍历，即使只改一个可见性图标~~ → 已修：单条显隐/改名走 `refreshRows`，批量 Show/Hide 走 `setRowsVisible`（改写复选框 + `dataChanged`），仅图元增删（`structureRevision` 推进）才防抖全量重建；`build()` 主循环改为整数选中集合，去掉双重 `QString` 分配。
- [ ] `markDataChanged()` 触发的 `notifySceneChanged()` 在可见性变更时仍有信号广播开销（虽然 `refreshSceneTree3DIfNeeded()` early return），可考虑新增 `markDataChanged(NotificationLevel)` 参数。
- [ ] `deleteSceneTreeSelection3D` 中 `markDataChanged()` 在 `deleteEntities()` 之后额外调用一次，而 `deleteEntities()` 内部已调 `notifySceneChanged()`。双重通知的开销很小但存在。

### 修复效果对比

| 操作 | 修复前 | 修复后 |
|------|--------|--------|
| 框选 N 个图元 | 1 次 `update()` + `m_meshDirty` → `gatherGeometry()` 全量 | 1 次 `requestSceneUpdate()` → 不设 `m_meshDirty`，不遍历 |
| 批量删除 N 个 | 1 次 `notifySceneChanged` + 1 次树重建 | 1 次 `notifySceneChanged` + 1 次防抖树重建（不变，但 #1 减少通知扇出） |
| 批量隐藏 N 个 | N 次 `refreshSceneTree3D()` | 1 次防抖 `refreshSceneTree3D()` + 进入 `LightUpdate` 增量路径 |
| 批量锁定 N 个 | `QStringList` + 逐个查找 + `notifySceneChanged` + 全量树重建 | 一次 `setEntitiesLocked` + 命令状态刷新；**零渲染刷新、零树重建** |
