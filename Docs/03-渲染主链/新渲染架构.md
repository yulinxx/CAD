# 新渲染架构设计

> 目标：渲染 DLL **只管「怎么画」**，应用层 **定义「画什么」**。  
> 原则：跨 DLL 零 STL 暴露、多窗口共享 GPU 资源、动态逐帧提交、视图不变性显式表达、深度有序。

---

## 0. 设计意图与要达到的目的

### 0.1 当前架构的核心矛盾

| 矛盾 | 当前表现 | 后果 |
|------|----------|------|
| 语义泄漏 | `RenderWorld` 存 `EntityId`/`PrimitiveType`/`MaterialIndex`/bbox/四叉树 | DLL 绑死 CAD 业务语义，无法复用 |
| 全量提交 | 每帧 `renderBeginScene` → `renderSubmitGeometry` ×N → `renderFrame` | 图元规模上去后 CPU 提交瓶颈明显 |
| 跨 DLL STL | `std::vector<VertexP3C3>`、`std::string` 穿过 C API | 不同编译器/STL 版本 ABI 崩溃风险 |
| 视图不变性缺失 | 缩放时所有图元等比缩放，无「屏幕空间固定」机制 | 标注、十字准星、Logo 等无法固定大小 |
| 深度混乱 | 2D 用 zOrder 字段、3D 用深度缓冲，二者割裂 | 面/线/点/位图叠加顺序不可控 |
| 多窗口单体 | `RenderDevice` 聚合全部状态 | 多窗口 = 多进程或串行，GPU 资源不共享 |

### 0.2 本设计要达到的目的

1. **彻底解耦**：DLL 只接收「字节流 + 绘制命令描述符」，不解析任何业务概念。
2. **动态逐帧渲染**：GPU 资源分「持久（跨帧）」与「瞬态（每帧）」两类；只有变更的图元重传顶点，静态图元只重排绘制命令。
3. **视图不变性显式化**：每个 `DrawCommand` 标注自己是 **世界空间** 还是 **屏幕空间**，屏幕空间图元在缩放/平移时保持像素级位置/大小不变。
4. **统一深度排序**：用全局 `sortKey`（含层、深度、半透明标志）对全部图元类型（点/线/面/位图）做确定性排序。
5. **多窗口共享**：进程级 `RenderRuntime`（共享 GL context / 管线 / 字体 / buffer 池）+ 每窗口 `RenderSession`（私有相机/视口/瞬态资源）。
6. **ABI 安全**：跨 DLL 边界只传递 POD 结构体 + 原始指针/句柄 + 长度计数，绝不暴露 `std::`。

**三层职责边界**

| 层 | 只见什么 | 不见什么 |
|----|----------|----------|
| Application | `SyEntity`、`Layer`、`SelectionSet`、`BusinessId` | RHI、GPU buffer、shader |
| Session | `DrawCommand`（POD）、`ViewMatrix`、`BufferHandle` | 业务语义、具体图元类型 |
| Runtime | 字节流、RHI 抽象、POD 描述符 | 任何应用概念 |

## 2. 图元类型映射

所有图元最终归一化为 `DrawCommand`。四类图元的映射关系：

| 应用图元 | 离散化产物 | 拓扑 (Topology) | 空间 | 典型 sortKey 层 |
|----------|------------|-----------------|------|-----------------|
| **点 (Point)** | 单顶点 + 点大小 | `Points` | 世界（或屏幕固定大小） | 中层 |
| **线 (Line/Polyline/Arc/Circle/Ellipse)** | 折线/环顶点序列 | `LineStrip` / `LineLoop` | 世界 | 中层 |
| **面 (Surface/Polygon/Fill)** | 三角网（索引缓冲） | `Triangles` | 世界 | 底层（被线/点覆盖） |
| **位图 (Bitmap/Image)** | 2 个三角形 quad + 纹理 | `Triangles` (instanced) | 世界或屏幕 | 可配置（通常底层或顶层） |
| **文本 (Text)** | 字形 SDF quad 实例 | `Triangles` (instanced) | 屏幕（或世界） | 顶层 |
| **Overlay (十字准星/预览)** | 线/点顶点 | `Lines` / `Points` | **屏幕空间** | 最顶层 |

> 注：文本、Overlay 由应用层在 `RenderSceneBuilder` 中离散化为 DrawCommand，DLL 不区分「文本」与「普通三角面」。

## 3. 视图不变性（View Invariance）

### 3.1 两种渲染空间

每个 `DrawCommand` 携带 `RenderSpace` 标志：

```c
typedef enum RenderSpace : uint8_t {
    RS_WorldSpace = 0,   // 受相机变换影响（缩放/平移/旋转）
    RS_ScreenSpace = 1,  // 完全不受相机缩放影响，仅随视口尺寸重新定位
} RenderSpace;
```

### 3.2 屏幕空间图元的处理流程

```
应用层 RenderSceneBuilder:
  - 对「固定大小标注」：将其世界坐标通过当前相机矩阵投影到 NDC，
    再换算为像素坐标，生成 RS_ScreenSpace 的 DrawCommand。
  - 对「固定位置 HUD」：直接给出像素坐标（viewport-relative）。

Session 提交时:
  - RS_WorldSpace:  vertexShader 用 uViewMatrix * pos
  - RS_ScreenSpace: vertexShader 用 uViewportMatrix * posPixel
                    且 posPixel 已经在 CPU 端算好（或传 NDC 让 GPU 不做缩放）

结果:
  - 缩放时：世界空间图元变大/变小；屏幕空间图元像素大小恒定。
  - 平移时：世界空间图元跟随；屏幕空间图元若绑定锚点(如右下角)则随视口动，否则不动。
```

### 3.3 常见不变性需求对照表

| 需求 | 设置 |
|------|------|
| 缩放时线宽不变（屏宽恒定） | `lineWidthSpace = RS_ScreenSpace`（shader 用像素宽） |
| 缩放时点大小不变 | 点用 `RS_ScreenSpace` 或 shader 内反除 scale |
| 标注文字大小恒定 | 文本 DrawCommand 设 `RS_ScreenSpace` |
| 十字准星居中固定 | 锚点 = viewport 中心像素，随 resize 重算 |
| 水印固定右下角 | 锚点 = viewport 右下角像素 |
| 网格背景随缩放变密 | `RS_WorldSpace` + 动态 LOD（应用层按 scale 决定网格步长） |

## 4. 深度排序（Depth Sorting）

### 4.1 统一排序键 sortKey（64-bit）

```
| 63..56 | 55..48 | 47..32 | 31..0 |
|  Layer |  Transp|  Depth |  Seq  |
|  (8bit)|  (8bit)| (16bit)|(16bit)|

Layer   : 应用层定义的绘制层（0=背景网格, 1=面, 2=线, 3=点, 4=overlay, 5=text）
Transp  : 半透明标志（0=不透明, 1=半透明 → 半透明必须后画做混合）
Depth   : 世界 Z 或 2D 伪深度（同一层内前后顺序，16-bit 量化）
Seq     : 同 key 内的稳定序号（保证确定性，避免闪烁）
```

### 4.2 排序规则

1. 先按 `Layer` 升序。
2. 同层内：不透明图元按 `Depth` 升序（远→近，Painter 算法）；半透明图元聚到该层末尾按 `Depth` 降序（近→远，正确混合）。
3. 同 key 内按 `Seq` 稳定排序（radix sort 天然稳定）。

> **GPU 深度缓冲只在 3D 模式启用**；2D 模式完全依赖 `sortKey` 的 Painter 排序，避免深度冲突导致线被面吞掉。

### 4.3 合批（Batching）

排序后，连续相同 `(pipelineIndex, materialIndex, topology, vertexBufferHandle)` 的 `DrawCommand` 合并为一次间接绘制（`DrawIndirect` / MDI），减少 API 调用。合批不破坏 sortKey 顺序。

## 5. 动态逐帧渲染（核心性能机制）

### 5.1 GPU 资源两类生命周期

| 类别 | 生命周期 | 示例 | 更新策略 |
|------|----------|------|----------|
| **持久 (Persistent)** | 跨帧，直到 Entity 删除/几何变更 | 静态图元顶点缓冲、纹理、网格 | 仅在 `EntityId` 几何变更时 `uploadBuffer` |
| **瞬态 (Transient)** | 单帧，下帧回收 | Overlay 顶点、预览线、每帧文本四边形 | 每帧从 ring-buffer 分配，帧末归还 |

### 5.2 持久缓冲管理（应用层拥有，Runtime 托管）

```
应用层 RenderSceneBuilder:
  - 为每个 EntityId 在 Runtime 申请持久 BufferHandle（首次出现时）
  - 几何变更时：runtimeUploadBuffer(handle, offset, size, data)
  - EntityId 删除时：runtimeDestroyBuffer(handle)

Session 每帧：
  - 不重新上传静态图元顶点
  - 仅重新生成 DrawCommand[]（sortKey 可能因为相机/选择态变化）
  - 提交 DrawCommand[] → Runtime 绑定已有 BufferHandle
```

### 5.3 瞬态 Ring-Buffer（Runtime 提供）

```
Runtime 内部维护 N 帧轮换的 vertex/index 池（如 3 帧，避免 CPU 写时 GPU 还在读）：
  TransientAlloc(size) → 返回 {BufferHandle, offset}
  帧末 sessionPresent() 后标记该帧瞬态区可回收

应用层 Overlay/预览：
  auto alloc = runtimeAllocTransient(vertSize);
  memcpy(alloc.cpuPtr, verts, vertSize);
  DrawCommand.vertexBufferHandle = alloc.handle;
  DrawCommand.vertexOffset = alloc.offset;
```

### 5.4 每帧流程（动态提交）

```
[应用层, 仅变更时触发]
  onEntityGeometryChanged(id):
      rebuild DrawCommand for id (离散化) → 写入持久 buffer
  onCameraChanged():
      仅重算屏幕空间 DrawCommand 的像素坐标 + 所有 sortKey（不重传顶点）

[Session, 每帧]
  sessionBeginFrame(session):
      收集 DrawCommand[]（应用层 push，或 Session 持有引用）
  sessionSubmitDrawCommands(session, DrawPacket):
      1. 若启用裁剪：GPU/CPU 可见性查询，过滤不可见图元
      2. Radix sort by sortKey
      3. 合批：连续同状态 → 间接绘制命令
      4. 绑定持久 buffer + 瞬态 buffer
      5. 通过 CommandEncoder → RenderGraph 执行 Pass
  sessionPresent(session):
      呈现，回收本帧瞬态区
```

> **关键收益**：平移/缩放时，90% 的图元顶点**完全不重传**，只重排 `DrawCommand` 数组（纯 CPU 排序，零 GPU 上传）。

## 6. 多窗口渲染

### 6.1 Runtime 共享，Session 私有

```
Runtime (进程唯一):
  - 创建共享 GL context（wglShareLists / GLX / Vulkan device / Metal device）
  - 所有 Shader/Pipeline/Texture/Buffer 跨 Session 可见
  - 字体 Atlas、全局 Buffer 池共享

Session A (Viewport A 窗口):
  - 私有：viewMatrix, viewport, DrawCommand[], 瞬态 ring-buffer 偏移
  - 引用同一 Runtime 的持久 BufferHandle（场景共享时）

Session B (Viewport B 窗口):
  - 不同相机、不同视口
  - 可引用同一批持久 BufferHandle（同一文档多视图）
  - 也可独立（不同文档）
```

### 6.2 多窗口同步场景数据

```
同一 Document 多视图：
  RenderSceneBuilder 生成一份持久 BufferHandle 集
  Session A / B 各自持有 DrawCommand[]（可能不同可见性/相机）
  → 顶点只存在一份（Runtime 托管），两个窗口共享

不同 Document：
  各自独立 RenderSceneBuilder + 独立持久 buffer
  → 仍共享 Runtime 的 shader/pipeline/font
```

### 6.3 资源冲突规避

| 冲突点 | 方案 |
|--------|------|
| GL context 并发 | 单线程渲染或每个 Session 在各自 context 但共享对象；命令提交串行化 |
| 瞬态 buffer 跨窗口 | 每个 Session 独立 ring-buffer 分区 |
| 字体 Atlas | Runtime 全局唯一，只读共享 |
| Pipeline 缓存 | Runtime 全局唯一，按 hash 查表 |

## 7. 跨 DLL ABI 规范（零 STL 暴露）

### 7.1 边界规则

| 规则 | 说明 |
|------|------|
| 只传 POD | 所有跨 DLL 结构体用 `#pragma pack` 对齐，仅含基础类型/句柄/指针 |
| 不传 `std::` | 禁止 `std::vector`/`std::string`/`std::map` 出现在 `render.h` 导出的签名 |
| 数组用「指针 + 长度」 | `const DrawCommand* cmds, uint32_t count` |
| 字符串用 `const char*` + 长度 或 调用前拷贝 | Runtime 内部转 `std::string` |
| 句柄为不透明 64-bit | `BufferHandle = uint64_t`，应用层不得解引用 |
| 内存所有权单向 | 调用方分配/释放调用方侧；Runtime 分配的通过 Runtime API 释放 |
| 结构体版本化 | `struct Header { uint32_t magic; uint32_t version; uint32_t size; }` 前缀 |

### 7.2 导出头文件最小集

```c
// render.h（DLL 唯一公开头）
#pragma once
#include <cstdint>

#ifdef RENDERX_EXPORTS
#  define RENDER_API __declspec(dllexport)
#else
#  define RENDER_API __declspec(dllimport)
#endif

typedef uint64_t RuntimeHandle;
typedef uint64_t SessionHandle;
typedef uint64_t BufferHandle;
typedef uint64_t PipelineHandle;
typedef uint64_t TextureHandle;

// ---- 所有结构体均为 POD，#pragma pack(8) ----

struct RuntimeDesc { /* backend, windowHandle, w, h, shaderDir... */ };
struct SessionDesc { /* runtime, windowHandle, w, h, clearColor[4] */ };
struct DrawCommand { /* 见 §8 */ };
struct DrawPacket  { /* cmds, count, viewMatrix[16], viewport[4], frameId */ };
struct VisibilityResult { /* indices, count, maxCount */ };
struct BufferDesc  { /* size, usageFlags, memoryFlags */ };
struct PipelineDesc{ /* vs/fs shader ids, blend, depth, topology */ };
struct TextureDesc { /* w, h, format, dataPtr, dataSize */ };

// ---- Runtime ----
RENDER_API RuntimeHandle runtimeCreate(const RuntimeDesc*);
RENDER_API void          runtimeDestroy(RuntimeHandle);
RENDER_API BufferHandle   runtimeCreateBuffer(RuntimeHandle, const BufferDesc*);
RENDER_API void           runtimeDestroyBuffer(RuntimeHandle, BufferHandle);
RENDER_API void           runtimeUploadBuffer(RuntimeHandle, BufferHandle, uint64_t off, uint64_t size, const void* data);
RENDER_API PipelineHandle runtimeCreatePipeline(RuntimeHandle, const PipelineDesc*);
RENDER_API TextureHandle  runtimeCreateTexture(RuntimeHandle, const TextureDesc*);
RENDER_API TransientAlloc runtimeAllocTransient(RuntimeHandle, uint64_t size); // {handle, offset, cpuPtr}

// ---- Session ----
RENDER_API SessionHandle sessionCreate(const SessionDesc*);
RENDER_API void          sessionDestroy(SessionHandle);
RENDER_API void          sessionResize(SessionHandle, uint32_t w, uint32_t h);
RENDER_API void          sessionSubmitDrawCommands(SessionHandle, const DrawPacket*);
RENDER_API void          sessionQueryVisibility(SessionHandle, const float viewMatrix[16], VisibilityResult*);
RENDER_API void          sessionPresent(SessionHandle);
RENDER_API void          sessionGetStats(SessionHandle, Stats*);
```

> 应用层可用薄封装（`.cpp` 内 `#include <vector>`）把 `std::vector<DrawCommand>` 转成 `DrawPacket`，但 **`.h` 不向 DLL 暴露 STL**。

## 8. DrawCommand 完整定义（POD, 64 bytes）

```c
#pragma pack(push, 8)
typedef enum PrimitiveTopology : uint8_t {
    PT_Points = 0,
    PT_Lines = 1,
    PT_LineStrip = 2,
    PT_LineStripAdj = 3,
    PT_Triangles = 4,
    PT_TriangleStrip = 5,
    PT_TriangleFan = 6,
} PrimitiveTopology;

typedef enum RenderSpace : uint8_t {
    RS_WorldSpace = 0,
    RS_ScreenSpace = 1,
} RenderSpace;

typedef enum VertexFormat : uint8_t {
    VF_P3C3 = 0,     // pos(3f) + color(3f)
    VF_P3C4 = 1,     // pos(3f) + color(4f)
    VF_P3N3C4 = 2,   // pos(3f) + normal(3f) + color(4f)  (3D)
    VF_P2UV = 3,     // pos(2f) + uv(2f)  (bitmap/text)
} VertexFormat;

struct DrawCommand {
    // ---- 顶点/索引缓冲（Runtime 托管的不透明句柄）----
    uint64_t vertexBufferHandle;   // 持久或瞬态
    uint32_t vertexOffset;         // 顶点起始（顶点数）
    uint32_t vertexCount;
    VertexFormat vertexFormat;     // 决定 stride
    uint8_t  _pad0;

    uint64_t indexBufferHandle;    // 0 = 无索引
    uint32_t indexOffset;
    uint32_t indexCount;
    uint8_t  indexType;            // 0=uint16, 1=uint32
    uint8_t  _pad1;

    // ---- 绘制状态 ----
    PrimitiveTopology topology;
    RenderSpace       space;        // 世界空间 or 屏幕空间
    uint16_t pipelineIndex;         // PSM 管线索引
    uint16_t materialIndex;         // 材质索引（Runtime 材质表）

    // ---- 实例化 ----
    uint32_t instanceCount;
    uint32_t firstInstance;

    // ---- 排序/语义 ----
    uint64_t sortKey;               // 见 §4.1
    uint64_t userData;              // 业务 ID 回传（拣选/命中测试），DLL 不解析

    // ---- 视口无关参数（屏幕空间用）----
    float    lineWidth;            // >0 时覆盖材质线宽（像素或世界由 space 决定）
    float    pointSize;
};
#pragma pack(pop)
// sizeof(DrawCommand) == 64 (验证: 8*8 = 64)
```

### 8.1 DrawPacket

```c
#pragma pack(push, 8)
struct DrawPacket {
    const DrawCommand* commands;   // 调用方分配的数组（不转移所有权）
    uint32_t           commandCount;
    uint32_t           _pad;
    float              viewMatrix[16];   // column-major
    float              viewport[4];       // x, y, w, h (像素)
    uint64_t           frameId;
    uint32_t           enableCulling;    // 0/1
    uint32_t           _pad2;
};
#pragma pack(pop)
```

## 9. 完整流程示例（缩放时的动态渲染）

```
用户滚轮缩放:
  1. Viewport A 更新 Camera2D → 新 viewMatrix
  2. RenderSceneBuilder::onCameraChanged():
       - 世界空间图元：DrawCommand 不变（顶点已持久上传）
       - 屏幕空间图元：重算像素坐标 → 更新对应 DrawCommand（仅命令，不传顶点）
       - 重算全部 sortKey（若深度/层受相机影响，例如 3D）
  3. sessionSubmitDrawCommands(sessionA, packet):
       - 可见性裁剪（GPU/CPU）→ 过滤视野外
       - Radix sort by sortKey
       - 合批
       - 绑定持久 buffer（零上传）
       - 瞬态 ring-buffer 写入本帧 overlay/preview
       - CommandEncoder + RenderGraph 执行
  4. sessionPresent(sessionA) → 回收瞬态

结果：缩放过程中 CPU 只做「排序 + 命令重组」，GPU 顶点带宽占用 ≈ 0（静态图元）。
```

## 11. 风险与对策

| 风险 | 对策 |
|------|------|
| 排序不稳定导致闪烁 | `sortKey` 含 `Seq` 稳定位；radix sort 稳定 |
| 瞬态 buffer 与 GPU 读冲突 | 3 帧 ring-buffer，present 后延迟回收 |
| 多 GL context 共享对象失败 | 创建时显式 `wglShareLists`/等价；失败回退单 context 串行 |
| 屏幕空间坐标精度 | 像素坐标用 float，NDC 变换在 shader 内做，避免 double→float 抖动 |
| 大坐标浮点精度 | 世界空间顶点仍采用 camera-relative（应用层减 center 再加回），与旧方案一致 |
| ABI 破坏 | 每个结构体带 `magic+version+size`，DLL 启动校验 |
| 回归 | P0-P5 每阶段跑现有测试；旧 `LegacyDevice` 双轨并行对比像素 |

## 12. 结论

本设计满足全部要求：

- ✅ **动态逐帧**：持久/瞬态资源分离，静态图元零重传
- ✅ **四类图元**：点/线/面/位图统一为 `DrawCommand`
- ✅ **视图不变性**：`RenderSpace` 标志显式区分世界/屏幕空间
- ✅ **深度排序**：64-bit `sortKey` 统一层/透明/深度/序号
- ✅ **多窗口**：Runtime 共享 + Session 私有
- ✅ **跨 DLL 零 STL**：全 POD + 句柄 + 指针/长度，ABI 版本化

DLL 最终只见「字节流 + DrawCommand 描述符」，应用层独占语义。

## 13. 已落地状态（与代码同步）

> 本节记录截至当前已在代码中真实落地的 API 与模块，确保文档与实现一致。
> 概念设计见上文；凡与本节冲突者以本节为准。

### 13.1 命名与入口

- 新框架命名空间：`Render::RT`（避免与旧 `Render::RenderRuntime` / `Render::RenderWorld` 冲突）。
- **`Runtime`**（非进程单例，由 `runtimeCreate(&RuntimeDesc)` 创建；多窗口共享同一 `Runtime*`）：
  拥有 `RHI::IDevice*`、PipelineStateManager、持久 Buffer/Texture/Pipeline/Material 表、瞬态 ring-buffer。
- **`Session`**（每窗口一个，由 `sessionCreate(&SessionDesc)` 创建）：
  持有 `Runtime*`、`viewMatrix[16]`、`viewport[4]`、私有统计；`submitDrawCommands` 做
  `beginFrame → clear → setViewport → 按 sortKey 稳定排序 → 逐命令绑定+绘制 → present`。
- 跨 DLL 接口全部在 `Renderx/include/render/runtime_session.h`（`extern "C"` + POD），
  实现见 `Renderx/src/c_api/renderCApiRuntime.cpp`。

### 13.2 默认管线（DefaultPipeline 枚举，含覆盖层 P3C4 变体）

| 值 | 枚举 | 顶点格式 | 空间 | 用途 |
|----|------|----------|------|------|
| 0 | WorldLine | P3C3 | 世界 | 实体线 |
| 1 | WorldTri | P3C3 | 世界 | 实体面 |
| 2 | WorldPoint | P3C3 | 世界 | 实体点 |
| 3 | ScreenLine | P3C3 | 屏幕 | 屏幕线 |
| 4 | ScreenTri | P3C3 | 屏幕 | 屏幕面 |
| 5 | ScreenPoint | P3C3 | 屏幕 | 屏幕点 |
| 6 | ScreenTextured | P2T2C4 | 屏幕 | 位图/文本 |
| 7 | WorldLine4 | **P3C4** | 世界 | 覆盖层线（带 alpha） |
| 8 | WorldTri4 | **P3C4** | 世界 | 覆盖层面（带 alpha） |
| 9 | WorldPoint4 | **P3C4** | 世界 | 覆盖层点（带 alpha） |
| 10 | ScreenLine4 | **P3C4** | 屏幕 | 屏幕线（带 alpha） |
| 11 | ScreenTri4 | **P3C4** | 屏幕 | 屏幕面（带 alpha） |
| 12 | ScreenPoint4 | **P3C4** | 屏幕 | 屏幕点（带 alpha） |

> 覆盖层（选择框/手柄/虚线轮廓/点标记/捕捉圈）统一使用 **世界空间 + P3C4（带透明度）**，
> 由 `World*4` 管线绘制；世界空间保证缩放时覆盖层随图元几何一致变换（与旧 `overlayQueue` 行为一致）。

### 13.3 DrawCommand 与 sortKey

- `RTDrawCommand` 为 **80 字节** POD（`static_assert(sizeof==80)`），字段：
  `vertexBufferHandle / indexBufferHandle / vertexOffset / vertexCount / indexOffset / indexCount /
   sortKey / userData / textureHandle / topology(RTPrimitiveTopology) / space(RenderSpace) /
   vertexFormat(uint8_t) / indexType / pipelineIndex / materialIndex / instanceCount /
   firstInstance / lineWidth / pointSize`。
- `sortKey` 布局与 §4.1 一致：`Layer(8) | Transp(8) | Depth(16) | Seq(16)`，
  由 `uint64_t rtMakeSortKey(uint8_t layer, uint8_t transparent, uint16_t depth, uint16_t seq)` 构造。
- 覆盖层固定使用 `layer=200`（高于实体默认层 0），`transparent=1`，确保绘制在实体之上。

### 13.4 瞬态缓冲（单帧 ring-buffer）

- `runtimeFrameBegin(rt)`：映射瞬态顶点缓冲（写映射）。
- `runtimeAllocTransient(rt, size, &RTTransientAlloc)` → `{handle, offset, size, cpuPtr}`；
  句柄即专用瞬态 BufferHandle；超出容量时回绕到 0（`frameBegin` 后从零重新累积）。
- `runtimeFrameEnd(rt)`：解映射。
- 单帧内由应用层"分配→memcpy→构造 DrawCommand"；跨帧不保留。默认容量
  `RuntimeDesc::transientBufferSize`（默认 64MB）。

### 13.5 应用层构建器（消费业务语义 → DrawCommand）

| 模块 | 路径 | 职责 |
|------|------|------|
| `RenderSceneBuilder` | `Main/Src/UI/Render/RenderSceneBuilder.{h,cpp}` | 实体：`SyEntity*` → `entityToVertices` → 瞬态上传 → `World*` 管线 DrawCommand |
| `OverlaySceneBuilder` | `Main/Src/UI/Render/OverlaySceneBuilder.{h,cpp}` | 交互/选择装饰：选择框/手柄/虚线轮廓/点标记/捕捉圈/预览线/控制线 → `World*4` 管线 DrawCommand（移植自 `RenderWidget` 旧 overlay 几何，剔除对 legacy `renderSubmitOverlayDraw` 的依赖） |
| `ViewRenderCoordinator` | `UI/2D/Src/UI/ViewWidget/ViewRenderCoordinator.{h,cpp}` | 每帧把 `setSelectionBox/setSelectionHandles/setSelectionOutlines/...` 累积进 `OverlayState`，由视口在渲染帧调用 `flushOverlay(rt, cmds)` 翻译成 RT DrawCommand |

> 渲染 DLL 完全不知道 `SyEntity` / 选择框 / 虚线等交互语义——它只接收字节流。

### 13.7 2D 全量迁移（B 收尾）落地方式

> 本环境无 Qt，无法编译主程序；以下为已在代码中落地的集成方案，需用户在 Qt 构建环境验证。

**帧所有权仍归旧 `renderFrame`，RT 作为「注入式绘制 Pass」共享同一 RHI 设备：**

- `RenderWidget::initializeGL` 创建 RT `Runtime`（通过 `RuntimeDesc.existingDevice` 复用 `RenderDevice` 的
  `RHI::IDevice*`，不创建/不拥有），并创建 `Session`；随后 `renderSetRTWorldDraw(device, session, cb, this)`。
- 旧 `renderFrame` 的 2D 分支：当 `device->rtSession != 0` 时，**关闭** `SceneEnv`(grid) / `World2DCollect`(实体) /
  `OverlayCollect` / `CommandExecute`(旧实体+overlay 合批) 四个 Pass，并**注入**两个 RT Pass：
  - `RTWorldBack`（phase=0）：`OverlaySceneBuilder` 思路复用——把 `SceneEnvironment::computeGeometry` 产出的
    grid/ruler 线翻译为 `World*`/`Screen*` 的 `RTDrawCommand`；
  - `RTWorldFront`（phase=1）：把 `RenderCommandList`(实体) 翻译为 `World*` DrawCommand，再调用
    `ViewRenderCoordinator::flushOverlay(rt, cmds)` 追加覆盖层(`World*4`)。
  - 两个 Pass 通过共享 RHI **直接绘制进当前帧**（RT `Session::submitDrawCommands` 在共享模式下
    **不** `beginFrame`/`clear`/`present`，仅排序+绘制），避免与旧帧的 present 冲突。
- 文本（标尺文字 + 屏幕文字）仍由旧 `Text`/`ScreenText` Pass 渲染；bitmap 仍由旧 `Bitmap` Pass 渲染。
- **回退安全**：若 RT 初始化失败，`m_useRT=false` 且不调用 `renderSetRTWorldDraw`，旧 2D 渲染路径完全不受影响。
- `Runtime` 在共享模式下 `ownsDevice()==false`，故 `Session::submitDrawCommands`/`present` 跳过帧生命周期，
  由旧 `renderFrame` 统一 `beginFrame`/`present`。

## 14. 跨平台 Shader 方案（Phase 4，已落地）

本节补上原文档缺失的一块：shader 如何在三个后端之间跨平台，且不引入第三方库依赖。

### 14.1 目标形态

- **零运行期文件 IO**：shader 在构建期编入 DLL。
- **零第三方库依赖**：只使用构建期可执行程序（Vulkan SDK 的 `glslangValidator`、
  Xcode 的 `xcrun metal`），不链接任何 shader 编译库。
- **DLL 不做跨语言转译**：库只按「名字 + 目标语言」查表；转译发生在构建期。

### 14.2 落地结构

```
src/shader/*.vert|frag|comp          GLSL 源（OpenGL 后端直接用）
src/shader/*.metal                   MSL 源（手写，Metal 后端）
        ↓  CMake/EmbedShaders.cmake  （cmake -P 脚本模式，构建期代码生成）
<build>/generated/shaderBlobs.cpp    unsigned char[] + { 名字, 语言, 指针, 字节数 } 表
        ↓
src/shader/shaderLibrary.{h,cpp}     find(name, language, &blob) / glslSource(name)
        ↓
后端 createPipeline                   拿到的字符串既可是源码本身，也可是库中文件名
```

- 语言按扩展名推断：`.vert/.frag/.comp` → GLSL，`.metal` → MSL，`.spv` → SPIR-V，
  `.metallib` → MetalLib。文本类语言额外补一个 NUL 字节，使数据可直接当 `const char*` 用，
  `sizeBytes` 仍是不含 NUL 的实际长度。
- shader 文件是 `add_custom_command` 的 `DEPENDS`：改 shader 即重新生成、重新编译。
- 同名多语言变体并存（`scene.vert` / `scene.vert.spv` / `scene.metallib`），后端通过
  `Capabilities::acceptedShaderLanguage` 声明自己接受哪一种。
- 新增 shader 只需把文件加进 `Renderx/CMakeLists.txt` 的 `RENDERX_SHADER_SOURCES`，
  不改任何 C++ 代码。
- 生成物与对应的 `shaderLibrary.cpp` 收在 OBJECT 库 `RenderxShaders` 中，由 `RenderX`
  与两个测试目标共同链接（`add_custom_command` 的 OUTPUT 只能被同目录目标消费，
  测试在子目录 `Test/`，故必须抽成目标而非直接列源文件）。

### 14.3 后续后端接入点

- **Vulkan（Phase 8）**：在 `RENDERX_SHADER_SOURCES` 之前插一个 `glslangValidator -V`
  的 `add_custom_command`，产出 `.spv` 后再交给 `EmbedShaders.cmake`；找不到
  `glslangValidator` 时不生成 `.spv`，Vulkan 后端在 `isBackendAvailable` 中返回 false。
- **Metal（Phase 7）**：手写 `.metal`，用 `xcrun -sdk macosx metal / metallib` 编成
  `.metallib` 后嵌入；非 Apple 平台跳过这一步。

### 14.4 被替换掉的旧方案与其三个实际故障

`src/shader/shaders.{h,cpp}`（18 个 `extern const char*` + `shader::initialize(shaderDir)`
运行期 `std::ifstream` 读取）已删除，原因：

1. 目录由 `renderCreateDevice` 用 `std::filesystem` 从可执行文件路径推导，macOS `.app`
   bundle 下推导失败 → 视口全黑（见 `Docs/Mac渲染.md` §4）。
2. shader 文件不是构建依赖，改了不重新拷贝，调试时跑的是旧 shader。
3. 文本加载无法承载 Vulkan/Metal 需要的 SPIR-V 与 metallib——这是原方案在架构上就走不到
   多后端的根因。

另外，真正在用的 11 个 shader 此前是 `rendererRuntime.cpp` 里的 11 段裸字符串字面量，
而 `src/shader/` 下的 18 个文件只服务于 legacy 路径（经 `rhiGl.cpp` 一段约 125 行的
`strcmp` 名字映射链，legacy 删除后已成死代码）。Phase 4 把前者提取为独立文件，
删除后者中已无用的 8 个（`scene_2d.*` / `overlay.*` / `overlay_screen.*` / `bitmap.*`）。

### 14.5 精度处理的归属变化

legacy 2D 路径靠 `scene_2d.vert` 里的 `uCameraCenter` uniform 做相机相对渲染。
当前 RT 世界空间 shader（`world_p3c3.vert` / `world_p3c4.vert`）只有一个 `uniform mat4 uView`，
大坐标的相机相对偏移**完全在 CPU 侧离散化阶段以 double 精度减去**——与 §1、§13.5
「离散化归应用层 `RenderSceneBuilder`」一致。Phase 10 迁移 2D 时须确保这一步不被漏掉，
否则大坐标场景会重现虚线/图元消失。
