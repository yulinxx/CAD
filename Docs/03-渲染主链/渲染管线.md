# 渲染核心统一管线

本文只保留当前可用的渲染设计、当前实现方向和未来收口目标，不保留阶段性实现记录。

---

## 1. 当前目标

当前渲染层的目标是把 2D / 3D 的统一渲染入口收口到 `Renderx` / `RenderX`，并让对外 C ABI 保持稳定。

---

## 2. 当前痛点

当前渲染层最重要的痛点有三个：

1. 入口必须保持统一，不再拆成多个旧库。
2. UI 语义必须继续下沉到适配层。
3. 渲染层必须继续保持“只做绘制，不做业务编排”。

---

## 3. 当前渲染架构

### 3.1 对外入口

当前生产入口以 `render/render.h` 为准，核心句柄是 `RenderDevice*`。

### 3.2 内部结构

RenderX 内部当前可按以下方式理解：

- `RenderDevice`：单窗口渲染运行时
- `RenderWorld`：2D 图元与脏数据管理
- `BatchQueue` / `DrawBatcher`：批次组织
- `OverlayQueue`：交互叠加层
- `TextAtlas` / `ScreenTextRenderer`：文本
- `MeshManager`：3D 网格与实例
- `SceneEnv`：场景环境
- `CommandEncoder` / `RenderGraph`：命令与流程编排
- `rhi`：后端抽象

### 3.3 RenderBridge 层组件

RenderBridge 位于渲染 DLL 与应用层之间，提供以下可复用组件：

| 组件 | 路径 | 职责 |
|------|------|------|
| `GeometryManager` | `RenderBridge/Include/RenderBridge/GeometryPipeline.h` | 封装 `PersistentGeometryStore`，提供块分配/写入/释放、槽号管理、内容哈希比对、绘制命令 upsert。2D/3D 构建器共用此抽象层 |
| `Discretizer` | `RenderBridge/Include/RenderBridge/Discretizer.h` | 曲线离散化：封装 `Eg::Tessellator` 的圆/弧/椭圆自适应离散化，管理 LOD 弦高误差与缩放参数 |
| `SceneRenderPipeline` | `RenderBridge/Include/RenderBridge/SceneRenderPipeline.h` | 统一帧生命周期协调：beginFrame → submitGeometry → submitTransient → submitOverlay → endFrame |
| `OverlayScene` | `RenderBridge/Include/RenderBridge/OverlayScene.h` | 覆盖层管理：选择框/手柄/虚线等交互装饰按层持有，逐帧合成到瞬态环 |
| `PersistentGeometryStore` | `RenderBridge/Include/RenderBridge/PersistentGeometryStore.h` | 几何仓底层实现：块式显存管理、脏区合并、GPU 增量上传 |

---

## 4. 当前数据流

### 4.1 2D

```text
SceneDocument2D
→ SceneManager
→ RenderSceneBuilder (ISceneGeometrySink)
  → Discretizer (圆/弧/椭圆离散化)
  → GeometryManager (块分配 + 槽号管理)
    → PersistentGeometryStore (几何仓)
    → DrawList (绘制列表)
→ RenderWidget
  → SceneRenderPipeline
    → beginFrame
    → submitGeometry (常驻几何仓 DrawList)
    → submitTransient (瞬态环：场景环境/位图/文本)
    → submitOverlay (覆盖层)
    → endFrame
→ Renderx / RenderX
→ Screen
```

### 4.2 3D

```text
SceneDocument3D / SceneManager3D
→ SceneRefreshCoordinator3D
→ Mesh3DBuilder (ISceneGeometrySink)
  → GeometryManager (块分配 + 槽号管理)
    → PersistentGeometryStore (几何仓)
    → DrawList (绘制列表)
→ RenderWidget3D
  → SceneRenderPipeline
    → beginFrame
    → submitGeometry (常驻几何仓 DrawList)
    → submitTransient (瞬态环：环境光/覆盖层)
    → endFrame
→ Renderx / RenderX
→ Screen
```

---

## 5. 当前设计原则

1. 对外只保留稳定的 C ABI。
2. 2D / 3D 共享同一套底层运行时。
3. 适配层只做转换，不做业务编排。
4. 后端抽象继续保留，但不再把旧 `RenderCore` 命名当作当前主线。
5. 提交入口要尽量语义化、统一化。

---

## 6. 未来收口方向

- 继续统一几何提交入口
- 继续减少专用交互 API
- 继续压缩 `RenderDevice` 的职责厚度
- 继续统一日志、统计、错误处理风格
- 继续让 2D / 3D 的命名与行为保持一致
