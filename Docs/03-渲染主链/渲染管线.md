# 渲染核心统一管线

本文只保留当前可用的渲染设计、当前实现方向和未来收口目标，不保留阶段性实现记录。

---

## 1. 当前目标

当前渲染层的目标是把 2D / 3D 的统一渲染入口收口到 `Renderx` / `SanYiRender`，并让对外 C ABI 保持稳定。

---

## 2. 当前痛点

当前渲染层最重要的痛点有三个：

1. 入口必须保持统一，不再拆成多个旧库。
2. UI 语义必须继续下沉到适配层。
3. 渲染层必须继续保持“只做绘制，不做业务编排”。

---

## 3. 当前渲染架构

### 3.1 对外入口

当前生产入口以 `render/render.h` 为准，核心句柄是 `RenderDevice*`。

### 3.2 内部结构

RenderX 内部当前可按以下方式理解：

- `RenderDevice`：单窗口渲染运行时
- `RenderWorld`：2D 图元与脏数据管理
- `BatchQueue` / `DrawBatcher`：批次组织
- `OverlayQueue`：交互叠加层
- `TextAtlas` / `ScreenTextRenderer`：文本
- `MeshManager`：3D 网格与实例
- `SceneEnv`：场景环境
- `CommandEncoder` / `RenderGraph`：命令与流程编排
- `rhi`：后端抽象

---

## 4. 当前数据流

### 4.1 2D

```text
SceneDocument2D
→ SceneManager
→ SceneGeometrySinkAdapter
→ RenderWidget
→ renderSubmitGeometry()
→ RenderDevice
→ renderFrame()
→ Screen
```

### 4.2 3D

```text
SceneDocument3D / SceneManager3D
→ 3D 提交入口
→ RenderWidget3DAdapter / IRenderer3D
→ RenderDevice
→ renderFrame()
→ Screen
```

---

## 5. 当前设计原则

1. 对外只保留稳定的 C ABI。
2. 2D / 3D 共享同一套底层运行时。
3. 适配层只做转换，不做业务编排。
4. 后端抽象继续保留，但不再把旧 `RenderCore` 命名当作当前主线。
5. 提交入口要尽量语义化、统一化。

---

## 6. 未来收口方向

- 继续统一几何提交入口
- 继续减少专用交互 API
- 继续压缩 `RenderDevice` 的职责厚度
- 继续统一日志、统计、错误处理风格
- 继续让 2D / 3D 的命名与行为保持一致
