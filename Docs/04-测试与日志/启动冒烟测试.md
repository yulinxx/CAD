# 启动冒烟测试

## `--smoke-exit-ms` 参数

用于启动冒烟测试的退出开关：显式传入后，应用在启动完成并进入事件循环时启动一个定时器，到时调用 `QCoreApplication::quit()`，按标准退出路径关闭。

| 项 | 说明 |
|---|---|
| 参数形式 | `--smoke-exit-ms=<毫秒>` |
| 取值范围 | 1..600000（毫秒），只接受纯数字 |
| 默认行为 | 不传该参数时不安装任何定时器，与未加入该开关前完全一致 |
| 触发时机 | `QApplication::exec()` 之前注册 `QTimer::singleShot`，从进入事件循环开始计时 |
| 退出路径 | `QCoreApplication::quit()`，`aboutToQuit` 等现有清理逻辑照常执行 |
| 退出码 | 正常退出为 0 |

## 非法值行为

以下情况会在 stderr 输出一行英文告警并**忽略该参数**，应用照常启动、不会自动退出：

- 值为空或含非数字字符（如 `--smoke-exit-ms=abc`）；
- 数值为 0；
- 数值大于 600000（防止误传导致进程长时间驻留）。

告警格式：

```
[smoke] warning: ignored invalid --smoke-exit-ms=xxx (expected 1..600000)
```

## 使用示例

```powershell
# 启动 3 秒后自动退出
April.exe --smoke-exit-ms=3000
```

判定：进程在预期时间附近自行退出、退出码 0，日志中出现 `[Smoke] auto exit scheduled in N ms`、`Application exited with code 0`、`Application shutdown complete`。

## 注意：输出通道必须被消费

本应用的异步日志（spdlog）会写 stdout。若把 stdout 重定向到**无人读取的管道**，管道缓冲写满后日志线程会阻塞，`spdlog::shutdown()` 等待线程池时表现为"退出卡死"。

因此做冒烟测试时，stdout/stderr 应重定向到**文件**（或让终端消费），不要用未读取的管道：

```powershell
Start-Process -FilePath April.exe -ArgumentList '--smoke-exit-ms=3000' `
  -RedirectStandardOutput out.txt -RedirectStandardError err.txt -PassThru
```

该开关仅用于自动化冒烟，不属于面向最终用户的功能。
