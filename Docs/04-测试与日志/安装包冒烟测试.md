# 安装包冒烟测试

> 状态：**已实现**（2026-10-21）
>
> 本文档描述 `Tools/package_smoke_test.py` 的设计、用法、CI 接入方式与已知限制。

---

## 1. 目的

验证 **安装 → 运行 → 覆盖升级 → 卸载** 这条核心链路在各平台、各打包格式下都能正常工作，防止：

- 关键 DLL/动态库漏打包（如 `Engine2D`、`EngineCommon`）
- rpath/搜索路径缺失导致程序无法启动
- NSIS 卸载残留/升级路径异常
- DMG/DEB 解包后的文件布局错误

---

## 2. 测试模式

| 模式 | 适用场景 | 核心动作 |
|------|----------|----------|
| **staged** | 本地构建树 / CI 预检 | `cmake --install` → 校验布局 → `--version` → 覆盖安装（幂等/升级） → `install_manifest` 卸载 |
| **nsis** | Windows 正式安装包 | 静默安装 `/S /D=...` → 运行 → 重复安装（升级路径） → `uninstall.exe /S` 卸载 |
| **dmg** | macOS 安装包 | `hdiutil attach` → 拷贝 `.app` + 同级 `bin/` → 运行 → 覆盖拷贝（升级） → 删除目录（模拟卸载） |
| **deb** | Linux Debian/Ubuntu 包 | `dpkg-deb -x` 解包 → 运行 → 覆盖解包 → 删除目录（模拟卸载） |

> **注意**：`dmg` 与 `deb` 模式不调用系统级安装器（`Installer.app` / `dpkg`），避免 CI 权限与系统污染；真正的 OS 级安装/卸载仍由人工/专项测试覆盖。

---

## 3. 运行示例

### 3.1 本地构建树 staged 测试（macOS/Linux）

```bash
# 已完成构建后
python3 Tools/package_smoke_test.py \
    --build-dir build \
    --qt-dir "$HOME/Qt/6.11.1/macos" \
    --expected-version 1.0.0
```

> macOS staged 安装需要 Qt 框架路径（`--qt-dir`），脚本会自动注入 `DYLD_FRAMEWORK_PATH`、`DYLD_FALLBACK_LIBRARY_PATH` 等环境变量。

### 3.2 Windows NSIS 安装包真实安装/卸载

```powershell
python3 Tools/package_smoke_test.py `
    --installer build/SanYiCAD-1.0.0-win64.exe `
    --expected-version 1.0.0
```

跨版本升级验证：

```powershell
python3 Tools/package_smoke_test.py `
    --installer build-new/SanYiCAD-1.0.1-win64.exe `
    --previous-installer build-old/SanYiCAD-1.0.0-win64.exe `
    --expected-version 1.0.1 `
    --previous-version 1.0.0
```

### 3.3 macOS DMG 内容校验（模拟安装/卸载）

```bash
python3 Tools/package_smoke_test.py \
    --installer build/SanYiCAD-1.0.0.dmg \
    --qt-dir "$HOME/Qt/6.11.1/macos"
```

> DMG 模式会挂载镜像、拷贝 `.app` 与同级 `bin/`，不执行系统级安装；真正的 `.app` 打包仍需 `macdeployqt` 把 Qt 框架打进 bundle。

### 3.4 Linux DEB 内容校验（模拟安装/卸载）

```bash
python3 Tools/package_smoke_test.py \
    --installer build/SanYiCAD-1.0.0.deb
```

> DEB 模式仅做 `dpkg-deb -x` 解包与文件校验；真实 `dpkg -i` 需要 root 权限，CI 里不建议直接跑。

## 4. 关键检查点

脚本在每一步都会执行以下自动校验：

| 检查项 | 说明 |
|--------|------|
| **主程序存在** | Windows `bin/SanYiCAD.exe` / macOS `SanYiCAD.app/Contents/MacOS/SanYiCAD` / Linux `bin/SanYiCAD` |
| **关键动态库 ≥ 3 个** | Windows `*.dll`、macOS `*.dylib`、Linux `*.so*`，且 Windows 必须包含 `Qt6Core.dll`、macOS/Linux ≥ 3 个共享库 |
| **Qt 插件目录** | Windows `platforms/qwindows.dll` 必须存在（`windeployqt` 产物） |
| **版本一致性** | `--version` 输出的版本号与 `--expected-version` / `--previous-version` 一致 |
| **升级幂等/版本升级** | 连续两次安装（或先装旧版再装新版）后版本号正确变更 |
| **卸载无残留** | 卸载后主程序可执行文件不存在；NSIS 额外检查 `uninstall.exe` 也被清理 |

## 5. CI 接入方式

### 5.1 文档检查（每次 PR 必跑）

在 `.github/workflows/ci.yml` 中新增 `docs-check` 作业：

```yaml
  docs-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0   # git log 需要完整历史
      - name: Check docs links & freshness
        run: python3 Tools/docs_check.py --fail-on-stale --max-age-days 365 --review-max-age-days 180
```

- `fetch-depth: 0` 用于 git 修改日期过期检查。
- 默认只把“断链”当错误；“过期/未入索引”默认只告警，避免存量文档一次性卡死 CI。需要严格模式时显式加 `--fail-on-stale` / `--fail-on-unindexed`。

### 5.2 安装包冒烟（仅手动触发 & 版本 Tag）

新建 `.github/workflows/package-smoke.yml`：

```yaml
name: Package Smoke

on:
  workflow_dispatch:
  push:
    tags:
      - 'v*'

jobs:
  smoke-windows:
    runs-on: windows-latest
    timeout-minutes: 180
    env:
      QT_VERSION: "6.8.1"
      VCPKG_ROOT: ${{ runner.temp }}\vcpkg
    steps:
      - uses: actions/checkout@v4
        with:
          submodules: recursive

      # Qt
      - uses: jurplel/install-qt-action@v4
        with:
          version: ${{ env.QT_VERSION }}
          arch: win64_msvc2022_64
          modules: qtbase
          cache: true

      # vcpkg
      - name: Setup vcpkg
        run: |
          git clone --depth 1 https://github.com/microsoft/vcpkg.git "$env:VCPKG_ROOT"
          & "$env:VCPKG_ROOT/bootstrap-vcpkg.bat" -disableMetrics
      - name: Install vcpkg dependencies
        run: |
          $deps = @('openssl','freetype','boost','clipper2','sqlitecpp','gtest','protobuf','spdlog','nanosvg','stb','libwebp','tiff','zlib','breakpad')
          & "$env:VCPKG_ROOT/vcpkg.exe" install $deps --triplet x64-windows

      # NSIS
      - name: Install NSIS
        run: choco install nsis -y

      # Configure
      - name: Configure
        run: |
          cmake -B build-pkg -G "Visual Studio 17 2022" -A x64 `
            -DCMAKE_BUILD_TYPE=Release `
            -DVCPKG_DIR=$env:VCPKG_ROOT `
            -DQt_INSTALL_DIR="${env:Qt_INSTALL_DIR}" `
            -DBUILD_ENGRAVING=OFF -DBUILD_GEOMODELCORE=OFF -DBUILD_VISION=OFF `
            -DBUILD_HARDWARE=OFF -DBUILD_PYTHON=OFF -DSANYI_PYBIND_CORE=OFF `
            -DBUILD_CAM=OFF -DBUILD_NESTING=OFF `
            -DBUILD_UI_DIMENSION=2D

      # Build & Package
      - name: Build
        run: cmake --build build-pkg --config Release --target SanYiCAD --parallel
      - name: Package (NSIS)
        run: cpack --config build-pkg/CPackConfig.cmake -C Release -G NSIS -B build-pkg/package

      # Smoke
      - name: Smoke test
        run: |
          $exe = Get-ChildItem build-pkg/package -Filter *.exe | Select-Object -First 1
          python Tools/package_smoke_test.py --installer $exe.FullName --expected-version 1.0.0 --timeout 300
```

> **说明**：
> - 该工作流仅在 `workflow_dispatch` 或 `v*` tag 推送时触发，避免占用日常 PR 资源。
> - Qt 版本（示例 `6.8.1`）需与项目实际 Qt 版本对齐；vcpkg 依赖列表需按实际 `find_package` 调整。
> - 首次跑通前可能需要根据报错微调 vcpkg 依赖列表、Qt 模块、CMake 选项。

## 6. 已知问题与修正记录

| 问题 | 症状 | 修正 |
|------|------|------|
| `Engine2D`、`EngineCommon` 漏安装 | staged/NSIS 安装后缺 DLL，`--version` 报 `Library not loaded` | 在 `CMakeLists.txt` 的 `SANYI_PROJECT_LIBS` 中补上 `EngineCommon Engine2D` |
| macOS staged 安装 rpath 丢失 | CMake 安装剥离构建期 rpath，安装后的 `.app` 找不到 `libLicense` 等 | `Main/CMakeLists.txt` 给 `SanYiCAD` 设 `INSTALL_RPATH "@loader_path/../../../bin"` |
| Windows NSIS 升级残留 | 旧版本卸载前未清理，导致并存 | `CMake/Packaging.cmake` 开启 `CPACK_NSIS_ENABLE_UNINSTALL_BEFORE_INSTALL ON` 并固定安装目录 `CPACK_PACKAGE_INSTALL_DIRECTORY "SanYiCAD"` |
| CPack 组件导致主程序被排除 | `CPACK_COMPONENTS_ALL` 设了但 `Unspecified` 未列，主程序归入 Unspecified 被丢弃 | 去掉 `CPACK_COMPONENTS_ALL`，回到单组件整包交付 |
| DMG/DEB 模式不复制 `bin/` | 仅拷贝 `.app`，缺少动态库 | `copy_app_from_dmg` 增加同级 `bin/` 拷贝；DEB 解包自带完整目录结构 |

## 7. 常见排查

| 现象 | 可能原因 | 排查步骤 |
|------|----------|----------|
| `--version` 报 `Library not loaded: @rpath/libX.dylib` | rpath 未生效 / 动态库未安装 | 1) 检查 `install_manifest.txt` 是否有该库 2) `otool -L` 看 rpath 3) 确认 `INSTALL_RPATH` 生效 |
| Windows 运行 `--version` 立即返回 `-1073741515` (0xC0000135) | 缺 `Qt6Core.dll` 或其他 DLL | 1) `dumpbin /DEPENDENTS SanYiCAD.exe` 2) 检查 `bin/` 下是否有 Qt DLL 3) 确认 `windeployqt` 已在 POST_BUILD 执行 |
| NSIS 静默安装卡住 / 返回非 0 | UAC 提示、路径包含空格、权限不足 | 1) CI runner 自带管理员权限 2) `/D=` 路径不加引号 3) 确认 `/S` 放在最后 |
| macOS staged `--version` 报 `dyld: Library not loaded` | Qt 框架未找到 | 1) 确认 `--qt-dir` 指向含 `QtCore.framework` 的目录 2) `DYLD_FRAMEWORK_PATH` 含 `$qt_dir/lib` |
| DEB 解包后找不到 `bin/SanYiCAD` | DEB 结构不同 | `dpkg-deb -c package.deb | head` 查看目录结构，脚本默认找 `opt/SanYiCAD/bin`、`usr/bin`、`bin` |

## 8. 与 CPack 的关系

- 脚本**不生成**安装包，只**消费** `cmake --install` 产出的 staged 布局，或消费 `cpack` 生成的 `.exe/.dmg/.deb`。
- `CMake/Packaging.cmake` 的关键设置（已修正）：
  - `set(CPACK_PACKAGE_INSTALL_DIRECTORY "SanYiCAD")` 固定安装目录，支持原地升级
  - `set(CPACK_NSIS_ENABLE_UNINSTALL_BEFORE_INSTALL ON)` 升级前自动卸载旧版
  - 不设置 `CPACK_COMPONENTS_ALL`，避免 `Unspecified` 组件被误排除
  - `install(TARGETS SanYiCAD ...)` 无 `COMPONENT`，随“整包”交付
- 如需 DMG/DEB 真实 OS 级安装测试，需在专用机器/虚拟机上人工跑 `Installer.app` / `dpkg -i`；脚本仅做内容与布局冒烟。

## 9. 扩展建议

- **代码签名/公证**：NSIS/DEB/DMG 真实发布时需在 CI 中集成证书签名、macOS 公证，脚本不涉及私钥管理。
- **自动更新**：如需验证“旧版本检测新版并静默更新”，需在旧版中集成更新器，冒烟测试可在安装旧版后模拟更新器下载新版安装包并调用静默安装。
- **多版本并存测试**：若产品支持同机多版本并存，需验证安装目录、注册表键、快捷方式互不冲突。
- **卸载用户数据清理**：当前测试仅验证程序二进制清理；如有 `%APPDATA%/SanYiCAD` 等用户数据，需单独编写清理用例。
