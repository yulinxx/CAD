## 一、目标态（正在按此演进）

### 1.1 统一适配器契约

目标是让厂商适配器不再依赖 C++ ABI：

- 工厂入口统一为 **`HwCreateDevice`**，返回**不透明句柄**；
- 跨边界结构体一律为**纯 POD**，首字段 **`structSize`**，用于版本守卫与向后兼容；
- 导出 **`HW_ABI_VERSION`** 与稳定的**错误码表**；
- 目标是**第三方可独立编写适配器**，并且**多版本可共存**（同一进程内不同适配器绑定不同 ABI 版本）；
- C++ 门面退化为**同工具链内部 API**，只服务本仓库内的调用方。

这条边界一旦成立，适配器可以单独发布、单独升级，不需要和主程序一起用同一套 MSVC 工具链与 Qt 版本编译。

### 1.2 六厂商职责边界

目标态的适配器只做**协议翻译**：

| 设备 ID | 厂商 | 目标接口面 | 厂商 SDK | SDK 处理方式 |
|---|---|---|---|---|
| `leadshine_ltdmc` | 雷赛 Leadshine | 运动 + IO | `LTDMC.dll` | pimpl 隔离，运行期加载 |
| `zmotion_zmc` | 正运动 ZMotion | 运动 + IO | `zauxdll.dll` | pimpl 隔离，运行期加载 |
| `aerotech_a3200` | Aerotech | 运动 + IO | `A3200C.dll` | pimpl 隔离，运行期加载 |
| `scanlab_rtc5` | SCANLAB | 振镜 + 激光 + IO | `RTC5DLL.dll` | pimpl 隔离，运行期加载 |
| `bjjcz_ezcad` | 金橙子 BJJCZ | 振镜 + 激光 | `MarkEzd.dll` | pimpl 隔离，运行期加载 |
| `ruida_rdc` | 睿达 Ruida | 运动 + 激光（文件通道） | 私有协议，无 SDK | 自实现协议与文件格式 |

目标约束：

- 适配器**不做工艺决策**：穿孔、功率曲线、飞行加工等由上层 IR 表达，适配器只翻译；
- 适配器**不做界面逻辑**，不直接弹窗、不阻塞 UI；
- 适配器**能力位必须诚实**：声明 `CapXxx` 就必须有实现，没有实现就返回 `NotImplemented` 且不声明该能力；
- 厂商 SDK 由 pimpl 隔离，**CMake 不直接链接厂商库**，未安装驱动的机器必须能正常启动并给出 `SdkNotFound`。

### 1.3 安全边界

- **安全功能只由硬回路承担**：急停按 **ISO 13850**，安全相关控制功能以 **ISO 13849-1 PL d / Cat 3** 为最终目标；
- 软件层只做**监测、提示、请求**；
- **第三方适配器只能上报状态，不得实现安全功能**。适配器的关光、停药动作是执行器请求，不构成安全认证链路；
- 适配器不得把「已调用关光 API」当作「已安全」，安全结论必须由硬回路给出。

### 1.4 可分发与多版本共存

目标是提供 `install()`、`HardwareConfig.cmake` 与**导出符号基线**（`.def` 或等价机制），使：

- 下游可以 `find_package(Hardware CONFIG REQUIRED)`；
- 导出面受控，可做 ABI 兼容性审计；
- 适配器与主程序可以各自升级，不必整体重编。

现状【实测】：`install(TARGETS)` + `install(DIRECTORY Include/)` + `configure_package_config_file` + `install(FILES)` 已落地（[Hardware/CMakeLists.txt](file:///c:/Users/xx/Documents/Cpp/CAD/Hardware/Hardware/CMakeLists.txt#L106-L129)）。

有意偏差：**没有使用 `install(EXPORT)`**，改为「显式 `April::Hardware` 导入目标 + `install(FILES)`」（[HardwareConfig.cmake.in](file:///c:/Users/xx/Documents/Cpp/CAD/Hardware/Hardware/CMake/HardwareConfig.cmake.in#L26-L50)），理由写在 CMake 注释里（[Hardware/CMakeLists.txt](file:///c:/Users/xx/Documents/Cpp/CAD/Hardware/Hardware/CMakeLists.txt#L87-L97)）。理由：`Hardware.dll` 私有链接 `Log` / `Utility`，CMake 要求导出目标的全部链接依赖（含私有）也位于导出集；若把它们并入导出集，会把 spdlog、线程池等外部头固化进 Hardware 的对外包，等于把别人的依赖打进交付物。

已知风险：`HardwareConfig.cmake` 只做了 `find_dependency(Qt6 COMPONENTS Core)`（[HardwareConfig.cmake.in](file:///c:/Users/xx/Documents/Cpp/CAD/Hardware/Hardware/CMake/HardwareConfig.cmake.in#L3-L6)），未声明 `Log` / `Utility`，仅在注释里要求宿主自带 `Log.dll`（[HardwareConfig.cmake.in](file:///c:/Users/xx/Documents/Cpp/CAD/Hardware/Hardware/CMake/HardwareConfig.cmake.in#L8-L24)）。消费工程一旦用到依赖这两者的符号，就会在链接阶段失败；「最小工程 `exit 0`」只覆盖触达 `Log` 的一条路径，**不能证明包可独立消费**。需要补 `find_dependency` 或明确要求宿主自带 `Log` / `Utility`。导出符号基线（`.def`）仍**不存在**。
