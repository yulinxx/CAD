# 厂商适配器接入指南

> 目标读者：要把一张新的运动卡 / 振镜卡 / 激光器 / IO 模块接进本框架的开发者。
> 前置阅读：[硬件抽象层架构.md](硬件抽象层架构.md)。
> 建立日期：2026-08-25

---

## 1. 你需要动的文件

新增一个厂商，**只应该动这三处**：

1. `Hardware/Hardware/Include/Hardware/Device/Vendors/<Vendor><Kind>Device.h`
2. `Hardware/Hardware/Src/Device/Vendors/<Vendor><Kind>Device.cpp`
3. `Hardware/Hardware/Src/Device/DeviceRegistry.cpp` —— 在 `registerBuiltinDevices()` 里加一行 `register<Vendor>Devices();`

如果你发现还得改 UI、改命令层、改 CMake 链接库，说明有东西放错了层，回到架构文档对一遍。

> 新增 `.cpp` 后必须重新配置一次：`cmake -S . -B build`。构建用的是 `file(GLOB_RECURSE ... CONFIGURE_DEPENDS)`，增量构建不保证重扫目录。

## 2. 十一步

### 第 1 步：先读 SDK，判断它的「编程模型」

这是最容易被跳过、也最容易导致返工的一步。厂商 SDK 大体分三类，决定了 `loadPlan`/`startPlan` 的实现形态：

- **立即执行型**（金橙子 MarkEzd）：调一次画一笔，卡上没有缓冲队列。适配器需要自己维护「执行到第几条」。
- **列表缓冲型**（SCANLAB RTC5）：把指令写进卡上 list，再 `execute_list` 一次性跑完，进度靠查 list 位置。
- **连续队列型**（雷赛 conti list、正运动 buffer、Aerotech task queue）：队列有容量上限，**必须边跑边续填**。填过量的典型后果是**几何被静默截断**——工件上少一块，软件毫无报错。

先把这件事写进头文件注释，后来的人（包括三个月后的你）不必重读厂商手册。

### 第 2 步：定 ID 与描述符

```cpp
inline constexpr const char* kAcmeDeviceId = "acme_xyz";   // 小写 + 下划线，配置文件里用它
```

`register*Devices()` 里填 `DeviceDescriptor`：`kind`（多能力设备用 `Composite`）、`vendor`、`displayName`（中文，给界面看）、`axisCount`、DI/DO/AI/AO 数量。`model`/`sdkVersion` 通常要等 `open()` 之后才知道，在 `doOpen()` 里回填。

### 第 3 步：继承

```cpp
class ACME_DEVICE_API AcmeMotionDevice final
    : public DeviceBase, public IMotionCard, public IIoModule
```

只继承**真的能实现**的接口。宁可少继承，也不要继承了然后整片返回 `NotImplemented`——`queryInterface` 返回非空就是在向上层承诺「这块我能干」。

### 第 4 步：实现 `queryInterface`

```cpp
void* AcmeMotionDevice::queryInterface(InterfaceId id)
{
    switch (id)
    {
    case InterfaceId::MotionCard: return static_cast<IMotionCard*>(this);
    case InterfaceId::IoModule:   return static_cast<IIoModule*>(this);
    default: return DeviceBase::queryInterface(id);
    }
}
```

**必须写 `static_cast<具体接口*>(this)`**。多重继承下 `return this` 交出的是错位的 vtable 指针，症状是在一个和原因完全无关的地方崩溃。

### 第 5 步：声明参数 schema

把 `open()` 需要的一切都声明出来（名称、类型、单位、范围、默认值、`required`、`advanced`）。参数面板是通用的，**声明完就有界面，不用写 UI 代码**。

命名沿用既有约定，便于跨厂商复用配置：`sdk_path`、`card_no`、`axis_count`、`pulse_per_mm`、`max_velocity`、`di_count`/`do_count`/`ai_count`/`ao_count`、`safe_output_levels`、`laser_enable_bit`（或 `laser_enable_io` / `laser_output_bit`）。

改错了会撞机或错烧的参数标 `advanced = true`，界面会折叠收起。

### 第 6 步：把 SDK 做成运行期加载

```cpp
m_sdk.setWindowsOnly(true);                    // 厂商只给 Windows DLL 时必须加
m_sdk.setSearchNames("AcmeSdk", sdkPathParam); // 不带扩展名，QLibrary 自己补
if (!m_sdk.load())
    return hwFail(HwError::SdkNotFound, "AcmeSdk.dll not found; ...");

m_moveAbs = m_sdk.resolve<MoveAbsFn>("Acme_MoveAbs");
if (!m_moveAbs)
    return hwFail(HwError::SdkSymbolMissing, "Acme_MoveAbs missing (SDK too old?)");
```

**绝对不要 `target_link_libraries` 厂商 `.lib`**——那样非 Windows 编不过，没插卡的开发机也起不来。

必需符号解析失败即 `open()` 失败；可选符号解析失败则**收窄能力位**并 `WARN`，不要上报一个用不了的能力。

### 第 7 步：把厂商返回码翻译成 `HwResult`

每个厂商的成功约定都不同，务必集中到一个 `check()` 帮助函数里，别散落在几十个调用点：

- 雷赛 LTDMC：`0` = 成功。但 **`dmc_board_init` 返回卡数量**，`<= 0` 才是错误——历史遗留的特例。
- 正运动 ZAux：`0` = 成功。
- Aerotech A3200：返回 BOOL，**非零 = 成功**，与国产卡完全相反。翻错的话「每一步都失败」或者更糟「每一步都成功」。
- SCANLAB RTC5：多数函数无返回值，靠 `get_last_error` / `get_status` 查。

`hwFail()` 的 message 里写清「哪个函数、返回什么、参数是什么」。只给枚举，现场排障等于零信息。

### 第 8 步：实现 `IMotionCard` / `IGalvoCard` 的运动部分

必须遵守的契约（细节见头文件注释）：

- `moveAbsolute`：**未回零必须拒绝**（`InvalidState`）。
- `moveRelative`：**不要求已回零**，与 `jog` 一致——把轴挪开限位是现场调机的第一步。
- `emergencyStop`：**任何状态下都要可执行**，不做前置检查、不申请锁；`Fault` 态也得能停。
- 参数越界：**拒绝，不要钳制**。钳制会让「请求 30 秒、实际 5 秒」看起来一切正常。
- 出光相关的暂停：`pausePlan` 必须强制关光，`resumePlan` 再恢复原状态。

### 第 9 步：翻译 MotionPlan

遍历 `MotionPlanView` 的 `MotionCommand` 数组，逐条映射到 SDK 调用。三条硬要求：

1. **单位换算集中一处**。RTC5 用 16 位 bits 而非 mm，Ruida 用 µm 整数；散落的换算迟早对不上。换算越界要**拒绝**（`InvalidArgument`），不要截断——截断的结果是图形悄悄变形。
2. **不支持的操作码返回 `NotImplemented`**，带上操作码名与指令下标。静默跳过 = 工件缺一块且无报错。
3. **不支持圆弧就离散**（弦高容差，参考实现取 0.01 mm 并限制最大段数），且不要上报 `CapArcInterp`。

队列型设备还要实现续填。注意 `planProgress()` 是 `const` 方法：把续填逻辑放进 `Impl` 的成员函数，通过 `m_impl` 指针访问天然可写，不需要 `mutable` 或 `const_cast`。

### 第 10 步：实现 `IIoModule`

- 写输出**逐位写**，不要整端口写：整端口写会把别人置起的夹具、气阀一起清掉。
- 卡没有输出回读能力时，在 `Impl` 里维护 `outputShadow` 并在注释里写明它是影子值而非实测值。
- `close()` 与 `emergencyStop()` 都要把输出恢复到 `safe_output_levels`。
- 通道越界返回 `InvalidArgument`，不要返回 0——「读到 0」和「读不到」在安全逻辑里是两回事。

### 第 11 步：写头文件注释（这不是可选项）

头注释至少要有四段：

1. **适用型号范围**（哪些卡共用这套 SDK）；
2. **SDK 的编程模型**（第 1 步的结论）；
3. **本适配器的取舍**（为什么不用控制器内置解释器、为什么激光走普通 DO 而不是 PSO……）；
4. **未实测的部分**：把所有「按手册写的、还没上机验证」的点逐条列出，并指向 [厂商接入现状.md](厂商接入现状.md)。第一次上机的人照着这份清单验证，比重读手册快一个数量级。

## 3. 提交前自检

- [ ] `Hardware` 目标能链接（新增的 `register*Devices()` 已在 `DeviceRegistry.cpp` 声明并调用）
- [ ] CMake 里没有任何厂商 `.lib`
- [ ] 接口签名里没有 `std::string` / `std::vector` / `QString`；STL 成员都在 `Impl` 里
- [ ] `queryInterface` 用的是 `static_cast<接口*>(this)`
- [ ] 所有 `advanced` 参数都标了，危险参数没有平铺在基本参数里
- [ ] 每条 `hwFail()` 的 message 都能定位到具体厂商调用
- [ ] `open()` 时把能力降级一次性 `WARN` 清楚
- [ ] 越界一律拒绝，没有静默钳制/截断/跳过
- [ ] `emergencyStop()` 无前置检查、无锁
- [ ] `close()` 把激光关掉、输出置安全态
- [ ] `HardwareTests` 全绿（新适配器不需要新增用例，但**不得破坏既有契约用例**）
- [ ] 头文件里有「未实测的部分」，并已在 `厂商接入现状.md` 建好条目

## 4. 无卡开发怎么做

用 `simulated_composite`。它同时实现四个接口，行为由确定性的 `tick(elapsedMs)` 推进——不起线程、不用 `QTimer`、不用随机数，因此上层逻辑与安全联锁可以在没有硬件的机器上完整跑通并写成可回归的用例。

新适配器的契约是否正确，判据是「同样一段 `MotionPlan` 与同样一组操作序列，在模拟设备上的可见行为与在真机上一致」。**模拟设备比真机更严或更松，都是 bug**：更松会让开发期漏掉约束，更严会让「模拟能过、真机不同」，抽象层就失去了参考价值。
