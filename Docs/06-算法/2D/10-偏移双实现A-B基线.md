# 偏移双实现 A/B 基线（Engine2D vs Engraving）

> 状态说明（2026-11-28）　状态：现行　维护：架构组
>
> 这是 [2D 算法框架分层设计](00-算法框架分层设计.md) §4「P3 收敛重复」的**前置数据**，
> 不是合并方案本身。工具只读生产实现，不改任何算法代码。

## 1. 为什么要有这份数据

仓库里有两份 2D 偏移实现：

| 实现 | 文件 | 量化 | 用途 |
|---|---|---|---|
| `Eg::Geo2DOffset` | `Engine/2D/Src/Geometry/Geo2DOffset.cpp` | `ClipperD(4)` = 1e-4 mm | 填充、图元偏移、螺旋/同心环、C ABI 门面 |
| `Engraving::PolygonOffset` | `Engraving/Engraving/Src/PolygonOffset.cpp` | `Paths64` scale=1000 = 1e-3 mm | 雕刻偏移、轮廓平行填充 |

设计文档要求「合并前先拿 A/B 数据」。本轮提供可重复生成的对照工具与基线 CSV，
用来回答：**哪些能力可以直接收敛，哪些必须先补参数化**。

## 2. 工具与复现

- 工具：`Tools/OffsetCompare/main.cpp`（目标 `AprOffsetCompare`，开关 `BUILD_OFFSET_COMPARE`）
- 基线：`Docs/performance-audit/offset-ab-baseline.csv`（85 行，含注释头）
- 构建（共享 `build/` 目录的 `BUILD_ENGRAVING` 当前为 OFF，故用独立目录）：

```bash
cmake -S . -B build-offset-compare -G Ninja \
  -DVCPKG_INSTALLED_DIR=/Users/ms/vcpkg/installed -DVCPKG_MANIFEST_MODE=OFF \
  -DBUILD_ENGRAVING=ON -DBUILD_OFFSET_COMPARE=ON -DBUILD_TESTS=OFF
cmake --build build-offset-compare --target AprOffsetCompare
./build-offset-compare/bin_Qt6/Release/AprOffsetCompare Docs/performance-audit/offset-ab-baseline.csv
```

### 2.1 输入与参数对齐

- 6 个规范图形：`square100`、`rect200x100`、`l_shape`、`square_with_hole`、`ten_point_star`、`circle_r50`
- 单次偏移 delta：`+0.5 / +1.0 / +2.0 / -0.5 / -1.0`（mm），共 30 行
- 逐层内缩：step=1mm，最多 8 层，共 48 行
- 单次偏移两侧都设为 `Round / miter=2 / arcTol=0.05`，只保留**量化精度**这一差异
- 逐层内缩：Engraving 的 `inflateRegionToRings` 硬编码 `Miter / 2.0 / 0.0`，公开 API 无参数；
  Engine2D 侧用 `Round / 2.0 / 0.05`。这一差异是刻意保留的，正是要量化的对象。

### 2.2 对齐口径

Engraving 的逐层结果是**扁平环列表**（每轮内缩把该层所有环顺序 push_back，不带层号）；
Engine2D 的 `insetRings` 是嵌套的「层 → 环」。工具按 Engine2D 每层环数切片对齐 Engraving 列表，
因此比较的是**同一层的环集合面积总和**，不是第 i 条环。

CSV 列：`kind, shape, param, layer, engine_area_mm2, engraving_area_mm2,
abs_diff_mm2, rel_diff_pct, engine_rings, engraving_rings, engine_points, engraving_points`。

## 3. 结论（以当前基线为准）

### 3.1 单次偏移：数值几乎一致，可优先收敛

| 指标 | 结果 |
|---|---|
| 样本数 | 30 |
| 最大相对差 | **0.0042%**（十角星，delta=+2.0） |
| 最大绝对差 | **0.2192 mm²**（对应图形面积约 5200 mm²） |
| 环数 / 点数 | 所有样本两侧完全一致 |

差异来源可用量化口径解释：Engine2D 单顶点误差 ≤5e-5 mm，Engraving ≤5e-4 mm，
两者相差一个数量级；在 100mm 级图形上累计到 0.2 mm² 量级属预期。

**建议**：单次偏移可以收敛到一份实现，优先保留 Engine2D（精度更高、参数可配、已被 C ABI 门面暴露）。
Engraving 侧改为薄包装或显式标记弃用，走真实入口回归后再删。

### 3.2 逐层内缩：浅层接近，深层不可直接合并

| 指标 | 结果 |
|---|---|
| 样本数 | 48 |
| 最大相对差 | **1.57%**（十角星第 7 层） |
| 最大绝对差 | **56.41 mm²**（带孔方形第 7 层） |
| 点数发散 | 十角星第 7 层：Engine2D 1818 点 vs Engraving 10 点；带孔方形第 7 层：1839 vs 8 |

浅层（前 1–2 层）差异通常在 0.1% 以内；深层点数的数量级差异不是量化误差，而是**策略差异**：

1. Engraving 用 Miter、弧容差 0（尖角保留），Engine2D 用 Round、弧容差 0.05（圆滑 + 点数增加）；
2. Engine2D 有残环/薄条环/完全重合环的剔除与统计，Engraving 没有对应机制；
3. Engine2D 的层上限按最大内切半径自适应，Engraving 用 `ceil(跨距/step)+2` 固定上限。

**建议**：逐层内缩**暂不合并**。要先让 Engraving 暴露 joinType/arcTolerance 参数并补齐残环策略，
再用本工具重跑基线；在那之前两份实现各自服务不同工艺路径是合理的。

## 4. 基线的使用纪律

1. 本 CSV 是**观测值**，不是验收阈值；不要把它直接写成「允许 2% 误差」。
2. 任何一侧实现改动后重跑工具，差异若**增大**，必须在提交说明里给出几何/工艺理由。
3. 合并前必须用真实零件图和真实入口（Fill2D / 雕刻路线）复现，不能只看 6 个合成图形。
4. 本工具只测数值结果，不测耗时与内存；性能另行用 `Tools/PerfBenchmark` 对照。

## 5. 收敛执行结果（2026-11-28）

按 §3.1 的结论，**单次偏移已收敛到 Engine2D**：

- `Engraving::offsetPolygons` / `offsetPolygon`（`EndType::Polygon`）改为委托
  Engine2D 稳定 C ABI `Eg2d_Offset`；Engine2D L1 内核成为唯一实现。
- C ABI 新增 `Eg2d_PathSetAddLoop`，使多环（外环 + 孔洞）输入可一次传入，不丢孔。
- 兼容保留：`EndType::Open/Joined` 仍走原 ClipperOffset（Engine2D L1 不处理开放路径）；
  `offsetDistance == 0` 返回输入轮廓（旧语义）。
- 依赖方向：Engraving → Engine2D（PRIVATE 链接），无反向依赖。
- 收敛后重跑工具：`Docs/performance-audit/offset-ab-after-convergence.csv`
  - 单次偏移 30 行：最大相对差 **0.0%**（同一实现）
  - 逐层内缩 48 行：最大相对差仍为 **1.57%**（该路径未合并，符合预期）
- 回归：`EngravingPolygonOffsetTests` **23/23 通过**（含零偏移、带孔、内外缩）。

## 6. 局限

- 输入是程序合成的 6 个规范图形，未覆盖真实扫描件、自交轮廓、极小特征；
- 未测 CAM 刀路编译与异步编排两条重复链（它们没有可比的纯数值输出，需另一套对照方式）；
- `build-offset-compare` 是为绕开共享目录 `BUILD_ENGRAVING=OFF` 的临时构建目录，未纳入 CI。
