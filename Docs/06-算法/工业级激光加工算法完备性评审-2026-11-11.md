### 1.2 有缺口

**（1）EvenOdd 约定会把重叠外轮廓变成孔 —— 影响加工结果，非 bug 但是产品级陷阱**

- 实现：`offsetContours` 先用 `EFillRule::EvenOdd` 求并归一化（[Geo2DOffset.cpp:536-540](file:///Users/ms/Documents/CAD/Engine/2D/Src/Geometry/Geo2DOffset.cpp#L536-L540)）；`insetRingLayers` 同（L616-617、L656-661）；螺旋源区域同（L757-758）。
- 测试明确锁定该契约：`Geo2DOffsetTest.OverlappingInputsFollowEvenOddRule` 断言两块重叠正方形外扩后面积 **严格小于**按并集外扩的 204（[Geo2DOffsetTests.cpp:176-190](file:///Users/ms/Documents/CAD/Engine/2D/Test/Geo2DOffsetTests.cpp#L176-L190)），说明公共区被抠掉。
- 调用侧未预合并：`offsetEntity` 把选中图元轮廓聚合成 `allContours` 后直接送入 `offsetContours`（[EntityOffset.cpp:162](file:///Users/ms/Documents/CAD/Engine/2D/Src/Algorithm/Offset/EntityOffset.cpp#L162)）。
- 同一约定也存在于填充：`RegressionTest.FillIntersectionAreaIsHole` 明确断言重叠区"期望 0 条填充线"（[RegressionTests.cpp:254-320](file:///Users/ms/Documents/CAD/Engine/2D/Test/RegressionTests.cpp#L254-L320)）。
- 后果：用户框选两个重叠零件做"外扩/填充"时，重叠带变成未加工孔洞。对激光切割是**漏切**，对雕刻是**空白带**。代码里已有 `NonZeroPrefilterAvoidsHoleInOverlap` 证明正确做法，但生产调用方没有用它。

**（2）`kInsetRingMaxLayers = 500` 硬上限**

- [Geo2DOffset.h:18](file:///Users/ms/Documents/CAD/Engine/2D/Include/Engine2D/Geometry/Geo2DOffset.h#L18)，在 [Geo2DOffset.cpp:643](file:///Users/ms/Documents/CAD/Engine/2D/Src/Geometry/Geo2DOffset.cpp#L643) 处取 `min(nMaxLayers, 500)`。
- 量化：步距 0.1mm 时最多覆盖 50mm 宽度；100mm 宽区域中心约 50mm 无填充。无告警，静默停止。

**（3）NURBS 离散段数与容差解耦**

- `EntityDiscretizer.cpp:27-28` 固定 `kMinCurveSamples = 32`、`kMaxCurveSamples = 256`；L225 采样数 `clamp(controlPointCount*8, 32, 256)`，**不读 `dDiscretize` 容差，也不看半径**。
- 量化：半径 1000mm 的整圆按 256 段离散，弦高误差 ≈ `R(1-cos(π/256)) ≈ 0.075mm`，已超过 0.01mm 级精度目标；反过来，小圆无法通过放宽容差减少段数。
- 后果：大尺寸曲线轮廓的几何精度不受用户容差控制。

**（4）尖角被 Miter limit 截断**

- `OffsetParameters.h:28` `dMiterLimit = 2.0`；2D 默认 `JoinType::Square`。
- 斜接长度上限 2.0 意味着夹角小于约 29° 的尖角会被截平。`KerfCompensator.cpp` 注释声称"角部保持尖角"，但同样用 `miterLimit=2.0`（约 L100-150），**注释与几何行为不一致**。对需要保留锐角的零件（刀模、尖角装饰）是可见缺陷。

**（5）无有限性校验**

- `booleanContours` / `offsetContours` 未对 NaN/Inf 输入做检查，Clipper2 会把它们量化成极端整数。生产上表现为不可预测轮廓而非明确报错。

**（6）填充规则不可选**

- `ScanlineFill.cpp` 按交点奇偶判定内外（even-odd），`BowFill.cpp` 同；无 NonZero 选项。与 (1) 叠加，重叠形状在填充阶段也会互相抵消。

**（7）发丝环的取舍**

- 末环判定只对 `rings.size() >= 2` 生效；单环本身过窄时仍保留（见 `insetSpiralPaths` 末环处理段）。测试 `LastHairlineRingIsSkipped` 覆盖的是多环场景，**单环发丝环无测试**。这是有意的 trade-off，但会在极小残留区留下一条几乎无宽度的扫描线。

**（8）精度的双网格**

- 2D 为 0.1µm（`kClipperDecimalPrecision=4`），3D 为 1µm（`PolygonOffset.cpp` / `VolumeProcessing.cpp` 多处 `scale=1000`）。同一零件在 2D 与 3D 浮雕链上的最小可分辨特征相差 10 倍，跨域组合时会出现"2D 能算、3D 算丢"的边界。

### 1.3 生产不可用

- 2D 矢量切割链**没有自动割缝补偿**：`OperationRegistrar` 把 `kerfMm` 硬编码为 0（[OperationRegistrar.cpp:55](file:///Users/ms/Documents/CAD/Main/Src/Composition/OperationRegistrar.cpp#L55)），`MotionPlanCompiler` 无割缝调用。唯一在产路径是光栅矢量化路由，且默认 `req.kerfMm = 0.0`（[RasterProcessOperation2D.cpp:533](file:///Users/ms/Documents/CAD/UI/2D/Src/Operation/RasterProcessOperation2D.cpp#L533)）。
- `KerfCompensator` 对**开轮廓原样返回**，不做补偿；对切割开口路径（刻线、断开轮廓）无法保证缝宽。

### 1.4 性能实测

`Engine2DOffsetBenchmark --ab`（64 边形，半径 60mm，步距 0.5mm）：

| 场景 | 生产归一化路径 | legacy | 变化 |
|---|---|---|---|
| 20 层 × 20 环 | 93.2ms | 17.5ms | +431% |
| 50 层 × 20 环 | 212.6ms | 69.4ms | +206% |

结论：归一化（EvenOdd Union）带来 2-5 倍开销，在 50 层量级仍 <0.25s，可接受；但这是"每层都归一化"的代价，环数再上一个数量级会线性放大。

### 1.5 测试覆盖判断

覆盖得好的：布尔、三种 join、内外缩、孔洞、退化、螺旋自交、末环。

**未被覆盖的边界**：重叠外轮廓在生产调用方的实际行为（只有 kernel 级契约测试，没有 `offsetEntity` 级测试）；500 环上限；单环发丝环；NaN/Inf；大半径 NURBS 的弦差；<29° 尖角。

**（1）缺字静默跳过，并按 0.55em 固定宽度推进**

- [TextConverter.cpp:1533-1537](file:///Users/ms/Documents/CAD/Engine/2D/Src/Text/TextConverter.cpp#L1533-L1537)：`++nMissingGlyphCount; dPenX += getCharAdvance(dFontSize); continue;`

- 后果：缺字位置既不报错也不占位显示，后续字符按固定宽度继续，可能重叠或错位；用户只在日志里看到计数。工业打标场景下这是**静默的成品错误**。

**（2）字号无任何校验/截断**

- 主路径 [L1380](file:///Users/ms/Documents/CAD/Engine/2D/Src/Text/TextConverter.cpp#L1380)、回退路径 L1283 均直接 `FT_Set_Pixel_Sizes(face, 0, static_cast<FT_UInt>(param.dFontSize))`。
- `dFontSize <= 0` 转 `FT_UInt` 会变成极大值，`FT_Set_Pixel_Sizes` 返回值被忽略；随后所有 glyph 加载失败，走缺字分支，**输出为空且无错误**。超大字号同样无上限。

**（3）无 kerning、无 complex shaping**

- 全文件只读 `face->glyph->advance.x`（L1152），检索 `Kerning` 零匹配；全仓无 HarfBuzz 使用。
- 后果：拉丁文字字距偏松/偏紧；阿拉伯文、天城文等需要连写的语言会输出孤立字形。中文场景不受影响。

**（4）行距字段是死字段**

- `AprText.h:97` `double dLineSpacing{ 1.0 };` 全仓仅定义、从未读取；实际固定 `dFontSize * 1.2`（L1444）。UI 若暴露行距，将完全无效。

**（5）无描边/线宽文字**

- 只有轮廓，没有"偏移成双线/单线雕刻"的文字线宽参数。激光刻字想要单线体必须依赖字体本身。

**（6）无大文本性能测试**

- 现有 9 例均为短字符串；万字符级文本的耗时、内存、日志量无门禁。

### 2.3 测试覆盖判断

4. **无 G2/G3**：3D 导出全部折线；曲面浮雕可接受，但轮廓边缘可见弦纹。
5. **引入/引出不识别内外轮廓与孔**：`LeadInOut` 不做孔/外轮廓分类，孔内引入可能压到已加工区。
6. **仅加工选中网格**：`ReliefEngravingProcessor3D.cpp` 只处理选中网格，多零件需逐个操作。

### 5.2 生产不可用 / 高风险

**A. 2D 生产链缺失的工艺能力（影响加工质量）**

1. **无自动割缝补偿**：见 1.3。所有矢量切割按名义轮廓走，实际缝宽偏移未补偿；内孔偏小、外形偏大。
2. **无引入/引出/穿孔**：`ToolPathJobInput.h:290-296` 的 `LeadInOutParams` / `piercePoints` 仅声明，`piercePoints` 全仓无赋值；2D 光栅路由把引入显式置 0（[ProcessRouteRegistry.cpp:452-457](file:///Users/ms/Documents/CAD/UI/2D/Src/ProcessRouteRegistry.cpp#L452-L457)）。切割起点直接全功率落点 → 穿孔烧痕、拐角过烧。
3. **无路径排序**：`MotionPlanCompiler.cpp:462-465` 按场景实体顺序逐条发射，每条前 `emitRapidTo`（L112/146/222）；`PathOptimizerV2` 零生产引用。空走总长不可控。
4. **不区分内外轮廓**：同一图层内先切内孔还是先切外形无策略，零件可能因应力/热变形移位后外形失准。

**B. 3D G-code 导出（潜在撞机/无效程序）**

5. **safeZ 硬编码**：`safeZ = maxZ + 5` 或 5，无工件高度/夹具高度/机床行程校验（[ReliefToolpathExporter3D.cpp:317-323,471-478,515-523](file:///Users/ms/Documents/CAD/UI/3D/Src/Relief/ReliefToolpathExporter3D.cpp#L317-L323)）。高夹具或负 Z 工件时 `G0` 可能撞件。
6. **rapidSpeed = max(scanSpeed×3, 3000) mm/s**：作为 G0 速度假设用于时间估算，3000mm/s = 180m/min 远超真实空移；时间预估严重低估，且 `G0` 不带 F，实际速度由固件决定，**估算与执行两套口径**。
7. **GRBL 的 `G4 P` 单位错误**：`delayCmd` 把 GRBL 与 Marlin 合并为毫秒（[ToolpathExporter.cpp:118-120](file:///Users/ms/Documents/CAD/Engraving/Engraving/Src/ToolpathExporter.cpp#L118-L120)），GRBL 规范为秒。默认 `laserOnDelayMs=0` 时不触发；一旦设置延时，实际停顿会放大 1000 倍。
8. **Custom 方言输出无坐标**：`customOnRapidMove("rapid")` / `customOnCutMove("cut")`（L69-88），回调签名不带坐标（`ToolpathExporter.h:45-50`）。选 Custom 且未提供完整实现时，生成的是**废程序**。
9. **空路径仍成功**：`toolpaths` 非空但每条都为空时，仍输出头尾并 `success=true`；空列表才失败。会产生"只有头尾"的空程序。

**C. 材料与工艺参数**

10. **材料预设只有 3 种**：`LaserStrategy.cpp:39-50` 仅 `wood/metal/acrylic`（含中文名）；`leather/glass` 落入默认分支静默不变，而 UI 下拉框提供 5 项（`ReliefEngravingDialog3D.cpp:404-408,693-697`）。用户选皮革/玻璃以为已调参，实际参数未变。
11. **预设累积漂移**：`applyMaterialPreset` 以当前 UI 值为 base 调用 `adjustParams`（[ReliefEngravingParams3D.cpp:55-75](file:///Users/ms/Documents/CAD/UI/3D/Src/Relief/ReliefEngravingParams3D.cpp#L55-L75)），metal 为 power×1.2 / speed×0.6 / layerHeight×0.5。反复切换材料会连乘，参数不可复现。
12. **`materialType == nullptr` 直接返回**，无默认预设、无提示。

**D. 参数校验**

13. 不校验 `NaN/Inf`、负坐标、超大坐标、`feedRate<=0` 之外的非法值。`feedRate<=0` 会回退到 `opt.rapidSpeed`（有测试锁定），意味着**零速会变成全速切割**，这是一个危险的回退语义。
14. 无 2D 方言选择、无后处理模板、无断电续切 checkpoint。

### 5.3 可追溯性

- 3D G-code 头部含 material/power/passes/lead-in（`ReliefToolpathExporter3D.cpp`），可追溯到工艺参数。
- 2D 直连设备链的 `MotionPlan` 有层/遍次/功率/速度，但**没有工艺文件落盘**；事后无法复现某次加工用了什么割缝/引入/排序策略（因为这些根本没进链）。
- 无加工仿真：没有材料去除、碰撞、过切校验，所有正确性依赖"看代码/看空跑"。

## 7. 核心问题回答

### 7.1 以工业级激光加工软件衡量，当前处于什么水平？

**分层结论：**

- **几何内核（2D/3D 切片/排样）：接近工业级。** 采用 Clipper2 + 成熟切片/排样算法，边界测试扎实，量化网格明确。这一层可以直接支撑产品。
- **工艺前处理与后处理：原型/轻工业试产级。** 割缝、引入、穿孔、排序、拐角、功率曲线、仿真这些"决定成品质量"的部分，要么缺失，要么只存在于测试代码中。
- **系统级交付：不可用于无人值守/连续生产。** 无过程监控、无仿真校验、无断点续切、无参数可追溯文件。

一句话：**"画得对、算得出"，但"切得准、切得稳、切得可复现"还没闭环。**

## 9. 建议交付路线（按依赖关系）

1. **先做"不撞机、不出废程序"**：P0-1/2/3/6/7。都是小改动，但直接决定能否让外部用户碰机器。
2. **再做"尺寸对"**：P0-4 割缝 + P1-1 引入/穿孔 + P1-2 排序。这三项决定零件能否装配。
3. **然后做"参数可信"**：P0-5 材料预设 + P1-5 层深联动 + P1-6/7 文字。决定批次一致性。
4. **最后做"可验证、可复现"**：P2-4 仿真 + P2-1 NC 导出 + P2-6 续切。决定能否无人值守/连续生产。

验收口径建议（可量化）：

- 割缝补偿后，标准试片孔径/外形偏差 ≤ ±0.05mm；
- 引入/穿孔后，起点烧痕直径 ≤ 设计值，无过烧；
- 排序后空走总长下降 ≥ 15%（与场景顺序基线比）；
- 3D 导出前越界程序 100% 被拒绝；
- 非水密网格 100% 有可见阻断/确认，不再静默漏切；
- 同一工艺参数重复导出 G-code 字节级一致（材料预设不漂移）。
