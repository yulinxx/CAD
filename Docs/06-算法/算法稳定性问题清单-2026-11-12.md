## 1. 已修复（本次，待提交）

### 1.1 中文图层名导出后自己读不回来（结果错误 → 已修）

**现象**：含中文图层名的 DXF 导出成功，但同版本导入 `FileImporter.Open` 返回 false；纯 ASCII 图层名正常。

**根因（两层）**：
1. 写出器是手写 R12（`$ACADVER=AC1009`），却把 UTF-8 原始字节直接写入且不写 `$DWGCODEPAGE`；
2. 更直接的原因是导入侧 `sanitizeDxfBytes` 的旧启发式：把「`0x0A` 前一字节 ≥ 0x80」一律替换为空格，误伤了以多字节字符结尾的行的真实换行，导致组码/值行错位、整份解析失败（由提交 6503033 为修 GBK 内嵌 `0x0A` 引入）。

**版本选择依据（以 libdxfrw 实际读回验证）**：

| 方案 | 实测结果 |
| --- | --- |
| R12 + UTF-8 原始字节 | 失败（换行被 sanitizer 破坏；修复 sanitizer 后可读，但 R12 声明与 UTF-8 仍不规范） |
| 仅把 `$ACADVER` 改成 AC1015/1018/1021/1024/1027/1032 | 全部失败：文档仍是 R12 形状（无 CLASSES/OBJECTS/句柄/子类标记），libdxfrw 判结构非法 |
| R12 + `$DWGCODEPAGE ANSI_936` + GBK 字节 | 成功，图层名逐字读回 |
| 仅 ASCII 的 R12 | 成功（保持历史字节兼容） |

**结论**：维持 R12（AC1009），非 ASCII 字符串按 ANSI_936（GBK）转码；仅在存在非 ASCII 时写 `$DWGCODEPAGE ANSI_936`，ASCII 文件字节不变。

**修改文件**：
- `FileIO/FileIO/Src/Writers/DxfFileWriter.cpp`
  - 新增线程局部 `DxfTextEncoder`（`DRW_TextCodec`，AC1009 + ANSI_936），导出时对图层名与文本转码，GBK 不可表示时记录 lossy 警告；
  - `write()` 条件写出 `$DWGCODEPAGE`；
  - 补齐 `TEXT` 图元导出（此前完全没有导出通道，中文图元文本往返的前提）。
- `FileIO/FileIO/Src/Parsers/DxfParser.cpp`
  - `sanitizeDxfBytes` 改为按「组码行必须是 0..1071 的十进制整数」的结构判断，只在“期待组码却读到非组码行”时修复被误切的换行，合法文件零改动；
  - 解析失败信息追加 libdxfrw 结构诊断与文件声明的 `$ACADVER`/`$DWGCODEPAGE`。

**证明「第 1 条修好」的用例**：
- `DxfEncodingRoundTripTest.ChineseLayerNamesRoundTripExactly`：断言导出文件含 `$DWGCODEPAGE`/`ANSI_936` 与 GBK 字节、不含 UTF-8 字节；重新导入后 `切割层`/`雕刻层` 名称逐字一致，且两个图元各自 `layerSourceId` 落在正确图层。
- `DxfEncodingRoundTripTest.ChineseTextContentRoundTrips`：`内孔加工` 文本、位置、高度、旋转角全部读回一致。

**证明「老 R12 文件仍可读」的用例**：
- `DxfEncodingRoundTripTest.LegacyAsciiR12FileStillImports`：手工构造 CRLF 行尾、无 `$DWGCODEPAGE`、双图层的 ASCII R12 文件，导入后 2 图层/2 图元、图层归属与文本均正确。
- 回归：`FileIOTests` 全量 **233 passed**（原有 228 条 + 新增 5 条，无退化）。
- 额外证据：修复前产出的坏文件 `/tmp/stab-repro/chinese_layer.dxf`（UTF-8 未声明代码页）现在可被 `FileImporter.Open` 成功导入，图层名逐字正确。

### 1.2 隐藏图层往返丢可见性（结果错误 → 已修）

**现象**：`visible=false` 的图层导出再导入后变为可见。

**根因**：LAYER 表 `70` 组码恒写 0，未映射可见性；写出器也不保存图层可见性。

**修法**：`DxfFileWriter` 的图层记录增加 `visible`，`70` 写 `visible ? 0 : 1`（bit0 冻结）。「关层」的负 ACI 颜色语义不混用。

**测试**：`DxfEncodingRoundTripTest.HiddenLayerVisibilityRoundTrips` 断言 `VISIBLE=true`、`HIDDEN=false`。

### 1.3 读取失败错误信息可指向版本/编码（体验 → 已修）

- `parse` / `parseToIR` 失败时输出：`[cause=<code>: <message>] [declared ACADVER=..., DWGCODEPAGE=...]`。
- 实测错误信息：`Failed to read DXF file: ... [cause=code-parsed: a group-code parser rejected the input] [declared ACADVER=AC1021, DWGCODEPAGE=(none)]`。
- 用例：`DxfEncodingRoundTripTest.ReadFailureErrorPointsToDeclaredVersion`。

**结论**：原先 `Open=false` 是**解析失败**（编码导致的记录错位），不是单纯的“版本不支持”；修复后该路径已消失。对真正的版本/结构不匹配，错误信息现在能直接指出声明版本与代码页。

**已提交（未推送）**：FileIO 子模块 `0821b8c`，`fix(fileio): DXF 中文图层/文本按 GBK 代码页往返并保留图层可见性`
