# 2D 图元算法框架

本文描述 2D 图元算法的当前分层方式，重点是把基础几何、通用查询、图元专用和编辑类能力分开。

---

## 1. 为什么需要独立框架

2D 图元后续会持续增加命中、投影、离散、编辑、分析类算法。把这些算法分散到 UI 或图元类中，会带来重复实现、命名混乱和依赖循环。

---

## 2. 总体目标

### 2.1 算法独立于 UI

算法应属于几何/实体层，不依赖菜单、工具栏、视口或鼠标事件。

### 2.2 算法可复用

同一个算法应尽量被选择、编辑、偏移、打断、离散等能力复用。

### 2.3 分层组织

建议沿以下层次组织：

```text
基础数学层
→ 基础几何层
→ 通用二维算法层
→ 图元专用算法层
→ 编辑 / 离散 / 分析算法层
```

---

## 3. 基础数学层

当前数值和基础向量运算已收口到 `Ut::GeomMath`，包括：

- 容差比较
- clamp / lerp
- 角度转换
- 近似相等判断

---

## 4. 基础几何层

这一层只关心点、线、圆、弧、多边形、包围盒等基础几何对象。

建议提供的核心能力包括：

- 点到线段距离
- 点到直线距离
- 线段相交
- 圆弧命中
- 多边形内外判断
- 包围盒计算
- 最近点计算

---

## 5. 通用二维算法层

当前代码里，`Geo2DQuery`、`Geo2DParallel`、`GeometryContext` 已承担这部分职责。常见能力包括：

- 命中测试
- 距离测量
- 最近点
- 点位投影
- 批量查询

---

## 6. 图元专用算法层

图元专用算法应只保留轻量入口，例如：

- `getBBox()`
- `transform()`
- `isValid()`
- `clone()`

复杂逻辑应下沉到几何服务类，不应堆在图元对象里。

---

## 7. 编辑 / 离散 / 分析算法层

编辑和分析算法应继续和命令系统分离，保持“算法只做算法、命令只做编排”的边界。

---

## 8. 当前维护原则

- 算法只放一处
- UI 不直接写几何逻辑
- 图元类保持轻量
- 新能力优先复用现有几何服务
