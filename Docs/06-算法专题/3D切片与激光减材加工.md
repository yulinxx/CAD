# 3D 切片与激光减材加工流程

> **文档定位**：3D 模式下「对三维图形分层切片 → 每片生成刀路 → 输出给激光设备做减材加工」的完整流程设计。
>
> **适用范围**：本文档是 `Engraving` 子模块（算法层）与上层调用方（Main / UI3D / 外部 C 客户端）之间**唯一**的契约文档。
>
> **同步约定**：本文档、代码注释、运行时日志、测试用例四者必须保持一致。任何流程/接口改动须先改本文档，再改代码与测试。
>
> **更新日期**：2026-10-27

## 1. 目标与整体思路

### 1.1 业务目标

| 阶段 | 输入 | 输出 | 说明 |
|------|------|------|------|
| ① 切片 | 三角网格（3D 图形） | 每层闭合轮廓 + 层高列表 | 固定层厚、显式层数或按表面斜率自适应切分，得到可加工的 2.5D 轮廓 |
| ② 刀路 | 每层轮廓 | 轮廓刀路 + 填充刀路 | 轮廓走边切割、光栅或轮廓平行填充去除层内材料，可叠加引入/引出、层内排序与多道次 |
| ③ 加工 | 全部层刀路 | 激光设备指令 / 中间文件 | 逐层焦点下移，执行**减材加工**（层间材料逐层去除） |

激光减材加工的核心物理模型：**每一层 Z 高度对应激光焦平面**，该层内只烧蚀「当前层轮廓/填充区间」内的材料，Z 向每完成一层下移一个 `layerHeight`，直至把三维图形「从毛坯中雕刻出来」。

### 1.2 整体思路

```
┌────────────────────────────────────────────────────────────────┐
│                        上层调用方（UI / 外部程序）              │

│                                                                │

│   └───────────────┬────────────────────────────────────┘       │
│                   ▼                                            │
│   ┌────────────────────────────────────────────────────┐       │
│   │ ② C++ 服务门面 EngravingAPI / 加工器               │       │

│   │    PolygonOffset（轮廓平行填充）                      │       │
│   │    LeadInOut / ToolpathOrder（工艺后处理）             │       │
```

分层原则（低耦合 / 封装性 / UI 算法分离）：

- **UI 与算法分离**：算法层（Engraving.dll）只依赖 C++17 + OpenCV，**不依赖 Qt、不依赖 Log 模块、不依赖任何 UI**。UI 只负责收集输入（选网格、填参数）与展示结果。
- **对外契约唯一**：跨模块/跨语言调用统一走 `EngravingCAPI.h`（纯 C ABI）；C++ 内部各 DLL 之间允许用 `ENGRAVING_API` 标注的 C++ 类。
- **单向依赖**：`上层调用方 → C API → C++ 服务 → 算法核心`，禁止反向依赖。

## 3. 切片流程设计（① 切片）

### 3.1 数据流

```
三角网格 TriangleMesh
   │  sliceMeshAtZ(mesh, z, planeEpsilon)
   ▼
切片线段 SliceSegment[]          ← 逐三角面与 Z 平面求交
   │  connectSegmentsToContours(segments, weldEpsilon)
   ▼
闭合轮廓 Contour[]（XY 平面）    ← 端点焊接 + 追踪成环 + 去重 + 定向
   │
   ├── 轮廓刀路：沿环走边，回到起点
   └── 填充刀路：fillContoursScanline 旋转扫描线光栅填充
                或 fillContoursContourParallel 轮廓平行内缩填充
```

- 只有真正回到起点的闭合环才会进入后续刀路；开口链、零面积环和逐点重复的环会被丢弃并记录告警。
- 轮廓方向统一为：外环逆时针（CCW），孔洞顺时针（CW）。

### 3.2 层高计算

- Z 范围由网格 AABB 的 `[minZ, maxZ]` 确定（或调用方显式指定裁剪框）。
- **显式层数**：`numLayers > 0` 时按该层数等分 Z 范围，`layerThickness = zRange / numLayers`；此时忽略 `adaptiveLayerHeight`。
- **固定层厚**：`numLayers <= 0` 且未启用自适应时按 `layerHeight` 计算层数：
  `numLayers = max(1, ceil(zRange / layerHeight))`，最后一层按剩余高度裁剪。
- **自适应层厚（3D 网格）**：`numLayers <= 0` 且 `adaptiveLayerHeight=true` 时，按三角面法向 Z 分量细分：
  `cusp = 层厚 × |n_z|`，某层允许的最大层厚为 `adaptiveCuspHeight / |n_z|`；结果夹在
  `[minLayerHeight, layerHeight]` 内。水平面取最薄层，垂直面可取最厚层；最后一层不足
  `minLayerHeight` 时并入当前层，避免碎片层。无有效三角面或参数非法时回退固定层厚。
- **自适应层厚（2.5D 高度图）**：同一开关下按高度图梯度分箱统计：
  `cusp = 层厚 / sqrt(1 + |∇h|²)`，允许层厚为 `adaptiveCuspHeight × sqrt(1 + |∇h|²)`，
  同样夹在 `[minLayerHeight, layerHeight]`。查询候选层区间时取区间内最大梯度；显式层数仍然优先。
- **多道次**：`passesPerLayer` 表示同一层重复加工的完整遍数，夹在 `[1, 100]`。重复遍不改变 Z、
  层高列表或层数，只把该层已生成的轮廓/填充/空走刀路整组重复；单层预览不重复。
- **切片平面**：每层取该层薄片的中截面，`heights[i] = (slabStart + slabEnd) / 2`，
  避免首层落在 `minZ` 相切面上产生空层/退化轮廓；返回列表始终为 Z 升序。
- **减材方向**：`bottomUp=true` 时从 `minZ` 向上逐层加工（先开粗底部再向上，材料自下而上剥离）；`bottomUp=false` 时从 `maxZ` 向下（表层先行，逐层下移焦点）。该参数只改变加工顺序，不改变层高列表。
- **2.5D 高度图**：`LayeredProcessing` 与上述规则一致（`numLayers > 0` 显式覆盖；否则固定层厚或自适应），层平面同样取薄片中心，不做额外偏移。
- 点云输入当前不生成刀路，仅参与包围盒计算；无序点列无法可靠转换为激光加工路径。

### 3.3 关键容差

| 参数 | 默认值 | 用途 |
|------|--------|------|
| `planeEpsilon` | `1e-5f` | 顶点共面 / 边平行判定 |
| `weldEpsilon` | `1e-4f` | 切片线段端点焊接合并容差 |
| 轮廓去重 | 逐点匹配（容差内） | 只删除几何上完全相同的环，不再使用“周长接近 + 质心接近”的宽松规则 |

### 3.4 数值健壮性要点

- 顶点坐标含 NaN/Inf 的三角面直接跳过。
- 三角面整体位于切片平面（`onCount == 3`）时跳过，避免退化线段。
- 顶点恰在平面上时按共边/单点分支处理，每面最多产生一条线段。
- 端点焊接使用 3×3 邻域量化网格查找，降低端点恰好落在网格边界时断链的概率。
- 追踪到开口链时整条链丢弃，禁止用“首尾补弦”方式强行闭合。
- 闭合环仅在首尾为同一焊接顶点时成立；去除重复尾点后要求至少 3 个点且面积非零。
- 非流形顶点（多个环在同一点相切）按“最左转”选择下一条未访问边，保证追踪贴着同一面，避免把两个相切环拼成一个错误轮廓。

## 4. 刀路生成设计（② 刀路）

### 4.1 刀路数据模型

`ToolpathPoint { x, y, z, power, speed }`：

- `power`：激光功率 0~100%，**0 表示关光/抬刀移动**（用于行间空走）。
- `speed`：扫描速度 mm/s。
- 一条 `Toolpath` 为一串有序点；`ToolpathList` 为多条（通常一层 = 轮廓多条 + 填充多条）。
- 相邻加工路径之间会插入**两点空走路径**：起点为前一路径终点，终点为后一路径起点，`power=0`、速度沿用 `scanSpeed`。该空走路径同样占 `ToolpathList` 中的一项，上层的 `showTravelMoves` 可据此预览。

**带类型刀路** `TaggedToolpathList { paths, kinds, layerIndices }`：

- 三个数组等长、同序；新增元数据不改变 `ToolpathList` 布局，旧接口（`generateToolpath` 等）继续可用。
- `ToolpathKind`：`Contour = 0`（轮廓）、`Fill = 1`（填充）、`Travel = 2`（空走/关光）。
- `layerIndex` 从 0 开始；`-1` 表示未分层（如单层预览未指定层号）。
- 旧数据缺少元数据时，`kindAt()` 按首点功率推断（`power≈0` 视为空走），`layerIndexAt()` 返回 `-1`。
- C ABI 侧对应 `EngravingTaggedToolpathList`（见 6.2）。

### 4.2 轮廓刀路

对每个闭合环逐点走边，回到起点闭合：
```
path: P0→P1→...→Pn→P0，每个点 power=laserPower
```
`includeContour=false` 时跳过轮廓，仅生成填充；轮廓刀路在需要时先做 Douglas-Peucker 简化，再应用引入/引出。

### 4.3 填充刀路

`includeFill=false` 时跳过填充。`useRaster=true` 走扫描线光栅填充；`useRaster=false` 走轮廓平行填充。

#### 4.3.1 光栅扫描（`fillContoursScanline`）

1. 以填充包围盒中心为原点，把轮廓变换到局部坐标系 `(u, v)`，`u` 沿扫描线方向；
2. 用包围盒四角确定局部 `v` 范围，按 `lineSpacing`（= `spotSize × (1 − overlapRatio)`）生成平行扫描线；
3. 每条扫描线只求交一次，对交点排序后按奇偶规则配对，得到轮廓内填充区间；
4. 同一扫描线上的区间按 `u` 合并，避免轮廓重叠导致重复烧蚀；
5. 区间反变换回世界坐标，奇偶行交替方向（蛇形），减少空走；
6. 每个填充段前后插入 `power=0` 关光点，避免行间/段间连续出光。

#### 4.3.2 轮廓平行填充（`fillContoursContourParallel`）

1. 直接消费切片轮廓（外环 CCW / 孔洞 CW），方向不限的环先按 EvenOdd 归一化为带孔区域；
2. 以 `lineSpacing` 为间距，用 Clipper2 `InflatePaths` 每轮向内偏移，得到外→内的闭合填充环；
3. 每条偏移环单独成为一条 `Fill` 刀路，环间由第 4.4 节的关光空走连接；
4. 区域过小、参数非法或偏移后为空时停止；迭代上限按区域跨度/间距推算，避免死循环。

与光栅填充相比，轮廓平行填充的空走更短、切削负载更均匀，适合薄壁/复杂孔洞；光栅填充更适合大面积快速去除。

### 4.4 路径间空走

`VolumeProcessing` 与 `LayeredProcessing` 在组装完成后统一插入空走：

- 轮廓→填充、填充→下一层轮廓、层与层之间均生成 `power=0` 的两点路径；
- 起点/终点分别复用前一路径末点与后一路径首点，避免额外抬刀坐标偏差；
- 起终点完全重合时不插入，防止零长度路径；
- 带类型输出中，空走条目的 `kind=Travel`，并继承当前层索引；排序（4.6）会丢弃空走条目后重新插入。

### 4.5 引入/引出（`LeadInOut`）

参数：`enableLeadInOut`、`leadInLength`、`leadOutLength`、`leadInRampAngle`。

- 只对切削刀路生效（首点 `power > 0`）；空走刀路原样返回。
- **引入**：沿起始切线反方向延伸 `leadInLength`，新增点 `power=0`，由上层先快移到该点，再以原首点功率切入。`leadInRampAngle > 0` 时引入点 Z 抬高 `leadInLength × tan(angle)`，角度夹在 `[0, 80]°`，切入段保持出光并沿 Z 下降；`0` 表示水平引入。
- **引出**：沿末端切线延伸 `leadOutLength`，功率沿用末端功率。
- 长度 ≤ 0、路径少于 2 点或起终点重合导致切线无效时不添加对应段。
- G-code 导出时引入段必须是带 Z 的 `G1`；禁止 `M5 + G0` 原地下扎，否则斜坡引入会退化成垂直扎刀（见 `ToolpathExporter` 注释与回归测试）。

### 4.6 层内路径排序（`ToolpathOrder`）

`enablePathOrdering=true` 时，对每层切削刀路做最近邻排序：

- 以 `(startX, startY, startZ)` 为当前位置，反复选择起点最近的刀路，走完后以末点为新当前位置；
- 按层索引分组，组间保持首次出现顺序，组内独立排序；
- 只调整刀路顺序，不改变每条刀路内部的点序、类型或层索引；
- 空刀路丢弃；传入列表应为切削刀路，空走条目在排序后由组装逻辑重新插入。

### 4.7 多道次（`passesPerLayer`）

- 同一层重复加工 `passesPerLayer` 遍，夹在 `[1, 100]`；默认 `1` 保持旧行为。
- 只重复该层已生成的完整刀路组（轮廓+填充+空走），**不改变 Z、层高列表或层数**。
- 单层预览（`generateLayerToolpath` / `generateTaggedLayerToolpath`）不重复，避免预览与实际全量输出不一致时产生误导。

### 4.8 工艺参数（策略模式）

`LaserStrategy`（接口）→ `DefaultStrategy`（默认实现）：

| 方法 | 作用 |
|------|------|
| `adjustParams(base, material)` | 按材料（wood/metal/acrylic 等）调整功率/速度/层厚 |
| `calculateLineSpacing(params)` | 填充线间距 |
| `calculateNumLayers(range, params)` | 层数 |
| `needsLayeredProcessing(maxH, params)` | 是否需分层 |

`ProcessingParams` 在原有字段上新增：引入/引出（`enableLeadInOut`、`leadInLength`、`leadOutLength`、`leadInRampAngle`）、层内排序（`enablePathOrdering`）、多道次（`passesPerLayer`）、自适应层厚（`adaptiveLayerHeight`、`minLayerHeight`、`adaptiveCuspHeight`）。默认值均保持旧行为。

策略可注入到 `VolumeProcessing` / `LayeredProcessing`，**替换策略不改算法本体**。

## 5. 激光减材加工（③ 加工）

### 5.1 加工语义

| 环节 | 说明 |
|------|------|
| 逐层出光 | 每一层只烧蚀该层轮廓/填充区间内的材料，Z 值 = 该层焦平面高度 |
| 焦点控制 | 每完成一层，Z 下移 `layerHeight`，实现层间材料逐层去除（减材） |
| 轮廓先行 | `includeContour=true` 时先切轮廓，界定该层材料边界 |
| 填充去除 | `includeFill=true` 时对轮廓内部做光栅或轮廓平行扫描，去除层内残余材料 |
| 工艺后处理 | 可选引入/引出、层内最近邻排序、多道次；默认关闭/1 遍，保持旧行为 |
| 空走关光 | 行间/段间及路径切换均为 `power=0`，不产生烧蚀 |

### 5.2 输出形式

1. **内存**：`EngravingToolpathList`（V1）或 `EngravingTaggedToolpathList`（V2，带类型/层索引）——供上层直接预览/下发。
2. **G-code（算法层）**：`ToolpathExporter` 提供安全后处理：
   - 方言：`Generic` / `GRBL` / `LinuxCNC` / `Marlin` / `LightBurn` / `Custom`（自定义回调）；
   - 安全 Z（`safeZ`）、快移速度（`rapidSpeed`，mm/min）、`G0/G1` 模态输出；
   - 激光 `M3/M4` + `S` 值（PWM 0~`laserPowerMaxPwm` 或百分比）、开/关光延时；
   - `exportTaggedGcode` 在程序头部写层号与 `kind=contour|fill|travel` 注释，控制器忽略 `;` 行；
   - `enablePowerRamping` / `powerRampUpDist` / `powerRampDownDist` / `minPowerPwm` 已预留，当前仅记录意图，尚未做路径分段功率爬升。
3. **JSON / 简易 G-code（UI3D）**：`ReliefToolpathExporter3D` 导出 `schemaVersion=2` 的 JSON：`process`（材料/模式/几何范围/引入引出/排序）、`estimate`（切削/空走/总时间与假设快移/安全 Z）、`layerHeights`、`paths`（`kind`、`layerIndex`、`z`、`stats`、`points`）、`layers`（每层类型计数与统计），并保留旧版 `toolpaths` 点数组以兼容旧读取器。简易 G-code 带工艺头注释、安全 Z、层号/类型注释与时间预估。
4. **设备**：3D 侧不下发。导出的刀路文件由 2D 工作台导入后经硬件模块执行（`ReliefHardwareDispatcher3D` 已于 2026-08-26 删除）。

> 算法层不负责文件格式与硬件协议，只保证输出**坐标/功率/速度/开关光语义**正确的刀路，保持职责单一、低耦合；UI3D 的 JSON/G-code 导出属于展示与交付层。

> **视口预览现状（2026-10-27）**：算法侧单层预览（`VolumeGenerateLayer` / `VolumeGenerateTaggedLayer`）是真实现，但 3D 视口的刀路覆盖层 `RenderWidget3D::setToolpathOverlay` 仍是空壳（数据被丢弃、`hasToolpathOverlay()` 恒 false）。浮雕对话框 "Preview Layer" 因此只给出段数统计并明确告知"视口中不会绘制"，不再报误导性的 "Preview updated"。落地方案（深拷贝进成员 vector → GL_LINES VBO + 纯色 shader → `paintGL` 中图元之后 gizmo 之前绘制、深度写关）写在 `UI/3D/Src/Render/RenderWidget3D.cpp` 空壳区注释中，属纯渲染改动，不涉及算法与硬件。

| 规范 | 落实 |
|------|------|

## 7. 日志设计（横切关注点）

### 7.1 设计约束

- **零外部依赖**：Engraving.dll 不链接 Log 模块（保持算法层独立），日志走**可插拔回调**。
- 调用方（Main / UI）通过 `Engraving_SetLogCallback` 注入回调，内部实现转发到上层 `SyLogger`；无回调时日志为 no-op，零开销。
- 回调为 C 函数指针 + `void* userData`，符合 DLL 导出规范第 41 条。

### 7.2 日志级别与宏

| 级别 | 宏 | 典型场景 |
|------|-----|----------|
| Trace | `ENG_LOG_TRACE` | 内部数值细节 |
| Debug | `ENG_LOG_DEBUG` | 单层切片/单层刀路统计 |
| Info | `ENG_LOG_INFO` | 流程阶段起止（切片开始、N 层生成完成） |
| Warn | `ENG_LOG_WARN` | 输入退化（空网格、空轮廓、图片加载失败） |
| Error | `ENG_LOG_ERROR` | 异常捕获、内部错误 |

### 7.3 打点位置

| 源文件 | 打点 |

## 11. 文档 / 代码 / 日志 / 注释同步规范

1. **先文档后代码**：任何流程或接口调整，先更新本文档，再改代码。
2. **注释即文档**：头文件用 Doxygen 风格注释描述每个结构/函数/参数；注释与实现必须一致。
3. **日志与代码同行**：新增分支/错误路径必须伴随 `ENG_LOG_*` 打点，日志消息与注释/文档用语一致。
4. **测试即契约**：每个对外接口至少有一个测试用例覆盖其成功与失败路径；接口签名变更必须同步修改测试。
5. **版本联动**：对外 ABI 变化时同步递增 `Engraving_GetVersion()` 与 CMake `VERSION_*`。
