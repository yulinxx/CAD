# 3D 切片与激光减材加工流程

> **文档定位**：3D 模式下「对三维图形分层切片 → 每片生成刀路 → 输出给激光设备做减材加工」的完整流程设计。
>
> **适用范围**：本文档是 `Engraving` 子模块（算法层）与上层调用方（Main / UI3D / 外部 C 客户端）之间**唯一**的契约文档。
>
> **同步约定**：本文档、代码注释、运行时日志、测试用例四者必须保持一致。任何流程/接口改动须先改本文档，再改代码与测试。
>
> **更新日期**：2026-08-16

---

## 1. 目标与整体思路

### 1.1 业务目标

| 阶段 | 输入 | 输出 | 说明 |
|------|------|------|------|
| ① 切片 | 三角网格（3D 图形） | 每层闭合轮廓 + 层高列表 | 沿 Z 轴等厚切分，得到可加工的 2.5D 轮廓 |
| ② 刀路 | 每层轮廓 | 轮廓刀路 + 填充刀路 | 轮廓走边切割、光栅扫描填充去除层内材料 |
| ③ 加工 | 全部层刀路 | 激光设备指令 / 中间文件 | 逐层焦点下移，执行**减材加工**（层间材料逐层去除） |

激光减材加工的核心物理模型：**每一层 Z 高度对应激光焦平面**，该层内只烧蚀「当前层轮廓/填充区间」内的材料，Z 向每完成一层下移一个 `layerHeight`，直至把三维图形「从毛坯中雕刻出来」。

### 1.2 整体思路

```
┌────────────────────────────────────────────────────────────────┐
│                        上层调用方（UI / 外部程序）              │
│   Main 3D 工作台 | UI3D Relief 工作流 | C#/Python 客户端       │
└──────────────┬───────────────────────────────────────────────┘
               │ 仅通过 EngravingCAPI.h（C ABI）或 C++ API 调用
               ▼
┌────────────────────────────────────────────────────────────────┐
│                      Engraving.dll （算法层）                  │
│                                                                │
│   ┌────────────────────────────────────────────────────┐       │
│   │ ① C API 门面  EngravingCAPI.h/.cpp                │       │
│   │    纯 C 头 / POD 结构 / 类型安全句柄 / 日志回调     │       │
│   └───────────────┬────────────────────────────────────┘       │
│                   ▼                                            │
│   ┌────────────────────────────────────────────────────┐       │
│   │ ② C++ 服务门面 EngravingAPI / 加工器               │       │
│   │    VolumeProcessing / LayeredProcessing             │       │
│   └───────────────┬────────────────────────────────────┘       │
│                   ▼                                            │
│   ┌────────────────────────────────────────────────────┐       │
│   │ ③ 算法核心                                            │       │
│   │    MeshSlicer（切片+轮廓+填充）                      │       │
│   │    LaserStrategy（工艺参数策略）                     │       │
│   │    HeightMap（2.5D 高度图）                          │       │
│   └───────────────┬────────────────────────────────────┘       │
│                   ▼                                            │
│   ┌────────────────────────────────────────────────────┐       │
│   │ ④ 横切关注点                                          │       │
│   │    EngravingLog（可插拔日志回调，零外部依赖）         │       │
│   └────────────────────────────────────────────────────┘       │
└────────────────────────────────────────────────────────────────┘
```

分层原则（低耦合 / 封装性 / UI 算法分离）：

- **UI 与算法分离**：算法层（Engraving.dll）只依赖 C++17 + OpenCV，**不依赖 Qt、不依赖 Log 模块、不依赖任何 UI**。UI 只负责收集输入（选网格、填参数）与展示结果。
- **对外契约唯一**：跨模块/跨语言调用统一走 `EngravingCAPI.h`（纯 C ABI）；C++ 内部各 DLL 之间允许用 `ENGRAVING_API` 标注的 C++ 类。
- **单向依赖**：`上层调用方 → C API → C++ 服务 → 算法核心`，禁止反向依赖。

## 3. 切片流程设计（① 切片）

### 3.1 数据流

```
三角网格 TriangleMesh
   │  sliceMeshAtZ(mesh, z, planeEpsilon)
   ▼
切片线段 SliceSegment[]          ← 逐三角面与 Z 平面求交
   │  connectSegmentsToContours(segments, weldEpsilon)
   ▼
闭合轮廓 Contour[]（XY 平面）    ← 端点量化焊接 + 追踪成环 + 去重
   │
   ├── 轮廓刀路：沿环走边，回到起点
   └── 填充刀路：fillContoursScanline 旋转扫描线光栅填充
```

### 3.2 层高计算

- Z 范围由网格 AABB 的 `[minZ, maxZ]` 确定（或调用方显式指定裁剪框）。
- 层数：`LaserStrategy::calculateNumLayers(heightRange, params)`，默认 `ceil(heightRange / layerHeight)`。
- 层高列表：`heights[i] = minZ + i * layerThickness`，`layerThickness = heightRange / numLayers`。
- **减材方向**：`bottomUp=true` 时从 `minZ` 向上逐层加工（先开粗底部再向上，材料自下而上剥离）；`bottomUp=false` 时从 `maxZ` 向下（表层先行，逐层下移焦点）。

### 3.3 关键容差

| 参数 | 默认值 | 用途 |
|------|--------|------|
| `planeEpsilon` | `1e-5f` | 顶点共面 / 边平行判定 |
| `weldEpsilon` | `1e-4f` | 切片线段端点焊接合并容差 |
| 周长去重 | 5% | 近似重复轮廓去重阈值 |

### 3.4 数值健壮性要点

- 三角面整体位于切片平面（`onCount == 3`）时跳过，避免退化线段。
- 顶点恰在平面上时按共边/单点分支处理，每面最多产生一条线段。
- 闭合环判定首尾距离 ≤ `weldEpsilon` 时去除重复尾点。

## 4. 刀路生成设计（② 刀路）

### 4.1 刀路数据模型

`ToolpathPoint { x, y, z, power, speed }`：

- `power`：激光功率 0~100%，**0 表示关光/抬刀移动**（用于行间空走）。
- `speed`：扫描速度 mm/s。
- 一条 `Toolpath` 为一串有序点；`ToolpathList` 为多条（通常一层 = 轮廓多条 + 填充多条）。

### 4.2 轮廓刀路

对每个闭合环逐点走边，回到起点闭合：
```
path: P0→P1→...→Pn→P0，每个点 power=laserPower
```

### 4.3 填充刀路（光栅扫描）

`fillContoursScanline` 算法步骤：

1. 以层包围盒对角线为扫描范围，按 `lineSpacing`（= `spotSize × (1 − overlapRatio)`）生成平行扫描线；
2. 每条扫描线按 `rasterAngle` 旋转映射到世界坐标；
3. 沿扫描线采样，求与所有轮廓的 X 交点，奇偶配对得到轮廓内填充区间；
4. 奇偶行交替方向（蛇形），减少空走；
5. 段首/段尾插入 `power=0` 关光点，避免行间连续出光。

### 4.4 工艺参数（策略模式）

`LaserStrategy`（接口）→ `DefaultStrategy`（默认实现）：

| 方法 | 作用 |
|------|------|
| `adjustParams(base, material)` | 按材料（wood/metal/acrylic 等）调整功率/速度/层厚 |
| `calculateLineSpacing(params)` | 填充线间距 |
| `calculateNumLayers(range, params)` | 层数 |
| `needsLayeredProcessing(maxH, params)` | 是否需分层 |

策略可注入到 `VolumeProcessing` / `LayeredProcessing`，**替换策略不改算法本体**。

## 5. 激光减材加工（③ 加工）

### 5.1 加工语义

| 环节 | 说明 |
|------|------|
| 逐层出光 | 每一层只烧蚀该层轮廓/填充区间内的材料，Z 值 = 该层焦平面高度 |
| 焦点控制 | 每完成一层，Z 下移 `layerHeight`，实现层间材料逐层去除（减材） |
| 轮廓先行 | `includeContour=true` 时先切轮廓，界定该层材料边界 |
| 填充去除 | `includeFill=true` 时对轮廓内部做光栅扫描，去除层内残余材料 |
| 空走关光 | 行间/段间移动点 `power=0`，不产生烧蚀 |

### 5.2 输出形式

1. **内存**：`EngravingToolpathList`（`EngravingCAPI.h` 定义）——供上层直接预览/下发。
2. **文件**：由上层 `ReliefToolpathExporter3D`（UI3D）导出 JSON 或简化 G-code（`.nc/.gcode`）。
3. **设备**：3D 侧不下发。导出的刀路文件由 2D 工作台导入后经硬件模块执行（`ReliefHardwareDispatcher3D` 已于 2026-08-26 删除）。

> 算法层不负责文件格式与硬件协议，只保证输出**坐标/功率/速度/开关光语义**正确的刀路，保持职责单一、低耦合。

> **视口预览现状（2026-08-26）**：算法侧单层预览（`VolumeGenerateLayer`）是真实现，但 3D 视口的刀路覆盖层 `RenderWidget3D::setToolpathOverlay` 仍是空壳（数据被丢弃、`hasToolpathOverlay()` 恒 false）。浮雕对话框 "Preview Layer" 因此只给出段数统计并明确告知"视口中不会绘制"，不再报误导性的 "Preview updated"。落地方案（深拷贝进成员 vector → GL_LINES VBO + 纯色 shader → `paintGL` 中实体之后 gizmo 之前绘制、深度写关）写在 `UI/3D/Src/Render/RenderWidget3D.cpp` 空壳区注释中，属纯渲染改动，不涉及算法与硬件。

## 6. C API 门面设计（DLL 导出收口）

> 遵循 `Docs/01-当前架构/DLL制作标准与现状.md`：优先 C 接口、纯 POD 传输、类型安全不透明句柄、谁分配谁释放、异常不跨边界、版本查询、日志回调。

### 6.1 文件

| 文件 | 类型 | 说明 |
|------|------|------|
| `EngravingExport.h` | 纯 C 头 | `ENGRAVING_API`（符号可见性）+ `ENGRAVING_C_API`（extern "C"） |
| `EngravingCAPI.h` | 纯 C 头 | 全部对外函数 / POD 结构 / 枚举 / 句柄声明 |
| `EngravingCAPI.cpp` | 实现 | POD⇆内部类型转换、句柄生命周期、异常兜底、thread_local 错误信息 |

### 6.2 POD 结构（跨 DLL 安全）

| 结构 | 关键字段 |
|------|----------|
| `EngravingParams` | 功率/速度/光斑/层厚/重叠率/层数/光栅角/开关光 + `structSize`（ABI 校验） |
| `EngravingMesh` | 扁平顶点数组 `const float*`（每三角面 9 个 float）+ `triangleCount` |
| `EngravingPoint` | `x y z` |
| `EngravingSliceSegment` | `a b` 两点 |
| `EngravingContour` | 点数组 + 点数 |
| `EngravingToolpathPoint` | `x y z power speed` |
| `EngravingToolpath` | 点数组 + 点数 |
| `EngravingToolpathList` | 路径数组 + 条数 |

### 6.3 函数分组

| 分组 | 函数 | 说明 |
|------|------|------|
| 版本 | `Engraving_GetVersion` / `GetVersionString` | ABI 兼容检查 |
| 日志 | `Engraving_SetLogCallback(cb, userData)` / `Engraving_SetLogLevel` | 可插拔日志回调（线程安全） |
| 参数 | `Engraving_InitParams` | 填充默认值 + `structSize` |
| 网格 | `Engraving_ComputeMeshBoundingBox` | AABB 查询 |
| 切片 | `Engraving_SliceMesh` | 单层切片线段（`Engraving_FreeArray` 释放） |
| 轮廓 | `Engraving_ConnectContours` | 线段→闭合轮廓（`Engraving_ContourListFree` 释放） |
| 加工器句柄 | `Engraving_VolumeCreate` / `Destroy` | 生命周期；`struct EngravingVolumeImpl*` 类型安全句柄 |
| 加工器配置 | `VolumeSetMesh` / `VolumeSetPointCloud` / `VolumeSetParams` / `VolumeSetBoundingBox` / `VolumeGetBoundingBox` | 输入与参数 |
| 加工器执行 | `VolumeComputeLayerHeights` / `VolumeGenerate` / `VolumeGenerateLayer` | 层高、全量刀路、单层预览 |
| 内存 | `Engraving_FreeArray` / `Engraving_ToolpathListFree` / `Engraving_ContourListFree` | 谁分配谁释放 |
| 错误 | `Engraving_GetLastErrorMessage` | thread_local，线程安全 |

### 6.4 DLL 导出规范落实点

| 规范 | 落实 |
|------|------|
| 纯 C 接口 | `EngravingCAPI.h` 为纯 C 头，无任何 C++ 语法/STL |
| 类型安全句柄 | `struct EngravingVolumeImpl*`，非 `void*` |
| POD 传输 | 所有跨 DLL 数据为 POD 结构体 + `const T*` + count |
| 谁分配谁释放 | DLL 内 `malloc` 的数组一律由 `Engraving_FreeArray` 等释放 |
| 异常不跨边界 | 每个导出函数 `try/catch(...)`，返回错误码 |
| 参数前置校验 | 每个导出函数第一行校验空指针/非法值 |
| 版本号 | `Engraving_GetVersion()` |
| 结构体大小校验 | `EngravingParams.structSize` 与 `sizeof` 比对 |
| 错误码枚举 | `EngravingResultCode`，0 = 成功，负数 = 各类失败 |
| 线程安全 | `thread_local` 错误信息；日志回调原子存储 |

## 7. 日志设计（横切关注点）

### 7.1 设计约束

- **零外部依赖**：Engraving.dll 不链接 Log 模块（保持算法层独立），日志走**可插拔回调**。
- 调用方（Main / UI）通过 `Engraving_SetLogCallback` 注入回调，内部实现转发到上层 `SyLogger`；无回调时日志为 no-op，零开销。
- 回调为 C 函数指针 + `void* userData`，符合 DLL 导出规范第 41 条。

### 7.2 日志级别与宏

| 级别 | 宏 | 典型场景 |
|------|-----|----------|
| Trace | `ENG_LOG_TRACE` | 内部数值细节 |
| Debug | `ENG_LOG_DEBUG` | 单层切片/单层刀路统计 |
| Info | `ENG_LOG_INFO` | 流程阶段起止（切片开始、N 层生成完成） |
| Warn | `ENG_LOG_WARN` | 输入退化（空网格、空轮廓、图片加载失败） |
| Error | `ENG_LOG_ERROR` | 异常捕获、内部错误 |

### 7.3 打点位置

| 源文件 | 打点 |
|--------|------|
| `MeshSlicer.cpp` | 切片段数、轮廓数、填充点数的 Debug 统计 |
| `VolumeProcessing.cpp` | 层高列表、逐层生成 Info/Debug |
| `LaserStrategy.cpp` | 材料参数调整 Debug |
| `HeightMap.cpp` | 加载成败 Warn/Info |
| `LayeredProcessing.cpp` | 分层与逐层路径 Info/Debug |
| `EngravingImageAPI.cpp` | 图像读取失败 Warn |
| `EngravingCAPI.cpp` | 入参非法 Warn、异常 Error |

## 11. 文档 / 代码 / 日志 / 注释同步规范

1. **先文档后代码**：任何流程或接口调整，先更新本文档，再改代码。
2. **注释即文档**：头文件用 Doxygen 风格注释描述每个结构/函数/参数；注释与实现必须一致。
3. **日志与代码同行**：新增分支/错误路径必须伴随 `ENG_LOG_*` 打点，日志消息与注释/文档用语一致。
4. **测试即契约**：每个对外接口至少有一个测试用例覆盖其成功与失败路径；接口签名变更必须同步修改测试。
5. **版本联动**：对外 ABI 变化时同步递增 `Engraving_GetVersion()` 与 CMake `VERSION_*`。
