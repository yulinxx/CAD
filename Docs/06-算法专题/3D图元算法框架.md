# 3D 图元算法框架

> 本文档用于设计和组织 `SyMeshEntity` 体系的底层三维算法。
>
> 目标是建立一套与 2D 图元算法框架（见 `Docs/06-算法专题/2D图元算法框架.md`）**同构、同分层、同收口风格**的三维算法框架，便于后续对 3D 模型进行拾取、测量、分析、编辑、离散、修复等处理。
>
> 核心原则：**算法与 UI 分离、低耦合、统一容差、一个算法一个权威实现、图元类保持轻量**。

---

## 1. 为什么 3D 也需要独立算法框架

`SyMeshEntity` 是当前 3D 唯一的图元类型（非索引三角网格，`vertices` 每 3 个一组构成三角形），后续会累积大量算法，例如：

- 拾取命中（射线与网格求交）
- 点到网格最近点 / 最近距离
- 表面积、体积、质心、包围盒
- 水密性 / 封闭性 / 流形性判断
- 法向一致性 / 朝向统一 / 法向重建
- 顶点焊接 / 去退化三角形 / 去重复三角形 / 网格清理
- 自相交检测
- 边界边提取、连通分量拆分
- 表面均匀采样、面质心采样、线框提取
- 网格变换、合并、细分（后续）

如果这些算法散落在命令类、UI 工具、加载器里，会出现与 2D 完全相同的后果：重复实现、命名混乱、依赖循环、改一处坏一片、代码膨胀。

所以必须与 2D 一样，从一开始就组织成有层次、有收口服务的框架。

---

## 2. 总体设计目标

### 2.1 目标一：算法独立于 UI

3D 算法全部位于 `Engine3D` 模块，不依赖：
- 菜单 / 工具条 / 视口
- 鼠标事件 / Qt 事件对象
- 渲染管线 / GPU 数据

UI 只负责调用，不负责定义算法本体。拾取、框选、测量等一律收口到 Engine 侧服务类。

### 2.2 目标二：算法可复用

例如：
- 点到三角形最近点：被拾取命中、距离测量、拖拽吸附复用
- 射线-三角形求交：被拾取、遮挡判断、点包含判定复用
- 顶点焊接：被网格清理、法向统一、拓扑分析复用
- 边拓扑：被水密性判断、边界提取、连通分量、朝向统一复用

### 2.3 目标三：算法分层，不要平铺

与 2D 一致，采用五层结构（见第 3 节）。不要把算法塞进 `SyMeshEntity`，也不要都堆进一个超级工具类。

### 2.4 目标四：先有基础算法，再叠加高级算法

- 先实现点、向量、线段、平面、射线、三角形的基础计算
- 再实现网格度量、拓扑、焊接、采样
- 最后实现自相交检测、朝向统一、连通拆分等复杂算法

### 2.5 目标五：避免代码膨胀

- 一个算法只放一处
- 其他模块通过调用 / 组合 / 适配复用
- 图元类只保留轻量入口（`getBBox()`、`transform()`、`isValid()`）
- 复杂算法一律下沉到服务类

## 3. 五层分层结构

```text
第一层  基础数学层        Ut::GeomMath + GeometryContext3D（统一容差）
→ 第二层  基础几何层        Geo3DTypes（基本类型）+ Geo3DPrimitives（底层原语）
→ 第三层  通用三维算法层    Geo3DQuery（查询）/ Geo3DAnalysis（分析）/
                           Geo3DSampling（离散采样）/ Geo3DParallel（并发）
→ 第四层  图元专用算法层    MeshAlgorithms（SyMeshEntity 语义薄封装）
→ 第五层  编辑 / 离散 / 分析  Geo3DEdit（编辑）/ Geo3DSampling / Geo3DAnalysis
```

依赖方向严格单向：低层可被高层调用，高层不得反向依赖低层之上的业务逻辑。

---

## 4. 第一层：基础数学层

### 4.1 职责

- 浮点容差比较 — `Ut::GeomMath::isZero()` / `almostEqual()` / `clamp01()`
- 角度转换 / 归一化 — `Ut::GeomMath::degToRad()` / `radToDeg()`
- **3D 统一容差** — `GeometryContext3D`（本框架新增）

### 4.2 统一容差：GeometryContext3D

与 2D `GeometryContext` 同构，采用 5 级分类（3D 使用 `float`，与 `Ut::Vec3f` 精度一致）：

| 字段 | 用途 | 默认值 |
|------|------|--------|
| `dModeling` | 建模容差 — 点重合、共线、平行、共面等高精度判定 | 1e-6f |
| `dTopology` | 拓扑容差 — 顶点焊接、边去重、封闭判定等宽松判定 | 1e-5f |
| `dDiscretize` | 离散容差 — 采样、网格近似最大偏差 | 1e-3f |
| `dPick` | 拾取容差 — 屏幕像素换算后的世界坐标半径 | 1e-3f |
| `dArea` | 面积/体积容差 — 零面积、零体积判定 | 1e-10f |

- 旧 `Geo3DTolerance` 标记 `@deprecated`，通过 `GeometryContext3D::toTolerance()` / `fromTolerance()` 桥接过渡。
- 公开 API 全部提供 `GeometryContext3D` 重载，旧重载保留过渡并标记 `[[deprecated]]`。

### 4.3 这一层不能做什么

- 不能知道 `SyMeshEntity` 的业务语义
- 不能依赖文档、UI、命令状态

## 5. 第二层：基础几何层

### 5.1 应提供的通用基础类型（Geo3DTypes）

- 点 `Ut::Vec3f` / 向量 `Ut::Vec3f`（复用 Utility）
- 射线 `Ray3f`（已有，含 AABB 求交）
- **平面 `Plane3f`**（新增：点 + 单位法向，含 signedDistance/distance）
- **线段 `Segment3f`**（新增：a、b 两端点，含 pointAt/closestPoint/distance）
- **直线 `Line3f`**（新增：点 + 方向，含 projectPoint/distance）
- **球 `Sphere3f`**（新增：中心 + 半径）
- 包围盒 `Ut::BBox3f`（复用 Utility）
- 变换矩阵 `Ut::Mat4f`（复用 Utility）

### 5.2 应提供的核心能力（Geo3DPrimitives）

#### 点 / 线关系
- 点到线段最近点 / 距离（已有）
- 点到无限直线投影点 / 距离（新增）
- 点是否在线段上（带容差，新增）
- 线段与线段最近点 / 距离（新增）

#### 射线 / 三角形 / 平面 / 球
- 射线-三角形求交（已有，Möller–Trumbore）
- 线段-三角形求交（新增，内部复用射线求交 + 参数范围裁剪）
- 三角形-三角形相交判定（新增，边缘求交 + 共面包含）
- 射线-平面求交（新增）
- 射线-球求交（新增）
- 平面构造 / 点到平面距离 / 点投影到平面（新增）

#### 三角形
- 三角形面积 / 法向（已有）
- 点到三角形最近点 / 距离（已有）
- 重心坐标 / 点是否在三角形内（带容差，新增）

#### 包围盒 / 球
- AABB 相交 / 包含（已有）
- 点到 AABB 最近点 / 距离（新增）
- 点在球内判定 / 球相交（新增）

### 5.3 推荐放置位置

```text
Engine/3D/Include/Engine3D/Geometry/Geo3DTypes.h        — 类型、容差、结果结构
Engine/3D/Include/Engine3D/Geometry/Geo3DPrimitives.h   — 底层纯函数算法
Engine/3D/Src/Geometry/Geo3DPrimitives.cpp
```

### 5.4 这一层的原则

- 只描述几何，不描述图元业务
- 不关心拾取、提交、撤销
- 所有网格算法最终都应落回这一层或调用它

## 6. 第三层：通用三维算法层

### 6.1 Geo3DQuery — 查询内核（已有，扩展）

面向 `SyMeshEntity` 的只读查询：

- 度量：`measure()` / `surfaceArea()` / `volume()` / `surfaceCentroid()`
- 射线求交：`raycastMesh()` / `raycastMeshFirst()` / `raycastMeshes()` / `raycastMeshesFirst()`
- 点查询：`closestPointOnMesh()` / `distanceToPoint()` / `hitTest()` / `locatePointInBBox()`
- 空间关系：`bboxIntersects()` / `spatialRelationBBox()` / `intersects()`
- **水密性：`meshIsWatertight()`**（新增，供体积有效性、封闭判定复用）
- **点在网格内：`pointInMesh()`**（新增，水密网格射线奇偶判定）

### 6.2 Geo3DAnalysis — 分析服务（新增）

所有面向 `SyMeshEntity` 的只读分析在此收口：

- 度量：表面积 / 体积 / 表面质心 / 体积质心 / 包围盒 / 综合 `measure()`
- 拓扑：水密性 / 封闭性 / 流形性 / 边界边数 / 非流形边数 / 退化三角形 / 重复顶点 / 法向一致性
- **自相交检测：`isSelfIntersecting()`**（AABB 粗筛 + 三角形对精细判定）
- **连通分量：`connectedComponents()`**（并查集，基于焊接后顶点）
- 点关系：`locatePoint()` / `isInside()` / `isOnSurface()`
- 空间关系：`spatialRelation()` / `intersects()` / `distance()` / `closestPoint()`

### 6.3 Geo3DSampling — 离散采样服务（新增）

- 顶点：`uniqueVertices()` / `uniqueVertexCount()`
- 面：`faceCentroids()` / `faceNormals()` / `face()`
- 边：`edges()` / `boundaryEdges()`（边按焊接后顶点去重，返回共享次数）
- 表面采样：`uniformSurfaceSample()`（按面积加权随机采样）/ `centroidSample()`

### 6.4 Geo3DParallel — 并发批量计算（已有）

- `pickFromCandidates()` / `measureBatch()` / `surfaceAreaBatch()` / `distanceToPointBatch()` / `closestPointBatch()` / `raycastMeshesFirstBatch()`

### 6.5 实现原则

- 通用算法不依赖具体图元之外的东西，输入为网格数据或 `SyMeshEntity*`
- 分析、查询为只读；编辑、采样按语义决定是否修改输入

---

## 7. 第四层：图元专用算法层

### 7.1 SyMeshEntity — 只保留轻量入口

当前 `SyMeshEntity` 已具备：
- 数据字段：`vertices` / `normals` / 材质
- 轻量接口：`getBBox()` / `isValid()` / `triangleCount()` / `transform()` / `translate()` / `scale()` / `clone()`

复杂算法一律委托服务类，不在此类堆函数。

### 7.2 MeshAlgorithms — 图元语义薄封装（新增）

仿照 2D 的 `LineAlgorithms` / `PolygonAlgorithms` 薄包装层，为 `SyMeshEntity` 提供"语义入口"，内部全部委托第三、五层服务：

- 度量 / 拓扑 / 点包含 → `Geo3DAnalysis`
- 最近点 / 距离 / 命中 → `Geo3DQuery`
- 采样 / 边提取 → `Geo3DSampling`
- 焊接 / 清理 / 法向 / 翻转 / 合并 → `Geo3DEdit`

好处：调用方只需记住 `MeshAlgorithms::xxx(mesh, ...)` 一个入口；服务类仍可独立使用。

---

## 8. 第五层：编辑 / 离散 / 分析算法层

### 8.1 Geo3DEdit — 网格编辑服务（新增）

编辑操作为**就地修改**（与 2D 返回克隆不同，因为网格数据量大、语义为数据容器）：

- 顶点编辑：`weldVertices()`（容差内顶点焊接）
- 清理：`removeDegenerateTriangles()` / `removeDuplicateTriangles()` / `clean()`（焊接+去退化+去重）
- 方向 / 法向：`flipWinding()`（翻转环绕并取反法向）/ `computeNormals()`（按面重算法向）/ **`unifyOrientation()`**（连通分量内统一朝向 + 按体积符号定向为外法向）
- 变换：`transform()` / `translate()` / `scale()` / `rotate()`
- 合并：`merge()`（把源网格三角形追加到目标网格）

### 8.2 组织方式建议

- 编辑算法独立于查询 / 分析，避免把"改"和"查"混在一起
- 编辑操作完成后应调用 `mesh->markDirty()` 通知渲染层失效
- 复杂度高的编辑（细分、简化、布尔）后续按专题拆服务，不在 `Geo3DEdit` 无限堆

## 12. 典型算法设计示例

### 12.1 点到网格最近点

- 输入：`SyMeshEntity*` + 点
- 输出：`ClosestPointOnMeshResult{ point, distance, triangleIndex, normal }`
- 实现：遍历三角形调用 `Geo3DPrimitives::closestPointOnTriangle()`，取最小距离
- 复用：命中测试、拖拽吸附、距离测量

### 12.2 射线求交（拾取）

- 输入：`Ray3f` + 网格
- 输出：按 t 升序的 `RayHit3D` 列表
- 实现：`Geo3DPrimitives::rayTriangle()`，AABB 粗筛可选
- 复用：`Geo3DParallel::pickFromCandidates()` 批量拾取

### 12.3 水密性判断

- 输入：网格顶点序列 + 拓扑容差
- 输出：bool
- 实现：焊接去重后统计每条无向边出现次数，全部恰好为 2 即水密
- 复用：体积有效性、封闭性、点包含判定前置条件

### 12.4 顶点焊接

- 输入：网格 + 拓扑容差
- 输出：修改后的网格
- 实现：坐标量化哈希分组，组内保留首点，重写三角形索引（展开为 3 顶点数组）
- 复用：网格清理、朝向统一、拓扑分析的前置

### 12.5 表面均匀采样

- 输入：网格 + 采样点数 + 随机种子
- 输出：点列表
- 实现：按三角形面积加权随机选面，面内随机重心坐标取点
- 复用：测量点云、可视化、后续点云算法

## 13. 容差策略必须统一

与 2D 一致：
- `GeometryContext3D` 是 3D 几何算法的**唯一权威容差来源**
- 公开 API 全部提供 `GeometryContext3D` 重载
- 旧 `Geo3DTolerance` 重载保留过渡，标记 `[[deprecated]]`
- 底层不再散落魔法数字，数值安全阈值（如零长度边 `1e-12f`）保留为内部常量

---

## 14. DLL 导出问题（重要）

`Engine3D` 是内部 C++ DLL（见 `Engine3DAPI.h` 注释），导出约定：

1. **服务类必须导出**：`Geo3DAnalysis` / `Geo3DSampling` / `Geo3DEdit` / `MeshAlgorithms` 等公开类一律加 `ENGINE3D_API`。
2. **值类型结果结构**：`Geo3DMeasure` / `RayHit3D` / `MeshTopologyStats` / `MeshEdge` 等 POD 结构不强制导出宏，但只允许 STL 与算术类型成员（同编译器 / 同 CRT 内部使用，遵循现有约定）。
3. **内联实现**：`Plane3f` / `Segment3f` / `Line3f` / `Sphere3f` 等轻量类型的简单方法在头文件内联（header-only），不产生导出符号，规避 MSVC 类导出成员警告。
4. **静态无状态服务**：服务类均为纯静态方法集合、无数据成员，不需要 pImpl，也不会触发 C4251（导出类含 STL 成员）问题。
5. **避免跨 DLL 传递复杂模板**：`std::function` / 自定义模板实例不出现在导出 API；批量接口使用 `std::vector`（项目既定约定允许）。
6. **日志依赖**：`SY_*` 日志宏来自 `Log` 模块，`Engine3D` 的 `CMakeLists.txt` 需在 `PUBLIC_INCLUDE_DIRS` 加 `SANYI_LOG_DIR/Include`，并在 `LINK_LIBRARIES` 加 `Log`（PUBLIC），供内部实现与下游调用方使用。

## 16. 结论

3D 算法框架与 2D 同构：

1. **基础数学层统一容差和数值规则** — `GeometryContext3D` 5 级分类，旧 `Geo3DTolerance` 标记 deprecated。
2. **基础几何层统一点线面、射线、三角形关系** — `Geo3DPrimitives` 统一底层计算。
3. **通用三维算法层统一查询、分析、采样、并发** — `Geo3DQuery` / `Geo3DAnalysis` / `Geo3DSampling` / `Geo3DParallel`。
4. **图元专用层只做语义封装** — `SyMeshEntity` 保持轻量，`MeshAlgorithms` 薄封装收口入口。
5. **编辑层单独收口** — `Geo3DEdit` 负责全部就地编辑操作，避免图元类膨胀。
6. **算法与 UI 分离、低耦合** — 单向分层依赖，DLL 导出遵循统一约定，日志接入 `Log` 模块。

只要这个框架先立住，后面 3D 算法再多，也不会失控。
