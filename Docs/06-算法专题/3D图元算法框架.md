# 3D 图元算法框架

本文描述 3D 网格算法的当前分层方式，目标是让拾取、测量、分析、采样和编辑能力保持同构和可收口。

---

## 1. 为什么需要独立框架

`SyMeshEntity` 后续会持续增加命中、测量、拓扑、采样、清理和编辑类算法。如果这些算法散落在 UI、命令类或加载器中，会和 2D 一样导致重复实现和依赖混乱。

---

## 2. 总体目标

### 2.1 算法独立于 UI

算法应位于 `Engine3D`，不依赖菜单、视口或 Qt 事件对象。

### 2.2 算法可复用

例如：

- 点到网格最近点可复用于拾取和测量
- 射线与三角形求交可复用于拾取和遮挡
- 顶点焊接可复用于清理和拓扑分析

### 2.3 分层组织

建议沿以下层次组织：

```text
基础数学层
→ 基础几何层
→ 通用三维算法层
→ 图元专用算法层
→ 编辑 / 离散 / 分析算法层
```

---

## 3. 基础数学层

当前 3D 基础层已经以 `GeometryContext3D` 作为统一容差来源，并保留旧容差结构的过渡桥接。

---

## 4. 基础几何层

这一层应提供：

- 点、向量
- 线段、直线、射线
- 平面、球
- 三角形
- 包围盒

以及它们之间的基础关系计算。

---

## 5. 通用三维算法层

当前代码里，这一层主要由 `Geo3DQuery`、`Geo3DAnalysis`、`Geo3DSampling`、`Geo3DParallel` 承担。常见能力包括：

- 射线求交
- 点到网格最近点
- 体积 / 表面积 / 质心
- 水密性与流形性判断
- 自相交检测
- 连通分量分析
- 顶点和边采样

---

## 6. 图元专用算法层

`SyMeshEntity` 应继续保持轻量，只保留少量入口，复杂算法应委托给通用几何服务。

---

## 7. 编辑 / 离散 / 分析算法层

编辑、采样、分析类能力应继续和 UI 分离，保持统一容差和统一入口。

---

## 8. 当前维护原则

- 算法只放一处
- UI 不直接写几何逻辑
- 图元类保持轻量
- 新能力优先复用现有几何服务
