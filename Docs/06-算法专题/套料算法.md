# 套料算法（Nesting v2）

> 本文档描述 `Nesting` 模块的算法原理、分层结构、C ABI 契约与集成方式。
>
> 套料（Nesting / 排样）解决的问题：把一批任意形状的 2D 零件紧凑地排到板材上，
> 在满足切缝、间距、纹理等工艺约束的前提下，最大化原材料利用率。
>
> 代码位置：`Nesting/Nesting`；模块 README：[`Nesting/README.md`](../../Nesting/README.md)

---

## 1. 算法概述

套料本质是带几何约束的组合优化，分两层：

- **内层（放置）**：给定一个入场顺序和每件的朝向，逐件决定"放在哪"。这一层要求**精确且完备**。
- **外层（搜索）**：决定"什么顺序、什么朝向"。这一层是 NP-hard，用元启发式。

v2 的核心判断是：内层必须做精确的 NFP，而不是网格采样。原因见 §3。

整体流程：

```
输入轮廓
  ↓ 定点化 + 清理 + 绕向归一 + 单连通修复
Part（多朝向展开：角度 × 镜像 × 纹理约束）
  ↓ BuildInstanceOrder（按 sortRule 生成初始顺序）
初始染色体（顺序 + 朝向）
  ↓ GA（OX1 交叉 / 锦标赛选择 / 精英保留）+ 可选模拟退火
  │   每次评估 = 一次完整的多板装箱（并行、纯函数）
  ↓
最优染色体
  ↓ 收尾重排（收集几何 + 余料矩形 + 共边长度）
放置结果 / 板材用量 / 未排入清单
```

## 3. 精确 NFP 驱动放置

### 3.1 合法域

放入第 k 件时，其平移向量 `t` 的合法集合是：

```
V = InnerFit(可用区, shape_k) \ ⋃ⱼ<ₖ ( NFP(shape_j, shape_k) + t_j )
```

- `InnerFit`：零件整体落在可用区内的平移集合（内配多边形）
- `NFP(A, B)`：B 相对 A 重叠的平移集合，其**边界**是"刚好相切"的位置

关键性质：对任何线性或单调的落位目标（Bottom-Left、重力方向、贴合度），**最优解一定落在
`V` 的顶点上**。所以：

- 不需要网格采样（v1 每个朝向做 256 次布尔运算，仍会漏掉网格点之间的最优位置）
- 不需要放置后再做碰撞复检 —— `V` 内的点天然无碰撞

### 3.2 Clipper2 Minkowski 的陷阱（v2 修复的最严重 Bug）

`Clipper2Lib::MinkowskiDiff(B, A, true)` 是**边界扫掠**，不是填实的 Minkowski 差。它返回的是
一条**环带**：外环是我们要的 NFP 边界，而环带内部的**洞**恰好是"B 能整体塞进 A 内部"的位置集合。

对 NFP 来说 A 是实心的，B 塞在 A 内部同样是重叠，所以这些洞**必须填掉**：

```cpp
// 只保留正向环，丢弃全部洞
Paths64 FillHoles(const Paths64& src) {
    Paths64 out;
    for (const Path64& ring : src)
        if (ring.size() >= 3 && Clipper2Lib::IsPositive(ring)) out.push_back(ring);
    return out;
}
```

不填的后果是求解器把"落在已放置件内部"当成合法解，**静默产出重叠布局**。这类错误在凸形状 +
SAT 检查的测试里不会暴露，必须用凹形状 + 布尔求交来验证（见 `Test/SolverTests.cpp`
的 `SolverInvariant.ConcavePartsNeverOverlap`）。

### 3.3 其他几何约定

- **定点化**：`scale = 1 / tolerance`，mm 映射到 int64，坐标上限 `2^40`，避免浮点误差与
  Clipper 溢出。
- **布尔运算全程 `FillRule::NonZero`**。累积并集若用 `EvenOdd`，重叠区会被挖成洞 ——
  等价于"静默漏判重叠"。
- **外扩用 `JoinType::Miter`（miter_limit = 4）**：`Square` 在锐角处收缩会让实际间距小于设定值
  （工艺上不可接受）；`Round` 在小 tolerance 下顶点数爆炸，拖垮后续 Minkowski。
- **单连通要求**：NFP 只用 `paths[0]`。多瓣输入（如自交蝴蝶形）会被修复为"保留面积最大的一瓣"，
  否则第二瓣在碰撞检测中被静默忽略。

### 3.4 间距语义

每个朝向维护两套几何：

- `shape`：精确几何，用于板材 `InnerFit`、面积统计与结果输出
- `clearance`：`shape` 外扩 `partSpacing / 2`，仅用于两两 NFP

双方各外扩一半，净间距恰好等于 `partSpacing`。板边余量则通过把可用矩形内缩 `sheetSpacing`
实现，**两者不叠加**（v1 是叠加的，实际间距偏大、利用率虚低）。

### 3.5 严格贴合位与 Clipper 的零面积消除（实测吃掉 4%+ 的坑）

Clipper2 无法表达零面积区域。合法域按 `V = Difference(容器盒, NFP并集)` 计算时，
"恰好塞得下"的位置会退化成一条**零宽线段**，被 Clipper 直接丢弃。

具体表现：板宽 1000、件宽 100，一行已排 9 件后剩余宽度正好 100，第 10 件本应严格贴合放下，
但此时 `fit` 的 X 上界与禁区边界重合，`V` 在该处零宽 → 候选点丢失 → 这一件被顶到上一层。
每一行都发生一次，误差逐行累积。

实测代价：60 件 100×80 排 1000 宽的板，最优 480，退化成 500（+4.17%）；
80 件直角三角形的算例更严重，+12.5%。**这类算例在钣金/激光排样里极其常见**
（同款件 + 整齐尺寸），属于必须修的缺陷而不是"精度损失"。

修法（`Placer.cpp` `CollectCandidates`）：

```cpp
// 容器盒外扩一个定点单位再求差,零宽缝隙变成 1 单位宽的细条从而得以保留
constexpr int64_t kEps = 1;
const Paths64 valid = Geometry::Difference(Nfp::BoxToPaths(fit.inflated(kEps)), forbiddenUnion);
// ... 取顶点后夹回精确域;被夹动过的点来自外扩壳,需单独校验是否落进禁区
```

引入的误差上界就是一个 `tolerance`，正是调用方已经接受的精度。
未被夹动的点本就在合法域边界上，跳过校验（那是热点路径）。

守卫用例：`SolverExactFit.SingleRowIsFilledCompletely` / `FullGridIsFilledCompletely` /
`SingleColumnIsFilledCompletely`。

## 4. 性能

- **NFP 缓存**：键 = `(partA, orientA, partB, orientB)` 打包成 `uint64`（4 × 16 bit），
  `unordered_map` + `shared_mutex`。实测 1,815,121 命中 / 163 未命中。
  > v1 用结构体做 key 且 `operator<` 不满足严格弱序 —— 是 UB。
- **带状搜索剪枝**：候选搜索限制在 `[板底, skyline + 2·件高 + 间距]` 区间，无解时回退全板。
  把 NFP 布尔运算量从 O(已放置件数) 降到 O(带内件数)。
- **并行边界**：只有 `EvaluatePopulation` 并行（纯函数、无共享可变状态）。所有随机决策都在
  主线程按固定顺序发生，因此 `deterministic = 1` 时结果与线程数无关。

## 5. 外层搜索

染色体 = `(order, orient)`，即实例入场顺序的排列 + 每个实例的朝向下标。

- **交叉：OX1（Order Crossover）**。结构上保证产出合法排列。
  > v1 用单点交叉 + 去重补丁，补丁可能留下默认值 0，产出非法个体。
- **选择：锦标赛（k = 3）**。
  > v1 用 `1 / (1 + fitness)` 轮盘赌，适应度量级大时选择压力趋于消失。
- **变异**：顺序做 swap / reverse / insert 三种，朝向按 `orientMutationRate` 重掷。
- **精英保留**：最优个体无条件进入下一代，保证最优适应度单调不劣化。
- **适应度（越小越好）**：

```
fitness = 未放置件数        × 1e6      // 硬性优先：先把件排完
        + 使用板材张数      × 1e3      // 其次：少用板
        + 末张板占用面积占比 × 1e2      // 再次：末张尽量集中，余料更完整
        - 共边总长(mm)      × 0.05     // 最后：能共边就共边
```

系数按**量级隔离**设计：低优先级项的最大取值不会翻转高优先级项的一个单位差，因此不需要归一化。
v1 存在两套量纲不可比的评分公式混用的问题。

**策略档位**：`FAST` 直接用排序后的贪心解，完全绕过优化器；`BALANCED` 走 GA；`QUALITY`
在 GA 之后追加模拟退火。

## 6. 多板装箱与余料

- 每轮从库存里选板，顺序为：**余料板优先 → `priority` 降序 → 面积小者优先**。
  余料优先带 1.15 的加权，目的是清理库存里的零碎板。
- 支持混合规格与库存配额（`quantity <= 0` 表示不限量）。
- 每张板产出**最大空矩形**（96 × 96 网格 + 单调栈求最大矩形），可直接登记为新的余料板回到库存。
- **收尾重排不受超时约束**：超时只终止外层搜索；最优染色体一定会被完整重排出几何。
  否则一旦超时就会返回空布局，把已经算出来的最优解丢掉。

## 7. 工艺增强

### 7.1 共边切割（Common-Line Cutting）

相邻零件贴合、共用一条切割边，可显著减少切割行程与热输入。实现方式是并行维护第二套
"零切缝"间距几何（`commonClearance` = `shape` 外扩 `commonLineKerf / 2`），在该几何下寻找贴合位，
再用精确的共线重叠测量统计实际共边长度，短于 `commonLineMinEdge` 的不计入。

样例实测：54 件在 2 张板上共节省 13,580 mm 切割长度。

### 7.2 孔内套排（Hole Nesting）

大件的孔洞是可用区。通过对孔洞轮廓求 `InnerFitPolygon` 得到合法域，配合
`allowOthersInMyHoles` / `allowMeInsideHoles` 两个开关控制。结果里通过
`hostPartId` / `hostInstanceIndex` 表明"这件排在了谁的孔里"。

### 7.3 纹理方向（Grain）

四种模式：`FREE`（不限）、`LOCKED`（只允许 0°）、`BIDIRECTIONAL`（0° / 180°）、
`ORTHOGONAL`（0/90/180/270）。可全局设置，也可逐零件覆盖；再叠加 `rotationMask` 做位级过滤。

## 8. 对外 C ABI

遵循 [`DLL制作标准与现状.md`](../01-当前架构/DLL制作标准与现状.md)：纯 C 接口、POD 结构体、
不透明句柄、跨边界不传 STL / 不抛异常。

### 8.1 变换契约（集成时最容易错的地方）

```
p_final = T(tx, ty) · R(rotationDeg) · M(mirrored) · p_input
```

- `p_input` 就是调用方传入的原始坐标，**没有任何隐藏参考点**，也不做居中预处理
- `M(mirrored)`：`x → -x`（沿 Y 轴镜像），**先镜像，再旋转**
- 返回的 `bboxMin/Max` 是套用上式后的世界包围盒，可用来自检

> v1 的契约是 `M = T(offset) · R(deg) · MirrorX · T(-refPoint)`——镜像在旋转之后，且带一个
> 调用方必须自己记住的参考点。v2 去掉了参考点，并把镜像挪到旋转之前。

### 8.2 版本与前向兼容

- 所有输入结构体第一个字段是 `structSize`，由 `Nesting_Init*` 填写。DLL 接受**更小**的
  `structSize`（老调用方，缺失字段走默认值），拒绝更大的（返回 `NESTING_E_STRUCT_SIZE`）。
  这样新增字段不必再升 ABI 版本。
- `Nesting_GetAbiVersion()` 返回 `NESTING_ABI_VERSION`（当前 `2`），加载后应先校验。
- Win32 x86 下 `NESTING_CALL` 显式为 `__cdecl`，避免调用约定不一致导致栈失衡。

### 8.3 进度与取消

进度回调签名为 `int32_t(const NestingProgress*, void*)`，**返回 0 即请求中止**，无需再单独调
`Nesting_Cancel`。中止会同步到 job 上，`Nesting_IsCancelled` 能观察到。

## 9. 在本项目中的集成

| 层 | 文件 | 职责 |
|---|---|---|
| 数据结构 | `UI/Common/Include/UI/Algorithm/INestingJobRunner.h` | UI 侧参数/结果结构与运行器接口 |
| 零件准备 | `UI/Common/Src/Algorithm/NestingPartPreparer.cpp` | 从场景抽取闭合图元、按几何分组、生成 `nestLocalVerts` |
| 调用点 | `UI/Common/Src/Algorithm/NestingEngine.cpp` | 唯一直接 include `Nesting/NestingApi.h` 的文件 |
| 2D 处理器/对话框 | `UI/2D/.../Algorithm/NestingProcessor.*`、`UI/Dlg/NestingDialog.*` | 参数界面与任务调度 |

`NestingPartPreparer` 传给 DLL 的是 `nestLocalVerts = worldVerts - refPoint`，而图元本身在世界
坐标，所以 `NestingEngine::buildPlacementMatrix` 要补一个平移：

```
M = T(tx, ty) · R(rot) · MirrorX · T(-refPoint)
```

**当前限制**：`NestingPartPlacement` 还没有板材序号字段，多板结果会全部叠在同一坐标系里，
因此 `NestingEngine` 暂时设置 `maxSheets = 1`。要在界面上支持多板排样，需要先给
`INestingJobRunner` 的结果结构加上 `sheetOrdinal` 并让 UI 分板展示。

## 11. 排样质量基准

`Examples/Example_Benchmark.cpp`。把问题化归为**定宽条带装箱**：板宽固定、板高给足、
只用一张板、间距为 0，于是唯一输出指标就是"用了多高"。

```
lower bound = Σ零件净面积 / 板宽
used height = 已放置件的最大 Y
excess      = used height / 参考高度 − 1      ← 主指标，越小越好
```

`rect-uniform` / `tri-pairs` 的最优解**精确已知**，`circles` 的可达最优（方阵 10×5）
也已知，所以这三个算例上的 excess 就是纯粹的算法损失，诊断价值最高。

**2026-08-25 基线（QUALITY 档，4 方向旋转，时限 5s；朝向几何去重之后）**

- `rect-uniform`（60 件 100×80，W=1000）：H=480，eff 100.00%，**excess +0.00%**（最优）
- `tri-pairs`（80 件直角三角形，W=1000）：H=320，eff 100.00%，**excess +0.00%**（最优）
- `rect-mixed`（82 件 4 种规格，W=1500）：H=1100，eff 96.85%，excess +3.25%
- `circles`（50 件 ⌀100，W=1000）：H=533，eff 72.84%，excess +6.60%
- `laser-mixed`（84 件 6 种规格，W=1500）：H=1273，eff 90.33%，excess +10.71%
- `L-shapes`（60 件 L 形，W=1000）：H=400，eff 84.00%，excess +19.05%（下界不可达）
- `crosses`（40 件十字形，W=1200）：H=400，eff 66.67%，excess +50.00%
- **7 个算例平均 excess +12.80%**

修复 §3.5 的贴合位缺陷带来的提升（同一套算例、同一时限）：

- `rect-uniform` +4.17% → **+0.00%**
- `tri-pairs` +12.50% → **+0.00%**
- `rect-mixed` +7.95% → **+4.19%**
- `crosses` +65.00% → **+50.00%**
- 平均（当时的口径）+22.47% → **+17.38%**

§13.2 的朝向几何去重带来的提升（同一套算例、同一时限）：

- `rect-mixed` +4.19% → **+3.25%**
- `laser-mixed` +11.13% → **+10.71%**
- 平均 +13.00% → **+12.80%**
- 同时省下大量无效计算：`circles` 2783ms → 1200ms，`crosses` 1127ms → 486ms（高度不变）

**还差在哪（按 excess 排序）**

1. `crosses` +50%：十字形能密铺平面，但需要对角错位。单趟 BL 只会一行一行堆，
   看不到这一层。要靠贴合目标（`CONTACT`）或配对预处理。
2. `L-shapes` +19%：同理，凹形互扣需要配对。
3. `laser-mixed` +11%：多规格混排，长条件与小件的先后顺序影响很大，属搜索算子问题。
4. `circles` +6.6%：六边形密排面积效率更高（90.7%），但 50 件时会变成 6 行（10/9/10/9/10/2），
   总高反而超过方阵的 5 行。这是"选哪种晶格"的全局取舍，逐件贪心结构上看不到。

`Example_Benchmark -v` 会额外打印朝向分布与行结构，这两个数字通常直接指出退化原因。

## 12. 距离"工业级激光套料"还差什么（备忘 · 2026-08-25）

> 这一节是差距盘点与推进路线，供后续择时推进用，不代表当前已实现。
>
> **当前定位要说清楚**：已经完成的是一个正确、快、可复现的**不规则件装箱引擎**，
> 还不是一套"激光套料软件"。几何内核与装箱框架已到位，缺的主要是**激光工艺层**。
>
> 当前阶段的工作重点是先把**纯基础图元排好**（§12.4），工艺层等基础排样质量站稳了再往上叠。

### 12.1 P0 — 不补就会出废品

**① 引入/引出线（lead-in / lead-out）没有参与排样。最危险的一项。**

`NestingOptions.partSpacing` 是各向同性标量，NFP 只按零件轮廓外扩它。但实际切割时每个轮廓要带
3~8 mm 的直线或圆弧引入线，它会伸到零件轮廓**外面**。所以现在按 0.5 mm 间距排出来的"合法"布局，
一上机引入线就会切进邻件。

正确做法是把引入线几何**并入 `Orientation.clearance` 参与 NFP**，而不是排完再检查——事后检查
只能拒绝，不能生成正确布局。

**② 切割顺序 / 刀路完全没有。**

现在只统计 `totalCutLength`，不产出切割序列。缺：内孔先于外轮廓、空程 TSP、起点避开尖角与圆弧、
穿孔点数最小化（穿孔是激光最慢也最易失败的动作）。

尤其是**共边**：现在只在适应度里给共边长度一点奖励（§5），但不产出共边切割路径。共边有强顺序
依赖——一条共用边必须一次切完，不能分两次走，否则热变形会让第二刀错位。**只统计不产出，等于
这个功能下游用不了。**

**③ 微连接 / 桥接（micro-joint / tab / bridge）没有。**

小件切完会掉进废料斗。工业上要留 0.2~0.5 mm 微连接，或用桥把小件连成串。这既是工艺功能，
也反过来约束排样（要留出桥的走线空间）。

**④ 禁放区 / 板材缺陷区没有。**

`NestingSheetDesc` 只有 `width` / `height` + 四边 margin，板材是纯矩形。真实余料板有孔、有划伤、
有夹爪区；切割床支撑肋位置固定，切割线压在肋上会反射伤镜。

> **这是性价比最高的一项**：内部 `Nfp::InnerFitPolygon` 已经支持任意多边形可用区，机器都在，
> 缺的只是 API 入口（`NestingSheetDesc` 加轮廓数组）和 `SheetStock` 的建模。

**⑤ 热变形 / 积热没处理。**

连续在同一区域切割会积热，工业上要"跳切"分散热量。而现在默认的 `BOTTOM_LEFT` 目标恰恰是
最集中的，等于在最大化积热。

### 12.2 P1 — 影响利用率，也就是影响竞争力

- **旋转只支持离散角度集合**（`rotations[64]`）。异形件用连续角度能显著提利用率，现在拿不到。
- **缺配对预处理（pairing）**：先把两个形状互补的件组成"超级件"再排，是不规则件套料的经典增益
  手段，通常能拿到几个百分点。
- **缺矩形族识别**：激光加工里很大比例的活是同款矩形件。这种情况下专用的 strip / guillotine
  算法在速度和结果上都完胜通用 NFP。理想架构是先分流矩形族走 strip，异形件再用 NFP 填缝。
- **搜索算子偏单一**：纯 GA + 退火。工业界主流已是 LNS / ruin-and-recreate 这类大邻域搜索，
  同样时间预算下收敛快得多。
- **没有跑公开基准 —— 这是当前最该先做的一件事。**
  ESICUP 标准数据集（Albano / Dagli / Jakobs / Mao / Marques / Shapes / Swim / Trousers）跑一遍，
  把利用率和文献 SOTA 摆在一起。"工业级"这个说法目前**没有数字支撑**：唯一的数据是 §11 那个
  自造 54 件样例的 87%，那个数字说明不了任何问题。有了基准，上面所有优化才有判断依据，
  否则是凭感觉改。

### 12.3 P2 — 产品化

- **不能预置已放置件。** API 没有"这几件已在这些位置，请在剩下空间里排"的入口。这直接堵死两个
  必备交互：用户手工拖动一件后重排、在已开工的板上补排。**明确的 API 缺口。**
- **不能增量重排**：改一个参数就得全量重算。
- **余料只报最大空矩形**，不报余料真实形状。要做余料回库闭环需输出多边形余料。
- **排样失败缺结构化诊断**：放不下只给一个 `errorMessage`，用户不知道是板太小、间距太大，
  还是纹理锁死。
- **跨平台是声明，不是事实**：CMake 里有 UNIX 分支，但只在 Windows / MSVC 上编译验证过，
  Linux / macOS 一次没编。README 里"跨平台"这句目前未经验证，需要补 CI。
- **大规模鲁棒性未验证**：几千件的 job，单板已放置件累积并集的顶点数会持续膨胀，目前没有定期
  简化或 skyline 近似机制。带状剪枝只优化了搜索范围，没优化并集本身的复杂度。
- **多连通零件是"静默保留最大一瓣"**：作为修复策略可以，但工业上应该报警让用户知道输入有问题，
  而不是悄悄改他的图。
- 圆弧按 `arcTolerance` 离散，无解析 NFP（对装箱影响有限，对相切精度有影响）。
- UI 层多板排样展示（见 §9 限制）。

### 12.4 建议推进顺序

1. ~~**建立可量化基准**~~ —— ✅ 已完成，见 §11（`Examples/Example_Benchmark.cpp`）
2. **纯基础图元排样质量攻坚**（进行中）
   - ✅ 修掉严格贴合位被 Clipper 零面积消除吃掉的缺陷（§3.5），平均 excess 22.5% → 13.0%
   - ✅ 朝向几何去重（§13.2），平均 excess 13.0% → 12.8%，圆形/十字算例快 2 倍以上
   - ⬜ 配对预处理（pairing）：直接针对 `crosses` +50% / `L-shapes` +19%
   - ⬜ 矩形族识别分流到 strip / guillotine
   - ⬜ 落位目标与搜索算子调优（LNS / ruin-and-recreate）
   - ⬜ 全局晶格取舍（`circles` 的方阵 vs 六边形，见 §11）
3. **禁放区 / 任意形状可用区**（机器已就绪，改动小，价值大）
4. **引入引出线并入 NFP**（安全问题，实际优先级比 3 更高，只是工作量大些）
5. **切割顺序 + 共边路径产出 + 微连接**（三者是一体的工艺层，建议一起做）

## 13. 构建解耦与可观测性（2026-08-25）

### 13.1 既能依赖兄弟 DLL，又能脱离主程序单独编译

两个要求同时成立，做法是把"复用仓库配置"和"依赖主程序"这两件事拆开：

```cmake
# Nesting/CMakeLists.txt
include(../Config.cmake)                                  # vcpkg / Qt / MSVC 运行库
include(${CMAKE_CURRENT_LIST_DIR}/../CMake/StandaloneInit.cmake)
project(SanYiNesting VERSION 2.0.0 LANGUAGES CXX)
sanyi_setup_compiler_options()                            # /W4 等必须在 project() 之后

if(NESTING_WITH_LOG AND NOT TARGET Log)
    add_subdirectory("${SANYI_LOG_DIR}" "${CMAKE_BINARY_DIR}/Log")
endif()
```

- **复用配置**用 `include()`，不需要主程序的 target 存在；
- **依赖兄弟 DLL** 时按需 `add_subdirectory` 把 Log 拉进本次构建。Log 自身只依赖 vcpkg 的
  spdlog，不牵扯主程序，所以这样拉是安全的；
- `Nesting/Nesting/CMakeLists.txt` 只在 `TARGET Log` 存在时注入 `NESTING_HAS_LOG`
  与 Log 的 include 目录，并 link Log。

验证口径（两种配置都要过）：

- `NESTING_WITH_LOG=ON`：产物 `Nesting.dll` + `Log.dll`，88 个用例全过；
- `NESTING_WITH_LOG=OFF`：产物只有 `Nesting.dll`（bin 目录里没有 Log.dll），88 个用例全过。

> Utility 目前**没有**被 Nesting 使用（几何全部自持，只依赖 Clipper2）。CMake 里保留的软链接
> 只是为了将来真用上时不必改脚本，不要往里加隐式依赖。

### 13.2 日志：可观测性，不是功能依赖

`Src/Core/Diagnostics.h` 是一层屏蔽宏：有 `NESTING_HAS_LOG` 就转发到 `SY_*F`，
没有就编成空操作。两种配置下**库的行为完全一致**。四条硬规矩：

1. **日志正文一律英文，注释一律中文。** 库日志会进产线日志文件、被脚本抓取、被海外客户看到，
   中文在非 UTF-8 控制台还会变乱码。
2. **绝不写 stdout / stderr。** v1 的 `fprintf(stderr, ...)` 是反例；失败原因走
   `Nesting_GetLastError`。
3. **不在热点路径打日志。** 候选生成 / NFP / 适应度评估是每秒百万次量级。`Pack()` 内的日志
   一律用 `collectGeometry` 兜住 —— GA 期间 `Pack()` 被调用成百上千次，只有最后那次收尾
   重排才允许输出。
4. **开关日志不改变语义。** 空操作分支通过可变参数模板照常求值实参，
   否则 `NEST_LOG_INFO("%d", i++)` 这种写法会因为编译配置不同而行为不同。

宏刻意声明成 `NEST_LOG_X(...)` 而不是 `NEST_LOG_X(fmt, ...)`：后者在"只有格式串、没有可变参"
时会展开出多余的逗号（MSVC 传统预处理器不吃掉 `##__VA_ARGS__` 前的逗号，直接 C2059）。
现在靠**相邻字符串字面量拼接**把 `"[Nesting] "` 前缀贴到格式串上，整串 `__VA_ARGS__` 原样传下去。

落点（都是"一次求解 O(1) 或 O(板材数) 次"的位置）：

- `Nesting_Run` 入口：规模 + 策略档位 + 线程数 + 时限；出口：板材数 / 放置率 / 利用率 /
  耗时 / 代数 / NFP 缓存命中；`unplacedCount > 0` 时单独 WARN（"成功但不完整"最容易被忽略）；
  三个 `catch` 分支各一条 ERROR。
- `StructSizeOk`：ABI 尺寸被拒时打出两边的字节数 —— "换了 DLL 忘了换头文件"的典型症状。
- `Solver::Run`：零件放不进任何板材时打出零件包围盒与板材可用区尺寸（现场最常见的配置错误）；
  因超时收尾时 WARN（提示还有提升空间）；取消且未产出任何放置时 WARN。
- `Solver::Pack`（仅 `collectGeometry`）：每块板一条 INFO；无法继续放置 / 死循环兜底 WARN+ERROR。
- `BuildOrientations`：所有朝向被 `rotationMask` / grain 筛光而退化为 0° 时 WARN
  —— 这是静默修复，不打日志调用方会以为自己的掩码生效了。
- `KeepLargestComponent`：轮廓有多个连通分量、只保留最大块时 WARN
  —— 静默丢弃几何是最难查的一类问题。

### 13.3 本轮调优

**朝向几何去重.** 原先只按 `(角度, 镜像)` 去重，几何上完全相同的朝向会各留一份。
最典型的是用多边形近似的圆：24 边形转 90°（正好 6 个顶点）后与原形逐点重合，
于是 4 个朝向有 3 个是白算的 —— NFP 缓存条目、候选点集、放置器要试的朝向数全部翻倍。

规范化两步走（`Model.cpp` 的 `CanonicalShape`）：平移到包围盒左下角贴原点，
再把每个环的起点转到字典序最小的顶点（旋转会让顶点序**循环移位**，少了这步同一图形也判不等）。
比较放在 `NormalizeOrientation` 之后、`BuildClearances` 之前 —— 后者才是真正贵的那步。

**只在同一 `mirrored` 取值内合并**：镜像意味着零件要翻面，对覆膜板、单面拉丝、
带纹理方向的材料是不同工艺，不能因为图形对称就合并掉。

**候选裁剪改为目标函数感知.** `kMaxCandidates = 192` 的截断原先一律按 BL 键 `(y, x)` 预排序，
与 `Better()` 的主项不一致时，截断本身就成了一次隐性换目标：重力方向配成横向时，
按 `(y, x)` 留下的是"最靠下"的一批，而 `Better()` 想要的是"最靠左"的一批。
现在 `objective == 1`（GRAVITY）改用同一个投影表达式排序（`Better()` 投影包围盒中心，
中心 = 平移量 + 常量，而 `CollectCandidates` 每次只处理一个朝向，两者次序等价）。
`objective` 2 / 3 依赖 `usedBox` / 真实接触长度，构造完候选才能算，只能沿用 BL 键，
属已知的残余近似（顶点数超过 192 才会显现）。

**NFP 缓存的悬垂指针.** `NfpCache::Insert` 在容量到顶时**整表清空**。条目原先直接存
`Paths64` 并返回裸指针，而多线程适应度评估共享同一个缓存 —— 一个线程正拿着上次查询的结果做
布尔运算时，另一个线程的插入把它脚下的内存抽走，是实打实的 use-after-free（只是要攒到
20 万条才触发，测不出来）。改成条目存 `std::shared_ptr<const Paths64>`：清空只丢掉表自己那份
引用，在用的调用方仍持有有效对象。代价是每次查询一次原子引用计数，相对一次 NFP 布尔运算可忽略。
守卫用例：`NfpCacheTest.EntryStaysValidAfterCapacityEviction`。
