# 代码签名与公证

本文档说明 April 在 macOS 与 Windows 上如何对安装包做代码签名、公证与验证。所有凭据只从环境变量读取，仓库内不保存任何真实密钥、证书或密码。

## 1. 目标与边界

- **可交付包必须签名**：未签名的 macOS 包会被 Gatekeeper 拦截，未签名的 Windows 包会触发 SmartScreen 警告。
- **凭据缺失不阻断构建**：CI 与本地打包在缺少凭据时打印明确告警并跳过签名/公证，退出码仍为 0，便于外部贡献者与无密钥环境继续验证构建。
- **凭据存在但签名失败必须失败**：避免产出「看起来已签名、实际不可用」的安装包。
- **仓库零密钥**：本文与脚本中的凭据全部是占位值，真实值只存在于 CI Secret 或本地 shell 环境。

## 2. macOS：codesign + notarytool

### 2.1 前置条件

1. 已加入 Apple Developer Program。
2. 本机钥匙串中已安装 `Developer ID Application` 证书（`security find-identity -v -p codesigning` 能看到）。
3. 已安装 Xcode Command Line Tools（提供 `codesign`、`xcrun notarytool`、`stapler`、`spctl`）。

### 2.2 凭据环境变量

| 变量 | 必填 | 说明 | 占位示例 |
| --- | --- | --- | --- |
| `APPLE_SIGN_IDENTITY` | 是 | 签名身份完整名称 | `Developer ID Application: Example Corp (ABCDE12345)` |
| `APPLE_TEAM_ID` | 视方式 | Apple Developer Team ID | `ABCDE12345` |
| `NOTARYTOOL_PROFILE` | 二选一 | 已存入钥匙串的 notarytool profile | `AprilNotary` |
| `APPLE_ID` | 二选一 | Apple ID | `developer@example.com` |
| `APPLE_APP_PASSWORD` | 二选一 | Apple ID 的 App 专用密码 | `xxxx-xxxx-xxxx-xxxx` |

推荐使用 `NOTARYTOOL_PROFILE`，避免在 CI 中传递 Apple ID 与密码：

```bash
# 只需在可信的打包机上执行一次；密码会写入钥匙串，不进入仓库。
xcrun notarytool store-credentials "AprilNotary" \
  --apple-id "developer@example.com" \
  --team-id "ABCDE12345" \
  --password "xxxx-xxxx-xxxx-xxxx"
```

### 2.3 打包与签名

```bash
# 方式一：环境变量提供身份
export APPLE_SIGN_IDENTITY="Developer ID Application: Example Corp (ABCDE12345)"
export NOTARYTOOL_PROFILE="AprilNotary"
Tools/Packaging/package-macos.sh --format dmg

# 方式二：命令行显式指定身份（公证凭据仍来自环境变量）
Tools/Packaging/package-macos.sh --format dmg \
  --sign "Developer ID Application: Example Corp (ABCDE12345)"

# 仅签名/公证已有的 .app 或 .dmg
Tools/Packaging/sign-macos.sh --app build/package-staging/April.app
Tools/Packaging/sign-macos.sh --artifact dist/April-1.0.0-macos-arm64.dmg
```

`sign-macos.sh` 的执行顺序：

1. 对 `Contents/Frameworks` 下的 `.framework` 与 `.dylib`、`Contents/Resources/bin` 下的辅助可执行文件逐个签名；
2. 以 hardened runtime（`--options runtime`）与安全时间戳（`--timestamp`）签名 `.app` 本体；
3. 将 `.app` 打成临时 zip 提交 `notarytool submit --wait`；
4. 对 `.app` 执行 `stapler staple` 与 `stapler validate`；
5. 打包脚本生成 `.dmg` 后，再对 `.dmg` 签名、公证并 staple。

zip 分发包不再单独提交公证：其内部的 `.app` 已在步骤 3–4 完成公证与 staple，重复提交只会增加排队时间。

### 2.4 缺失凭据时的行为

| 场景 | 行为 |
| --- | --- |
| 未设置 `APPLE_SIGN_IDENTITY` | `sign-macos.sh` 告警并跳过签名/公证，退出码 0 |
| 设置了身份但无任何公证凭据 | 完成 Developer ID 签名，告警并跳过公证，退出码 0 |
| `package-macos.sh` 未提供身份 | 回退 ad-hoc 签名，并告警说明不会公证 |
| 身份/公证凭据齐全但签名或 notarytool 失败 | 非 0 退出，打包失败 |

> ad-hoc 签名只适合本机调试；分发给其他机器必须使用 Developer ID 并完成公证。

### 2.5 验证

```bash
codesign --verify --strict --verbose=2 dist/April.app
spctl --assess --type execute --verbose=2 dist/April.app
xcrun stapler validate dist/April.app
xcrun stapler validate dist/April-1.0.0-macos-arm64.dmg

# 公证失败时查看日志
xcrun notarytool log <submission-id> --keychain-profile "AprilNotary"
```

## 3. Windows：signtool

### 3.1 凭据环境变量

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `APR_WIN_SIGN_THUMBPRINT` | 二选一 | 证书存储中的证书指纹 |
| `APR_WIN_SIGN_PFX` | 二选一 | PFX 文件路径 |
| `APR_WIN_SIGN_PASSWORD` | 否 | PFX 密码；未设置时由 signtool 交互输入 |
| `APR_WIN_SIGN_TIMESTAMP` | 否 | RFC 3161 时间戳地址，默认 `http://timestamp.digicert.com` |

命令行参数 `-SignThumbprint` / `-TimestampUrl` 优先于环境变量。

### 3.2 打包

```powershell
# 使用证书存储中的指纹
$env:APR_WIN_SIGN_THUMBPRINT = "0123456789ABCDEF0123456789ABCDEF01234567"
.\Tools\Packaging\package-windows.ps1 -MakeInstaller

# 使用 PFX
$env:APR_WIN_SIGN_PFX = "C:\secrets\april-signing.pfx"
$env:APR_WIN_SIGN_PASSWORD = "placeholder-password"
.\Tools\Packaging\package-windows.ps1 -MakeInstaller
```

脚会对暂存目录下的 `.exe`、`.dll`、`.pyd` 逐个执行：

```text
signtool sign /fd sha256 /tr <timestamp-url> /td sha256 /sha1 <thumbprint> <file>
signtool sign /fd sha256 /tr <timestamp-url> /td sha256 /f <pfx> /p <password> <file>
```

没有凭据时打印两条告警并继续打包，退出码不变。

### 3.3 验证

```powershell
signtool verify /pa /v .\dist\April\April.exe
Get-AuthenticodeSignature .\dist\April\April.exe | Format-List Status, SignerCertificate
```

### 3.4 说明

- 普通 OV 代码签名证书仍可能触发 SmartScreen 信誉提示，EV 证书或持续积累下载信誉后才会消失。
- EV 证书通常存放于云 HSM，`signtool` 需要对应的自定义 CSP/插件；本文脚本不覆盖该场景，需在发布流水线中替换签名命令。
- 不要将 PFX、密码或证书指纹写入仓库、日志或构建产物。

## 4. CI 中的接入方式

两个平台的打包作业都只读取同名环境变量。在 GitHub Actions 中配置 Repository Secrets 后注入即可：

```yaml
env:
  APPLE_SIGN_IDENTITY: ${{ secrets.APPLE_SIGN_IDENTITY }}
  NOTARYTOOL_PROFILE: ${{ secrets.NOTARYTOOL_PROFILE }}
  APR_WIN_SIGN_THUMBPRINT: ${{ secrets.APR_WIN_SIGN_THUMBPRINT }}
```

未配置 Secret 时，作业仍会完成构建与打包冒烟，仅在日志中出现签名跳过告警。这是刻意设计：签名是发布门槛，不是构建门槛。

## 5. 常见问题

| 现象 | 排查方向 |
| --- | --- |
| `code object is not signed at all` | 先签嵌套 framework/dylib，再签 `.app`；不要只签主可执行文件 |
| `errSecInternalComponent` | 钥匙串被锁定或无交互权限；在 CI 中先 `security unlock-keychain` |
| notarytool 返回 `Invalid` | 用 `notarytool log` 查看具体条目，常见为 hardened runtime 缺失或 entitlements 不允许 |
| `spctl` 在 CI 上失败 | CI runner 没有完整 Gatekeeper 数据库，属于环境限制；以 `stapler validate` 与公证结果为准 |
| Windows 签名后仍提示未知发布者 | 证书链不受信任或未带时间戳；检查 `signtool verify /pa /v` |
