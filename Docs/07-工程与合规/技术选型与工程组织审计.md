## 1. 结论摘要

### 1.1 是否存在系统性技术路线偏差

**是，但只有两条是「系统性」的，其余都是点状。**

1. **几何偏移存在两套精度模型、三套实现，且没有声明唯一权威。**
   `Engine/2D` 走 Clipper2 **浮点 API（`ClipperD`/`PathsD`）**，内部定点精度取 **precision=2（0.01 mm = 10 µm 网格）**；`Engraving` 与 `Nesting` 走 Clipper2 **整数 API（`Paths64`）**，scale=1000（1 µm 网格）。同一份 Clipper2 静态库，两套数量级不同的量化口径。
   实测（本文附录基准，Clipper2 + MSVC Release）：`PathsD p=2` 相对理论的**最大轮廓误差 11.72 µm、RMS 3.51 µm**，且 3600 顶点的圆内缩后**只剩 2889 个顶点（丢 19.75%）**；`p=4` 把误差压到 **0.10 µm**，`Paths64(1000)` 为 **1.01 µm**。
2. **第三方类型从 DLL 公共边界泄漏。**
   `Engraving/PolygonOffset.h` 公共头直接 `#include <clipper2/clipper.h>`，并把 `Clipper2Lib::JoinType`/`EndType` 作为导出结构体成员；`Engraving/CMakeLists.txt` 还把 OpenCV 的 include 路径与库以 PUBLIC 转发。对照 `Raster`/`Vision` 用 `*_ABI_GUARD` 硬拦 OpenCV/Qt/STL 的做法，这是同一仓库内**两套互斥的边界策略**。

除此之外：依赖冗余（Engine2D 链了 SQLiteCpp/OpenSSL 却零使用点、protobuf 全量版与 lite 版并存）、目录/命名/导出宏的不一致（Renderx）都是**点状确认偏差**，不影响主链路正确性。

### 1.2 最该改的三处（按性价比排序）

| # | 改动 | 理由（有数字） | 工作量 |
|---|---|---|---|
| 1 | `Engine2D` 偏移精度从 `ClipperD(2)` 提到 `ClipperD(4)`（或统一 `PathsD` 精度常量） | 误差 11.72 µm → 0.10 µm（100 倍改善），顶点丢失 19.75% → 0（见附录 A/B 基准）。代价：单条 1 万顶点轮廓 5.39 ms → 11.06 ms（+5.67 ms），1 万小轮廓 54.16 → 52.64 ms（无变化）。对激光切割 0.1–0.3 mm 割缝的 5% 级偏差，属于「一次改一个常量」的高性价比项 | 1 个 .cpp，~8 个调用点 |
| 2 | 唯一权威偏移收口：`Geo2DOffset` 为 2D 唯一入口，`Engraving`/`Nesting` 保留领域专有能力（3D 分层、NFP），删除重复的 2D 多边形布尔/偏移入口 | 三套实现的语义差异已经可见（`float offsetDistance` vs `double delta`、单位网格 1 µm vs 10 µm、`arcTolerance` 0.25 mm 硬编码）。不清掉，任何一次「偏移结果不一致」都要跨三个模块排查 | 接口层 3 个 .h + 若干转发；不需要动 ABI（都是内部实现） |
| 3 | 砍掉 `Engine2D` 的 SQLiteCpp / OpenSSL 链接；`FileIO` 与 `Persistence` 统一 protobuf 运行时（建议都走 `-lite`，或都走全量，二选一） | Engine2D 对 sqlite/OpenSSL 引用数实测为 **0**；protobuf 两套运行时并存意味着链接时同时拉入 `libprotobuf` 与 `libprotobuf-lite`，符号重复风险与部署体积翻倍，且 `Persistence` 的**公共头** `SceneManagerSerializer.h` 直接 `#include <google/protobuf/message.h>`，把 protobuf 头与 ABI 暴露给所有下游 DLL | 3 个 CMakeLists.txt + 1 个公共头（pimpl 化） |

### 1.3 看起来像问题、但核查后**不是问题**的典型项

| 项 | 为什么不是问题 |
|---|---|
| 用 Clipper2 做布尔，而不是自研求交 | 布尔/偏移的稳健性正是 Clipper2 的强项，自研只会更差；且 `Clipper2` 以**静态库**方式链接（部署目录无 `clipper*.dll`），不存在跨 DLL 的第三方类型传递（除 Engraving 那一处泄漏） |
| `Raster` 用 OpenCV 而不是纯手写图像算法 | `Raster/CMakeLists.txt` 实测**无 Qt 依赖**，公开头是纯 C ABI + `RASTER_ABI_GUARD`（出现 OpenCV/STL 容器/异常/`dynamic_cast` 直接 configure 失败）。边界干净，用 OpenCV 是正确选择 |
| Raster 的「割缝」用像素形态学 | 那是像素域的位图腐蚀/膨胀（`RasterContour.cpp`），与矢量几何偏置不是同一件事，已见于总账表 B14，不重复展开 |
| JSON 用 Qt 而不是 nlohmann | 全仓 `nlohmann` 命中 **0**，`QJsonDocument` 系 API 单套实现；不存在「两套 JSON 并存」的问题 |
| 日志是「自己写的一套」 | `Log/CMakeLists.txt` 实测 `find_package(spdlog CONFIG REQUIRED)` + `PRIVATE spdlog::spdlog`，`SyLogger` 是 spdlog 封装 + 自制宏，不是从零实现的日志器 |
| 线程池「重复造轮子」 | 两处线程池（`Engine/Common/.../EngineParallel.h`、`Nesting/.../ThreadPool.h`）都是对 **BS::thread_pool** 的封装，不是自研调度器 |
| UI 通过 30 个转发头访问 Engine 是「假解耦」 | `UiEngineAccess` 是 INTERFACE 门面，`CheckDependencies.cmake` 规则 3 硬失败禁止 UI 直链 Engine；转发头是显式的「依赖面扩张决策」，属于设计选择 |
| 未使用 Eigen | 全仓 `Eigen::` / `#include <Eigen` 命中 0。项目里矩阵运算规模很小（2D 仿射、3×3 法线/旋转），手写 `Ut::Vec/Mat` 比引入 Eigen 的编译开销更划算 |
| `dynamic_cast` 遍地 | 这是真偏差（`Geo2DEdit.cpp` 单文件 46 处），但**仓库规范 §3.5 已自己承认尚未替换**，属已知待办，本文不重复展开 |

| 优先级 | **P1**。不改：编译面污染 + 升级 Clipper2 时的隐性 ABI 断裂 |

### A-05 float 与 double 混用：Engraving 的 `Point3D` 是 `float`

| 字段 | 内容 |
|---|---|
| 领域 | 数值 |
| 现状 | [VolumeProcessing.h](file:///c:/Users/xx/Documents/Cpp/CAD/Engraving/Engraving/Include/Engraving/VolumeProcessing.h#L31) `struct Point3D { float x, y, z; }`；Engine2D 侧统一 `Ut::Vec2d`（double）；`PolygonOffset` 的 `fromClipperPath` 用 `static_cast<float>` 中转 |
| 应有做法 | 几何数据统一 double；只有在 GPU/内存密集的体素域（高度场）才用 float，并在跨域转换点显式舍入 |

| 影响面 | 位图雕刻（高度场、分层刀路）与 2D 矢量的接缝；不影响激光 2D 切割主链路 |
| 迁移成本 | `Point3D` 是公共类型，改 double 会改 ABI 并增加高度场内存（float→double 翻倍）；建议**不改类型**，只在跨界转换处显式 `double` 计算 |
| 结论档 | **确认偏差（量级小）** |
| 优先级 | **P2**。不改：不会产生可测量的加工偏差，但会长期让「精度问题」的排查多一个可疑项 |

## 6. 建议的整改顺序（按性价比）

| 顺序 | 事项 | 收益 | 风险 | 是否动 ABI | 是否需重跑基线 |
|---|---|---|---|---|---|
| 1 | **A-01** 偏移 precision 2 → 4（或统一常量） | 轮廓误差 11.7 µm → 0.1 µm，顶点丢失归零 | 极低（单常量） | 否 | 是（偏移/填充用例） |
| 2 | **A-19** 删 Engine2D 的 SQLiteCpp/OpenSSL 死依赖 | configure 更鲁棒、构建更快 | 极低 | 否 | 否 |
| 3 | **A-13/A-14** protobuf 收口（统一 lite + 公共头 pimpl） | 去一套运行时、去掉公共头泄漏 | 中（要确认是否用到反射） | 是（Persistence） | 是（序列化基线） |
| 4 | **A-03** Engraving 公共头去 Clipper2/OpenCV | 编译面干净、ABI 稳定 | 中（`PolygonOffsetOptions` 变类型） | 是 | 是（雕刻相关） |
| 5 | **B-01** `MaterialDatabase`/`SafetyManager`/`ToolpathExecutor` 归位 | Hardware 自洽、Main 变薄 | 中（动 3 个 .cpp 与链接） | 否 | 是 |
| 6 | **A-02** 偏移唯一权威 | 消除三处实现漂移 | 中（Engraving 转调） | 是（Engraving 导出符号） | 是 |
| 7 | **B-06** 子模块工作流条款 + 当前漂移收敛 | 防并发丢改动 | 低 | 否 | 否 |
| 8 | **B-03/B-04/B-05/B-09** 命名与文档一致性 | 规范可用 | 低 | 是（Renderx 宏，仅重编） | 否 |
| 9 | **A-08/A-04** 两个「需实测」项补基准 | 决定是否要换库 | — | — | — |
| 10 | **A-22/A-23** 取色链路收口 + 部署配置校验 CI | 防随机崩溃 | 低 | 否 | 否 |

> 原则：**先改「一个常量就能拿到数量级收益」的，再改结构性重复，最后动 ABI。** 第 1、2 项可以在任何并行会话的空窗期独立完成，不与其他会话冲突。
