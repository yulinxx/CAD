### 10.4 顺带修掉的构建期缺口

屏蔽清单是 **configure 期输入**（`file(STRINGS)` + `file(WRITE)` 生成链接参数文件），
只在 `Engine/2D/CMakeLists.txt` 里加 `LINK_DEPENDS` 只能覆盖生成文件的变化，
**改源清单本身不会触发重新 configure**，生成的屏蔽文件会停留在旧内容。
本次补上：

```cmake
set_property(DIRECTORY APPEND PROPERTY CMAKE_CONFIGURE_DEPENDS "${ENGINE2D_B2_LIST}")
```

与 `LINK_DEPENDS` 配合后，"改清单 → 重新 configure → 重新链接" 才形成闭环，
负向验证与手工复现不再依赖人工先跑一次 configure。

## 11. 已知不对称（本轮不修）

以下符号仍被屏蔽，且与类级 `ENGINE2D_API` 的平台语义不一致：

| 符号 | 现状 | 断链触发条件 | 当前全仓用法 |
|---|---|---|---|
| `vtable` / `typeinfo` / `typeinfo name` for `UndoRedoManager::LambdaCommand` | 类标 `ENGINE2D_API`，但三个符号在屏蔽清单 | 消费者 `dynamic_cast` 到 `LambdaCommand`、`typeid`、或继承该类 | 无 |
| `vtable` / `typeinfo` / `typeinfo name` for `UndoRedoManager::ModifyEntityCommand` | 同上 | 同上 | 无 |
| `typeinfo` / `typeinfo name` for `Eg::SegmentIndex2D` | typeinfo 被屏蔽，vtable 实际导出（`S` 段） | 消费者 `dynamic_cast` 到 `SegmentIndex2D`、`typeid`、或继承该类 | 无 |

说明：Windows 上这些类因 `__declspec(dllexport)` 会导出 vtable/typeinfo，macOS/Linux 上被
清单隐藏，形成平台不对称。**消费者若 `dynamic_cast` 到这些具体类型或继承它们，会在
macOS/Linux 断链；当前全仓无此用法**（已用 `dynamic_cast<...>` / `typeid(...)` 全仓检索确认）。
本轮按决定不改；下一批可二选一：恢复导出以对齐类级 API，或明确这些类型禁止跨 DLL RTTI。
