# Engine2D 导出面收敛方案（2026-11-12）

> 定位：本文只回答"1619 个导出符号怎么收敛"，不实施。批准后按 §5 分批落地。
> 关联：[DLL导出与ABI约定-2026-11-11.md](./DLL导出与ABI约定-2026-11-11.md) §2.3/§4/§6、[模块边界与依赖审查.md](./模块边界与依赖审查.md)
> 约束：本轮不改任何源码；不改 `Tools/`（含不更新基线）；不改 `Engine/2D/Src/Geometry/` 与
> `Engine/2D/Include/Engine2D/Geometry/`（螺旋残环 WIP 与窄条兜底在另一条线）；不改 Raster / libdxfrw 等子模块。

## 0. 结论先行

1. **`-fvisibility=hidden` 已经是现状，不是待办。** `Config.cmake:178-179` 全局设置了
   `CMAKE_CXX_VISIBILITY_PRESET hidden` + `CMAKE_VISIBILITY_INLINES_HIDDEN ON`，实测 `build/` 里
   Engine2D 每个翻译单元的编译行都带 `-fvisibility=hidden -fvisibility-inlines-hidden`。
   所以"开 hidden 会让未标注符号立刻丢失"这个顾虑不成立——**丢失早就发生了**，现在能跨 DLL 用的
   1619 个符号，全部是 `ENGINE2D_API` 显式放出来的。
2. **真正的问题是标注粒度，不是可见性开关。** 99 处 `ENGINE2D_API` 打在**类**上，导出的是类的
   全部成员；其中生产侧真正在链接期引用的只有 **341 / 1627**（21%）。
3. **收敛是"把类级标注降为成员级 + 整类下线"，不是"加 `-fvisibility=hidden`"。**
   前者可以按类、按批提交并逐批验证；不存在"一次大改、只能整体回滚"的形态。
   原任务描述里"一次大改 + 回滚点"的前提与实测不符，方案据此调整（§5 说明为什么反而更安全）。
4. **一次性例外必须写进变更记录。** 收敛会删符号，违反 `Tools/Abi/check_exports.py` 的
   "只允许追加"。窗口定义：收敛各批次期间校验脚本**预期 FAIL**，REMOVED 行逐条对照批准清单；
   全部批次完成后，由用户批准执行**一次** `--update` 重建基线，之后纪律恢复为只追加，不再有第二次例外。
5. **收敛前必须先处理基线漂移。** 当前构建比基线**少 2 个、多 10 个**符号（螺旋残环改签名导致），
   现在跑 `check_exports.py Engine2D` 已经 FAIL。若不先让基线回到可解释状态，"本次删除"与
   "本来就漂移"无法区分。

## 2. 符号分类（实测分桶，不看头文件猜）

### 2.1 判定方法

三步交叉，缺一不可：

1. **符号来源**：`nm -gU` 取导出集 → `c++filt` 还原 → 按 owner（类/命名空间/第三方）归类；
2. **声明来源**：扫描 `Engine/2D/Include` 全部 119 个头，建立"类名 → 头文件 + 是否带
   `ENGINE2D_API`"的映射，判断该符号是否属于本模块公开面；
3. **真实引用**：对 `bin_Qt6/Release` 下全部产物做 `nm -u`，与导出集求交。生产侧只算
   6 个真实消费者（UI2D / Main / EnginePersistence / FileIO / UICommon / PyBind），
   其余 25 个测试与基准单列。

### 2.2 分桶结果（互斥，合计 1627）

| 桶 | 符号数 | 判定依据 | 处置 |
|---|---|---|---|
| **A. 必须导出** | **341** | 生产消费者 `nm -u` 有直接引用（含其 typeinfo/vtable） | 保留，标注不动 |
| **B. 类成员顺带导出** | **656** | 所在类有生产引用，但这些成员本身无任何生产引用（441 完全无引用 + 215 仅测试引用） | 类级标注降为成员级，只留 A 用到的 |
| **C. 整类可下线（仅测试引用）** | **179** | 所在类无生产引用，仅被 `Engine2DTests` 等测试/基准引用 | 先迁移测试，再整类撤标注 |
| **D. 完全无引用** | **359** | 无生产引用、无测试引用、非第三方 | 直接撤标注，风险最低 |
| **E. 第三方静态库泄漏** | **92** | 名字在 `Clipper2Lib::` 命名空间，本模块无声明、无消费者引用（86 函数 + 6 RTTI） | 不属于 API，构建期屏蔽 |
| **头文件内联模板实例** | **0** | `nm` 无 `W` 符号，`-fvisibility-inlines-hidden` 已生效 | 无需处理 |

> 交叉核对：47 个 owner 完全没有生产引用，共 630 个符号 = C(179) + D(359) + E(92)。
> 53 个 owner 有生产引用，共 997 个符号 = A(341) + B(656)。

### 2.4 需要注意的"分类陷阱"

- **`nm -u` 看不见虚函数分派**。消费侧通过基类指针调 `entity->computeBBox()` 时不产生未定义符号，
  只引用 vtable。实测 137 个导出符号是虚函数（按公开头 `virtual` 声明匹配），它们"无引用"不代表可删。
- **`typeinfo` 是 C++ 跨 DLL 的隐性必需品**。生产侧实测引用 9 个 `typeinfo for Eg::AprXxx`
  （UI2D 的 `BezierEditor/PolygonEditor/EllipseEditor/CircleEditor/SplineEditor/Bezier2Editor/ArcEditor`
  共 7 处 `dynamic_cast`）。删掉即静默返回 `nullptr`，不是链接错误。
- **vtable 被引用 = 消费侧直接构造该类型**。`vtable for Eg::AprSmartLine/AprPoint/...` 出现在
  生产引用里，说明这些类在 UI2D/Main 里 `new`，整类下线时不能碰。

## 4. 改造方案

### 4.1 宏：不新增语义，只改挂载位置

`Engine/2D/Include/Engine2D/Engine2DAPI.h` 现状正确（GCC/Clang 分支不分叉、一律
`visibility("default")`），**不需要改**。收敛只做两件事：

1. 把 99 处**类级** `class ENGINE2D_API Foo` 中的大部分降为**成员级** `ENGINE2D_API 返回类型 方法(...)`；
2. 对必须保留类级标注的类，明确写注释说明"为什么必须是类级"（RTTI / 消费侧构造 / 跨 DLL 继承）。

**必须保留类级标注的判定条件**（任一命中就不降级）：

- 消费侧对它做 `dynamic_cast`（实测 9 个 `typeinfo for Eg::AprXxx`）；
- 消费侧直接 `new` / `delete` / 按值持有（实测 15 个 `vtable for Eg::AprXxx` 被引用）；
- 消费侧继承的**具体类**（如各 `XxxBridge`）——但被继承的**纯虚接口**
  （`ILayerManagerObserver`、`IUndoRedoObserver`、`ISceneNotifier::IObserver`）dtor 已在头内
  `= default`，实测消费侧只引用 `addObserver/removeObserver`，接口本身**不需要**导出；
- 含跨 DLL 传递的 `std` 容器成员（模板实例化需要同一个符号）。

其余（`Geo2DPrimitives`、`Tessellator`、`PolygonAlgorithms`、`SnapEngine`、`UndoRedoManager` 等）
全部降为成员级。

### 4.2 模板与内联

- 实测无 `W` 符号，`-fvisibility-inlines-hidden` 已生效，**不需要额外处理**；
- 但**不要**把带 `ENGINE2D_API` 的成员函数改成 `inline` 放头文件——那会把符号从"导出"变成
  "每个镜像一份私有副本"，跨 DLL 的 `std::vector<Eg::X>` 释放会直接崩；
- 模板类/模板成员一律只留头内定义、不加导出宏（现状即如此，保持）。

### 4.3 `std::` 与 Qt 类型的跨 DLL 注意事项

- 公开头 **0 个 Qt include**，无需处理 Qt 容器/vtable；**94 个头**用 `std` 容器，
  这是本模块 ABI 的真实脆弱面：删除某个 `inline` 构造/析构会改变消费侧的实例化归属；
- **typeinfo/vtable 分裂是已知坑且已真实发生过**（Engine3D `AprMeshEntity` 在 UI3D
  `dynamic_cast` 静默失败，见 `CMake/AbiVisibilityGuard.cmake:1-35`）。
  本次收敛的防线有三条：
  1. 类级标注只降不撤（RTTI 必需的类保持类级）；
  2. `apr_check_export_macro_visibility(HEADERS Engine2DAPI.h)` 继续在配置期拦截宏写错；
  3. 验证清单里保留"UI2D 7 处 entity `dynamic_cast` 路径"的人工冒烟，不靠编译通过判定。

### 4.4 Clipper2 泄漏（92 个）的修法

`Clipper2::Clipper2` 是 **vcpkg 静态库**（`/Users/ms/vcpkg/installed/arm64-osx/lib/libClipper2.a`），
PRIVATE 链接进 Engine2D 后，其对象文件按自身编译期的**默认可见性**进入 dylib，`-fvisibility=hidden`
管不到别人的 `.o`。Windows 上因为只有 `__declspec(dllexport)` 才导出，**不存在这个问题**——
即这是 macOS/Linux 独有的泄漏。

推荐做法（不改第三方源码、不动 `Tools/`）：

- macOS：目标链接选项追加
  `-Wl,-unexported_symbols_list,<清单文件>`，清单写 `_ZN11Clipper2Lib*`、`_ZTI*Clipper2Lib*` 等通配；
- Linux：追加 `-Wl,--version-script,<脚本>`，只 `global:` 本模块导出模式；
- Windows：无需动作，验证清单里确认导出集不变即可。

清单文件放构建目录生成（由 `CMake/` 内脚本产出），**不进仓库**，避免变成第二份需要维护的基线。

### 4.5 与 ABI 纪律/版本的关系

- `DLL导出与ABI约定` §4.1 明确"删除导出符号 = 破坏性变更"，本次是**唯一一次**批量例外，
  窗口、批次、清单都在本文留痕；
- 收敛后引擎没有外部二进制消费者（仓内 6 个消费方同版本发布），因此不触发主版本 +1；
  但需在 `DLL导出与ABI约定` 的符号基线表里把 Engine2D 的 1619 改成收敛后的实测值，
  并注明"2026-11-12 一次性收敛，之后恢复只追加"。

## 5. 分批计划

**与原设想不同**：不需要"一次大改 + 回滚点"。因为 `-fvisibility=hidden` 已生效，每次撤标注都是
**纯删导出**，天然可以按类切分；只要每批单独提交、单独验证，回滚粒度就是"一个类"。

| 批次 | 内容 | 前置 | 出口门禁 |
|---|---|---|---|
| **B0 度量冻结** | 在独立目录 `build-abi-converge` 全量重建；导出 `symbols-before.txt`；生成"批准删除清单"（本文 §2 的 C/D/E 桶逐条列名） | 无（`Geometry/` 内的数字标为暂定，B5 时重测） | 重建后实测符号数与 §2 偏差 ≤ 5%；清单经用户确认 |
| **B1 第三方泄漏（92）** | 只改 `CMake/`：ld64 `-unexported_symbols_list` / version script；Windows 不动 | B0 | 全量构建通过；`nm` 中 `Clipper2Lib*` 清零；`Engine2DTests` 的 2 个 Clipper2 引用改由本地 `.a` 提供后仍通过 |
| **B2 完全无引用（359）** | 整类撤 `ENGINE2D_API` 或降到成员级；**只动 A 桶为空的类** | B1 | 生产 6 个消费者全部链接通过；UI 冒烟；测试预期失败项与清单一致 |
| **B3 仅测试引用（179）** | 先把测试改为不依赖（改走公开 API 或测试内自带实现），再撤标注 | B2 | `Engine2DTests`/`MainTests` 恢复全绿 |
| **B4 保留类成员级裁剪（656）** | 按类逐个提交：`SceneManager`(103→26)、`LayerManager`(92→51)、`GridSnapManager`(54→32)、`Tessellator`(46→6)…… | B3 | 每类一个 commit，逐类构建 + UI 冒烟 |
| **B5 Geometry 解冻（308）** | 另一条线合并后，对 `Geometry/` 做同样处理（生产引用仅 22） | 螺旋 WIP 落地、冻结解除 | 同上 |
| **B6 基线重建** | 用户批准后执行 `check_exports.py Engine2D --update`；更新 `DLL导出与ABI约定` §6 数字 | B2~B5 全部完成 | 之后纪律恢复"只追加"，不再有例外 |

**终态估算**：

- B2~B4 完成、Geometry 仍冻结：约 **649**（341 必需 + 330 冻结目录 − 22 重叠），降幅 60%；
- B5 完成后：约 **350~400**（仅剩生产必需 + RTTI/vtable/vtable 关联符号）。

**为什么不做 `-fvisibility=hidden` 开关切换**：该开关已在全局生效（`Config.cmake:178`）。

## 7. 风险清单（"删掉就一定炸"的几类）

| # | 风险类 | 为什么会炸 | 保护措施 |
|---|---|---|---|
| R1 | **跨 DLL `dynamic_cast` 的 typeinfo** | 类级标注撤掉 → typeinfo 变私有，`dynamic_cast` 静默返回 `nullptr`（Engine3D 已发生过一次） | 9 个实测被 cast 的 `AprXxx` 保持类级标注；UI 冒烟覆盖 7 处编辑路径；`AbiVisibilityGuard` 继续在配置期校验 |
| R2 | **消费侧 `new`/`delete` 的类** | vtable + ctor/dtor 必须可见；漏一个就是链接期 undefined | 以"vtable 被 `nm -u` 引用"为保留判据（实测 15 个 vtable），整类不降级 |
| R3 | **虚函数经 vtable 分派** | `nm -u` 看不到，看似"无引用" | 不按符号删类；只降成员级，保留 vtable 所在的类级可见性 |
| R4 | **跨 DLL 的 `std::vector/std::string` 成员** | 内联成员被隐藏后，消费侧生成私有副本，跨 DLL 释放堆内存崩 | 公开头 94 个含 STL 容器的类，`inline` 成员不动；模板成员只留头内定义 |
| R5 | **外部客户插件 / 客户 SDK** | 仓外编译，链接期才炸；本轮无法测量 | 发布说明列出删除清单；`Clients/_template` 只链 `UICommon`，无 Engine2D 直接依赖，风险中低 |
| R6 | **测试全面依赖导出面** | 546 个符号被 `Engine2DTests` 引用，隐藏后大面积链接失败 | 测试迁移单列 B3 批次，先改测试再撤标注；不与生产批次混提 |
| R7 | **基线漂移混入** | 当前已 −2/+10，"删除"与"漂移"无法区分 | B0 先重建并冻结基线；`before` 快照以收敛前一次完整构建为准 |
| R8 | **Clipper2 双份实例** | 现状 `Engine2DTests` 已有 2 个符号来自 dylib、其余来自本地 `.a`（split-brain） | B1 隐藏后全部落到本地 `.a`，用内缩 A/B 基准（`Engine2DOffsetBenchmark`）比对结果一致性 |

| R10 | **冻结目录误触** | `Engine/2D/{Src,Include/Engine2D}/Geometry/` 有另一条线在改 | 批次 B2~B4 的清单显式排除该目录；B5 单列并在解冻后执行 |
