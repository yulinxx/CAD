## 一、结论速览

### 1.1 严重级别统计

| 级别 | 数量 | 含义 |
|---|---|---|
| P0 | 3 | 数据损坏 / 安全状态机失效 / 不可恢复 |
| P1 | 28 | 明显可用性或一致性问题 |
| P2 | 22 | 体验债、入口缺失、反馈缺口 |
| 设计选择 | 9 | 自洽，不计缺陷 |

### 1.2 P0 摘要（必须优先处理）

| ID | 标题 | 一句话后果 |
|---|---|---|
| IX-P0-01 | 2D 布尔四命令全部退化为「并集」 | 用户选「差集/交集/异或」，实际执行并集，几何结果错误且只有日志告警 |
| IX-P0-02 | 3D 布尔/分割撤销后 B-Rep 永久丢失 | Ctrl+Z 后实体能看能选，但再布尔/分割报「需要 B-Rep」，STEP 导出静默跳过 |
| IX-P0-03 | 菜单急停与浮窗急停走两套状态机 | 从菜单急停后设备停了，但 UI 不进只读、不弹浮窗、不写闭锁；且软件闭锁无菜单可复位 |

### 1.3 三条系统性根因（多数 P1 由此派生）

1. **命令目录缺条目 → 菜单恒亮 + 参数富化被绕过。** `algo.fill / algo.offset / algo.array / algo.boolean_* / algo.relief_engraving / edit.move / edit.ungroup` 只有别名表，没有 `CommandCatalog` 目录条目（`UI/2D/Src/Operation/CommandCatalog.cpp:1028-1037`），`menuIdForCommandId` 返回 0（同文件 `:1219-1256`）。后果有两层：启用态永不刷新；分发退回 `OperationBus` 裸跑，跳过 `OperationRouting::dispatch` 的参数富化（`UI/2D/Src/Operation/OperationRouting.cpp:41-60`）。
2. **快捷入口绕过分发层。** 视口里裸建的 `QShortcut`（Delete/Backspace/Ctrl+A/F12/Esc）直接调 `OperationBus`（`Main/Src/UI/Workbench/Workbench2D.cpp:579-608`），绕过唯一的安全/可用性拦截点 `MenuDispatcher`（`Main/Src/UI/Workbench/MenuDispatcher.cpp:148-181`）。
3. **对话框默认值、算法默认值、Schema 默认值三套并存。** 同一物理量在对话框、参数结构、`DialogParameters`、`getParameters` 回退处分别写死，且已经漂移（详见 IX-P1-13、§4.2）。

## 三、缺陷清单

### 3.1 P0

#### IX-P0-01 2D 布尔四命令全部退化为「并集」

- **链条**：菜单 `Edit > Boolean`（`configs/base.json:105-108`，命令 ID `edit.boolean_union/intersection/difference/xor`）→ `MenuDispatcher::dispatch`（`Main/Src/UI/Workbench/MenuDispatcher.cpp:181`）→ `Workbench2D::dispatchCommand`（`Main/Src/UI/Workbench/Workbench2D.cpp:167-185`）→ `CommandCatalog::menuIdForCommandId` 返回 0（`UI/2D/Src/Operation/CommandCatalog.cpp:1219-1256`，因为 `Algo_Boolean*` 只在别名表 `:951-954`，没有目录条目）→ 回退 `operationBus->run(op, params)`（`Workbench2D.cpp:205-206`）→ 空 params → `Boolean2DTaskHandler::doPrepare` 缺 `booleanOp`，落到 `EBooleanOp::Union`（`UI/2D/Src/Algorithm/AlgorithmTaskRegistration2D.cpp:685-693`）。
- **代码自己已写明这个后果**：`OperationRouting.cpp:41-43` 注释「漏填的后果是 … 四个菜单项全部退化成 Union」；但该富化只在 `menuId != 0` 分支执行。
- **用户可见后果**：选「交集」得到并集面积；选「差集」得到并集；异或得到并集。界面无弹窗，只有 DEBUG/WARN 日志。
- **严重级别**：P0（几何数据错误）。
- **建议修法**：给四个布尔命令补 `CommandCatalog` 目录条目（`shortcutId` + `menuId` + `Cmd::RequiresMultiSelection`），或让 `Workbench2D` 的回退分支也调用 `OperationRouting::dispatch(op→menuId 映射)`。二者择一，不要加第二份映射表。

#### IX-P0-02 3D 布尔/分割撤销后 B-Rep 永久丢失

- **链条**：3D 布尔 `ModelOperations3D` → 先 `detachBRep(removedAId/BId)`（`UI/3D/Src/Operation/ModelOperations3D.cpp:381-382`）→ 三角化合成新体 → `pushReplaceUndo(ctx, {旧网格}, {新网格})`（`:402`）。分割同理（`:267`、`:295`）。`detachBRep` 会从服务里 erase 形状（`UI/3D/Src/Service/BRepModelService3D.cpp:204`）。
- **撤销实现**：`Engine/3D/Src/Edit/SceneUndoCommands3D.cpp` 全文只有 Transform 命令带 `BRepTransformCallback3D`（`:154-157`、`:270`、`:299`）；`ReplaceEntitiesCommand3D`（`:509`、`:564`）只恢复网格，没有 `attachBRep`。
- **用户可见后果**：Ctrl+Z 后实体能显示、能选中、能变换；但再次布尔/分割会报「需要 B-Rep」；STEP 导出在 `BRepModelService3D.cpp:465-498` 静默跳过该实体。用户唯一恢复手段是重做或重画。
- **严重级别**：P0（不可恢复的数据退化）。
- **建议修法**：`ReplaceEntitiesCommand3D` 携带 `entityId → shared_ptr<TopoShape>` 快照，undo 时 `attachBRep`，redo 时再 detach；删除命令同理。

#### IX-P0-03 菜单急停与浮窗急停走两套状态机

- **链条 A（菜单）**：`laser.emergency_stop` → `LaserOperationRegistry.cpp:172-192` → `host->requestEmergencyStop()` + `job->abortJob()`。**不调用** `EmergencyStopController::triggerEmergencyStop()`。
- **链条 B（浮窗）**：`EmergencyStopOverlay.cpp:119-131` → `controller->triggerEmergencyStop()` → 进入只读、显示浮窗、持久化闭锁（`Main/Src/UI/Safety/EmergencyStopController.cpp:117-127`）。
- **全仓搜索结果**：`triggerEmergencyStop` 只被 `EmergencyStopController.cpp` 自身与 `EmergencyStopOverlay.cpp` 调用；菜单链路完全没有。
- **用户可见后果**：从菜单（或快捷键）急停后，设备确实关光停机，但：主界面仍可编辑（`MenuDispatcher.cpp:148-169` 的只读门以 controller 状态为准，controller 未被置位）；急停浮窗不出现；闭锁未持久化，重启后状态丢失；菜单里又没有 `laser.reset_safety` 入口（`configs/base.json:233-239` 只有 4 项），软件侧复位无路可走。
- **严重级别**：P0（安全状态机不一致）。
- **建议修法**：`Laser_EmergencyStop` handler 内统一调用 `controller->triggerEmergencyStop()`，由 controller 再驱动 `host->requestEmergencyStop()`，保证菜单/浮窗/物理输入三条路径共用同一状态机；在 base.json 增加「复位安全」菜单项。
- **配套设计选择**：菜单急停 `canExec` 恒 true（`LaserOperationRegistry.cpp:188-191`）是刻意的，保留。

### 3.2 P1 — 文件 / 编辑

#### IX-P1-01 视口裸 `QShortcut` 绕过统一分发与安全门

- **证据**：`Main/Src/UI/Workbench/Workbench2D.cpp:579-588`（Delete/Backspace 直连 `deleteSelectedShapes`）、`:591-597`（Ctrl+A 直接 `operationBus->run(Edit_SelectAll)`）、`:604-608`（F12 截图）。
- **后果**：`MenuDispatcher.cpp:148-169` 的急停只读门对这三个键无效；`Workbench2D.cpp:853-861` 菜单判锁里的「图元锁」也不生效（`SceneEditService` 删除只查图层锁）。用户在急停锁定态仍能删除；图元级锁定对象仍可被 Delete 删除。
- **建议**：把 Delete/Ctrl+A/F12 改为 `dispatchCommand("edit.delete")` 等命令 ID；在 `SceneEditService::deleteSelected` 补图元锁校验（菜单判锁与执行层同一规则）。

#### IX-P1-02 Ungroup 空操作也入栈 →「要按两次 Ctrl+Z」

- **证据**：`edit.ungroup` 只有别名（`UI/2D/Src/Operation/CommandCatalog.cpp:948`），无目录条目 → 无启用规则；`SceneEditService::ungroupSelected` 后无条件 `pushExecutedCommand`（`Engine/2D/Src/Edit/SceneEditService.cpp:522-539`；`SceneManager::ungroupSelected` 空选在 `SceneManager.cpp:1256` 直接 return）。before/after 相同仍压一条 `GroupStateCommand`。
- **后果**：空选或未分组对象点 Ungroup，第一次 Ctrl+Z 无任何视觉变化，用户以为撤销失效。
- **建议**：`before == after` 时不压栈；补 `Cmd::RequiresGroupedSelection` 启用规则。

#### IX-P1-03 圆角/倒角一次动作产生 3 条撤销记录

- **证据**：`Engine/2D/Src/Edit/FilletChamfer.cpp:158/172/189` 三次独立写回（`UiEdit.cpp:170` 三处 `CommitMode::Undoable` 且 `bMergeIntoLast=false`）。
- **后果**：一次 F 圆角要连按 3 次 Ctrl+Z 才回到操作前；与既有口径「一条命令一次提交」冲突（`Docs/激光加工前处理分层规划.md:110-121`、`Docs/激光加工软件完善度总账.md:366`）。
- **建议**：整批用显式事务（总账 A22 计划中的 `beginTransaction/commitTransaction`，`Docs/激光加工软件完善度总账.md:1451`）或传 `bMergeIntoLast=true` 合并。
- **附**：`EditOperationRegistry.cpp:167-203` 忽略 `applyFillet` 返回值、半径默认 5.0 硬编码、`parent=nullptr`，失败静默。

#### IX-P1-04 PasteText / PasteImage 启用态反向

- **证据**：三条粘贴命令全部声明 `Cmd::RequiresClipboard`（`UI/2D/Src/Operation/CommandCatalog.cpp:325-350`）；而剪贴板快照 provider 只看图元剪贴板（`Main/Src/UI/Workbench/Workbench2D.cpp:933-935`，`Engine/2D/Src/Core/EntityClipboard.cpp:102-105`）。菜单项因此：复制图元后 `Paste as Text` 反而亮；剪贴板只有文本/图片时菜单是灰的，但快捷键（Ctrl+Shift+V / Alt+V）走裸总线可执行。
- **后果**：菜单与快捷键行为不一致；点了必弹 `Clipboard does not contain text...`（`Main/Src/Composition/EditOperationRegistry.cpp:362-367`）。
- **建议**：快照拆成 `hasEntities / hasText / hasImage` 三个布尔，分别对应三个命令。

#### IX-P1-05 New/Open 不复位图层，跨文档污染

- **证据**：`FileOperationRegistry::resetDocumentState` 只清路径/撤销/脏标记（`Main/Src/Composition/FileOperationRegistry.cpp:164-191`）；`SceneManager::clearScene` 只清图元（`Engine/2D/Src/Core/SceneManager.cpp:1061`）；`LayerPersistenceBridge::setDocumentId` 仅换 key（`Main/Src/Persistence/LayerPersistenceBridge.cpp:23-26`）。打开文件时同名图层直接复用旧属性（`ImportService.cpp:1115-1123`）。
- **后果**：New 之后仍看到上一文档的图层；Open 会把上一文档同名图层的颜色/锁定/输出/工艺参数带到新文档。
- **建议**：New/Open 时重建 LayerManager 默认层并清图层持久化键；或在文档切换时显式 reload。

#### IX-P1-06 导入「落库阶段」可重入

- **证据**：进度框是非模态（`ImportProgressRunner.cpp:152-159`），落库在主线程但 `processEvents` 泵消息（`ImportService.cpp:794`）；只在落库期禁用取消按钮（`ProgressDialog.cpp:183-186`），没有 busy 门。
- **后果**：导入写入过程中可以 New/Open/编辑；二次 Open 会取消首个导入并在第二个结束后弹「Import canceled」（`ImportService.cpp:445-467`）；场景与图层可能写进新文档。

#### IX-P1-07 用户取消导入被当成错误弹窗

### 3.3 P1 — 2D 算法与绘制

#### IX-P1-08 `algo.*` 无目录条目 → 菜单恒亮

- **证据**：`algo.fill / algo.offset / algo.array / algo.nesting / algo.relief_engraving` 只在别名表（`UI/2D/Src/Operation/CommandCatalog.cpp:1028-1037`），`kCommands` 无条目 → `menuIdForCommandId == 0`（`:1250-1255`）→ `CommandActionHubActions2D::applySnapshotToAction` 对 `menuId==0` 直接早退（`UI/2D/Src/Operation/CommandActionHubActions2D.cpp:546-549`）→ 动作永远 `enabled=true`。
- **后果**：无选中、锁定图层、加工中都能点；点了靠 handler 内 `prepare` 兜底，校验层级错位；菜单灰显与真实可用性不一致。
- **对比**：`Algo_BitmapProcess / Algo_VectorizeBitmap` 有目录条目（`CommandCatalog.cpp:825-838`），所以这两项灰显是对的。
- **建议**：补目录条目与启用规则（Fill/Offset/Array/Relief 至少 `Cmd::RequiresSelection`；Relief/Vectorize 还需 `Cmd::RequiresBitmapSelection`）。

#### IX-P1-09 填充命中锁定图层仍报「成功」，用户零反馈

- **证据**：`AlgorithmTaskRegistration2D.cpp:381-389` 锁定图层时跳过写场景，只 `SY_WARN`；`:414-415` 仍 `result.success = true`、`message = "Fill completed"`。
- **后果**：用户点确认后什么都没发生，却没有任何提示或失败标记。
- **建议**：锁定图层应 `success=false` + `errorCode=LockedLayer`，由 `AlgorithmRunner.cpp:130-134` 统一弹框。

#### IX-P1-10 取消不真中止（Fill / Offset / Boolean）

- **证据**：`AlgorithmTaskRegistration2D.cpp:212-216` 与 `:252-259` 只在计算前后检查 `isCancelled`，计算本身不可中断；落库阶段 `ProgressDialog.cpp:181`、`:202` 禁取消，`doApply` 只读 `m_cancelled`，无法阻断写回（Fill 写回在 `:368-389`，Offset 在 `:596-628`，Boolean 在 `:756-768`）。
- **后果**：进度条上的 Cancel 只能在两个窗口期生效；大图形填充时按取消经常「取消成功但仍写入」或「毫无反应」。
- **正面对照**：阵列是正确样板，`ArrayProcessor.cpp:80-89` 接 `cancelRequested` + `progressCallback`。
- **建议**：把可取消性做成 handler 契约（compute 支持分段检查、apply 前最后一次检查），并在 apply 前查 `isCancelled` 后直接返回 `userCancelled`。

#### IX-P1-11 偏移 / 布尔不校验锁定图层就删源

- **证据**：Offset `:596-628`、Boolean `:756-768` 直接 `deleteEntitiesBatch(m_entities)`；只有 Fill 有 `isAnyEntityOnLockedLayer`（`:382`）。
- **后果**：锁定图层上的图形会被偏移/布尔静默删除。
- **建议**：删除前统一走 `SceneEditService` 的锁定校验，或在 prepare 阶段统一拒绝。

#### IX-P1-12 位图处理缺交互栅栏与取消入口

- **证据**：`RasterProcessOperation2D.cpp:300-420` 只自身 busy，未接 `UiInteractionGate`；`AsyncPipelineExecutor` 的 `requestCancel` 只被 shutdown 调用；`:188-230` 无选中时回退处理**全部**图像（注释称「第一张」）；`:401`、`:413` 空结果静默。
- **后果**：位图处理期间可编辑/删源；用户无法取消；无选中时一次处理整场景所有位图（耗时与内存不可预期）。
- **建议**：接入统一 busy 门；把 `requestCancel` 暴露到进度框；修正「第一张」语义或明确提示「将处理 N 张」。

#### IX-P1-13 参数默认值四处写死且已漂移

- **证据（填充）**：对话框 `FillDialog.cpp:438` 角度默认 33.3，而 `Engine/2D/Include/.../FillParameters.h:31` 为 0.0；色容差 `FillDialog.cpp:520` 为 3，而 `ColorFillParameters.h` 为 0.01；`DialogParameters.h:284-314/429-441` 是第三套；`FillDialog.cpp:864-875` 的 `getParameters` 回退是第四套。填充间距 1.0mm 在 `Docs/轮廓偏移填充设计.md:383-402` 已作为「定案默认值」记录，本次补充的是**多处副本清单**，不重复立项。
- **证据（偏移）**：`OffsetDialog.cpp:199` 连接方式默认 Square，而 `OffsetParameters.h:27` 默认 Round；`OffsetDialog.cpp:276-309` 另有回退副本。
- **用户可见后果**：用对话框默认值跑出来的结果与引擎/测试默认值不同；同一操作在不同入口得到不同几何。
- **建议**：默认值只保留一处（建议放进 `Eg::ProcessContract` 或参数结构），对话框从结构读默认；总账 `Docs/CAM契约重构设计.md:128-144` 已记录该方向，本次复用该结论。

### 3.5 P1 — CAM / 硬件 / 视觉

#### IX-P1-20 加工命令菜单恒亮、拒绝静默

- **证据**：菜单启用态只判「命令是否注册」（`UiLayoutBuilder.cpp:217-243`）；`Cmd::Always` 条目永不写 enabled（`UI/Common/Include/UI/Command/CommandActionHubBase.h:108-111`）；`OperationBus` 拒绝只打 DEBUG（`UI/2D/Src/Operation/OperationBus.cpp:71-82`）；`MenuDispatcher::dispatch` 不看返回值（`MenuDispatcher.cpp:176-181`）。

#### IX-P1-21 加工进度、完成、部分成功不可见

- **证据**：`jobProgress`、`jobWarning` 只 emit（`ProcessingJobService.cpp:491-495`、`:799`）；生产代码只有 DevicePanel 连 `started/finished/stateChanged`（`DevicePanel.cpp:98-117`），全仓只有测试连 `jobProgress`。无进度条、无完成提示；「部分参数生效」警告被吞。

#### IX-P1-22 abort 失败仍显示「加工中」；急停闭锁无 UI 复位

- **证据**：`abortJob` 失败直接返回、不 `finishJob`（`ProcessingJobService.cpp:673-679`）；急停路径忽略 abort 结果（`LaserOperationRegistry.cpp:182-186`）。急停执行器把 `EmissionGuard` 置 Latched（`DeviceHost.cpp:147-160`、`EmissionGuard.h:105-109`）；`confirmReset` 只清软件急停（`EmergencyStopController.cpp:129-149`），无 UI 调 `acknowledgeSafetyCutoff`（仅 `ProcessingJobService.cpp:700-712` 与测试）。
- **后果**：复位后 `active` 仍为 true，Start 灰、Stop 亮，表现为「卡在处理中」；确认复位后仍不能出光，只能重启。
- **建议**：abort 失败也要本地 fail-safe 收尾并提示；Confirm Reset 同时确认解除出光闭锁，或新增「确认出光」命令。

#### IX-P1-23 物理急停不进入 UI 急停态

- **证据**：`EmergencyStopController.cpp:152-168` 只在已 `EmergencyStopped` 时才检测输入；物理急停上升沿不会触发 `triggerEmergencyStop`，UI 不锁定、不持久化，仅 `SafetyMonitor.cpp:248-263` 拦启动。
- **后果**：操作员按下物理急停后软件界面看起来一切正常，仍可编辑；恢复时容易误判。
- **建议**：物理输入上升沿同样进入急停态（与 IX-P0-03 同一状态机）。

#### IX-P1-24 大量硬件/视觉动作不可达；自动连接失败无重试

- **证据**：只注册 5 个激光命令（`LaserOperationRegistry.cpp:214`）；Connect/Home/TestFire/MaterialDB/ProcessParams/SelfCheck 只在目录（`CommandCatalog.cpp:643-733`），base 菜单只有 4 项（`configs/base.json:233-239`）。Vision 11 个 Test 操作只有目录（`CommandCatalog.cpp:735-820`），无 registry/handler/菜单。
- **后果**：用户看不到「连接设备/回零/试打光/材料库/工艺参数」；启动自动连接失败后没有恢复路径。Vision 实际不可达，所以「测试结果写回/撤销」也不存在。
- **建议**：补齐入口，至少提供 Connect 与错误重试；Vision 明确标注为未启用而不是留死条目。

### 4.1 文件 / 编辑

**导入 DXF（主链）**
`菜单 file.import_dxf` → `MenuDispatcher::dispatch`（`MenuDispatcher.cpp:181`）→ `Workbench2D::dispatchCommand` → `OperationBus` → `FileOperationRegistry` handler → `FileDialogService::getOpenFileName` → `ImportService` → 解析工作线程 → `ImportProgressRunner` → 主线程 `processEvents` 落库（`ImportService.cpp:794`）→ `SceneManager`（`CommitMode::Direct`，无撤销，`ImportService.cpp:796-801`）→ 最近文件 → 状态栏。
- 取消：仅解析期有效；落库期按钮被禁（`ProgressDialog.cpp:183-186`）。
- 失败：统一 `QMessageBox`，连主动取消也弹（IX-P1-07）。

**保存（主链）**
`Ctrl+S` → `file.save` → `FileDialogService::getSaveFileName` → 同步写盘 → `resetDirty` / `setCurrentFilePath` / 图层 docId / 最近文件（`FileOperationRegistry.cpp:208-228`）。
- 缺陷：允许 .dxf/.svg 走 Save，导致「已保存」与「原生文档未保存」混淆（IX-P2-05）。

**删除（快捷键链）**
`QShortcut(Key_Delete)`（`Workbench2D.cpp:579`）→ `deleteSelectedShapes` → `SceneEditService::deleteSelected`（只查图层锁）→ `DeleteEntitiesCommand`（1 条撤销）。
- 与菜单链（`edit.delete` → `MenuDispatcher` 安全门 + `Workbench2D.cpp:853-861` 判锁）不一致（IX-P1-01）。

**撤销链**
`Ctrl+Z` → `edit.undo` → `MenuDispatcher`（急停只读时被拦）→ `OperationBus` → `UndoRedoManager::undo` → 命令反向应用 → 视图刷新。
- 例外：Delete 等裸快捷键不进此链；Fillet 一次动作 3 条（IX-P1-03）。

**Ungroup 链**
`edit.ungroup` → 无目录条目 → `OperationBus` → `SceneManager::ungroupSelected`（空选 return）→ `SceneEditService` 无条件压 `GroupStateCommand`（IX-P1-02）。

### 4.2 2D 算法

**填充链**
`algo.fill` → `Workbench2D` 回退分支（无 menuId）→ `OperationBus` → `AlgorithmRunner` → `AlgorithmApplicationService::runAsync` → `FillTaskHandler`
→ prepare：场景/选中校验（`AlgorithmTaskRegistration2D.cpp:190`）→ `AlgorithmTaskUiHost2D::collectFill` 弹 `FillDialog`
→ compute（`:210-260`，进度 0.02 → 1.0）
→ apply（`:355-415`，`runAsSingleUndoStep` 包一层 batch）
→ 结束回调 → 失败弹框（`AlgorithmRunner.cpp:130-134`）或状态栏。
- 锁定图层：跳过写回但 `success=true`（IX-P1-09）。
- 取消：仅两个窗口期生效（IX-P1-10）。

**偏移链**
`edit.offset` / `algo.offset`（两入口同 OperationId）→ 同样走无目录条目回退 → `OffsetTaskHandler` → `OffsetDialog` → `EntityOffset` → `Geo2DOffset::offsetContours` → 批量写回 + 删源。
- 删源不查锁定（IX-P1-11）；默认连接方式与引擎不一致（IX-P1-13）。

**布尔链（缺陷主链）**
`edit.boolean_*` → `menuIdForCommandId == 0` → `bus->run(op, {})` → `Boolean2DTaskHandler` → 缺 `booleanOp` → `Union`（IX-P0-01）。

**阵列链（正确样板）**
`algo.array` → `ArrayTaskHandler` → `ArrayDialog` → `ArrayProcessor`（`ArrayProcessor.cpp:80-89` 支持取消与进度）→ 主线程写回 1 条撤销。

**圆角/倒角链**
`edit.fillet` → `EditOperationRegistry` → `applyFillet`（返回值被忽略）→ `FilletChamfer.cpp:158/172/189` 三次写回 → 3 条撤销。

### 4.3 3D

**创建图元**
`model.make_box` → `Workbench3D::dispatchCommand` → `OperationBus` → `ModelOperations3D::makeBox` → 固定尺寸 → `BRepModelService3D::tessellateToEntity`（失败时弹框，`ModelOperations3D.cpp:91-100`）→ `pushReplaceUndo` 1 条。
- 无参数对话框（IX-P1-19）。

**布尔/分割**
`model.boolean_fuse` → `ModelOperations3D` → `detachBRep` → 三角化 → `pushReplaceUndo`（只网格）。
- 撤销丢 B-Rep（IX-P0-02）；三角化失败回滚不 `attachBRep` 且只 WARN（`:386-394`）。

**Display 勾选**
`view.grid` → `MenuDispatcher` → `dispatchCommand`（无 `checked`）→ `ViewOperations3D` 默认 true → 互斥组取消其他项（IX-P1-14）。

**Nesting**
`algo.nesting_from_mesh` → `AlgorithmRunner3D` → `runSync`（无进度）→ `AlgorithmTaskRegistration3D` → 仅 `mesh->translate` + 单位矩阵 undo → 空结果 success（IX-P1-16/17）。

### 4.4 CAM / 硬件 / 视觉

**开始加工**
`laser.start_process` → `LaserOperationRegistry.cpp:71-120` → `ProcessingJobService::beginJob`（门控 host/active/running/canStart，`ProcessingJobService.cpp:368-393`）→ `MotionPlanCompiler`（同步，`:446`）→ 下发/工作线程 → `jobProgress`（无 UI 消费）。

**急停**
菜单链：`LaserOperationRegistry.cpp:172-192`（不碰 controller）。

- 两条状态机（IX-P0-03）；abort 失败/出光闭锁无复位（IX-P1-22）。

### 4.5 全局设置

**主题**
`theme.dark` → `MenuDispatcher.cpp:101-106` → `WorkbenchWindow::triggerTheme` → `SettingsService::saveTheme` → `ThemeManager`（全局样式）→ 状态中心记录 → 菜单勾选回填。画布不刷新（IX-P1-25）。

**语言**

## 五、设计选择（不计缺陷）

1. **急停菜单恒可点**：`LaserOperationRegistry.cpp:188-191` 明确注释「任何 canExec 判断都可能把它变灰」，保留。
2. **导入不进撤销栈**：`ImportService.cpp:796-801` 用 `CommitMode::Direct`，为省内存；打开文件本身不可撤销。
3. **进度框应用阶段禁取消**：`ProgressDialog.cpp:181/202`，语义是「落库不可中断」——但应与「计算阶段可取消」配合（见 IX-P1-10）。
4. **Gizmo 拖动一次撤销**：`RenderWidget3D.cpp:2920-2946`、`:3122-3145` 拖动期只改预览矩阵，释放时烘焙；Esc 回起点（`:3613-3630`）。**没有撤销爆炸**。
5. **Split by Picked Plane 两阶段回调**：取消即清状态，不留半成品。
6. **主题勾选以 ThemeManager 为真相**：`WorkbenchMenuManager.cpp:820-825`，System 勾 System 而非解析皮肤。
7. **图层管理器无 OK/Cancel、即时写回**：符合「图层属性实时预览」习惯；撤销只能在关闭后用。
8. **快捷键按工作台分文件**：`UiShortcutRegistry::beginBuild` 同作用域复用内存覆盖，语言重建不丢用户覆盖（`UiShortcutRegistry.cpp:52-63`）。
9. **Nesting 用 XY 包围盒作 footprint**：`AlgorithmTaskRegistration3D.cpp:97-119`，有意的粗粒度简化。
