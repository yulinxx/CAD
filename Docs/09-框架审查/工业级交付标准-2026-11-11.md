## 0. 等级与判定口径

| 等级 | 含义 | 未满足时的后果 |
|---|---|---|
| **必须（M）** | 对外交付的准入条件 | 不得发版、不得交付客户现场 |
| **应当（S）** | 影响长期维护成本或现场效率 | 必须有书面豁免（记录风险、责任人与到期时间），否则视同 M |
| **可选（O）** | 视客户合同/机型而定 | 不阻塞交付 |

判定方式只允许以下四类，任何一条要求必须落到其中至少一类：

1. **命令**：可直接复制执行的 shell 命令（含退出码/输出判据）。
2. **CI job**：`.github/workflows/*.yml` 中具名 job，失败即阻断合并。
3. **测试**：可执行的测试用例名（gtest），`ctest -R <pattern>` 可复现。
4. **指标**：可测量的数值阈值（帧时、内存、覆盖率、恢复时间）。

术语：
- **当前状态** 取 2026-11-11 工作树。
- **目标状态** 是达标后的最小可接受形态（不做超配）。
- **差距** 指向评审报告的具体章节与证据位置。

## 7. 验收执行清单（命令级）

以下命令构成一次完整验收；任一非零退出即验收不通过。

```bash
# 1) 配置与门禁（依赖方向 / include 棘轮 / 写面 / 导出宏可见性）
cmake -B build-verify -G Ninja -DBUILD_TESTS=ON -DBUILD_HARDWARE=ON

# 2) 全量构建
cmake --build build-verify --parallel

# 3) 测试（不允许 0 测试通过）
ctest --test-dir build-verify --output-on-failure --no-tests=error

# 4) 安装包
cmake --build build-verify --target package
# macOS: codesign --verify --deep --strict <app> && spctl -a -vv <app>
# Windows: signtool verify /pa <installer>

# 5) 数据安全演练（人工，记录在验收单）
#   编辑 → kill -9 → 重启 → 恢复成功
#   连续保存两次 → .bak 存在且可打开
#   拔设备 → 30s 内重连

# 6) 追溯验收
sqlite3 "$HOME/Library/Application Support/SanYiCAD/data/cad_database.sqlite" \
  "select id, started_at, operator, doc_path, result from machining_jobs order by id desc limit 1;"
```
