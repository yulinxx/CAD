## 0. 结论速览

- **原理一句话**：虚线不是 Qt 画笔（没有 `QPainter` / `QPen` / dash pattern），而是把选中图元先离散成「带累积弧长的世界坐标折线」，再由 `OverlayScene` 按**物理像素**换算的 dash/gap 沿弧长切成一堆独立线段，每帧重新切一遍，相位由单一时钟推进的全局像素偏移驱动，最终作为一条 `Lines` 拓扑的绘制指令提交。
- **最严重的问题**：默认设置下这套动画**看不见**——虚线与图元本体同色、同几何、叠画在上面，且「隐藏原图」默认关闭（`selection/hide_original=false`），所以 60Hz 定时器 + 每帧全视口重绘换来的是零视觉变化。
- **性能结论**：默认预算（2000 图元 / 20 万轮廓顶点）下，每帧的虚线展开是「两遍全量遍历 + 两次整块内存拷贝」，按代码事实推算单帧顶点写放约 11MB、内存流量约 22MB，60Hz 即 ~1.4GB/s；真正的重头不是虚线本身，而是**动画每 16ms 触发一次整视口全量重绘**（`NoPartialUpdate`）。
- **建议一句话**：先去掉重复描边（让动画可见）、再去掉两遍展开与视口外计算（纯收益）；结构上把「覆盖层独立重绘」或「GPU 侧虚线」作为中期方案。

### 1.2 阶段 A：选择状态 → 轮廓折线（只在选择/缩放/预算变化时发生）

- 轮廓来源是 `SelectionGizmo` 把选中集解析成实体指针数组后交给 `drawSelectionOutline`（`SelectionGizmo.cpp:919-922`）。
- **缓存键**：实体 ID 集合指纹（XOR+旋转）+ `log2(pixelToWorld)/0.5` 量化档位 + 预算参数；命中即复用，不重新离散（`SelectTool.cpp:218-274`）。缩放档位变化（约 41% 比例变化）会触发一次全量重离散。
- **预算裁决**：图元数 > 2000 或离散后顶点总数 > 200000 时直接丢弃整批轮廓、只留包围盒，并打一条 skip 日志（`SelectTool.cpp:283-309`，默认值见 `UI/2D/Include/UI2D/Settings/SettingsKeys2D.h:151-152`）。
- **离散**：曲线类图元按 0.25px 弦高误差离散（`SelectionOutlineBuilder.cpp:29`），再做虚线专用细化（最大边长 8px、尖角收紧到 20%、单路径顶点上限 4096）（`SelectionOutlineBuilder.cpp:31-36 / 129-192`）。`LINE`/`POLYGON` **不细化**（`SelectionOutlineBuilder.cpp:213-227`），因为直线段插值即可，只在拐角保真。
- **弧长参数化**：`appendPolyline` 逐点累加长度写入 `arcLength`，闭合路径在末尾补一个 `arc = total` 的首点副本（`SelectionOutlineBuilder.cpp:386-404`）。
- **颜色**：`entity->getColor()`（`SelectionOutlineBuilder.cpp:469`），与场景本体取色同源（`Tessellator.cpp:262`），见缺陷 D1。

### 1.3 阶段 B：虚线的「画笔」实际上是弧长切分

- 没有 dash pattern 对象。`dashLengthPx` / `gapLengthPx` / `speedPxPerSec` 存在 `SelectionDashStyle` 中（`RenderBridge/Include/RenderBridge/RenderBridgeTypes.h:55-63`），经 `ViewRenderCoordinator` 逐字段中转（`ViewRenderCoordinator.cpp:348-360`）。
- 每帧在 `OverlayScene::submit` 里把三个像素量乘 `pixelToWorld`（`OverlayScene.cpp:764-770`），然后由 `appendSelectionDash` 沿弧长推进：
  - `period = dash + gap`，`phase = fmod(offset, period)`（`OverlayScene.cpp:198-211`）；
  - 单向前进游标 `advance` 找区间所在折线段（`OverlayScene.cpp:216-222`），`posAt` 在段内线性插值（`223-229`）；
  - dash 区间内把原始拐点原样穿进去（避免虚线抹平拐角）（`248-259`）；
  - 关闭 dash 时整体实线：`dash = 1e9`（`OverlayScene.cpp:768`）。
- 产物 `segs` 是独立线段点对，逐点带路径颜色，最后**整个选中集只生成一条 DrawInstruction**（`OverlayScene.cpp:797`），没有逐图元 draw call。

### 1.4 阶段 C：相位推进与重绘

- 定时器：`QTimer`，间隔 `kSelectionDashIntervalMs = 16`（约 60Hz，`RenderWidget.cpp:51 / 118-119`）。
- 相位变量：`m_selectionDashOffsetPx`，**RenderWidget 成员，全局唯一**（所有选中图元共享同一相位），声明于 `UI/2D/Include/RenderWidget.h:624`。
- 推进：用实测 dt（`m_selectionDashClock.restart()`）避免速度随帧率漂移，再对 `period` 取模防浮点尾数退化（`RenderWidget.cpp:121-131`）。
- 重绘请求：`QWidget::update()`（**整个控件**），不经过刷新调度器，也不限定脏区（`RenderWidget.cpp:132`）。
- 启停：每帧末尾 `updateSelectionDashTimer()`，判据是 `OverlayScene::hasAnimatedSelectionOutlines()`（路径非空 + `enabled` + `animated` + `speed > 0`）（`RenderWidget.cpp:1101 / 585-608`，`OverlayScene.cpp:636-640`）。停止时同时 `m_selectionDashClock.invalidate()`，重启时 `restart()`，避免首个 tick 的 dt 尖峰（`RenderWidget.cpp:596-607`）。

### 1.5 阶段 D：最终描边

- `emitWorld` 走 `emitAs`：从瞬态环 `allocTransient` 申请字节、整块 `memcpy`、填 `DrawInstruction`（`Lines` 拓扑、`World` 空间、`PositionColorAlpha`、overlay 层 200 + 透明混合位）（`OverlayScene.cpp:54-100`）。
- 线宽未设置（`lineWidth` 保持默认 0），后端回落到 1 像素（`RenderAbstraction/Include/RenderAbstraction/IRenderTypes.h:249`；`Renderx/src/rt/rxSession.cpp:471-475`）。
- 提交不经过视口裁剪：`packet.enableCulling = false`（`RenderWidget.cpp:1014`），overlay 也没有 view volume，只有 GPU 的光栅阶段会丢掉视口外图元。

### 1.6 与题设假设的差异（重要）

审查要求里描述的「虚线画笔（dash pattern）生成与应用」「`paintEvent` 里如何描边」在本实现中**都不存在**：

- 没有 `QPainter`、没有 `QPen`、没有 `QPainterPath`、没有 `setDashPattern` / `setDashOffset`；
- `paintEvent`（Metal 分支，`RenderWidget.cpp:226-232`）只是帧泵，真正绘制由 Renderx 后端完成；
- 因此「每帧重建 QPainterPath/QPen」这一常见代价在这里**不成立**，真正的每帧代价 = 弧长切分 + 顶点写放 + 内存拷贝 + 整视口重绘。

## 2. 逻辑问题

严重度按「对用户可见 / 对性能影响 / 是否真 bug」排序。

### D1（严重，产品可见性）默认设置下虚线完全不可见

- 虚线颜色 = 图元自身颜色（`SelectTool.cpp:317`、`SelectionOutlineBuilder.cpp:469`），与本体同源（`Tessellator.cpp:262`）。
- 「隐藏原图」默认关闭：`m_hideSelectedOriginal{ false }`（`RenderWidget.h:585`）、`SELECTION_HIDE_ORIGINAL = false`（`SettingsKeys2D.h:150`）、读取处 `SettingsUiCoordinator2D.cpp:243-244`。
- overlay 层 200 画在图元层之上（`OverlayScene.cpp:25`），几何位置与本体完全重合、颜色相同、线宽同为 1px（见 1.5）。
- 结果：默认状态下用户看到的是「实线 + 包围盒 + 橙色起点小方块」，虚线被本体的实线完全吞掉；而 60Hz 定时器与整视口重绘照常在跑。这不是渲染 bug 而是**选中态视觉设计自相矛盾**：注释明确写了「虚线是本体视觉的替代品」（`SelectTool.cpp:314-316`、`Docs/03-渲染主链/虚线.md:87`），但替代关系默认不生效。
- 判定：**确认缺陷**（严重度按「功能不可见 + 持续消耗」计）。修法见建议 C1。

### D2（中）拖动变换期间虚线冻结在按下时的位置

- 拖拽 `SelectionGizmo::onMouseMove` 只调 `repaintHandles()`，并明确注释「拖拽交互中只重绘手柄，不触发轮廓离散化」（`SelectionGizmo.cpp:625-629`）。
- `SelectTool` 只在选择集同步时才重建轮廓（`SelectTool.cpp:1207-1214`），拖拽期间该路径不会被逐帧触发；变换回调只做 `invalidateOutlineCache()` + `notifySceneChanged()`（`SelectTool.cpp:636-640`）。
- 结果：手柄和包围盒跟着走，虚线停留在按下瞬间的几何位置，到 `onMouseRelease` 才统一重建（`SelectionGizmo.cpp:691-694`）。
- 判定：**确认缺陷**（视觉不一致）。它是刻意的性能取舍，但代价被隐藏了——用户会看到「选中框在动、虚线不动」。建议至少对**当前拖拽的那批图元**做轻量路径平移（几何整体平移时只改顶点坐标、不重离散），见建议 A5。

### D3（中）长轮廓被静默截断，且预算口径不覆盖虚线展开

- 单路径段数上限 `kMaxSegmentsPerPath = 16384`，达到即 `break`（`OverlayScene.cpp:194 / 240-243 / 252`）。
- 16384 段 ≈ 32768 个点；按 18px 周期（10+8），约 147k～295k 屏幕像素弧长就会触顶——高倍放大下的长闭合轮廓（如大圆）会少画一截，**且没有任何日志**（对比预算丢弃有 skip 日志，`SelectTool.cpp:295-299`）。
- 预算只统计轮廓顶点（`SelectTool.cpp:286-301`），而虚线展开后的点数可达轮廓点数的 1.5~2 倍，所以「顶点数没超预算但仍被截断」是可能的。
- 判定：**确认缺陷**（低成本可观测性问题 + 高缩放下可见的轮廓缺失）。

### D4（低）闭合轮廓首尾相位不连续

- 展开循环从 `s = phase`、`drawing = true` 开始，走到 `total` 结束（`OverlayScene.cpp:231-271`），闭合路径在 `arc = total` 处不回绕到 0。
- 因此首尾接缝处：（a）起点前 `phase` 长度是空白；（b）终点可能正好截断一个 dash。除非 `total` 是 `period` 的整数倍，接缝处图案必然间断。
- 现有橙色起点方块标记（`SelectTool.cpp:243-263 / 350-373`）在视觉上掩盖了一部分，但它本身不是虚线的一部分。
- 判定：**确认缺陷**（低，接缝处 dash 长度突变）。

### D5（低）相位没有重置点，且注释与实现不符

- `m_selectionDashOffsetPx` 全仓只有三处引用（写 `RenderWidget.cpp:125/130`、读 `1089`），**没有任何复位**：换选择、缩放、关闭再开启动画都接着上次的相位。
- `SelectionGizmo.cpp:660-662` 的注释声称「完整 repaint() 会重新提交 setSelectionOutlines()，使 RenderWidget 复位虚线动画相位」——与实现相反（`setSelectionOutlines` 完全不碰相位）。该注释会误导后续维护者。
- 影响：切选时相位延续，视觉上是「新选中的轮廓从中途相位开始」（本身可接受，因为每条路径都是从自己的弧长 0 起算），但注释是错的。
- 判定：**确认缺陷**（注释级，低）。

### D6（低）高 DPI 下虚线长度与速度减半

- `pixelToWorldScale()` 用的是**物理像素**：`backingSize()` 乘过 DPR（`RenderWidget.cpp:490-497`），`Camera2D::pixelToWorldScale` 直接返回 `1/zoomX`（`UI/Common/Src/Render/Camera2D.cpp:106-115`）。
- 而手柄、捕捉标记等装饰按**逻辑像素**声明、乘 DPR 后传入（`OverlayScene.cpp:628-634 / 804-811`）。
- 结果：`dashLengthPx = 10` 在 2× DPR 屏上只有 5 个逻辑像素、`speedPxPerSec = 48` 只有 24 逻辑像素/秒；同屏的手柄尺寸不变。两套像素基准不一致。
- 判定：**确认缺陷**（低，Retina 上虚线偏细偏慢）。

### D7（低）失焦/最小化仍在 60Hz 空转

- 只按 `hasAnimatedSelectionOutlines()` 启停定时器（`RenderWidget.cpp:591`），全仓没有 `focusOutEvent` / `hideEvent` / 可见性判断（`UI/2D/Src` 内无相关实现）。
- 窗口最小化或切到后台时 Qt 会合并 `update()`，但定时器仍然每 16ms 唤醒主线程并做相位推进（几乎零成本），随后一次无效的 update。属于后台功耗问题，不是可见 bug。
- 判定：**确认缺陷**（低）。

### D8（低）视口外选中图元的虚线每帧照样全量展开

- overlay 提交不带任何裁剪体积（`RenderWidget.cpp:1103-1107`），`packet.enableCulling = false`（`1014`）；`appendSelectionDash` 完全不知道视口。
- 场景：全选 2000 个图元后放大到局部，屏幕外 90% 的轮廓仍然每帧参与弧长切分与顶点写放。
- 判定：**确认缺陷**（低—中，取决于使用场景；纯 CPU 浪费）。

### D9（低）图层被隐藏后虚线残留并继续动画

- 图层显隐只翻标志位 + `notifySceneChanged()`（`Engine/2D/Src/Interaction/LayerManager.cpp:660`，说明见 `Main/Src/UI/Render/SceneRefreshCoordinator.cpp:1223`），没有任何地方清理 `SelectionOutlines` 层（`clearSelectionDecoration` 只在 `RenderWidget.cpp:738` 的选择框路径被调用）。
- 结果：先选中某图层的图元、再隐藏该图层，本体消失但虚线轮廓仍留在 overlay 上并且继续流动。
- 判定：**确认缺陷**（低—中，需要一次运行验证；静态看清理钩子确实缺失）。

### D10（设计取舍，不按缺陷计）多选相位并非世界统一

- 所有路径共用同一 `offset`，但每条路径都从自己的 `arc = 0` 起算（`OverlayScene.cpp:209 / 233`），所以是「每条轮廓各自从头流动」，不是全场景统一的 marching 图案。
- 路径内部无缝隙错位（游标单调、拐点原样穿入，`OverlayScene.cpp:245-267`）。
- 判定：**设计取舍**，除非产品明确要求多选时图案跨图元对齐。

补充回答审查清单中的三个问题：

- **dash pattern 单位**：最终是**物理像素**（`p2w` 由 backing size 推导），因此缩放时虚线视觉长度保持不变（不会失真），但 DPR 语义有偏（D6）。缩放跨过 0.5 log2 档位时轮廓会重离散（最多约 41% 边长差异），拐角保真度会跳变，虚线本身不失真。
- **加粗/高亮与虚线是否重复描边**：是。没有独立的加粗/发光通道，虚线就是叠加在本体实线之上的第二次描边（同色同宽），即 D1。
- **被裁剪/遮挡时是否仍动画**：不会被遮挡（overlay 在最上层），但视口外仍在算（D8）；图层隐藏后仍在动画（D9）。

## 3. 性能

### 3.1 帧驱动

- 定时器 16ms → 62.5 次/秒，与 60Hz 显示器差 0.67ms，长期会有轻微的相位-帧节拍漂移；相位用实测 dt 补偿，速度本身不漂移，但会出现周期性的「一帧内两次 update 被合并 / 偶尔跳一格」。
- 每 tick 一次 `QWidget::update()`：**整个控件**。GL 分支还显式设了 `NoPartialUpdate`（`RenderWidget.cpp:100`），Metal 分支 `WA_OpaquePaintEvent`（`108-110`）——两条后端都只能整视口重绘。
- 因此「每帧代价」= 虚线展开 + 覆盖层全量重传 + 场景环境重算判断 + 常驻 draw list 的全量重新提交/光栅化 + 全屏合成。

### 3.2 每帧 CPU 成本（按代码事实推算）

设：轮廓顶点总数 `V`，屏幕弧长 `L`（像素），dash 周期 `P = 18px`，展开后点数 `S`。

1. **两遍全量展开**：`OverlayScene::submit` 先统计 `totalSegs` 再重新展开写顶点（`OverlayScene.cpp:778-796`），即 `2 × (V + D)` 次弧长推进 + 插值，其中 `D = L / P` 为 dash 数。
2. **顶点规模**：每段 dash 至少 2 点，dash 区间内的原拐点各再贡献 2 点（`OverlayScene.cpp:248-266`），故 `S ≈ 2 × (D + 0.556 × V)`（0.556 = dash/period）。
3. **默认预算下的上界**（`V = 200k`，细化边 8px ⇒ `L ≈ 1.6M px`，`D ≈ 88k`）：`S ≈ 2 × (88k + 111k) ≈ 400k 点`。
4. **内存写放**：`OVertex` = 7×float = 28 字节（`OverlayScene.cpp:29-35` + `IRenderTypes` 的 `PositionColorAlpha` 步长），`S ≈ 400k` ⇒ 单帧 `v` 向量写 ≈ **11MB**；随后 `emitAs` 再整块 `memcpy` 进瞬态环（`OverlayScene.cpp:76`）⇒ 单帧内存流量 ≈ **22MB**，60Hz ≈ **1.4GB/s**。
5. 另有每帧一次 ~11MB 的 `v.reserve`（新分配 + 释放）与 `segs` 复用容量（`OverlayScene.cpp:772-785`），即每帧一次大块堆操作。
6. **迭代次数**：`2 × (V + D) ≈ 2 × 288k ≈ 0.6M` 次/帧 ⇒ ~35M 次/秒的纯标量循环。这是「选中几千图元卡死」此前留下的痕迹（`OverlayScene.cpp:182-186` 的注释已经说明历史复杂度是 `O(V×D)`）。

结论：**虚线展开本身在默认预算上界是「毫秒级、每帧固定」的开销**，但绝大多数实际选择（几个到几十个图元）可以忽略。真正的隐形成本是 3.3。

### 3.3 全视口重绘是主要成本

- 每帧都执行：`beginFrame` → 场景环境（按脏标志）→ 世界文字 → 常驻 `submitDrawList` → overlay → `endFrame`（`RenderWidget.cpp:1003-1132`）。
- 覆盖层「逐帧全量重传」是设计如此（`RenderWidget.cpp:1073-1077` 注释）；场景本体虽是保留式 draw list，但**GPU 仍然每帧重新光栅化全部可见图元**。
- 所以动画开着的代价 ≈ 「以 60fps 一直渲染静止场景」：29 万图元的高缩放下，这是帧耗时的主项，虚线展开只是附加项。**任何只优化虚线算法的方案都无法把这条链的性能上限提上去**（见建议 B1）。

### 3.4 规模增长与预算悬崖

- 选择集变化时才 `O(N)` 做指纹哈希（`SelectTool.cpp:218-232`），不逐帧。
- 每帧成本对选中集是 `O(ΣV_i)` 线性，但存在**硬阈值悬崖**：1999 个图元 → 每帧全展开；2001 个 → 一条虚线都不画。跨阈值时帧率与视觉同时跳变，且此时「隐藏原体」的有效状态翻转还会触发一次增量重建（`RenderWidget.cpp:843-885`）。
- 空选择时预算丢弃后 `paths` 为空 → 定时器停止（`OverlayScene.cpp:638-639`），**不存在取消选择后的空转定时器**（这一条审查项通过）。

### 3.5 抗锯齿 / 线宽 / 高 DPI

- dash 是 1 物理像素的线图元（`lineWidth` 默认 0 → 后端 1px），没有几何宽度，也没有独立的 AA 处理；视觉上的「毛刺」主要来自 1px 线在图元实线边缘上叠加。
- 若把线宽提到 2~3px，`Lines` 拓扑在部分后端（GL core profile）不可靠，需要三角化，CPU 顶点数按宽度倍数增长——**当前实现没有为加宽留出结构**。
- 高 DPI：轮廓细化的「8px 最大边长」也是物理像素（`SelectionOutlineBuilder.cpp:31 / 140-141`），DPR 翻倍 ⇒ 世界边长减半 ⇒ 顶点数约 ×2，虚线点数同比例增加，即每帧成本随 DPR 近似线性上升。这是 D6 的性能侧后果。

### 3.6 怎么测（不跑长时间基准）

现成手段（无需改代码）：

1. **帧率/帧耗时**：Debug 构建右下角已有 FPS overlay（`m_fpsMeter`，`RenderWidget.cpp:1134-1139`；开关见 `SettingsKeys2D` 的 `FPS_OVERLAY`）。
2. **A/B 五组对照**（同一相机、同一图纸，只改一个变量）：
   - V0：无选择（基线空转）；
   - V1：选中 1 个长圆；
   - V2：选中 2000 个图元（贴近预算上界）；
   - V3：同 V2 但把 `selection/dash_animated` 置 false（相位不动，仍每帧画）；
   - V4：同 V2 但把 `selection/dash_enabled` 置 false（实线，无展开）；
   - V5：同 V2 且 `hide_original=false`（验证 D1 不可见）。
   比较 V1/V2 与 V3 的帧耗时差 = 相位推进 + 整视口重绘的净代价；V2 与 V4 差 ≈ 虚线展开的净代价；V3 与 V0 差 ≈ 覆盖层每帧重传的净代价。
3. **离线量**：`Tools/RenderBenchmark` 可以单独喂覆盖层提交路径，测 `appendSelectionDash` + `emitAs` 的纯 CPU 时间。
4. 若要拿到 3.2 的实测数字，需要在 `OverlayScene::submit` 的 dash 分支临时打印 `segs.size()`/`v.size()` 与耗时（本任务只读，未做）。

## 4. 优化建议

### A 级：改动小、收益大（全部是纯收益，不牺牲画质）

| # | 改动点 | 预期收益 |
|---|---|---|
| A1 | **去掉两遍展开**：`OverlayScene::submit` 改成单遍累加（用一个成员级 `std::vector<OVertex>` 保留容量，push 完直接 emit），必要时才 reserve | 每帧虚线 CPU 减半（≈ 0.3M 次迭代/帧 的上界回到 0.3M 而不是 0.6M），去掉每帧一次 11MB 的重复遍历 |
| A2 | **视口内裁剪**：给 overlay dash 分支传入当前可见世界矩形（`m_frameParams` 里已有 p2w，补一个 view box），先按路径 AABB 跳过完全不可见者，再对可见路径做弧长区间裁剪 | 大选择 + 高缩放下可直接省掉 80~95% 的展开与写放；画质仅需在裁剪边界外留 1~2 个 period 余量，实际无损 |
| A3 | **可见性/焦点停表**：加 `hideEvent` / `focusOutEvent` / `isVisible()` 判断，进 `updateSelectionDashTimer` 的 want 判据 | 后台 CPU/GPU 归零，无画质影响 |
| A4 | **截断可观测 + 预算口径修正**：命中 16384 段时打一条与 skip 同级日志；把「展开后点数」纳入预算统计（或改为按设备上限动态放宽单路径段数） | 消除 D3 的静默缺画；让设置项语义与真实成本一致 |
| A5 | **拖动期轻量跟随**：变换矩阵已知时，把已缓存的轮廓顶点整体做一次仿射（不改拓扑、不重离散），只重建虚线展开 | 修 D2 且几乎零成本（O(V) 平移 vs O(N) 离散） |
| A6 | **相位复位接口**：明确设计——要么在选择集变化时把 `m_selectionDashOffsetPx` 归零，要么删掉 `SelectionGizmo.cpp:660-662` 的错误注释 | 消除 D5 的误导；行为可预期 |

### B 级：需要改结构，收益最大

| # | 结构改动 | 收益 / 代价 |
|---|---|---|
| B1 | **覆盖层独立重绘**：场景渲到离屏 target（FBO / 额外 render pass），dash 动画只重绘 overlay 层再合成；同时把 `NoPartialUpdate` 改成自管脏区 | 收益：动画期间不再重光栅化静止场景，帧耗时从「全场景」降到「overlay + 合成」。代价：显存 + 两条后端都要改，属于中期工程 |
| B2 | **把虚线交给 GPU**：顶点带屏幕空间弧长参数，片元里按 `(arcLen - phase) mod period` 做 discard / stencil，相位只更新一个 uniform | 收益：每帧 CPU 展开 + 11~22MB 内存流量直接归零，单帧仅一次 uniform 更新；任意线宽都能做（顺带解决 D6 与加宽问题）。代价：需要新的顶点格式/管线，是最大的一笔结构改造 |
| B3 | **多视口共享一层 overlay 缓存**：若未来多视口并存，把 dash 段按（路径缓存 + 节距 + 相位）留在 GPU buffer 上，只改相位 uniform | 与 B2 配套后收益最大 |

### C 级：画质/交互取舍（不是纯收益）

| # | 取舍 | 说明 |
|---|---|---|
| C1 | **让动画可见**：默认打开「选中时隐藏原图」，或给虚线一个高对比色（不取本体色）/ 加一条外侧发光描边 | 直接修 D1。代价是改变用户熟悉的「本体不变、只加框」形态，属于产品取舍；注意 `Docs/03-渲染主链/虚线.md:87` 明确反对换色，需要产品决策 |
| C2 | **多选相位统一到世界空间**（用屏幕空间 x/y 或世界偏移做相位而非每路径弧长起点） | 修 D10，视觉更「整体流动」；但会让闭环接缝更明显，需与 D4 一起处理 |
| C3 | **闭合轮廓相位回绕**：把 `phase` 在闭合路径上按 `total mod period` 平移，使接缝连续 | 修 D4，属于画质修正，但有 1~2 行的实现风险 |
| C4 | **动态降帧**：非交互时把 dash 刷新降到 30Hz 或 15Hz | 减半/减四分之三的快捷手段，但动画流畅度下降；只有在 B1 无法落地时才值得 |

### 优先级建议（按投入产出）

1. C1 + A3（立刻让功能可见、让后台不空转）——工作量最小，用户感知最强。
2. A1 + A2 + A4（纯收益，全部落在 `OverlayScene::submit` 与 `RenderWidget` 两个点）。
3. A5 + A6（修交互一致性与注释误导）。
4. B1 / B2 作为中期方案单独立项，先做 B1（不需要新管线），B2 视线宽与多视口需求再评估。
