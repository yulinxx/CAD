## 0. 执行原则（每阶段都必须满足）

1. **可编译、可提交**：阶段内按"提交切分"逐条提交，每条提交后 `cmake --build` 通过、相关测试全绿；不允许阶段末一次性大提交。
2. **单一主题**：一条提交只做一件事；重命名/搬迁/行为变更不混提。
3. **不夹带**：与本阶段无关的脏改动（子模块指针、翻译产物、Camera2D 等）不进入提交。
4. **可回滚**：每条提交都能独立 revert；涉及数据格式的变更必须先有迁移与兼容读，再切换写入。
5. **出口条件**：阶段验收项全部通过 + 全量构建绿 + `ctest --no-tests=error` 绿，才进入下一阶段。

阶段之间的依赖是**硬依赖**（下图箭头）；同一层可并行。

```text
S1 数据安全 ──┐
              ├──> S3 可观测性/作业记录 ──> S6 工艺链
S2 交付工程 ──┘             │
                             v
S4 线程模型 ──> S5 错误契约与门禁扩面 ──> S7 序列化收敛
                                            │
                                            v
                                         S8 质量加固
```

## 2. S1 数据安全闭环（P0）

**目标**：崩溃不再丢未保存内容；保存对掉电有最基本的耐久性；误覆盖有退路。

**交付物**

1. 自动保存服务：定时（60s）+ 空闲（30s）双触发，写入 `autosave/` 快照（含文档 ID、时间戳、CRC）。
2. 崩溃恢复：启动检测脏标记，弹出恢复对话框（恢复 / 另存 / 丢弃），恢复失败时保留快照不删除。
3. 写盘耐久：`AprSerializer` 写路径补 `fsync(file)` → `rename` → `fsync(dir)`；Windows 用 `FlushFileBuffers`。
4. 备份：保存成功后保留上一版本 `.bak`（单份）。
5. 测试：`AutosaveTests`、`AprSerializerTests`（含 fsync 计数与 `.bak` 断言）。

**涉及模块**：`Main/Src/Persistence`、`Main/Src/UI/Documents`、`FileIO/FileIO`、`UI/2D`（脏标记接入）。

**验收标准**：DS-1、DS-2、DS-3、DS-4 全部通过；`ctest -R "Autosave|AprSerializer"` 全绿。

**依赖关系**：无。可与 S2 并行。

**风险与缓解**

| 风险 | 影响 | 缓解 |
|---|---|---|
| 自动保存与用户保存竞争同一文件 | 文件损坏 | 快照写独立目录，永不覆盖原文件；用同一原子写函数 |
| 大文档序列化造成主线程卡顿 | UI 卡顿 | 序列化在工作线程完成，仅 rename 回主线程；设"两次快照间隔内不重复调度" |
| 恢复流程误判（正常退出也被判脏） | 打扰用户 | 正常退出清理脏标记；启动校验快照 mtime + 进程锁 |

**提交切分**

1. `feat(fileio): 写路径补 fsync 与 .bak，提升掉电耐久性`
2. `feat(main): 文档自动保存与崩溃恢复`
3. `test(main): 覆盖自动保存、恢复与 .bak 行为`

## 3. S2 交付工程（P0）

**目标**：任意开发者机器上稳定产出可安装、可签名、可复现的包；macOS 构建不再是盲区。

**交付物**

1. macOS / Linux 全量 CI job（构建 `April` + 全部测试目标 + `ctest`）。
2. `vcpkg.json` + `builtin-baseline`，CI 改为 manifest 模式并缓存。
3. macOS 签名 + 公证（`codesign` / `notarytool` / `stapler`），Windows `signtool`；密钥走 CI secret。
4. macOS 安装包冒烟（DragNDrop：安装、启动、卸载）。
5. 崩溃符号表归档（与 S3 的 OB-2 对接，先落归档与 build id 规则）。

**涉及模块**：`.github/workflows`、`CMake/*`、`Config.cmake`、`scripts/`、`Main`（版本注入）。

**验收标准**：DL-1、DL-2、DL-3、DL-4 全部通过；两次干净构建的依赖清单一致。

**依赖关系**：无。可与 S1 并行。

**风险与缓解**

| 风险 | 影响 | 缓解 |
|---|---|---|
| manifest 模式导致依赖版本与当前 binary 不一致 | 编译失败/行为变化 | 先以现有 `vcpkg list` 生成 baseline，再逐步升级 |
| macOS runner 上 OCCT/Qt 体积导致超时 | CI 不稳定 | 缓存 vcpkg 二进制；拆分 job；仅打包 job 打开全部模块 |
| 签名证书权限 | 发布阻塞 | 本地可手工签名脚本兜底；CI 缺 secret 时降级为"未签名产物 + 显式告警" |

**提交切分**

1. `build: 引入 vcpkg manifest 与 baseline，锁定依赖版本`
2. `ci: 增加 macOS/Linux 全量构建与测试 job`
3. `ci: macOS 签名公证与安装包冒烟`
4. `build: 归档崩溃符号表并按 build id 命名`

## 4. S3 加工可追溯 + 崩溃上报（P1）

**目标**：每次加工都能回答"谁、何时、什么参数、什么结果"；现场崩溃可在 10 分钟内远程定位。

**交付物**

1. `machining_jobs` 表 + 仓储 + 写入点（开始/结束/中止）+ 最小查询导出（CSV）。
2. 参数快照（JSON + schema 版本 + 哈希）。
3. 崩溃 dump 自动上传（客户端可选开关，默认关；企业版默认开）+ 服务端符号化说明或本地脚本（`minidump_stackwalk` + 符号目录）。
4. 一键诊断包（日志、配置、最近 dump、设备与版本信息，脱敏）。

**涉及模块**：`Main/Src/Persistence`、`Engine/Persistence`、`CrashHandler`、`Log`、`UI`（作业列表入口）。

**验收标准**：MC-2、MC-3、OB-2、OB-4 通过；`ctest -R "MachiningJob"` 全绿。

**依赖关系**：依赖 S1（保存与恢复已稳定）、S2（符号归档已就绪）。

**风险与缓解**

| 风险 | 影响 | 缓解 |
|---|---|---|
| 作业记录写失败影响加工主流程 | 生产中断 | 记录写入与主流程解耦，失败只告警不阻断；本地队列重试 |
| dump 上传涉及隐私/合规 | 客户拒用 | 默认关闭 + 明确告知 + 不含文档内容 |
| 参数结构频繁变化 | 历史不可读 | 快照带 schema 版本，读取端做兼容分支 |

**提交切分**

1. `feat(persistence): 新增加工作业表与仓储`
2. `feat(main): 加工开始/结束/中止写入作业记录与参数快照`
3. `feat(crash): dump 自动上传与符号化脚本`
4. `feat(main): 一键导出诊断包`

## 5. S4 线程模型收敛（P1）

**目标**：大图纸操作不卡 UI；3D 长任务可取消；场景并发写有硬约束。

**交付物**

1. 3D 算法统一走 `runAsync`（复用 2D 的 `BackgroundAlgorithmTaskHandler` 契约）。
2. 渲染提交拆分：几何构建/脏图元处理移出 GUI 线程；GL 调用仍集中在 GUI 线程（或引入专用提交路径），用有界队列 + 背压。
3. `SceneManager` 记录 owner 线程，写入入口 Debug 断言；跨线程写必须经消息队列。
4. `Main/UI` 中同步 IO、`sleep`、`processEvents` 清理，CI 加扫描白名单。

**涉及模块**：`UI/3D`、`UI/2D`、`Main/Src/UI/Render`、`Engine/2D/Core`。

**验收标准**：RT-1、RT-2、RT-5、RT-6 通过；5 万图元压测报告入库。

**依赖关系**：依赖 S1（避免自动保存与线程改动互相干扰）。

**风险与缓解**

| 风险 | 影响 | 缓解 |
|---|---|---|
| 3D 异步引入对象生命周期问题 | 崩溃/悬垂指针 | compute 阶段只读快照；apply 在主线程重建；沿用 2D 的成熟模式 |
| 渲染提交线程化触碰 GL 上下文 | 黑屏/崩溃 | 第一阶段只搬"数据准备"，GL 调用不动；按模块灰度 |
| 场景断言在 Release 被关闭 | 现场仍竞争 | Release 记录 owner 不匹配日志（限流），配合崩溃统计 |

**提交切分**

1. `refactor(ui3d): 3D 算法任务切换到异步契约`
2. `refactor(render): 脏图元构建移出 GUI 线程`
3. `feat(engine2d): 场景写入增加线程归属断言`
4. `chore: 清理主线程同步 IO 并加 CI 扫描`

## 6. S5 错误契约与门禁扩面（P1）

**目标**：失败有分类、有文案、可统计；架构门禁没有盲区。

**交付物**

1. 引擎错误码枚举 + `ErrorCode → 用户文案` 映射表；`OperationResult.message` 为空时按错误码兜底。
2. 清理空 catch（保留的必须写理由）；引擎边界补异常兜底（第三方面向 OCCT/Clipper2 的入口）。
3. 依赖方向门禁覆盖 FileIO / Hardware / Nesting / Vision / Network / Engraving / GeoModelCore / PyBindCore / PythonHost / Raster。
4. 3D 写入口收敛（对齐 2D：private + 窄 friend + 写面门禁）。
5. 新增文件 `-Werror`（存量基线清单）。

**涉及模块**：`CMake/CheckDependencies.cmake`、`CMake/SceneWriteSurface.cmake`、`Engine/3D`、全模块错误路径。

**验收标准**：QG-4、QG-6 通过；负样本测试证明违规会 configure 失败。

**依赖关系**：依赖 S4（线程改动会新增错误路径，先稳定再统一）。

**风险与缓解**

| 风险 | 影响 | 缓解 |
|---|---|---|
| 门禁扩面暴露存量违规 | 一次性大量失败 | 先生成违规清单，按模块分批加入白名单，再逐批消除 |
| 3D 写面收敛影响调用方 | 编译大面积失败 | 同 2D 做法：先加网关与 Direct 接口，再 private 化，最后迁移测试 |
| `-Werror` 阻塞正常开发 | 团队抵触 | 只对新增文件生效；基线文件显式豁免并设清理期限 |

**提交切分**

1. `feat(engine): 统一错误码与用户文案映射`
2. `refactor: 清理空 catch 并补第三方异常兜底`
3. `build: 依赖方向门禁覆盖全部模块`
4. `refactor(engine3d): 收敛 3D 场景写入口`
5. `build: 新增文件启用 -Werror`

## 7. S6 工艺链 M1（P2）

**目标**：从"能画轮廓"到"能下工艺"。

**交付物**

1. 割缝补偿、引线/引出、穿孔、功率曲线、共边、拐角处理六项，各带 golden 基准。
2. 后处理抽象（`IPostProcessor` 注册表），至少两种输出（设备原生格式 + 通用 G 码子集）。
3. 工艺路由从 UI 层下沉到 CAM/Engine（或抽公共模块），UI 仅做配置与选择。
4. 参数快照接入 S3 的作业记录。

**涉及模块**：`CAM/CAM`、`UI/2D`（路由）、`Engine/2D`（几何支撑）。

**验收标准**：MC-1、MC-4、MC-6 通过；CAM 数值基准全绿；实机试样记录归档。

**依赖关系**：依赖 S3（作业记录与参数快照）。

**风险与缓解**

| 风险 | 影响 | 缓解 |
|---|---|---|
| 工艺参数与设备强耦合 | 换机型即失效 | 参数按"工艺能力"抽象，设备适配器负责映射 |
| 数值基准与实机不一致 | 试样报废 | 先仿真基准，再小批量试切；容差按材料分档 |
| 工艺路由下沉影响现有 UI | 回归 | 先做适配层，UI 行为不变；再迁实现 |

**提交切分**

1. `feat(cam): 割缝补偿与拐角处理`
2. `feat(cam): 引线、穿孔与功率曲线`
3. `feat(cam): 共边切割与后处理注册表`
4. `refactor: 工艺路由从 UI 下沉并保留兼容层`

## 8. S7 序列化唯一化 + 持久化测试（P2）

**目标**：消除双序列化抽象；文档打开/保存在 CI 有回归保护。

**交付物**

1. 确认唯一实现（当前生产为 FileIO/AprSerializer），删除或接线 `ISceneSerializer/SceneManagerSerializer`。
2. `Engine/Persistence/Test` 建立，覆盖：旧版本样例、损坏文件、超大文档、CRC 校验失败。
3. 旧版本样例文件入库（至少两个历史版本）。

**涉及模块**：`Engine/Persistence`、`FileIO/FileIO`、`Main/Src/Persistence`。

**验收标准**：DS-5、DS-6、QG-7（Persistence）通过。

**依赖关系**：依赖 S5（错误码统一后，反序列化失败才有稳定分类）。

**风险与缓解**

| 风险 | 影响 | 缓解 |
|---|---|---|
| 删除抽象时发现隐藏调用方 | 编译失败 | 先 `git grep` 全量 + 编译驱动；两阶段删除（标记弃用 → 移除） |
| 旧样例缺失 | 迁移无法验证 | 用当前格式造 v1/v2 样例并冻结，后续版本追加 |

**提交切分**

1. `refactor(persistence): 收敛文档序列化到单一实现`
2. `test(persistence): 建立持久化测试与历史样例回归`

## 9. S8 质量加固（P2）

**目标**：让"回退"能被自动发现，而不是靠人。

**交付物**

1. ASan/UBSan job（每周 + 手动触发），TSan 覆盖算法/渲染线程用例。
2. PerfBenchmark 阈值入库，PR 对比报告，回归 >10% 失败。
3. 覆盖率统计（核心模块 ≥60%，新代码 diff ≥70%）。
4. 长稳压测脚本（8h）与 nightly job。

**涉及模块**：`.github/workflows`、`Tools/PerfBenchmark`、各测试目标。

**验收标准**：QG-2、QG-3、QG-5、RT-4 通过。

**依赖关系**：依赖 S5（门禁与告警基线）、S7（测试目标补齐）。

**风险与缓解**

| 风险 | 影响 | 缓解 |
|---|---|---|
| 存量 sanitizer 报错过多 | 无法开闸 | 先全量跑一次，生成豁免清单，按模块清零 |
| 性能阈值在 CI 机器抖动 | 假失败 | 用相对基线 + 3 次取中位数；只在专用 runner 上跑 |
| 覆盖率追求数字 | 无效测试 | 只对核心模块设阈值，评审关注新增分支 |

**提交切分**

1. `ci: 增加 sanitizer 作业与豁免清单`
2. `ci: 性能预算阈值与 PR 对比`
3. `ci: 覆盖率统计与阈值`
4. `test: 8 小时长稳压测脚本`

## 10. 风险登记（跨阶段）

| 风险 | 概率 | 影响 | 触发信号 | 应对 |
|---|---|---|---|---|
| 工艺链工作量被低估 | 高 | 交付延期 | M1 单项超期 | 先做割缝+穿孔（客户最痛），其余分批 |
| 线程化引发难复现崩溃 | 中 | 稳定性回退 | 灰度期崩溃率上升 | 保留同步开关，按客户灰度 |

| 签名证书与 CI secret 管理 | 低 | 发布阻塞 | 打包 job 失败 | 本地脚本兜底 + 证书备份流程 |
| 数据格式变更导致客户文件打不开 | 低 | 严重客诉 | 旧样例测试失败 | 迁移先行、双读兼容、样例冻结 |

## 11. 里程碑定义（对外可承诺的最小集合）

| 里程碑 | 包含阶段 | 可对外表述 |
|---|---|---|
| M-A "不丢数据" | S1 | 崩溃可恢复、保存可耐久 |
| M-B "装得上" | S2 | 三平台构建、签名安装包、依赖可复现 |
| M-C "查得到" | S3 | 每次加工有记录，崩溃可远程定位 |
| M-D "跑得稳" | S4 + S5 | 大图纸不卡、3D 可取消、门禁无盲区 |
| M-E "能生产" | S6 | 六项工艺落地并有实机试样 |
| M-F "可维护" | S7 + S8 | 序列化唯一、sanitizer/性能/覆盖率门禁 |
