## 0. 核心结论

1. **当前最大的瓶颈不是命中测试，而是"选中之后每帧的高亮覆盖层合成"。**
   [OverlayScene.cpp](file:///c:/Users/xx/Documents/Cpp/CAD/RenderBridge/Src/OverlayScene.cpp#L772-L797) 原第 781 行 `v.reserve(v.size() + segs.size())` 在逐路径循环里做"精确容量预留"，每加一条路径都强制整段重新分配并拷贝已累积的全部顶点，复杂度是 O(P²)（P=轮廓路径数）。**已于 2026-11-04 修复（`7cd0fc5`，改成循环外一次性预留），见 6.P0-1。**
2. **实测（纯 CPU、无 GPU 提交，修复前）**：默认流水虚线动画开启时，1000 选中 3.72 ms/帧、2000 选中 14.4 ms/帧、5000 选中 95.8 ms/帧（p90 295 ms）。虚线动画由 16 ms QTimer 持续驱动，只要存在选中轮廓就一直在跑，所以这不是"偶发卡顿"，而是**选中即持续掉帧**。修复后 5000 选中降到 0.96 ms/帧。
3. **同一模式的最小复现**：1000/2000/5000 条路径，逐路径 `reserve` 为 0.945/4.77/28.3 ms，循环外一次性预留仅 0.005/0.010/0.025 ms，确认热点就出在预留策略，而不是虚线生成本身（虚线生成已改为 O(V+D) 游标推进）。
4. **点选与框选的空间查询本身很快**：官方 `AprPerfBenchmark` 200k 场景 1000 次点拾取共 0.97 ms（单次约 0.001 ms）；10% 包围盒框选 3.46 ms；本仓库临时基准 50k 全场景框选约 2.2 ms。**索引查询不是瓶颈**。
5. **第二大瓶颈是选择变化引发的 UI 命令快照**：`SelectionService::visitSelectedIds` 把每个选中 id `std::to_string` 后交给回调，回调再 `parseEntityId` + `findEntityById`；实测 50k 选中该循环 21.6 ms（p90 38 ms），随每次选择变化同步触发。**已在 2026-11-04 让选择上下文 provider 改走 `scene->forEachSelected` 绕过字符串往返（Main 内部，未提交），见 6.P1-1。**
6. **历史优化大部分仍在**（空间索引+分解缓存+段级网格、SelectionManager 差集早退、Gizmo RTree+hover 节流、拖拽跳过轮廓离散、纯选择变更只 Repaint 等）；**被绕过/回退的有三处**：`15d939b` 的 `forEachSelected` 免拷贝被 `9950a9a` 回退（全局仍退回拷贝，但本报告的 provider 已直接用 `forEachSelected`）；`91a3d7c` 引入的 O(P²) 预留**已于 `7cd0fc5` 修复**；`efb3e84a` 引入的字符串 C ABI **在选择热路径上已被 provider 绕开**（`visitSelectedIds` 仍保留供其它调用方）。
7. **最值得先做的三件事**：① 修 OverlayScene 的逐路径预留 —— **已完成（`7cd0fc5`）**；② 选择快照改走 `EntityId`/实体指针，去掉字符串往返 —— **轻档已完成（Main 内部，未提交）**，进一步压到 2 ms 以内需要重档（改 `EntityId` 接口，未实施）；③ 批量索引更新（200k 移动 10% 图元索引段 68.7 ms）改为延迟/异步，避免拖拽松手同步阻塞 —— **未实施**。

- 线段：解析点到线段距离（`Geo2DPrimitives::distancePointToSegment`）。

高亮画法结论：

- **不是重建图元，也不是改材质**：选中反馈是覆盖层流水虚线轮廓 + 屏幕定尺寸手柄；
- **不触发整场景重建**：纯选择变更只到 `RefreshLevel::Selection`（`RenderWidget::update()`）；只有"隐藏选中本体"生效时才走 `LightUpdate` 差量增删，代码注释明确禁止回到 `FullRefresh`（29 万图元单次十几秒）；
- **GPU 侧是单批次提交**：整个选中集合成一条 `DrawInstruction`（逐顶点颜色，路径间不必分批）。但**每帧都会重新展开虚线并重新上传顶点**，因为虚线相位在动。

5. **P1-2 验证**：选中 10% 图元 → 拖动一次 → 松手，观察松手瞬间卡顿；对比"选中 1 个再拖动"。
6. **对照**：同一操作在 Debug 下会更明显，但请以 Release 数据为准（本报告全部为 Release）。
