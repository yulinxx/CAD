# 位图处理交互设计（v1 第一阶段）

> 面向激光雕刻 / 激光切割工艺的位图（栅格）处理交互流程，
> 覆盖两条方向：**矢量 → 位图加工**（雕刻 / 打标）与 **位图 → 矢量**（轮廓化 / 切割路径提取）。
> 设计基于项目已有 Raster 模块（v1.2）的真实 API 能力，不引入 Cairo/Skia 等新依赖。

---

## 0. 核心思路

三条数据链路对应三条工艺路线：

```
矢量实体 → 光栅化 → Raster 位图处理 → AprImage 入场景 → 激光雕刻走位图扫描
位图导入 → Raster 位图处理 → AprImage 入场景 → 激光雕刻走位图扫描
位图导入 → Raster_Vectorize → AprPolyline 入场景 → 激光切割走矢量轮廓
```

第一阶段只实现闭环：**选中位图实体 → 参数对话框（实时预览）→ Raster 处理 → 新位图实体入场景 → Undo 压栈**。
矢量→位图加工（选中矢量实体 → DPI 光栅化 → 工艺处理）放在下一阶段。

## 2. 入口位置

激光软件（LightBurn/EZCAD/RDWorks）的惯用做法是：

- 位图处理参数放在 **Edit → Path Operations** 子菜单或新建的 **Process** 菜单
- 右键选中的 AprImage 实体时，上下文菜单里也出现「Process Bitmap... / Vectorize Bitmap...」
- 工具栏可选放一个"位图处理"按钮（图标建议用 `:/ui/common/Icons/View3D/bitmap.svg`）

**第一阶段菜单接入**：
- Edit → Path Operations 子菜单底部新增两个 action：
  - 「Process Bitmap...」（`algo.bitmap_process`）
  - 「Vectorize Bitmap...」（`algo.vectorize_bitmap`）
- 右键菜单同入口（`kMenuCtx` surfaces）
- 启用条件：`Cmd::RequiresSelection`，且选中集中至少有一个 `EType::IMAGE` 实体

## 3. 流程一：位图 → 工艺处理（雕刻 / 打标）

### 3.1 入口前置条件

- 用户在场景中选中一个或多个 `AprImage` 实体（支持批量）
- 或点击「Process Bitmap...」时自动选中场景中的第一张 AprImage（如果当前没选中）
- 如果场景中没有任何 AprImage，对话框显示提示并 disable 「确定」按钮

### 3.2 参数对话框

**布局**：自适应（固定宽度最小 520px、高度最小 480px；用户可拉大）。
左侧是 400×300 的实时预览区（QLabel + QPixmap，用 `setScaledContents(true)` 保持预览大小）；
右侧是参数面板（QScrollArea 包裹）。

参数分组（激光工艺语义）：

#### 组 1：二值化 / 阈值

| 参数 | 类型 | 默认值 | 取值范围 | 工艺语义 | Raster 函数 |
|---|---|---|---|---|---|
| 阈值模式 | 下拉 | Otsu | Otsu / Fixed / Adaptive / None | 如何把灰度图变成黑白 | `Raster_Threshold` (method) |
| 固定阈值 | SpinBox | 128 | 0-255 | 仅当 Fixed 模式时生效；暗于阈值的被当成雕刻区 | Threshold value |
| 反向 | CheckBox | 否 | — | 交换黑白（白雕刻/黑留白 → 常见于不锈钢打标） | `Raster_Invert` |

#### 组 2：加工模式（决定激光出光方式）

| 参数 | 类型 | 默认值 | 取值范围 | 工艺语义 | Raster 函数 |
|---|---|---|---|---|---|
| 模式 | 下拉 | Black/White | Black/White / Dither / Halftone / Power Map / Skeleton | **Black/White** = 纯黑白二值，振镜开关光；**Dither** = 抖动灰度转黑白，适合灰度雕刻；**Halftone** = 网点化，适合网版印刷或 CO2 点阵；**Power Map** = 功率映射（灰度→功率），适合深度变化雕刻；**Skeleton** = 骨架化/中心线，适合仅雕轮廓 | `Raster_Dither` / `Raster_Halftone` / `Raster_PowerMap` / `Raster_Skeletonize` |
| 抖动方法 | 下拉 | Floyd-Steinberg | Floyd-Steinberg / Ordered / Stucki | Dither 模式时选择抖动算法 | `Raster_Dither` method |
| 网点大小 | SpinBox | 4 | 2-16 px | Halftone 模式的网点直径（像素） | `Raster_Halftone` cellSize |
| 功率映射模式 | 下拉 | Linear | Linear / Exponential / Gamma | Power Map 模式的功率曲线 | `Raster_PowerMap` mode |

#### 组 3：雕刻工艺参数（**只显示，不入场景实体属性**）

| 参数 | 类型 | 默认值 | 经验值建议 | 说明 |
|---|---|---|---|---|
| 功率 % | SpinBox | 50 | 木材 30-60 / 亚克力 40-70 / 金属氧化膜 15-30 | **仅记录在导出的加工参数里**，不影响位图本身 |
| 速度 mm/s | SpinBox | 500 | 木材 800-2000 / 亚克力 500-1500 / 金属 100-500 | 同上 |
| 遍数 | SpinBox | 1 | 1-10 | 同上；多层雕刻时用 |
| 扫描方向 | 下拉 | Left-Right | Left-Right / Right-Left / Top-Bottom / Bottom-Top | 同上；影响振镜运动效率 |
| 反向雕刻 | CheckBox | 否 | — | 仅 Power Map 模式下有意义：反转功率映射 |

> **为什么功率/速度不入场景实体**？因为 AprImage 实体只承载像素数据和四角点，功率/速度属于**加工配方**（Recipe），最终在 Laser_ProcessParams 或 MaterialDB 里管理。
> 对话框里让用户看到这些参数是为了**让他们在处理位图时就知道最终加工效果**——比如 Halftone 的网点大小和功率共同决定最终打标效果的精细度。
> 第一阶段这些参数**只做显示/记忆**，真正接到 Laser 输出管线是后续。

#### 组 4：几何处理

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| 分辨率 DPI | SpinBox | 300 | 矢量→位图时的光栅化精度（本阶段暂不生效，下一阶段用） |
| 缩放 | DoubleSpinBox | 1.0 | 位图→位图时可等比缩放 | `Raster_Resize` |
| 角度 | DoubleSpinBox | 0.0 | 顺时针旋转角度 | `Raster_Rotate` |
| 水平翻转 | CheckBox | 否 | — | `Raster_Flip(axis=0)` |
| 垂直翻转 | CheckBox | 否 | — | `Raster_Flip(axis=1)` |
| 反失真 | CheckBox | 是 | 缩放时用双线性插值 | `Raster_Resize` 默认 |

#### 组 5：图片增强（预处理）

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| 亮度 | Slider | 0 | -100 到 +100 | `Raster_AdjustBrightnessContrast` brightness |
| 对比度 | Slider | 0 | -100 到 +100 | `Raster_AdjustBrightnessContrast` contrast |
| 去噪 | 下拉 | None | None / Median / Gaussian / Bilateral | `Raster_Denoise` |
| 锐化 | Slider | 0.0 | 0.0 到 3.0 | `Raster_Sharpen` amount |

### 3.3 预览机制

- 对话框打开时自动把选中的 AprImage 的 `pixelData` + `nWidth/nHeight` 传给 `Raster_CreateImage`
- 任何参数变化（`valueChanged` / `currentIndexChanged`）触发后台处理管线：
  1. 克隆 RasterImage
  2. 依次应用亮度/对比度 → 去噪 → 锐化 → 几何变换 → 二值化/阈值 → 加工模式
  3. `Raster_GetImageView` → 提取 pixel data → QImage → QPixmap → `setPixmap`
- 处理中显示 QProgressBar（Raster 内部 progress callback 回调），用户可随时改参数触发重新处理
- 预览**不影响场景中的原始 AprImage**——只有点「确定」才把结果作为新实体入场景

### 3.4 确定后发生什么

1. **参数校验**：必填参数不为空、阈值在有效范围、网点大小 ≥2
2. **后台线程处理**（Raster API 全部纯 CPU，可在任意线程调用）：完整管线处理 → 产出最终 RasterImage
3. **主线程创建 AprImage**：
   - `AprImage* newImg = new AprImage();`
   - `newImg->nWidth / nHeight / ePixelFormat = Gray8;`
   - 世界坐标：以选中实体的 `basePoint` + 偏移量作为新实体基准（避免和原图重叠）
   - 4 角点：按像素尺寸 + DPI 换算到世界坐标（DPI 未指定时 1 world unit = 1 pixel）
   - `newImg->setPixelData(pixelData, size);`
   - `newImg->layer = 当前图层（或新建的"加工结果"图层）;`
4. **SceneManager 接管**：`sm->addEntity(newImg);`
5. **Undo 压栈**：
   - `SceneUndoCommands` 的 `EntitySnapshotsCommand` 或自定义 `AddEntityUndoCommand`
   - `redo()` = `addEntity(newImg)`，`undo()` = `deleteEntity(newImg)`
6. **状态栏提示**：`"Processed image created: {width}x{height}, {mode}, Undo available"`
7. **成功后**：自动选中新实体，Fit 视图到新实体（可选）

### 3.5 取消时

- 对话框关闭（`QDialog::Rejected`），不做任何场景修改
- 后台处理线程通过 Raster progress callback 返回非 0 可以取消（Raster API 内部有 cancel 机制）

### 3.6 异常处理

| 场景 | 处理方式 |
|---|---|
| Raster 处理失败（返回非 OK status） | 对话框内 ErrorLabel 显示中文错误信息（`Raster_GetLastError` 取中文描述），Disable 确定按钮 |
| 结果图像为空（处理后全部纯白或全部纯黑） | 警告提示"处理后图像无有效像素，可能需要调整参数"，仍允许确定 |
| 内存不足（大图处理） | QMessageBox Critical 提示，不崩溃 |
| 选中实体不是 AprImage | 入口命令 disable；右键菜单只在 AprImage 上弹出 |
| 无选中实体 | Process Bitmap 命令弹 QMessageBox Information 提示"Please select an image first." |

## 4. 流程二：位图 → 矢量（轮廓化）

### 4.1 入口前置条件

- 选中一个 AprImage 实体（`EType::IMAGE`）
- 右键菜单的「Vectorize Bitmap...」或 Edit → Path Operations → Vectorize Bitmap

### 4.2 参数对话框

**布局**：与 Process Bitmap 类似的 QDialog，自适应；左侧预览，右侧参数面板。

#### 组 1：二值化 / 阈值（与流程一完全共享）

| 参数 | 类型 | 默认值 |
|---|---|---|
| 阈值模式 | 下拉 | Otsu |
| 固定阈值 | SpinBox | 128 |
| 反向 | CheckBox | 否 |

#### 组 2：轮廓提取（直接映射到 Raster_Vectorize 参数）

| 参数 | 类型 | 默认值 | 工艺语义 | Raster 参数 |
|---|---|---|---|---|
| 拟合方法 | 下拉 | Polygon | Polygon = 多边形折线近似 / Smooth = 移动平均平滑 / Arc = Kasa 圆拟合 + 圆弧采样 | `fitMethod` (RASTER_FIT_POLYGON/SMOOTH/ARC) |
| 拟合容差 | DoubleSpinBox | 1.0 px | 控制简化后轮廓和原图的最大允许偏差（像素）；越大轮廓点越少 | `tolerance` |
| 最小面积 | DoubleSpinBox | 10.0 px² | 过滤掉面积小于此值的轮廓（杂点/噪点） | `minArea = max(1.0, tolerance * tolerance)` 内部计算 |

#### 组 3：输出

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| 输出图层 | 下拉 | "加工轮廓" | 不存在时自动新建 |
| 世界坐标 DPI | SpinBox | 300 | 轮廓像素坐标 → 世界坐标的换算比例 |
| 孔洞保留 | CheckBox | 是 | 内轮廓作为孔洞（isHole），还是全部当成独立轮廓 | `Raster_Vectorize` 已按 hierarchy 自动标记 isHole |
| 平滑处理 | CheckBox | 是 | 拟合后再做一次移动平均平滑 | 额外调 `Raster_SmoothContours` |

### 4.3 确定后发生什么

1. `Raster_Vectorize(srcImage, fitMethod, tolerance, &contours)` → `RasterContourSet`
2. 如果返回 `RASTER_E_NOT_FOUND`（全白/全黑图像）→ 提示"No contours found in the image"
3. 遍历 contours 数组：
   - 每条 contour（`RASTER_FIT_POLYGON` 时是点序列）转换为 `AprPolyline`（开放）或 `AprPolygon`（闭合）
   - `isOpen = contour.isOpen`（vectorize 默认全闭合）
   - `isHole` 的轮廓放到同一图层但**颜色不同**（用户可在图层管理器里设置孔洞颜色 = 留白色）
4. 批量 `addEntity` 入场景 + Undo 压栈（一次命令一个 Undo record，redo 重放所有 add，undo 全部 delete）
5. 状态栏提示：`"Vectorized {N} contours (H={H}, O={O}), Undo available"`
6. 可选：`Raster_ApplyPathParams` 加微连接/引入线、`Raster_OptimizeTravel` 排序优化（**第一阶段不做，下一阶段**）

## 5. 与 Raster 能力对齐 — 当前限制与降级策略

| 设计需求 | Raster 能力 | 能否兑现 | 降级策略 |
|---|---|---|---|
| **灰度/彩色位图处理** | ✅ ToGray/Denoise/Sharpen/Adjust 全部支持 Gray8+RGB | 是 | — |
| **Even-Odd 填充** | ❌ OpenCV fillPoly 仅 Winding | 否 | 禁用 Even-Odd 选项，下拉只显示 Winding |
| **stroke join/cap 精细** | ⚠️ polylines 近似处理 | 近似 | UI 不暴露 stroke join/cap 参数，或标记"approximate" |
| **多边形孔洞裁剪** | ✅ Raster_Vectorize 按 hierarchy 标记 isHole | 是 | — |
| **矢量→位图光栅化** | ✅ RasterizePath/DrawPathOnImage 支持 | 是 | DPI 参数暂不生效（scale=1:1），下一阶段世界坐标→像素坐标换算 |
| **功率映射 Power Map** | ✅ Raster_PowerMap 有 Linear/Exponential/Gamma | 是 | 映射结果存在 RasterImage 的亮度梯度里（不影响实体属性） |
| **网格路径优化** | ❌ 无独立 API（用 ContourSet 层级） | 降级 | 当前只输出轮廓，不生成完整刀路 |
| **颜色分层** | ⚠️ 依赖 Raster_ToGray 先转灰度 | 降级 | 彩色图处理前自动 ToGray，UI 提示"Color image will be converted to grayscale first" |
| **自定义工艺管线** | ✅ Raster_Pipeline + Raster_RegisterCustomOp | 是（但第一阶段不暴露） | 第一阶段用硬编码管线（固定顺序），管线编辑器留到 v2 |

## 6. 撤销栈与事务

### 6.1 SceneUndoCommands 模式

Engine2D 的 `EntitySnapshotsCommand`：
- redo() = `replaceEntitiesById(after)` 或 `addEntities`
- undo() = `extractEntitiesById(before)` 或 `deleteEntities`
- 不 clone 实体，直接交换状态——O(1)

### 6.2 我们用它的方式

```cpp
// 添加一个 AprImage 到场景
auto* cmd = new Eg::EntitySnapshotsCommand(sceneManager, {newEntity}, /*添加*/ true);
undoStack->push(cmd);
```

### 6.3 批量操作

Vectorize 可能一次产出几十上百个 AprPolyline。用**一个** EntitySnapshotsCommand 包起来（一次性 add），撤销时**一次性** delete，不产生 N 个 undo 记录。

## 8. 后续路线图（不在 v1）

- **矢量→位图完整加工链路**：选中矢量实体 → DPI 光栅化 → 工艺处理 → 入场景
- **完整刀路生成**：Vectorize → 路径排序 → 微连接 → 割缝补偿 → g-code / HPGL 输出
- **颜色分层**：不同颜色不同加工模式（Engrave/Cut/Mark），一次 Vectorize 按颜色拆出多组轮廓
- **工艺管线编辑器**：图形化编排 `Raster_Pipeline` 操作序列，保存为 Recipe
- **参数记忆（Settings）**：QSettings 记住用户上次填的阈值/模式/DPI
- **更多对话框类型**：去重、反失真参数面板、阈值自动检测阈值范围的直方图显示
