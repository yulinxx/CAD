> **用途**：记录 Docs 中已设计但尚未完全落地、或设计更先进可作为后续优化方向的内容。按模块分类，标注优先级与实现难度。

## 1. 套料算法 - Nesting v2（最完整的先进设计）

文档：《Docs/06-算法专题/套料算法.md》§12

### P0 — 不补会出废品/安全事故
| 项 | 现状 | 先进设计要点 | 难度 |
|---|---|---|---|
| **引入/引出线并入 NFP** | 无。`partSpacing` 是各向同性标量，引入线伸出轮廓外未参与碰撞检测 | 把引入线几何并入 `Orientation.clearance` 参与 NFP 计算，而非事后检查。排完再检只能拒绝，不能生成正确布局。 | 高（几何并入 NFP） |
| **切割顺序 / 刀路产出** | 仅统计 `totalCutLength`，无切割序列 | 内孔先于外轮廓、空程 TSP、起点避开尖角/圆弧、穿孔点最小化。**共边有强顺序依赖**——必须一次切完，分两次热变形会错位。 | 高（需新 CAM 模块） |
| **微连接 / 桥接** | 无 | 留 0.2~0.5mm 微连接或桥把小件连成串。既是工艺功能，也反向约束排样（留桥走线空间）。 | 中 |
| **禁放区 / 板材缺陷区** | 板材只支持纯矩形 | `Nfp::InnerFitPolygon` 已支持任意多边形可用区，仅缺 API 入口（`NestingSheetDesc` 加轮廓数组）和 `SheetStock` 建模。**性价比最高**：机器已就绪，改动小。 | 低~中 |
| **热变形 / 积热** | 无。默认 `BOTTOM_LEFT` 目标最大化积热 | "跳切"分散热量。需在适应度加热惩罚项或引入时空调度。 | 中~高 |

### P1 — 影响利用率/竞争力
| 项 | 现状 | 先进设计要点 | 难度 |
|---|---|---|---|
| **连续旋转角度** | 仅支持离散角度集合 `rotations[64]` | 异形件用连续角度能显著提利用率。需把朝向展开从离散化改为连续优化（或混合）。 | 高 |
| **配对预处理** | 无 | 先把互补形状组成"超级件"再排，经典增益手段，通常拿几个百分点。 | 中 |
| **矩形族识别分流** | 无 | 激光加工大量同款矩形件 → 专用 strip/guillotine 算法完胜通用 NFP。理想架构：先分流矩形族走 strip，异形件再用 NFP 填缝。 | 中 |
| **大邻域搜索 (LNS / ruin-and-recreate)** | 纯 GA + 退火 | 工业界主流已是 LNS 类，同样时间预算下收敛快得多。 | 高 |
| **公开基准跑分 (ESICUP)** | 无 | 跑 Albano/Dagli/Jakobs/Mao/Marques/Shapes/Swim/Trousers 标准数据集，把利用率与文献 SOTA 对齐。无基准无法判断优化有效性。**最该先做的一件事**。 | 低（工程投入） |
| **全局晶格取舍** | 无 | `circles` 六边形密排面积效率 90.7% 但 50 件变 6 行反而比方阵 5 行高。"选哪种晶格"是全局取舍，逐件贪心看不到。 | 中 |

### P2 — 产品化
| 项 | 现状 | 先进设计要点 | 难度 |
|---|---|---|---|
| **预置已放置件 API** | 无。改参数就得全量重算 | 支持"这几件已在这些位置，请在剩余空间排"。直接支撑：用户手工拖动后重排、已开工板上补排。 | 中 |
| **增量重排** | 无 |  | 高 |
| **余料真实形状输出** | 仅报最大空矩形 | 余料回库闭环需输出多边形余料。 | 中 |
| **结构化失败诊断** | 仅 `errorMessage` | 放不下时区分：板太小 / 间距太大 / 纹理锁死 / 禁放区冲突。 | 低 |
| **跨平台 CI** | 声明跨平台，仅 Windows/MSVC 验证过 | Linux/macOS 编译验证进 CI。 | 低（工程投入） |
| **大规模鲁棒性** | 无顶点简化/skyline 近似 | 几千件 job，已放置件并集顶点数持续膨胀。带状剪枝只优化搜索范围，未优化并集本身复杂度。 | 高 |
| **多连通零件报警** | 静默保留最大一瓣 | 工业上应报警让用户知晓输入有问题，而非悄悄改图。 | 低 |
| **解析圆弧 NFP** | 按 `arcTolerance` 离散 | 对装箱影响有限，对相切精度有影响。 | 中 |

## 3. 新渲染架构

文档：《Docs/03-渲染主链/新渲染架构.md》

| 设计点 | 现状 | 先进设计 | 难度 |
|---|---|---|---|
| **进程级 RenderRuntime 单例** | 设计中 | 多窗口共享 GL context / 管线 / 字体 / buffer 池。每窗口 `RenderSession` 私有相机/视口/瞬态资源。 | 高 |
| **GPU 剔除 Compute (Vulkan/Metal) / CPU 回退** | 设计中 | 视锥剔除下放 GPU，避免 CPU 遍历 10 万实体。 | 高 |
| **屏幕空间不变性 (View Invariance)** | 设计中 | `DrawCommand` 标注 `RS_WorldSpace` / `RS_ScreenSpace`。缩放时：世界空间图元变大/变小；屏幕空间图元像素大小恒定（标注、十字准星、HUD、水印）。 | 中（部分已在 RenderSceneBuilder 体现） |
| **统一 sortKey 深度排序** | 设计中 | 64-bit: Layer(8) | Transp(8) | Depth(16) | Seq(16)。2D 全靠 Painter 算法，避免深度冲突导致线被面吞。 | 中 |
| **持久/瞬态 GPU 资源两类生命周期** | 部分落地 (GeometryStore + DrawList) | 持久：静态图元顶点缓冲、纹理、网格。瞬态：Overlay 顶点、预览线、每帧文本四边形 → 每帧 ring-buffer 分配。 | 中 |
| **字体接口：DLL 只出字形度量与图集，宿主自己拼四边形** | ABI 5.0 已调整 | `rxFontCreate` 系列替代旧 `rxFontLoad`。排版在宿主，图集在 DLL。 | 已落地 |

## 8. 综合建议：后续优化框架的优先级建议

### 立即可做（低成本、高收益）
1. **Nesting：禁放区/任意形状可用区** — 机器已就绪（`InnerFitPolygon`），仅补 API 入口
2. **UI：场景树右键菜单迁移到配置驱动** — 按现有 `contextMenus` + `dynamicSections` 模式
3. **UI：配置校验单测补齐** — 命令 ID 注册检查、feature 拼写检查
4. **UI：客户专属 C++ 目录约定落地** — `custom/<clientId>/` + 运行期注册
5. **文档：feature 命名规范与授权矩阵文档化** — 对齐 `UiConfigSelfCheck` 映射表

### 近期规划（中成本、核心竞争力）
1. **Nesting：引入/引出线并入 NFP** — 安全问题，P0
2. **Nesting：跑 ESICUP 公开基准** — 建立可量化基准，后续所有优化有判断依据
3. **Nesting：配对预处理 + 矩形族分流** — 直接攻克 `crosses` +50% / `L-shapes` +19%
4. **HAL：SafetyMonitor 落地** — 语义层 IO 点位映射，客户加传感器只改配置

### 中长期（高成本、架构级）
1. **Nesting：LNS / ruin-and-recreate 搜索算子** — 替代纯 GA，收敛快得多
2. **Nesting：切割顺序 + 共边刀路 + 微连接** — 三位一体的 CAM 工艺层，**建议单开 CAM 模块**
3. **渲染：进程级 Runtime + GPU Compute Culling** — 多窗口共享资源、大场景性能
4. **跨平台 CI + 大规模鲁棒性验证** — 真正的工业级交付基线
