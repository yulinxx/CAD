## 0. 结论先行

1. **现状是"只排不切"**。Nesting 侧只有共边排布：`Placer.cpp` 用 `enableCommonLine` 构造第二套零切缝几何找贴合位，按共线重叠累计 `commonLineMm`；`Solver.cpp` 只把它累进报告并从 `totalCutLength` 里减掉。切割侧没有共用轮廓提取、没有合并走刀、没有单侧补偿。
2. **识别必须发生在割缝补偿之前**。当前生产路径的割缝补偿在桥接层 `Main/Src/CAM/CamInputBridge.cpp` 按图元逐条外扩，CAM 内部 `KerfParams` 被显式关闭。对已补偿轮廓做事后识别，两件的共边已经变成两条相距 k 的平行线，无法可靠区分"共边"与"普通留缝"，也无法执行单侧补偿。
3. **一刀两件，只有一条刀心线**。共边段的补偿不是"A 外扩 k/2、B 再外扩 k/2 各切一刀"，而是由共边处理器统一生成一条位于两件名义边之间的共用刀心线，缝宽由这一刀的 k 一次决定。两侧各自偏置只在 `d = k` 时数值上恰好重合，不能当作通用做法。
4. **CAM 落点**：识别、单侧补偿、合并单元生成属于 `GeometryTransform`（规划中已有 `CoEdgeFinder.cpp` 位置）；走刀顺序与引入引出约束属于 `Order`；缝宽、目标缝距、共边开关等参数汇聚属于 `Process`；`Emit` 只做指令翻译，不碰几何。
5. **收益量级**：矩形阵列基准下切削总长可降约 40%～45%，空移/穿孔次数可降约 50%～80%，板材面积节省取决于留缝 g 与目标缝距 c 的差值，g=2～4mm 时约 2.5%～5%，默认 g=0.1mm 时不足 1%。代价是尺寸让料与工艺窗口收窄，见第 5 章。
6. **先做只读识别与长度对账**：用名义轮廓识别共边段、统计长度，与 Nesting 的 `commonLineLength` 对账；对得上再做单侧补偿与合并走刀。对账口径差异已在 1.5 节列全。

### 1.2 切割侧现状

CAM 只有 M0 骨架：`Include/CAM/` 的四个契约头（`CamCore.h`、`CamPlan.h`、`ToolpathJobInput.h`、`CamContext.h`），另有 `CAMExport.h` 只提供导出宏；`Src/{Emit,Estimate,GeometryTransform,Order,Process,Validate}` 全是 `.gitkeep`。`CamPlan.h` 明确写着 M0 不做共边切割，`CamCore::compile` 的主流程是"校验 → 分层 → 按 `sourceEntityId` 排序 → 每轮廓前插一条 Rapid → 统计长度/包围盒"。

同时有一个边界外的事实必须纳入设计：**割缝补偿目前已经在桥接层完成**。`CamInputBridge.cpp` 在每个图层内调用 `Eg::Cam::KerfCompensator::apply`，把 `kerfMm` 当作单边值、以 `kerfWidth = 2 × |kerfMm|` 做等距偏置，然后把 `bucket.kerf.enabled = false`，避免 CAM 二次偏置。也就是说，CAM 今天拿到的 `EntitySnapshot.contours` 已经是补偿后轮廓，名义轮廓在桥接层被覆盖后不再保留。

> 规划文档中的 `Src/GeometryTransform/CoEdgeFinder.cpp` 是目标态位置，不是现状。本文的接口与数据结构都是提案，落地前需要按 CAM 的 ABI 约定（字段只允许尾部追加）评审。

### 1.3 术语

| 术语 | 定义 |
|------|------|
| 名义轮廓 | 零件图纸轮廓，未做割缝补偿 |
| 补偿轮廓 | 按单边补偿值偏置后的刀心轨迹（普通留缝切割时使用） |
| 共边段 | 两个不同零件的名义边在容差内平行、按目标缝距相对、且材料分处两侧的公共区间 |
| 共用刀心线 | 共边段上唯一的一条刀心轨迹，一刀同时形成两件的边界 |
| 共边组 | 通过共边段连通的若干零件及其边构成的切割子图 |
| 目标缝距 c | 排样时两件名义边的设计间距，对应 Nesting 的 `commonLineKerf` |
| 实际缝宽 k | 当前工艺（材料、板厚、功率、速度、气压、焦点）下切缝的实际宽度 |
| 实测间距 d | 落位后两件名义边之间的实际垂距（受排样精度影响，通常 d ≈ c） |
| 单边损失 δ | 共边切割后单件在共边侧被切掉的材料厚度，`δ = max(0, (k − d)/2)` |

## 2. 共边段的几何识别

### 2.1 输入前提（硬约束）

1. **必须输入名义轮廓**。补偿后的轮廓在共边处已经是两条相距约 k 的线，且 d 与 k 的差异被补偿吞掉，无法判断该不该共用。识别器只接受未补偿几何。
2. **同图层、同工艺参数**。共边意味着一刀同时满足两件的功率/速度/遍次；跨图层或参数不同的轮廓禁止合并。判断依据是 `sourceLayerId` 与 `LayerBucket.params` 的工艺键，不是几何。
3. **不同零件**。`sourceEntityId` 必须不同；同一实体的外环与孔环之间不得共边。
4. **一期只处理闭合外轮廓的直线段**。孔洞边、开放轮廓、圆弧/样条共边一律拒绝并计数，理由见 2.4。
5. **两件材料分处共边线两侧**。这是区分"真共边"与"重合重复图元"的关键：后者材料在同一侧，一刀切下去只是复切同一条边。

### 2.2 判据

对候选轮廓对 (A, B) 的线段对 (a, b) 依次判定：

| 序号 | 判据 | 建议默认 | 说明 |
|------|------|----------|------|
| C1 | 两段均为 `Line`，且长度 > 0 | — | 圆弧/样条一期直接拒绝 |
| C2 | 方向平行（含反向）：`\|sinθ\| ≤ ε_ang` | `ε_ang = 1e-4 rad`（约 0.006°） | 与 Nesting 的 1e-6 相比更宽，但仍远小于工艺角差 |
| C3 | 名义间距匹配目标缝距：`\|d − c\| ≤ ε_gap` | `ε_gap = max(0.01mm, 0.05 × k)` | 排样偏差、定点量化、旋转误差都落在这里 |
| C4 | 沿共边方向的重叠长度 `L_ov ≥ max(minSharedLengthMm, 2 × ε_gap)` | `minSharedLengthMm = 5mm`（沿用 Nesting 默认） | 过滤擦角、短搭接 |
| C5 | 材料异侧：A 的外法向与 B 的外法向点积 `≤ −cos(ε_ang)` | — | 排除重合重复图元与同侧贴合 |
| C6 | 取共边区间中点 m，`m` 不在任何一件内部；`m ± n·(k/2 + ε_gap)` 分别落在 A、B 的材料内 | `n` 为共边法向 | 用点在多边形内测试，排除薄壁与自交退化 |
| C7 | 共边区间内部不得被第三条第轮廓穿越（无 T 型接头） | 距离容差 `ε_pos` | T 型接头留到二期，见 2.5 |
| C8 | 共边区间两端都落在 A、B 的顶点上（允许 `ε_pos` 偏差） | `ε_pos = max(tolerance, 0.01mm)` | 部分搭接（一端在段中间）一期拒绝 |
| C9 | 共边段不应作为某件的"唯一剩余边"，即该件至少还有一条非共边段可用于引入 | — | 见 3.3 的引入引出约束 |

判定结果分三类：`Accepted`、`Rejected(reason)`、`Deferred(reason)`。拒绝原因必须可枚举（弧段、间距不符、材料同侧、短搭接、T 型接头、部分搭接、跨层），并进入统计，不能静默丢弃。

### 2.3 唯一化与复杂度

- 先把每条轮廓中相邻且共线的线段合并成一条"支撑线段"，再做线段对匹配，避免同一条物理边被拆成多段重复计数。
- 以 `(min(entityA, entityB), max(entityA, entityB), 支撑线 id)` 为键；同一对轮廓在同一支撑线上的重叠区间做一维区间并集，保证一条物理共边只生成一个 `SharedEdge`。
- 粗筛用包围盒外扩 `ε_gap + ε_pos` 做 sweep，再按方向分桶；精确判定为线段对。目标复杂度 `O((n + k) log n + m)`，其中 `m` 为候选线段对数；小规模（< 200 条轮廓）可退化为 O(n²)，但必须在日志里标注走的是朴素路径。
- 单个零件外围可能同时与多个零件共边；`SharedEdge` 按"件-件"记录，不允许把三条边并成一条。

### 2.4 圆弧与曲线共边的处理

Nesting 的共边测量跑在 Clipper 的 `Paths64` 上，圆弧在桥接/离散化阶段已经变成弦段，因此弯曲贴合会被逐弦累计出可观的 `commonLineMm`。切割侧的语义共边是"一条连续共用边界"，弦段匹配会把一条圆弧拆成几十条共边，补偿与走刀都无法按弦处理。

一期明确**不支持圆弧共边**：识别器遇到圆弧贴合返回 `Rejected(ArcShared)`，并把估算长度单独统计为"弧段共边（未合并）"。这样既不会静默少算，也不会把圆弧硬拆成弦导致过切。二期若要做，需要按同心/同半径/同向做弧-弧重叠判定，并在刀心线上做圆弧偏置，工作量与直线段不是一个量级。

### 2.5 端点与 T 型接头

- **两端都在顶点**：共边段与两件的非共边段在端点相接，补偿从"共用刀心线"切回"各自外扩 k/2"时会产生横向跳变，跳变量为 `δ = max(0, (k − d)/2)`。`d = k` 时跳变为 0，是最干净的配置。
- **一端在段中间（部分搭接）**：搭接端没有现成顶点，跳变位置落在材料内部，必须插入过渡段并决定过切归属；一期拒绝。
- **T 型接头**：第三条轮廓垂直落在共边区间内部，会把共边段切成两段并产生奇数度顶点。一期拒绝；二期按"拆段 + 每段独立判定 + 接头处留微连接"处理。

### 2.6 切缝宽度、目标缝距与补偿的关系（核心物理约束）

设 A 的材料在共边线左侧、B 在右侧，两件名义边相距 d，实际缝宽 k，一刀的切除带以共用刀心线为中心、带宽 k：

```
A 材料 |<-- δ -->| 切除带宽度 k |<-- δ -->| B 材料
       名义边                        名义边
       x = 0                         x = d
       δ = max(0, (k − d) / 2)
       刀心线 x = d / 2
```

| d 与 k 的关系 | 单刀能否成立 | 单件尺寸 | 结论 |
|---------------|--------------|----------|------|
| `d ≈ k` | 能 | 名义尺寸 | 推荐配置；两件各自外扩 k/2 的刀心线恰好重合在中线 |
| `0 ≤ d < k` | 能 | 共边侧单边缩短 `δ = (k − d)/2` | 可以做，但必须由工艺/质量确认让料 |
| `d > k` | 不能作为共边 | 名义尺寸，但两件之间残留宽度 `d − k` 的连料条 | 拒绝合并；按普通留缝切两刀，否则残条会翘起/撞头 |

由此得到三条硬结论：

1. **补偿只能按单侧切缝算**。共边段只有一条刀心线，缝宽由这一刀的实际 k 决定；不能把 A、B 两条补偿轮廓各发一遍。各发一遍等于同一位置切两刀：热输入翻倍、缝宽扩大到约 2k、挂渣与热影响叠加，且当 `d ≠ k` 时两条线还会错位，直接切进邻件。
2. **`d = k` 是唯一不需要让料的配置**。这也解释了为什么 Nesting 的 `commonLineKerf` 注释写"通常 = 切缝宽或 0"：填 0 时零件贴死，一刀下去两件各让 k/2；填成实际缝宽时两件都保名义尺寸。
3. **`c > k` 必须被拦截**。排样允许 `commonLineKerf` 取到 10mm，远大于常见激光缝宽 0.1～0.3mm；此时共边合并不成立，CAM 必须降级为普通留缝切割并给出告警，而不是按共边处理。UI/桥接层应在下发前做 `c ≤ k` 校验。

默认参数的现实影响：Nesting 默认 `commonLineKerf = 0`，光纤激光切 1～3mm 碳钢的 k 约 0.1～0.3mm，因此默认共边会让每件在共边侧单边少 0.05～0.15mm。这不是 CAM 能替用户决定的事，必须显式暴露（见第 7 章）。

### 2.7 与 Nesting `commonLineLength` 的对账口径

切割侧统计要能和现有报告对上，必须知道两边口径的差异：

| 维度 | Nesting 现状 | CAM 识别（建议） | 对账处理 |
|------|--------------|------------------|----------|
| 几何来源 | `shape`（名义轮廓的定点折线） | 名义轮廓 | 一致 |
| 距离容差 | `probeInt` 由 `partSpacing/2` 的定点值再整除 2 得到，约 `partSpacing/4`，随间距放大 | `ε_gap`，与 k 挂钩 | 基准用例固定 `partSpacing` 后再比 |
| 平行容差 | 归一化叉积 ≤ 1e-6 | `ε_ang = 1e-4 rad` | 直线基准无差异 |
| 最小长度 | 门槛作用在"单个候选对所有邻件的合计"上，不是单对 | 单段 `minSharedLengthMm` | CAM 更严格；对账时 CAM 先不做单段过滤再比 |
| 曲线 | 弦段逐段累计，会计入弯曲贴合 | 一期不支持弧共边 | 只在线段基准上对账，弧段单独列差 |
| 板边 | API 注释称"含板边"，实现只遍历已放置件，未与板材边求共边 | 只做件-件 | 板边共边按 0 预期 |
| 重复计数 | 每个件对"已放置件"各算一次，天然一对一次 | 键唯一化 | 一致 |

建议的对账门槛：单板 `|CAM − Nesting| ≤ max(0.5mm, 0.5%)`；逐对共边长度误差 ≤ `ε_gap`；弧段与 T 型接头单独出"未合并长度"清单，不计入误差。达不到时先查口径，不要先改识别容差。

## 3. 合并走刀与路径顺序

### 3.1 合并后的拓扑：切割图

把每件名义轮廓的每条边作为一个图边，顶点为边的端点；共边段是**一条图边挂两个面引用**（A 的面、B 的面），不是两条重合边。合并后的 `CutUnit` 是图上的连通走刀单元，可以是一条轮廓，也可以是若干净轮廓沿共边串成的链。

对规则矩形阵列可以算出理论上界：N×N 个正方形满共边时，内部网格交点为 4 度，板材外边界上的 T 型交点为 3 度（奇数度），奇点数为 `4(N−1)`。欧拉路径需要的抬刀次数下界为 `奇点数/2 − 1 = 2(N−1) − 1`，而逐件切割需要 `N² − 1` 次空移。9×9 时约 15 次对 80 次，空移次数降约 80%；穿孔次数同量级下降（每次抬刀后重新穿孔）。这是**理想上界**，实际会被引入引出、热约束、分组策略抬高，见 3.2、3.3。

### 3.2 顺序约束

| 编号 | 约束 | 类型 | 违反后果 |
|------|------|------|----------|
| O1 | 内孔先于所属外轮廓 | 硬 | 外轮廓先切完，件已脱离，再切孔会位移、孔位超差 |
| O2 | 同一共边段全流程只切一次 | 硬 | 重复切割导致热影响叠加、缝宽扩大、挂渣 |
| O3 | 共边段不得作为任一件的最后闭合段 | 硬 | 闭合瞬间件被完全释放，后续走刀振动/件位移会夹住喷嘴或撞头 |
| O4 | 穿孔点、引入点、引出点、过切点不得落在共边段及其端点 | 硬 | 在共边处穿孔会在两件上各留一个缺口；过切会切进邻件 |
| O5 | 相邻非共边平行线的间距必须 ≥ k + 安全余量 | 硬 | 两条切缝搭接，实际变成一条宽缝，两件都超差 |
| O6 | 共边组内不得让两件的最后闭合段在窄桥两侧相邻 | 硬 | 窄桥两端几乎同时被切开，件翻转/掉落 |
| O7 | 共边段与件的闭合段之间至少隔一条非共边段 | 软（推荐） | 让闭合发生在刚性强、远离共边的一侧，降低位移风险 |
| O8 | 共边组内连续切割长度超过阈值时插入分段/冷却 | 软（工艺） | 连续长路径热积累，局部过烧；分段又增加穿孔，需权衡 |
| O9 | 小件、细长件、重心偏离大的件晚于大件切 | 软（推荐） | 小件先落，后续大件移动/吸附可能带飞小件 |
| O10 | 同一共边组内优先切"离组外引入点近"的单元 | 软（空移） | 空移变长，收益被抵消 |

O3 与 O4 是"会切坏已切好的件"的两条主因，必须在 `Order` 层作为不可违反的约束，而不是靠排序后的启发式补救。

### 3.3 引入、引出与过切

- **穿孔点**：只能放在非共边段上，优先放在废料侧或远离成品的角部。共边段端点两侧都是成品，穿孔延时会在两件上同时造成热斑与缺口，禁止。
- **引入线**：方向沿切割方向切向进入，且从远离共边的一侧进入。若某件的所有边都是共边（满网格的中间件），单件内部不存在合法穿孔点，只有两条路：按"组"整体引入（组外穿孔，一次走完整组），或在共边端点做微连接/桥接。前者把风险集中到整组，后者需要工艺与后处理支持，属于第 7 章的待决问题。
- **引出与过切**：过切通常发生在轮廓闭合点，长度 o。若闭合点落在共边段上，过切会越过共用刀心线切进邻件，形成 double-cut；若闭合点落在非共边段，过切只影响本件。规则：闭合点必须在非共边段，且过切终点不得越过任何共边线。
- **共边组整体走刀**：把整组当一个 `CutUnit` 时，一次穿孔、一条连续路径，空移与穿孔最少；但组内任一点异常会导致整组报废，且热输入连续。建议默认按"行/列链"分组，不默认整板一组，阈值由工艺试验确定。

### 3.4 明确会切坏已切好件的顺序（负面清单）

1. 先切某件的闭合段，再沿它的共边切邻件：件已自由，切割振动与熔渣会把件推离原位。
2. 沿同一条共边切两遍：热影响区叠加、缝宽扩大、下表面挂渣，薄板会翘曲。
3. 把共边段当作邻件的引入段：穿孔落在已切缝上，光会从缝里漏下去，穿孔检测与电容调高失效。
4. 从共边端点起弧/收弧：端点成为两件共用的缺口，尖角处热集中，形成烧边。
5. 先外轮廓后内孔：违反 O1，件脱离后孔位漂移。
6. 两件最后闭合段隔着一条窄桥相对：桥被两端夹切，件翻转或掉落。
7. 共边组内跨件长距离连续切且不降速：热量沿路径累积，末端过烧；但盲目插入分段又会增加穿孔与空移，必须用试切数据定阈值。
8. 小件先切、大件后切且共用吸附区域：大件切割时的振动/吸附释放会把已落小件带飞。

## 4. 与 CAM 骨架的落点

### 4.1 分层归属

| 能力 | 归属 | 理由 |
|------|------|------|
| 共边段识别（几何判据、容差、唯一化） | `GeometryTransform`（`CoEdgeFinder`） | 纯几何、无设备依赖；规划文档已预留该文件位置 |
| 单侧补偿与共用刀心线生成 | `GeometryTransform`（`SharedPathBuilder`，新增） | 与识别共享同一套名义几何与 k/c 参数，必须同层完成 |
| 共边组合并、切割图构造 | `GeometryTransform`（`CutGraphBuilder`，新增） | 输出 `CutUnit`，供排序消费 |
| 走刀顺序、引入引出/过切约束 | `Order`（扩展现有 `ContourSorter` 的输入为 `CutUnit`） | 顺序是全局问题，不能塞进几何变换 |
| 共边开关、c、k、最小共边长、偏置策略的参数汇聚 | `Process`（`ParamIntegrator` 扩展） | 参数来自 `LayerBucket` 与工程默认值，集中在一处解析 |
| 发射 | `Emit` | 只把已确定的 `CamPlan` 翻成 `MotionPlan`，不做任何几何判断 |
| 统计与校验 | `Validate` / `Estimate` | 覆盖率、双切长度、未合并长度、时间预估 |

**结论**：共边处理的主体在 `GeometryTransform`，`Order` 只消费合并后的单元并施加顺序约束，`Process` 只提供参数。不存在"在 `Emit` 里合并"的选项——那会丢失轮廓包含关系与绕向信息，也无法回写统计。

### 4.2 与当前补偿位置的冲突及三种落地方式

| 方案 | 做法 | 优点 | 缺点 | 建议 |
|------|------|------|------|------|
| A. 补偿上移到 CAM | 桥接层输出名义轮廓，`GeometryTransform/KerfCompensator` 统一补偿，共边识别与补偿在同一层 | 语义完整，可做单侧补偿与偏置，统计可对账 | 需要一次行为保持的重构，回归面较大 | **目标态，推荐** |
| B. 桥接层先共边后补偿 | 在 `CamInputBridge` 补偿前调用共边识别，把结果传给 CAM | 改动小，能快速验证 | 几何逻辑分裂在 Main 与 CAM 两处，CAM 单测拿不到名义输入，长期不可维护 | 仅作为 P0 的临时取数手段 |
| C. 补偿后去重 | CAM 在已补偿轮廓上找重合折线并去重 | 实现最简单 | 只在 `d ≈ k` 时两条线才重合；`c = 0`（默认）时两条线相距 k，完全失效；无法判断 d 与偏置策略 | 不推荐作为方案，最多做兜底告警 |

方案 A 与 M1 规划一致（`KerfCompensator.cpp` 本来就在 `GeometryTransform`），建议按"A + 分阶段"推进：P0 先用桥接层导出的名义快照做只读识别，P1 再把补偿迁入 CAM。

### 4.3 建议的数据结构（内部，非最终 ABI）

`NominalContour` / `CompensatedContour` 指内部几何包装（轮廓索引、`sourceEntityId`、`layerId`、绕向、闭合标志、折线/路径），只在 `GeometryTransform` 内部使用，不进公开 ABI。

```cpp
namespace Cam::GeometryTransform
{
    /// 共边识别与补偿参数，由 Process 层从 LayerBucket 汇聚
    struct CoEdgeParams
    {
        bool enabled = false;
        double nominalGapMm = 0.0;        ///< 目标缝距 c，来自排样 commonLineKerf
        double kerfWidthMm = 0.0;         ///< 实际缝宽 k，来自工艺参数
        double minSharedLengthMm = 5.0;   ///< 单段有效共边最小长度
        double posToleranceMm = 0.01;     ///< 位置/共线容差
        double angleToleranceRad = 1e-4;  ///< 平行度容差
        int32_t bias = 0;                 ///< 0 中线，+1 偏向 A，-1 偏向 B
        bool allowArcShared = false;      ///< 一期固定 false
    };

    /// 一条共边段：两个名义轮廓的一个公共区间
    struct SharedEdge
    {
        uint32_t id = 0;
        int32_t layerId = 0;
        uint32_t contourA = 0;            ///< 轮廓索引，A < B 保证唯一
        uint32_t contourB = 0;
        uint32_t supportLineA = 0;        ///< 合并共线段后的支撑线编号
        uint32_t supportLineB = 0;
        Ut::Vec2d start;                  ///< 共边区间起点，用户坐标
        Ut::Vec2d end;                    ///< 共边区间终点
        double lengthMm = 0.0;
        double measuredGapMm = 0.0;       ///< 实测名义间距 d
        double kerfMm = 0.0;              ///< 当前缝宽 k
        double lossPerPartMm = 0.0;       ///< 单边损失 δ = max(0, (k - d) / 2)
        int32_t bias = 0;                 ///< 该段的偏置决策
        bool valid = true;
    };

    /// 识别结果
    struct SharedEdgeSet
    {
        std::vector<SharedEdge> edges;
        std::vector<std::vector<uint32_t>> perContour; ///< 轮廓 → 共边段 id
        double totalLengthMm = 0.0;
        double rejectedArcLengthMm = 0.0;              ///< 弧段共边估算长度，仅统计
        uint32_t rejectedCount = 0;
        uint32_t deferredCount = 0;
    };

    /// 走刀单元：单轮廓，或沿共边串起来的轮廓组
    struct CutUnit
    {
        uint32_t id = 0;
        std::vector<uint32_t> members;      ///< 轮廓索引
        std::vector<uint32_t> sharedEdges;  ///< 本单元内被合并的共边段
        bool closed = false;
        double cuttingLengthMm = 0.0;
        Ut::Vec2d entry;                    ///< 入口点，须在非共边段
        Ut::Vec2d exit;                     ///< 出口点，须在非共边段
        int32_t piercePolicy = 0;           ///< 单件穿孔 / 组级穿孔 / 微连接
    };

    /// 切割图：单元 + 邻接 + 奇点统计
    struct CutGraph
    {
        std::vector<CutUnit> units;
        std::vector<std::vector<uint32_t>> adjacency; ///< 单元间空移邻接
        uint32_t oddDegreeCount = 0;
        uint32_t lowerBoundLiftCount = 0;             ///< 奇点数/2 - 1，抬刀次数下界
    };
}
```

## 5. 与"件间留缝"方案的取舍

### 5.1 收益模型

设单板共边总长 `L_s`、留缝 `g`、目标缝距 `c`、缝宽 `k`、板材面积 `A_s`：

- 面积节省：`ΔA ≈ (g − c) × L_s`（只有当 c ≤ g 时为正；c > g 不存在，因为排样不会主动放大间距）
- 面积节省比例：`ΔA / A_s`
- 切削长度：从 `Σperimeter` 降到 `Σperimeter − L_s`，降幅 `L_s / Σperimeter`
- 穿孔/空移：从逐件 `N` 次降到图上的抬刀次数，理想下界 `奇点数/2 − 1`

注意 `ΔA` 是"排布占用面积"的减少，不等于可排件数一定增加：能否多排一件取决于离散尺寸是否刚好跨过门槛。若 `c < k`，还要把两件各 `δ` 的尺寸让料单独记账，不能与面积收益相加。

**算例（解析估算，非实测）**：1000×1000mm 可排区，81 个 100×100mm 正方形（9×9），`k = 0.2mm`。

| 指标 | 留缝 g=2mm | 共边 c=0.2mm | 变化 |
|------|-----------|--------------|------|
| 单件周长合计 | 32,400mm | 32,400mm | — |
| 共边总长 `L_s` | 0 | 14,400mm | — |
| 实际切削长度 | 32,400mm | 18,000mm | −44.4% |
| 面积节省 `(g−c)·L_s` | 0 | 25,920mm² | 约占单板 2.6% |
| 空移次数（理想上界） | 80 | 约 15 | −81% |
| 穿孔次数（理想上界） | 81 | 约 16 | −80% |

若生产留缝取 g=4mm，面积节省升到约 5.5%；若取 Nesting 默认 g=0.1mm 且 c=0，面积节省约 0.14%，此时共边的主要收益是切削长度、穿孔与热输入，而不是省料。**不要用"默认 0.1mm 留缝 + 共边"去承诺省料比例**，那会把切长收益误报成利用率收益。

### 5.2 工艺风险

| 风险 | 机理 | 影响 | 缓解 | 验证方式 |
|------|------|------|------|----------|
| 尺寸让料 | `d < k` 时单边损失 `(k−d)/2` | 共边侧尺寸偏小，可能超差 | 强制 `c = k`；或显式选择偏置侧，只让一件 | 三坐标/影像仪抽检共边侧 |
| 热影响叠加 | 相邻切缝距离小于热影响区，或复切 | 过烧、挂渣、薄板翘曲 | 单刀只切一次；间距 < k 的边禁止并存；必要时降功率/提速度 | 金相/挂渣等级、平面度 |
| 件位移 | 共边把两件同时释放，闭合段切完即掉 | 尺寸漂移、撞头、废件 | O3/O6/O9；微连接；吸附分区 | 试切后件位复测 |
| 共边处毛刺/挂渣 | 无引出空间，熔渣向两件同时排 | 双面挂渣，去毛刺成本上升 | 引入引出放非共边侧；气压/焦点专项试验 | 挂渣等级、去毛刺工时 |
| 端点缺口 | 穿孔/过切落在共边端点 | 两件同时缺口 | O4；闭合点移到非共边段 | 端点放大检查 |
| 残条/薄壁 | `d > k` 留残条；T 型接头留薄壁 | 残条翘起、薄壁烧穿 | 拒绝 `d > k`；一期拒绝 T 型接头；设最小残留壁厚 | 试切观察 + 壁厚抽检 |
| 板材变形 | 连续长路径热积累 | 切割失焦、下半部分超差 | O8；分段/冷却；随动调高 | 长路径试切 |
| 返修与追溯 | 共边损伤会波及邻件 | 单件报废牵连多件 | 共边组粒度追溯；组内质量联检 | 质量流程评审 |
| 余料回收 | 共边切碎余料，最大空矩形变小 | 余料板不可回收 | 共边只用于内部密集区，边缘留整料 | 余料报表对比 |

### 5.3 决策建议

| 场景 | 建议 | 理由 |
|------|------|------|
| 薄板（≤ 3mm）碳钢/不锈钢，密排矩形件 | 默认开启，`c = k` | 热影响可控，切长与穿孔收益最大 |
| 厚板（> 6mm） | 默认关闭，仅长直边、成对开启 | 缝宽大、热影响区宽、尺寸让料风险高 |
| 铝/铜/高反材料 | 默认关闭，需试切标定 | 缝宽与挂渣对参数敏感 |
| 需要单件可追溯/可返修的订单 | 默认关闭 | 共边损伤会牵连邻件 |
| 余料需回收的订单 | 仅在内部密集区开启 | 保护边缘整料 |

## 6. 分阶段落地建议

### P0：共边识别 + 长度对账（只读，不改变刀路）

- **交付物**：`GeometryTransform/CoEdgeFinder` 的识别内核、拒绝原因枚举、单元测试、对账用例；结果只进内部诊断，不写 `CamPlan`，不改变现有输出。
- **取数方式**：桥接层导出名义轮廓快照（方案 B），或在测试中直接构造 `ToolpathJobInput` 名义几何；不动生产补偿逻辑。
- **验收门槛**：
  - 合成用例（矩形贴合、L 形贴合、部分搭接、T 型、弧贴合、重合重复图元、跨层）判定 100% 符合预期；
  - 9×9 矩形阵列识别共边 14,400mm，与解析值误差 ≤ 0.1%；
  - 与 Nesting `commonLineLength` 单板对账误差 ≤ `max(0.5mm, 0.5%)`（仅直线基准；弧段/T 型单列）；
  - 对照用例（普通留缝、重合重复图元、跨层贴合）误合并数 = 0；
  - 2000 条轮廓的单层识别耗时 ≤ 100ms（参考机，需实测记录）。
- **为什么先做它**：识别是纯几何、可独立验证，且能立刻暴露"两边口径不一致"的问题；不改刀路，风险最低。

### P1：单侧补偿 + 合并单元（仍按单元顺序切，不做高级排序）

- **交付物**：`SharedPathBuilder`、`CutGraphBuilder`；每个共边段在 `CamPlan` 中只出现一次；补偿迁入 CAM `GeometryTransform`（或先保持桥接层但共享同一识别结果）。
- **验收门槛**：
  - 每条名义边被覆盖且仅被覆盖一次：`uncoveredEdgeLengthMm = 0`、`doubleCutLengthMm = 0`；
  - 9×9 基准切削总长 = 18,000mm（相对解析值误差 ≤ 0.1%）；
  - 关闭共边时，输出与 M0 当前结果几何等价（黄金文件比对，差异 = 0）；
  - `c > k`、`d > k`、弧段、T 型、部分搭接全部走拒绝路径并计数，无误合并。

### P2：顺序约束与引入引出

- **交付物**：`Order/orderCutUnits`，实现 O1～O10；穿孔点、引入引出、过切落点规则；约束校验器。
- **验收门槛**：
  - 基准集上 O1～O6 违反数 = 0；
  - 空移次数相对 P1 下降 ≥ 30%，穿孔次数下降 ≥ 30%；
  - 共边段上穿孔/过切落点数 = 0；
  - 每个 `CutUnit` 至少有一个合法入口；无合法入口的单元被标记并降级为单件切割（不得静默通过）；
  - 与 `SimulatedDevice` 跑通完整指令序列，无空移穿越已切区（按几何检查）。

### P3：工艺参数联动与试切

- **交付物**：`Process` 层的 `c` 与 `k` 联动校验（`c > k` 报错/降级、`c ≠ k` 告警）、共边段功率/速度降额策略、UI 提示、材料-板厚参数矩阵。
- **验收门槛**：
  - 试切件共边侧尺寸偏差 ≤ 工艺给定公差（需质量确认，建议先按 ±0.1mm 做目标）；
  - 挂渣等级、热影响宽度不劣于留缝方案的同材料基准；
  - 连续切割长度阈值、最小残留壁厚由试切数据给出正式值，不使用拍脑袋常量；
  - 形成"材料 × 板厚 × 功率 × 速度 × c/k"的参数表，未覆盖的组合默认关闭共边。

每个阶段都以"数字门槛"收口；P0 不达标不进入 P1。

## 7. 代码层无法回答、需要工艺或法务判断的问题

| 问题 | 为什么代码无法回答 | 需要谁 | 影响 |
|------|--------------------|--------|------|
| 共边侧尺寸让料归谁：两件各让 `(k−c)/2`，还是只让一件 | 取决于客户图纸公差与装配关系，不是几何问题 | 质量/客户 | 决定 `bias` 默认值与是否允许 `c < k` |
| 缝宽 k 与材料、板厚、功率、速度、气压、焦点的对应关系 | 必须试切标定，无法从代码推导 | 工艺 | 决定 `c = k` 能否成立 |
| 最小可接受共边长度、最小残留壁厚、最小窄桥宽度 | 与材料、板厚、件重、吸附方式相关 | 工艺/设备 | 决定 C4、C7、O6 的阈值 |
| 孔边、内轮廓能否共边；孔内套料的件能否与宿主共边 | 涉及功能与装配语义，当前排样明确保持孔壁安全距离 | 产品/工艺 | 决定一期是否只做外轮廓 |
| 共边段是否需要降功率/提速度，降多少 | 热输入与路径连续长度相关，需实验数据 | 工艺 | 决定 P3 的参数矩阵 |
| 是否允许微连接/桥接，残留如何去除 | 涉及后处理工序与客户验收 | 工艺/质量 | 决定满共边中间件的引入方案 |
| 件位移的抑制手段（吸附分区、膜、夹具）是否可用 | 设备与工装条件 | 设备/工艺 | 决定 O3/O9 的严格程度 |
| 共边切碎的余料是否还允许登记回收 | 生产与库存策略 | 生产 | 决定共边区域是否避让板材边缘 |
| 共边导致两件表面/挂渣差异是否在合同允许范围内 | 合同与验收标准 | 法务/销售/质量 | 决定默认开关与客户告知文案 |
| 共边切割相关专利的实施许可（FTO） | 需要专利检索与法律意见 | 法务 | 决定功能是否可默认商用 |
| 共边组内单件报废的返修与责任划分 | 质量流程与商务条款 | 质量/法务 | 决定追溯粒度与联检规则 |
| 设备拐角动态性能对共边段热输入的影响 | 需要真机加速度/带宽数据 | 设备厂/工艺 | 决定共边段速度曲线 |

以上问题未闭环前，代码层只能提供"可配置 + 默认保守"的实现：默认关闭共边、默认 `c = k`、默认只做直线外轮廓、默认拒绝 T 型与弧段。
