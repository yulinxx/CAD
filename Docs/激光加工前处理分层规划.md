## 0. 结论摘要

### 0.1 三句话结论

1. **能力不是零，但位置错了。** 打断 / 合并 / 闭合 / 偏移 / 布尔 / 圆角 / 倒角 / 求交 / 包含判定都已成熟，在 `Engine2D`；**裁剪与延长却只有一份"线-线 + 端点移动"的实现在 `Main/Src/Composition/EditOperationRegistry.cpp`**，既没有保留侧选择，也不支持圆弧/样条，更没有批量语义。
2. **"现在真在跑的 CAM"是 `MotionPlanCompiler`，不是 `CAM` 模块。** `Cam::compile` 与 `CamBridge::buildJobInput` 生产零调用；CAM 的六个阶段目录里只有 `.gitkeep`。`MotionPlanCompiler` 做的是"读图元 → 按图层分桶 → 按文档图层序重排 → 提几何"，**不排序、不加引线、不穿孔、不共边、不割缝**。
3. **排序与引线的算法已经写好但没接线。** `PathOptimizerV2`（k-d 树最近邻 + 2-opt + 开放段翻转）与 `Engraving::LeadInOut`（直线切线引线）都在仓库里，生产链路零引用。P0 的性价比最高动作是"接线"，不是"重写"。

### 0.3 最缺的三块（针对本领域）

1. **裁剪/延长是"演示级"而非"生产级"**：只有线-线，且"保留哪一侧"由"哪个端点更近"隐式决定，用户点哪边都不影响结果。圆弧、样条、椭圆一律拒绝（`OpRegistryHelpers::extractLineSegment`，`Main/Src/Composition/OpRegistryTypes.h:272`）。
2. **规划层不存在**：排序、引线、穿孔、共边、过切、时间估算全部没有生产实现；`CAM` 六个阶段目录为空壳。
3. **批量语义只在核心层有，UI 层没有**：`SceneEditService::addEntities` 已做到"一批一条 undo"（`Engine/2D/Src/Edit/SceneEditService.cpp:258-331`），但加工前处理没有"选 1000 条 → 统一应用 → 一条 undo → 可取消"的入口。

### 0.4 最该先做的三件

1. **把裁剪/延长搬进 Layer A**，补齐保留侧、圆弧支持、残段策略、批量入口。
2. **把 `PathOptimizerV2` + `LeadInOut` 接进 `MotionPlanCompiler`**（先接线，不搬家），立刻得到"空移变短 + 引线可控"。
3. **只读的加工前检查清单**：复用 `Geo2DQuery` 的 `isClosed / isSelfIntersecting / intersectsBox`，全部在 Worker 线程算，主线程只做高亮，零新框架。

**关键结论：**

- **"保留哪一侧"这件事，全仓没有任何 UI 参数承载。** `TransformParameters` 只有 `trimTargetId` / `trimBoundaryId`（`UI/Common/Include/UI/TransformParameters.h:224-241`），没有 `keepSide` / `pickPoint` 字段。
- **只支持直线。** `OpRegistryHelpers::extractLineSegment`（`Main/Src/Composition/OpRegistryTypes.h:272`）对非 `SyLine` 直接返回 false，裁剪/延长遇到圆弧即静默无操作。
- **打断已在正确的位置**（Engine2D，纯几何、返回克隆），但**没有可执行的 UI 命令**：`OperationId` 枚举里没有 Break（`UI/Common/Include/UI/Command/OperationId.h:23-52`）；`MenuActionId::Edit_Break` 已预留（`UI/Common/Include/UI/Menu/MenuActionId.h:163`）且被列入菜单 ID 白名单（同文件 `:464`），但**没有对应的 `OperationId` 与 `CommandCatalog` 条目** → 点了没有行为。`Edit_Join` 同理（`:465`）。
- **拓扑查询能力齐备**：`Geo2DQuery` 提供 `intersects / intersectionPoints / containsEntity / closestPointOnEntity / intersectsBox / isClosed / isSelfIntersecting / hasDuplicatePoints / hasZeroLengthEdges`（`Engine/2D/Include/Engine2D/Geometry/Geo2DQuery.h:76-120`）。这意味着**裁剪/打断/延长不需要新增拓扑基础设施**，只缺"把结果组织成裁剪语义"的那一层。

## 2. 分层方案

### 2.1 划分原则

- **不同模块，不同业务，逻辑不交集**：几何算子不知道场景；规划不知道 Qt；交互不知道设备。
- **能力只有一份**：既有定案"填充侧不得再写第二份偏移实现"（`Docs/轮廓偏移填充设计.md`）同样适用于 CAM —— **CAM 不得再写第二份偏移/求交/打断实现**，几何能力只能调 Layer A。
- **依赖单向**：A ← B ← C ← D 的依赖方向不允许反转，也不允许形成环。

### 2.2 四层定义

#### Layer A｜几何算子层（`Engine/2D` 的 `Geometry/` 与 `Algorithm/`）

**做什么**
- 纯几何变换：裁剪、打断、延长、合并、闭合、清理、偏移、圆角、倒角、布尔、求交、包含判定、自交判定。
- 引线的**几何原语**：给定轮廓 + 起点/终点 + 长度/角度/半径，算出引线点串（**不含**"该不该加、加哪一侧"的业务判断）。
- 输入输出**都是几何对象**（`Eg::SyEntity` 或 `Eg::Cam::Contour/PathSegment`），全部返回新对象，不改输入。

**不做什么**
- 不碰 `SceneManager`、不碰 `SceneEditService`、不碰 undo、不碰 `QVariantMap`、不碰 Qt。
- 不决定"保留哪一侧"的业务默认值（默认值属于 Layer C 的参数面板；Layer A 只接受显式参数）。
- 不做排序（排序是规划语义，不是几何变换）。

**落地文件（现状 + 拟新增）**

| 内容 | 文件 |
|---|---|
| 打断 / 合并 / 闭合 / 清理（已有） | `Engine/2D/Include/Engine2D/Algorithm/Geo2DEdit.h` |
| 裁剪 / 延长（**新增，从 Main 迁入**） | 同一 `Geo2DEdit.h` 追加函数，不新开类 |
| 求交 / 包含 / 自交 / 闭合判定（已有） | `Engine/2D/Include/Engine2D/Geometry/Geo2DQuery.h` |
| 偏移 / 圆角 / 倒角（已有） | `Engine/2D/Include/Engine2D/Geometry/Geo2DOffset.h` |
| 布尔（已有） | `Engine/2D/Include/Engine2D/Geometry/Geo2DBoolean.h` |
| 加工几何（Contour/Segment）与提取（已有） | `Engine/2D/Include/Engine2D/Cam/{ToolpathTypes,GeometryExtractor,ContourContainment,KerfCompensator}.h` |
| 引线几何原语（**新增**） | `Engine/2D/Include/Engine2D/Cam/LeadGeometry.h` + `Engine/2D/Src/Cam/LeadGeometry.cpp` |

#### Layer B｜加工规划层（`CAM` DLL）

**做什么**
- 吃"几何 + 工艺参数"，产出可执行刀路计划：顺序、引线、穿孔、共边、桥接、过切、多遍、时间估算、检查结论。
- 决策类工作：保留侧默认值、引线方向策略、先内后外、分区、优先级约束、碰撞检查的**策略**（几何查询调 Layer A）。
- 产物是 `CamPlan`（有序轮廓 + 穿孔点 + 长度统计）与诊断列表。

**不做什么**
- **不写第二份偏移 / 求交 / 打断 / 包含判定**。需要几何就调 Layer A（`Eg::Cam::*` 或 `Eg::Geo2D*`）。
- 不直接调 `Hw::MotionPlanBuilder` 之外的设备接口；不下发设备。
- 不做 UI：不弹对话框、不读 `QVariantMap`、不碰 Qt。

| 计划容器（ABI） | `CAM/CAM/Include/CAM/CamPlan.h` | 已有，**只能加字段不能删** |

#### Layer C｜交互与批量层（`UI/2D` + `Main/Src/Composition`）

**做什么**

- 批量应用：多选 → 统一参数 → 一次执行 → 一条 undo。
- 预览高亮（临时图元 / 场景高亮）、进度条、取消、失败定位跳转。
- 参数面板与工艺参数编辑（含批量改工艺）。
- 命令注册：`OperationId` / `MenuActionId` / `CommandCatalog` / `OperationBus`。

**不做什么**
- 不算几何、不排顺序、不生成刀路。
- 不直接调 `Hw`（Layer D 由 `ProcessingJobService` 收口）。

**落地文件**

#### Layer D｜执行层（`Hardware` + `Main/Src/Hardware`）

**做什么**

- 加工前软限位检查（在 `Validate` 结论之上做设备侧复核）。

**不做什么**

**落地文件**：`Hardware/Hardware/Include/Hardware/Device/MotionPlan.h:44-154`（`MotionOp` / `MotionCommand` / `MotionPlanView`）、`Hardware/Hardware/Src/Device/MotionPlan.cpp`、`Main/Src/Hardware/ProcessingJobService.cpp:435-457`、`Main/Src/Hardware/MotionPlanCompiler.cpp:267-404`。

| 影响 | 操作员要在"轮廓多出一段搭边"时手工删线重画；圆弧件无法裁剪，只能炸开成折线再改，精度与工时双损；批量清理毛刺轮廓只能一条条点 |
| 归属层 | A（算子） + C（交互/批量） |
| 优先级 | **P0** —— 激光前处理第一高频动作；不做则后面的"打断/延长"也没有可比对的语义基线 |

**设计要点**

- 输入：`target`（被裁图元，开放曲线或闭合曲线）+ `boundary`（裁剪边界，可为任意图元：线/圆/弧/样条/闭合轮廓）+ `TrimOptions`。
- 输出：`TrimResult{pieces, droppedPieceCount, diagnostic}`；`pieces` 是 **0..N 段新图元**（原来是闭合的，裁剪后变成开放路径）。
- 关键参数：
  - `keepSide`：`PickPoint`（按参考点判定保留侧）/ `PositiveParam`（保留参数 t 增大方向）/ `LongerPiece`（兼容旧行为）；
  - `pickPoint`：`keepSide=PickPoint` 时必填，世界坐标 mm；
  - `minResidualLengthMm`：默认 **0.5 mm**，低于该值的残段丢弃并计入 `droppedPieceCount`；
  - `toleranceMm`：交点合并容差，默认 `1e-6`（与 `Geo2DQuery` 一致）。
- 失败与退化：
  - 无交点 → `status=1`，**不改场景**，提示英文 `"Trim failed: no intersection between target and boundary"`；
  - 目标类型不支持 → `status=3`，提示 `"Trim failed: unsupported entity type"`；
  - 全部残段小于 `minResidualLengthMm` → `status=4`，提示 `"Trim would remove the entire entity"`，**默认不执行**（宁可拒绝也不静默删图元）。
- 自交/尖角：裁剪本身不制造尖角；但**裁剪后必须检查** `Geo2DQuery::isSelfIntersecting(piece)`，命中则把该段标为 `DiagnosticLevel::Warning`，仍写入场景（用户可见警告）。

### 3.4 F-EXTEND 延长

| 字段 | 内容 |

| 功能名 | 延长 / `extend` |

- 输出：`ExtendResult{newEntity, extendedLengthMm, status, diagnostic}`；**返回新图元**，不再原地改端点（原地改会让撤销快照与"方向保持"变复杂）。
- 关键参数：`mode`、`boundary`（`ToBoundary` 必填）、`extendLengthMm`（`ByLength` 必填，可为负表示反向缩短）、`whichEnd`（`Start` / `End` / `Auto`，默认 `Auto` = 选更近的一端）、`maxExtendMm`（默认 `1000`，防"边界在无穷远"时拉出离谱长度）、`allowSelfIntersection`（默认 false）。
- 延长到边界：两条候选（沿起点反向、沿终点正向），取"交点更近"的一条；与现有实现一致但**改为显式返回 `whichEnd`**，让用户可在对话框里锁定。
- 退化：超出 `maxExtendMm` → `status=6`，提示 `"Extend failed: boundary is too far (exceeds max extend length)"`；延长后自交且 `allowSelfIntersection=false` → `status=7`，提示 `"Extend failed: result would self-intersect"`。

**依赖库**：**零新增**（`Geo2DQuery::intersectionPoints` + `Geo2DPath`）。

### 3.5 F-LEAD 引线（引入 / 引出）

| 字段 | 内容 |
|---|---|
| 功能名 | 引线 / `lead-in-out` |
| 现状 | 半成品：`Engraving::LeadInOut` 仅直线切线，**生产零引用**（`Engraving/Engraving/Src/LeadInOut.cpp:74-132`）；`Cam::ProcessParams` 无引线字段（`CAM/CAM/Include/CAM/ToolpathJobInput.h:196-228`） |
| 行业内地位 | **必备**（公开资料明确：激光切割的引入引出是标准工艺参数，切割软件普遍提供直线/圆弧两种形式） |
| 影响 | 起刀点直接在轮廓上 → **入口处必然留下一个凹坑（burn-in mark）**；厚板起刀点挂渣；内外轮廓同一引线方向会让内轮廓入口朝向零件本体，直接报废 |
| 归属层 | **A 出几何原语**（`LeadGeometry`）+ **B 出策略**（加哪一端、多长、朝哪边、碰撞检查） |
| 优先级 | **P0（直线）/ P1（圆弧 + 碰撞）** |

**设计要点**

- 输入：一条 `Eg::Cam::Contour`（有序 `PathSegment`）+ `LeadOptions` + 邻域几何（用于碰撞检查）。
- 输出：`LeadResult{leadInSegments, leadOutSegments, status, diagnostics}`；引线段**不并入轮廓**，由 Layer B 决定拼接顺序。
- 关键参数：
  - `form`：`Line` / `Arc` / `Normal`（法向）；
  - `lengthMm`：默认 `2.0`，量程 `0.1–50`；
  - `angleDeg`：直线引线与轮廓切线的夹角，默认 `0`（纯切线），量程 `-90–90`；
  - `arcRadiusMm`：圆弧引线半径，默认 `lengthMm / 2`；
  - `applyAtStart` / `applyAtEnd`：默认都 true；
  - `side`：`Auto` / `Left` / `Right`（相对轮廓走向）；
  - `collisionCheck`：默认 true；
  - `clearanceMm`：引线与已有轮廓的最小间隙，默认 `0.1`。
- 退化：
  - 引线落在零件内部（`collisionCheck=true` 且与本体轮廓相交）→ 自动换到另一侧；两侧都不行 → `status=8`，`"Lead-in skipped: both sides collide with existing contours"`，**该轮廓仍然切割，只是不带引线**（不阻断整份作业）。
  - 轮廓是**开放路径**：只在起点加引线，终点不加（开放段末端无闭合需求）。
- 多层加工策略：内轮廓（`isHole=true`）引线朝孔内，外轮廓引线朝零件外 —— 由 `ContourContainment::fillHoleFlags`（`Engine/2D/Include/Engine2D/Cam/ContourContainment.h:29`）提供的 `isHole` 决定，不靠用户手填。

### 3.6 F-PIERCE 穿孔 / 切入切出

| 字段 | 内容 |

| 功能名 | 穿孔 / `pierce`（含切入 `lead-in` / 切出 `lead-out`，与 §3.5 耦合，独立实现） |

| 行业内地位 | **必备**（行业通行：厚板切割必须穿孔后进入轮廓，穿孔点与引线起点是同一位置） |
| 影响 | 从轮廓起点直接开光 → 起刀点挂渣、穿孔时间不可控、厚板直接打不穿；`piercePoints` 永远为空，后续仿真与时间估算全是错的 |

| 优先级 | **P1**（依赖引线；只有引线没有穿孔，厚板加工仍然不可用） |

**设计要点**

- 输出：`piercePoints`（每条轮廓一个）+ 穿孔段（静止出光 N 毫秒 + 可选功率斜坡）。
- 关键参数：

  - `rampDurationMs`：默认 `0`，功率斜坡时长。

- 控件：`QCheckBox` "启用穿孔"（默认勾选）；`QSpinBox` 穿孔延时（μs，默认 `0`，量程 `0–500000`）；`QDoubleSpinBox` 穿孔功率（%，默认 = 切割功率，量程 `0–100`）；`QSpinBox` 穿孔次数（默认 `1`，量程 `1–10`）；`QCheckBox` "预穿孔"（默认不勾，勾选时弹提示"将增加一次全幅空走"）。
- 参数联动：`pierceCount > 1` 时显示"每次穿孔功率递减 %"；关闭引线时穿孔点退回轮廓起点。
- 预览：穿孔点在刀路预览中以**实心圆点**标记。
- 错误提示：`"Invalid pierce parameters"`（阻断，可改参数继续）。
- 确认后：只生成刀路。

**数据流**：`ProcessParams.pierce*` → `ToolpathJobSpec.layerParams` → `Cam::compile` → `PiercePlanner::planPierce` → `CamPlan::piercePoints` → `MotionPlanBuilder` 生成"激光开 + 停 N ms + 关光/开光"。

**实现步骤**

1. `PiercePlanner` 纯计算：每条闭合轮廓生成一个穿孔点（= 引线起点）。单测 `Pierce_OnePointPerClosedContour`。
2. 参数校验 + `CamPlan::piercePoints` 回填；单测 `Pierce_InvalidParams_Rejected`。
3. `MotionPlanBuilder` 侧把穿孔点转成 `SetLaserOn + Delay + SetLaserOff`（Layer D 的 `MotionOp` 已有 `Delay` / `LaserOn` / `LaserOff`）。
4. 预穿孔模式（两遍：先全部穿孔，再全部切割）。
5. 工艺面板控件。

**验证**

- 单测：`CAM/CAM/Test/PiercePlannerTests.cpp`（工程 `CAMTests`）。断言：点数 = 闭合轮廓数、点坐标 = 引线起点、非法参数被拒。
- 集成：`CamBridgeTests.cpp` 加"启用穿孔 → `CamPlan::piercePoints` 非空"。
- 性能基线：**1000 条轮廓 ≤ 5 ms**（纯点计算）。
- 回归：关闭"启用穿孔"时 `CamPlan` 与改造前逐字节一致（防回归）。

**风险与不做条件**

- 坑 1：**穿孔点必须与引线起点重合**，否则会出现"先穿孔在 A 点，再从 B 点起弧"的双坑。
- 坑 2：**预穿孔会让空移翻倍**。默认关闭；开启时必须给出时间代价提示（复用 F-TIME 估算）。
- 坑 3：`pierceDelayUs` 与 `Delay` 指令的**单位**容易错（μs vs ms）。`ProcessParams` 约定是 μs（`ProcessParams.h` 头注释），`MotionOp::Delay` 需实测确认单位，不一致时在 Layer D 转换，**不在 Layer B 猜测**。
- **不做条件**：只切薄板时可只支持"穿孔延时 = 0"，即"开光即走"；触发做完整穿孔的条件是"客户有 ≥ 3 mm 板材"。

### 3.7 F-ORDER 排序

| 字段 | 内容 |
|---|---|
| 功能名 | 排序 / `ordering`（同图元内段序 + 图元之间顺序） |
| 现状 | **算法有，生产零接线**。`Eg::PathOptimizerV2`（k-d 树最近邻 + 2-opt + 开放段翻转，`Engine/2D/Include/Engine2D/Algorithm/PathOptimizerV2.h:117-180`）；`Engraving::optimizeTaggedOrder`（层内贪婪最近邻，`Engraving/Engraving/Src/ToolpathOrder.cpp:31-90`）；`CAM/Src/Order/` **空** |
| 行业内地位 | **必备**（行业通行：排序是切割软件的基本能力，直接决定空移时间） |
| 影响 | 大型排版件空移能占加工时间的 30–60%；不排序时按图层序切割，激光头在板材上来回横跳；薄板还会因热输入集中而翘曲 |
| 归属层 | **B**（算法实现复用 A 的 `PathOptimizerV2`） |
| 优先级 | **P0（最近邻 + 2-opt 接线）/ P1（先内后外 + 起点约束）** |

**设计要点**

- 两级排序：
  1. **图元之间**：`nearest-neighbor`（k-d 树，阈值 64 时退化为暴力）+ `2-opt` 改进；起点 = 上一图元终点（不是固定原点），形成链。
  2. **图元内部**：闭合轮廓不改段序（改了会毁几何）；开放路径允许整段翻转（`flip`），但**不允许重排中间段**。
- 约束（P1）：
  - **先内后外**：由 `ContourContainment::fillHoleFlags` 得 `isHole`，孔先切、外轮廓后切；
  - **优先级/图层约束**：`ToolpathJobSpec` 的图层顺序是硬约束（当前 `MotionPlanCompiler` 已按图层序分桶，排序必须在**桶内**做，不跨桶）；
  - **分区**（P2）：按包围盒聚类成若干区，区内排序、区序按最近邻。
- 参数：`strategy`（`None` / `NearestNeighbor` / `NearestNeighbor2Opt`）、`startPoint`（`Origin` / `CurrentHead` / `Specified`）、`twoOptMaxRounds`（默认 50）、`kdTreeThreshold`（默认 64）、`maxTravelMm`（默认 `-1` 不限，超过则报 `Warning` 让用户知道空移过大）。
- 输出：排序后的轮廓索引序列 + 每段的 `travelBeforeMm` + `totalTravelMm`（直接喂时间估算 F-TIME）。
- 退化：轮廓数 < 2 → 不排序；轮廓数 > 5000 且 `strategy=NearestNeighbor2Opt` → 自动降级为 `NearestNeighbor` 并 `Warning`（2-opt 的 O(n²) 在大规模下不可接受）。

**依赖库**：**零新增**（`PathOptimizerV2` 自带 k-d 树，`Boost::boost` 已在 Engine2D 依赖中，`Engine/2D/CMakeLists.txt:85`）。

**代码落点**

| 产物 | 工程 | 文件 | 位置 |
|---|---|---|---|
| `CAM.dll` | `CAM` | `CAM/CAM/Src/Order/OrderPlanner.cpp`（**新增**） | M1；**薄封装**，内部调 `Eg::PathOptimizerV2` |
| `CAM.dll` | `CAM` | `CAM/CAM/Src/Order/OrderPlanner.h`（**新增**，内部头） | 不导出 |
| `CAM.dll` | `CAM` | `CAM/CAM/CMakeLists.txt` | 追加源 + `PRIVATE_LINK_LIBRARIES Engine2D` |
| `SanYiCAD.exe` | `SanYiCAD` | `Main/Src/Hardware/MotionPlanCompiler.cpp` | **P0 捷径**：在图层分桶之后（`:339` 后）、几何提取之前插入排序调用；此处**直接调 `Eg::PathOptimizerV2`**，不经过 CAM（见 §5 分期说明） |
| `CAM.dll` | `CAM` | `CAM/CAM/Include/CAM/ToolpathJobInput.h` | `ProcessParams` 追加 `orderStrategy / orderStartMode`（只加不删） |

> **P0 与 M1 的取舍**：`Cam::compile` 目前零生产调用。若 P0 就要求"必须走 CAM"，等于同时做完 M1 全部阶段才能上线，风险不可控。因此 **P0 允许 `MotionPlanCompiler` 直接调 `PathOptimizerV2`**（同一份几何实现，不产生第二份排序算法），M1 时再把这段搬进 `CAM/Src/Order/OrderPlanner.cpp`，`MotionPlanCompiler` 改为调 `Cam::compile`。**这是"先接线、后搬家"，不是双实现** —— 搬家时删除 `MotionPlanCompiler` 内的直接调用。

**接口草案**

- 为什么不直接暴露 `Eg::PathOptimizerV2`：CAM 公共头不得 include Engine2D 头（见 §2.4）。`OrderPlanner.h` 是**内部头**，只在 `CAM/Src/` 内使用。
- ABI：零影响。

**交互逻辑**

- 入口：**不新增独立命令**。挂在"开始加工"前的 `ToolpathJobSpec` 参数上（`LaserOperationRegistry` 组装的工艺面板）。
- 控件（"排序"分组）：
  - `QComboBox` 策略：不排序 / 最近邻 / 最近邻 + 2-opt，默认"最近邻 + 2-opt"；
  - `QComboBox` 起点：原点 / 当前激光头位置 / 指定点，默认"当前激光头位置"；
  - `QCheckBox` "先内后外"，默认勾选；
  - 只读 `QLabel` 显示预估空移长度（排序后立即计算，不需要实际加工）。
- 参数联动：策略 = 不排序 → 起点与"先内后外"禁用；起点 = 指定点 → 弹出坐标输入。
- 预览：排序结果以**序号标签**叠在轮廓上（临时图元），不写场景。
- 错误提示：`"Ordering skipped: fewer than two contours"`（可继续）；`"Ordering degraded to nearest-neighbor: contour count exceeds 5000"`（可继续）。
- 确认后：只生成刀路。

**数据流**

```
ToolpathJobSpec（orderStrategy / 起点 / 先内后外）
  → MotionPlanCompiler::compile（P0）
      → 图层分桶（现状）
      → 【新增】Eg::PathOptimizerV2::optimize（桶内）
      → GeometryExtractor
  → MotionPlan
```

**实现步骤**

1. `MotionPlanCompiler` 在分桶后插入"桶内排序"（直接调 `Eg::PathOptimizerV2`，参数先硬编码 `NearestNeighbor2Opt`）；单测断言"50 条乱序直线 → 总空移 ≤ 乱序的 60%"。
2. `ToolpathJobSpec` 加排序参数（`orderStrategy` 等）+ 工艺面板控件。
3. 先内后外（`ContourContainment` 判定后重排）；单测"孔先于外框"。
4. 性能降级阈值（>5000 自动降级）+ `Warning`。
5. M1：`CAM/Src/Order/OrderPlanner.cpp` 薄封装，`Cam::compile` 接入；`MotionPlanCompiler` 改为经 `Cam::compile`（删除直接调用）。

**验证**

- 单测：`Engine/2D/Test/PathOptimizerV2Tests.cpp` 已存在的能力做回归；新增 `CAM/CAM/Test/OrderPlannerTests.cpp` 断言索引序列与 `totalTravelMm`。
- 集成：`Main/Src/Hardware/Test/MotionPlanCompilerTests.cpp` 断言"排序开关打开后 `MotionPlan` 的 rapid 段数减少"。
- 性能基线：**1000 条轮廓最近邻 + 2-opt ≤ 200 ms**（单线程）；5000 条降级后 ≤ 500 ms。
- 回归：关闭排序时输出与改造前逐指令一致。

**风险与不做条件**

- 坑 1：**排序跨图层会破坏工艺顺序**。必须在桶内排，绝不能把所有轮廓混在一起排。
- 坑 2：**2-opt 在大规模下退化**。必须设降级阈值，否则 5000 条会卡死 UI 线程。
- 坑 3：**起点用"当前激光头位置"时结果不可复现**。测试与报告导出必须用"原点"或"指定点"，否则同一文件两次排序结果不同，无法写断言。
- 坑 4：**开放路径翻转会改变切割方向**。对某些材料（如带涂层）方向影响切缝质量；`flipFlags` 必须可由用户关闭（`allowFlip`）。
- **不做条件**：若轮廓数普遍 < 50，2-opt 收益低于实现成本，可只做最近邻（P0 已够）。触发做 2-opt 的条件是"实测空移占比 > 20%"。

### 3.8 F-COMMON-EDGE 共边 / 微连接 / 过切（P1–P2）

三条合并成一节，因为它们的**几何前置相同**（都是"在轮廓上开缺口或共享段"），且都要等打断/裁剪稳定后才可做。

#### 3.8.1 共边切割 `common-edge-cut`

| 字段 | 内容 |
|---|---|
| 现状 | **切割侧无**。Nesting 只有排版参数 `enableCommonLine`（`Nesting/Nesting/Include/Nesting/NestingApi.h:244-247`），切割侧零实现 |
| 行业内地位 | **必备**（公开资料明确：套料软件的"共边切割"是标准功能，直接省板材与时间） |
| 影响 | 相邻零件之间留两条切缝 + 中间废料条 → 板材利用率低 5–15%，空移与切割长度翻倍；废料条窄到切缝宽时还会翘起撞头 |
| 归属层 | B（策略）+ A（重合段提取，**缺**） |
| 优先级 | **P2** |

**为什么排后面（不做/延后的理由）**：共边需要"两条轮廓的重合段提取"，`Geo2DQuery` 现在只有 `intersects / intersectionPoints`，**没有重合段 API**（见 §2.5）。先做共边等于先写一个几何能力，而该能力只在共边场景用；同时共边要求排版侧已经生成"贴合排布"，否则根本没有共边可找。**触发条件**：① 排版侧共边排布已可用；② 客户实测板材利用率是痛点。

**设计要点**（概要，不展开到接口级，因为前置未就绪）
- 输入：一组相邻 `Contour` + 容差。
- 输出：共享段合并后的切割路径（一条切缝服务两个零件）+ 每个零件的"归属边"。
- 关键参数：`overlapToleranceMm`（默认 `0.01`）、`commonEdgeMinLengthMm`（默认 `1.0`，太短的共边不值得合并）、`keepCommonEdgeSide`（`Left` / `Right` / `Both`）。
- 失败：重合段长度不一致（> 容差）→ 放弃共边，按普通切割处理并 `Warning`。
- **必须复用**：`Geo2DQuery::intersectionPoints` + 新增 `overlapSegments`（Layer A），**不得在 CAM 内自写折线比对**。

#### 3.8.2 微连接 `microjoint`

| 字段 | 内容 |
|---|---|
| 现状 | **位图侧有**（`Raster/Raster/Src/Cut/RasterCut.cpp:343-578`，参数 `microJointCount / microJointLength` 在 `RasterTypes.h:634-635`）；**矢量侧无** |
| 行业内地位 | **常见**（行业通行：防止小零件掉落/翘起，套料软件普遍提供） |
| 影响 | 切小件时零件掉进废料堆、二次分拣；薄板切完翘起撞头；没有微连接只能靠"留一点不切"手工处理 |
| 归属层 | A（开缺口算子）+ B（位置策略） |
| 优先级 | **P1**（实现成本低：复用 `splitAtParams`） |

**设计要点**
- 输入：闭合 `Contour` + `count`（默认 4）+ `lengthMm`（默认 0.5）+ `position`（`Uniform` / `AtCorners` / `AvoidLeadIn`）。
- 输出：被打断成 `count` 段的轮廓 + 段间缺口（缺口 = 不切）。
- 参数：`count` 量程 `1–16`；`lengthMm` 量程 `0.1–5.0`；`avoidLeadInDistanceMm`（默认 2.0，缺口不得落在引线附近）。
- 退化：轮廓周长 < `count * lengthMm * 2` → 减少 `count` 并 `Warning`；开放路径 → 不支持，直接跳过。
- **复用**：`Geo2DEdit::splitAtParams`（Layer A），不新写打断。

#### 3.8.3 过切 / 回退 `overcut`

| 字段 | 内容 |
|---|---|
| 现状 | **无**。仅 `Cam::ToolpathJobInput.h:247` 有 `overcutMm` 字段 |
| 行业内地位 | **常见**（行业通行：闭合轮廓首尾重叠一小段以保证切断） |
| 影响 | 闭合轮廓首尾接缝处留下一丝未切断的"筋"，需要人工掰断；厚板尤其明显 |
| 归属层 | B |
| 优先级 | **P2**（与共边/微连接互斥场景多，参数组合复杂） |

**设计要点**：`overcutMm` 默认 `0`，量程 `0–5`；仅在闭合轮廓上生效，且**必须与引线协调**（过切段不能吃掉引线起点）。退化：`overcutMm` 大于轮廓周长的 10% → 拒绝并 `"Overcut exceeds 10% of contour length"`。

### 3.9 F-BATCH 成批处理

| 字段 | 内容 |
|---|---|
| 功能名 | 批量加工前处理 / `batch-preprocess` |
| 现状 | **框架有、业务无**。`SelectionManager` 支持框选（`Engine/2D/Include/Engine2D/Core/SelectionManager.h:31-47`，方向语义 `SelectTool.cpp:1307-1375`）；`SceneEditService::addEntities` 已做到一批一条 undo（`Engine/2D/Src/Edit/SceneEditService.cpp:258-331`）；`AlgorithmApplicationService` 三段式已就绪；但**没有任何批量前处理命令**（检索式：`BatchTrim|BatchExtend|ApplyLeadToSelection` 全仓零匹配） |
| 行业内地位 | **必备**（行业通行：批量清理是导入后的第一道工序） |
| 影响 | 1000 条轮廓要逐条点 → 一小时级别的操作；中途失败无法回滚到"操作前"，只能整体撤销重来 |
| 归属层 | **C** |
| 优先级 | **P0**（裁剪/打断/延长一旦可用，批量是必然诉求） |

**设计要点**

- **选择语义**（现在缺两项）：
  - 已有：单选、框选（左→右相交 / 右→左完全包含）、全选、反选、清空（`OperationId::Edit_SelectAll / Edit_ClearSelection / Edit_InvertSelection`，`OperationId.h:31-33`）；
  - **需新增**：按图层选（`SelectByLayer`）、按类型选（`SelectByType`）。两者都是 `SelectionManager` 之上的一次过滤，**不需要新框架**。
- **批量应用**：一次对话框 → 一次执行 → 一条 undo。
- **幂等性**：重复应用同一次裁剪不应叠加。实现方式：裁剪/延长都是"以当前几何为输入"，天然不幂等（第二次裁剪会得到不同结果）。**正确的幂等定义**：批量处理的结果必须可由"原始几何 + 参数"完全重现；因此批量命令**必须记录原始几何快照**（`SceneEditService` 的 before-snapshot 已经做了，`SceneUndoCommands.cpp:156-180`）。重复点击"应用"时，先撤销上一次再应用（对话框上给出明确文案），**不做自动去重**。
- **失败原子性**：
  - 默认 **`AllOrNothing`**：任一条几何失败 → 整批不写入，`GeometryEditResult.status=Failed`，`Diagnostics` 列出每条失败的 `entityId` + 原因；
  - 可选 **`SkipFailed`**：成功的写入，失败的保持原样，`status=PartialSuccess`，对话框列出失败清单；
  - **不允许**"静默跳过"（与 `ToolpathJobSpec::failOnUnmachinableEntity` 的既有立场一致，`Main/Src/Hardware/ToolpathJobSpec.h:91-99`）。
- **大数量（1000+）**：
  - 门槛：**> 200 条走异步**（`AlgorithmApplicationService::runAsync`）；
  - 进度：`AlgorithmTaskContext::progressCallback(0.0–1.0, message)`，每 1% 或每 50 条回调一次（避免主线程被信号淹没）；
  - 取消：`isCancelRequested()` 每 50 条检查一次，取消后**不写入任何结果**（保持 `AllOrNothing` 语义）；
  - 内存：1000 条 × 每条 2 段新图元 ≈ 2000 个 `SyEntity` 克隆，峰值可控（`SyEntity` 是小对象 + 少量 vector）。
- **性能目标**：1000 条裁剪 ≤ 3 s（含 Worker 调度与 UI 刷新），超过 10 s 视为不可接受。

**依赖库**：**零新增**（`AlgorithmApplicationService` / `SceneEditService` / `SelectionManager` 全部已有）。

**代码落点**

**交互逻辑**

- 入口：无独立命令，附在裁剪/打断/延长对话框的"应用范围"分组。
- 控件：
  - `QComboBox` 应用范围：选中图元 / 同图层全部 / 同类型全部，默认"选中图元"；
  - `QComboBox` 失败策略：全部成功才应用 / 跳过失败继续，默认"全部成功才应用"；
  - `QProgressBar`（仅 >200 条时显示）+ `QPushButton` "取消"。
- 参数联动：范围 = 同图层 → 立即统计条数并显示"N 条将被处理"；条数 > 200 → 自动切异步并显示进度条。
- 预览：只预览**前 20 条**（避免 1000 条临时图元拖慢渲染），其余显示"N more"。
- 错误提示：`"Batch aborted: 3 of 250 entities failed, nothing was applied"`（`AllOrNothing`）；`"Batch completed with 3 failures, 247 applied"`（`SkipFailed`）。
- 确认后：写入场景，**一条 undo**；取消 = 零写入。

**数据流**

```
SelectionManager（选中集 / 按图层 / 按类型）
  → OperationBus::run(OperationId::Edit_Trim, params{scope, failPolicy})
  → EditOperationRegistry::handleTrim
      ├─ scope=Selected → 直接用选中集
      └─ scope=Layer/Type → SelectionManager::selectByLayer/ByType 得到目标集
  → 条数 <= 200：同步循环调 Layer A，聚合 GeometryEditResult，一次 applyEditResult
  → 条数 >  200：AlgorithmApplicationService::runAsync
        → BatchEditTaskHandler::prepareBackgroundRun（主线程抓集 + 快照）
        → computeBackgroundRun（Worker 逐条调 Layer A，回调进度，检查取消）
        → applyBackgroundRun（主线程一次 applyEditResult）
  → 一条 undo
```

**实现步骤**

1. `SelectionManager::selectByLayer / selectByTypes` + 两个 `OperationId` 条目；单测"按图层选中数量正确"。
2. `EditOperationRegistry` 抽 `applyBatchEdit(targets, fn)` 私有函数（同步路径），聚合结果；集成测试"100 条 = 1 条 undo"。
3. `BatchEditTaskHandler` 三段式实现；集成测试"250 条走异步 + 取消后零写入"。
4. 对话框加"应用范围 / 失败策略 / 进度条"。
5. 预览限流（前 20 条）。

**验证**

- 单测：`Engine/2D/Test/SelectionManagerTests.cpp`（工程 `Engine2DTests`）。
- 集成：`Main/Test/BatchEditTests.cpp`：① 100 条一条 undo；② 250 条异步 + 中途取消 → 场景零变化；③ `SkipFailed` 下 3 条失败 → `status=PartialSuccess` 且 247 条生效。
- 性能基线：**1000 条裁剪 ≤ 3 s**（含异步调度）；同步路径 200 条 ≤ 500 ms。
- 回归：单条路径行为不变（批量只是循环 + 聚合）。

**风险与不做条件**

- 坑 1：**`applyEditResult` 的 `replacements` 语义**。`EntityReplacement{originalId, newEntity}` 是"用新图元替换旧图元"，一条原图元只能替换成一条。裁剪可能产生 2 段 → 必须"第一段替换原图元，第二段作为 `NewEntity` 加入"，并保证 `preserveProcessParams=true`，否则工艺参数会丢。
- 坑 2：**`SnapshotScope` 选错**。批量裁剪只动目标图元、不产生额外图元时用 `Subset`；若产生 `NewEntity`（第二段），重做时必须能清理这些新 id → 用 `WholeScene`（与 `EntitySnapshotsCommand` 的 `WholeScene` 语义一致，`SceneUndoCommands.cpp:182-239`）。
- 坑 3：**进度回调频率**。每条约一次回调会让主线程在 1000 条时收到 1000 次信号，UI 卡顿；必须节流。
- 坑 4：**取消时机**。Worker 已算出部分结果但未 apply，取消必须丢弃 `m_pendingResult`，不能"部分写入"。
- **不做条件**：若用户规模普遍 < 50 条，可只做同步路径（省掉 `BatchEditTaskHandler`）；触发做异步的条件是"实测单次操作 > 500 ms"。

### 3.10 F-PRECHECK 加工前检查清单

| 字段 | 内容 |
|---|---|
| 功能名 | 加工前检查 / `pre-cut-check` |
| 现状 | **无成体系实现**。原子判定齐全：`Geo2DQuery::isClosed / isSelfIntersecting / intersectsBox / hasDuplicatePoints / hasZeroLengthEdges`（`Engine/2D/Include/Engine2D/Geometry/Geo2DQuery.h:76-120`），但**没有任何"检查器"把它们组织成结论**（全仓零匹配：`PreCheck|PreCutCheck|MachiningChecklist`） |
| 行业内地位 | **必备**（行业通行：切割软件普遍有"加工前检查/预检查"，因为切废一块板不可逆） |
| 影响 | 未闭合轮廓会切出一个"开口零件"；自交轮廓会切出双层切缝并烧穿；超出行程会撞限位；小于最小孔径的孔切不出来但会漏切 —— 这四类全部只能靠操作员肉眼发现，废件成本 = 一整块板材 + 机时 |
| 归属层 | **B（判定与结论）+ C（展示与定位）** |
| 优先级 | **P0**（零新框架，纯只读，风险最低，收益最直接） |

**设计要点**

- 输入：`SceneManager` 的只读快照 + `ToolpathJobSpec`（加工范围与行程）+ 工艺参数（最小孔径）。
- 输出：`CheckReport{items[], summary{errorCount, warningCount, infoCount}}`；每项 `{severity, code, message, entityId, position}`。
- 检查项（P0 四项，全部可单测）：

| 检查项 | code | 判据 | 级别 |
|---|---|---|---|
| 未闭合轮廓 | `UnclosedContour` | `Geo2DQuery::isClosed(entity, tol)` 为 false 且该图元被标记为"应切割" | Error |
| 自交 | `SelfIntersection` | `isSelfIntersecting(entity, tol)` 为 true | Error |
| 超出行程 | `OutOfTravelRange` | 图元包围盒超出 `spec` 的机床行程（软限位） | Error |
| 小于最小孔径 | `BelowMinHoleDiameter` | 闭合内轮廓的等效直径 < `minHoleDiameterMm` | Warning |
| 零长度 / 重复点 | `DegenerateGeometry` | `hasZeroLengthEdges / hasDuplicatePoints` | Warning |
| 空移过大 | `ExcessiveRapidTravel` | 排序后 `totalTravelMm` > `maxTravelMm` | Info |

- 参数：`minHoleDiameterMm`（默认 `0.0` = 不检查，量程 `0–50`）、`closureToleranceMm`（默认 `0.01`）、`checkScope`（选中 / 全图）。
- 退化：`minHoleDiameterMm=0` 时跳过该项；行程未知时跳过 `OutOfTravelRange` 并打 `Info` 说明"未配置机床行程，跳过行程检查"。
- **性能**：只读、可并行；1000 图元 ≤ 300 ms。**必须在 Worker 线程算**（`AlgorithmApplicationService::runAsync`）。

**依赖库**：**零新增**。

    {

    {
        std::vector<CheckItem> items;
        int32_t errorCount = 0, warningCount = 0, infoCount = 0;

    };

**验证**

- 单测：`CAM/CAM/Test/PreCheckPlannerTests.cpp`（`CAMTests`）。断言 `errorCount/warningCount`、`entityId` 正确、`code` 正确。
- 集成：`Main/Test/PreCheckIntegrationTests.cpp`：① 含 1 个未闭合 + 1 个自交 → `errorCount=2`；② 1000 条检查 ≤ 300 ms；③ Error 存在时 `startJob` 被阻止。
- 性能基线：**1000 图元 ≤ 300 ms**。
- 回归：不影响 `MotionPlanCompiler` 输出。

**风险与不做条件**

- 坑 1：**"应切割"的判定标准**。隐藏图层、`ProcessParams.enabled=false` 的图元不应报错，否则会刷出大量噪音。必须复用 `skipHiddenLayers / skipLockedLayers` 语义（`ToolpathJobSpec.h:84-86`）。
- 坑 2：**容差**。`isClosed` 的容差过严会误报（DXF 导入常见 `1e-4` 级缝隙），默认 `0.01 mm` 是经验值，必须可调并在 UI 上写明。
- 坑 3：**最小孔径**。等效直径对非圆孔不准确（矩形孔按内切圆算更合理）；P0 只报圆孔，非圆孔跳过并 `Info` 说明。
- **不做条件**：若只有四项中的两项能稳定判定，就只上两项 —— 误报比不检查更伤信任。

## 4. 与同行软件的差距对照 + 缺口设计

> **本节只出现一次。** §3 已展开到接口级的功能（裁剪、打断、延长、引线、穿孔、排序、共边、微连接、过切、批量、加工前检查）**本节不再重复**，只在其品类行里给一句交叉引用。本节负责：三组对照结论 + 其余品类的缺口条目 + 差异化取舍。

### 4.1 对照口径与证据强度

按激光加工行业的**实际使用场景**分三组，不混着比：

| 组 | 代表产品类型 | 典型能力边界 | 与本产品的可比性 |
|---|---|---|---|
| **G1 激光切割控制/编程一体** | 排料 + 切割工艺 + 机床控制一体的软件 | 排版 → 工艺 → 刀路 → 下发全链 | **最高**（本产品目标形态） |
| **G2 套料/编程** | 排版套料 + NC 生成的编程软件 | 排版 + 后处理，通常不含机床控制 | 中（排版侧可参考，工艺侧弱于 G1） |
| **G3 打标/雕刻** | 振镜打标软件 | 矢量/位图打标，不做板材切割 | **低**（只作参照，不对齐） |

**证据强度**只允许三种标签：**公开资料明确** / **行业通行** / **推测（未证实，需产品确认）**。本节**不写任何"据说某软件有 X"**，也不写具体厂商的菜单名；若需要精确到某厂商的某功能是否存在，必须由产品侧提供官方功能清单或手册页作为证据。

### 4.2 三组对照结论

| 组 | 我方已对齐的 | 我方明显缺的 | 结论 |
|---|---|---|---|
| G1 | 布尔/偏移/圆角/倒角/阵列；6 家设备适配器；图层→工艺参数 | 排序未接线、无引线/穿孔/共边/过切、无加工前检查、无刀路仿真、无 NC 导出、无时间估算 | **差在"工艺 → 刀路"这一段**，不在几何与设备 |
| G2 | Nesting 真 NFP 求解器 + GA/SA；阵列；DXF/SVG/PLT/PDF/STEP 导入 | 无共边排版打通、无余料库、无板材/零件库、无切割机床后处理（只有雕刻口径的 `GcodeDialect`）、无 BOM/报告 | 排版内核已有，**周边工程化缺失** |
| G3 | 位图扫描线/抖动/矢量化/功率图；矢量打标命令 | 无位图侧引线/穿孔（打标本来也不需要）；无打标专用的振镜校正/填充优化 | **不必对齐**，只在位图雕刻文档里做 |

### 4.4 差异化建议（值得作为竞争优势去做）

| # | 功能 | 为什么对本产品有优势 | 成本估计 |
|---|---|---|---|
| 1 | **加工前检查 + 定位高亮（F-PRECHECK）** | 单机激光加工的废件成本 = 板材 + 机时 + 交期；同行多数把检查做成"可选插件"或干脆没有。**做到"检查结论可直接双击定位到图元"**，是低成本高感知的差异点。依赖已有 `Geo2DQuery`，零新框架 | 低（3 个文件 + 1 个对话框） |
| 2 | **引线 + 穿孔的"内外轮廓方向自动化"** | 大多数用户手工决定引线朝向，做错就废件。用 `ContourContainment` 自动判定 `isHole` 并选择引线侧，**把一条经验规则变成默认正确**。这是工艺知识固化的差异点 | 中（LeadGeometry + LeadPlanner） |

## 5. 分期实施顺序

### 5.1 P0 最小闭环（用户真正能用起来）

**P0 结束时的用户可见状态**：

> 选中一条轮廓 → 用圆弧或直线边界裁掉多余的一段（能选保留哪一侧）→ 打断成几段 → 把差一点的缺口延长到相邻边界 → 选 100 条一次性套用，撤销一次全恢复；开始加工前跑一次检查，未闭合/自交会列出来并能双击定位；加工时空移明显变短，起刀点有直线引线，割缝补偿生效。

包含的功能：

| # | 功能 | 做到什么程度 |
|---|---|---|
| 1 | F-TRIM 裁剪 | 任意曲线目标（线/弧/样条）+ 任意边界；保留侧（点选/参数正向/较长段）；残段阈值；单条 + 批量 |
| 2 | F-BREAK 打断 | 按点 / 按交点 / 按等分；段序与方向保持；闭合性回传；UI 命令 |
| 3 | F-EXTEND 延长 | 到边界 / 到交点 / 按长度；自交与超距保护 |
| 4 | F-ORDER 排序 | **接线**：`MotionPlanCompiler` 桶内调 `PathOptimizerV2`（最近邻 + 2-opt），起点可配置 |
| 5 | F-LEAD 引线 | 直线切线引线，内/外轮廓方向自动；无碰撞检查或仅做"同侧粗检" |
| 6 | 割缝接线 | `KerfCompensator` 接进 `MotionPlanCompiler`（几何在 Engine2D，不新写） |
| 7 | F-BATCH 批量 | 选中 / 同图层 / 同类型；`AllOrNothing` 默认；>200 条走异步；一条 undo |
| 8 | F-PRECHECK 检查 | 未闭合 / 自交 / 超行程 / 退化几何四项；只读；双击定位 |

**为什么是这 8 项**：它们共用 `Geo2DQuery` 与 `PathOptimizerV2` 两块既有能力，**不引入任何新框架**；且每一项都能被用户直接感知（裁剪手感、空移时长、起刀痕、废件率）。

**P0 明确不做**：圆弧引线、引线碰撞检查、穿孔、共边、微连接、过切、时间估算、NC 导出、套料增强。

**验收（P0 出口条件）**：

| 项 | 判据 |
|---|---|
| 功能 | 8 项全部有 UI 入口，且无一项需要手工改文件 |
| 撤销 | 任意批量操作 undo 一次完全恢复（含"新产生的第二段"） |
| 性能 | 1000 条裁剪 ≤ 3 s；1000 条排序 ≤ 200 ms；1000 条检查 ≤ 300 ms |
| 回归 | `Edit_Trim` / `Edit_Extend` 旧行为可通过"较长段"选项复现；关闭所有新开关时 `MotionPlan` 与改造前一致 |
| 稳定性 | 空选择、单条、全闭合、全开放、含样条 5 类边界输入均不崩溃 |

### 6.2 已知的、本方案**故意保留**的张力

| 张力 | 事实 | 为什么保留 | 何时消除 |
|---|---|---|---|
| P0 期间 `MotionPlanCompiler`（Layer D 侧）直接调 Layer A 的排序 | 严格说排序属于 Layer B，放在 `MotionPlanCompiler` 内是"层越位" | P0 若先建 Layer B 再上线，等于把 M1 全部做完才能交付，风险不可控 | M1 落地时搬进 `CAM/Src/Order/OrderPlanner.cpp` 并从 `MotionPlanCompiler` **删除**直接调用；删除动作作为 M1 的完成判据 |
| `Cam::Contour` 与 `Eg::Cam::Contour` 并存 | 两套类型同语义 | P0 统一会破 ABI 且触及 M0 骨架 | M2 结束后统一（需产品同意做一次计划格式版本升级） |
| `Engraving::LeadInOut` 与新的 `LeadGeometry` 并存 | 两套引线 | 一位图一矢量，业务不同；合并会污染 Raster/Engraving 的 float 链路 | 不合并；在文档层面明确"矢量链只认 `LeadGeometry`" |

### 6.3 与"冗余 21 处"审查结论的关系

用户刚完成一轮冗余/过度设计审查（结论：确认 21 处冗余）。本方案**主动避免新增以下类型**：

- ❌ 不新建"前处理框架/管线/调度器"——全部复用 `OperationBus` + `AlgorithmApplicationService` + `SceneEditService`。
- ❌ 不新建第二套参数结构——全部挂在 `Eg::ProcessParams`。
- ❌ 不新建第二套几何实现——全部调 Layer A。
- ❌ 不为未来功能预留空目录/空接口——`CAM/Src/*` 保持空到 M1 真做时再填。
- ✅ 唯一"新增文件"集中在：`LeadGeometry`（1 组）、`LeadPlanner` / `OrderPlanner` / `PiercePlanner` / `PreCheckPlanner`（各 1 组）、`BatchEditTaskHandler`（1 组）、4 个对话框（`BreakDialog` / `PreCheckDialog` + 2 个既有对话框的页签）。**新增文件总数 ≤ 10 组**，且每组都有明确调用方。
