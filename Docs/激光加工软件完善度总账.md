## 0. 结论摘要

### 0.1 完善度口径

不拍总分。按真实工作流分 10 段，每段 0-3 级：

| 级别 | 含义 |
|---|---|
| 0 | 必备功能在生产链路上完全跑不通 |
| 1 | 有零散实现或只在测试/示例跑通，生产链缺关键环节 |
| 2 | 主链能跑，但缺行业常见能力，需人工兜底 |
| 3 | 必备能力齐备且有验证手段，可直接商用 |

判定只看一件事：**该段必备功能里，有多少已经在生产链路（用户点菜单 → 出加工计划/下发设备）上真正跑通**。算法存在但只被 Test/Example 调用的，不算跑通。

### 0.2 十段结果（详见第 6 节）

| # | 工作流段 | 级别 | 一句话依据 |
|---|---|---|---|
| 1 | 导入 | 2 | DXF/SVG/PLT/PDF/STEP/OBJ/STL/UG/AI 齐全；无 DWG，无部分失败诊断 |
| 2 | 编辑与清理 | 2 | 布尔/偏移/圆角/倒角/裁剪/延伸/阵列齐备且有 UI；缺图纸体检与精度修复 |
| 3 | 排版/套料 | 1 | 真 NFP 求解器；UI 受开关门控；缺共边/余料/板材库/零件库 |
| 4 | 工艺参数 | 1 | 图层→工艺映射可编辑、内存工艺库 `Eg::ProcessLibrary` 在位；材料库弃用未替代；缺 UI/持久化/批量改参/模板 |
| 5 | 刀路生成 | 1 | 割缝在跑；排序/引线/穿孔/过切未进生产编译链 |
| 6 | 位图雕刻 | **1** | 算法成熟（92 个导出函数、133 用例），但**生产链拒收位图**、**导入侧 DPI 恒 96**、**无雕刻预览**；依据 `Docs/08-Raster/…能力盘点…md` §1.6/§3.2/§3.4 实测修正（原评 2） |
| 7 | 仿真与校验 | 0 | 无刀路仿真、无加工前检查（全仓零匹配） |
| 8 | 输出与后处理 | 1 | 无用户级 NC/G-code 导出与方言；`estimatedSeconds` 零读者 |
| 9 | 加工与回读 | 2 | 6 家适配器 + 作业服务 + 安全输入在链路；回读/对账未接通 |
| 10 | 工程化 | 2 | 撤销/日志/崩溃/基准都有；大批量与长任务体验待验证 |

### 0.3 最缺的三块

1. **加工前校验与刀路仿真（第 7 段为 0）**：没有未闭合/自交/超行程/小于最小孔径检查，也没有刀路回放。
2. **输出与后处理（第 8 段）**：无用户级 NC/G-code 导出与方言层；时间估算字段零读者，报价与排产没有真实口径。
3. **刀路工艺接入（第 5 段排序/引线/穿孔）**：`PathOptimizerV2` 已存在，生产编译链 `MotionPlanCompiler` 未调用；引线**已有实现但不可直接用**——`Engraving::LeadInOut` 只有直线切线、float 精度、且在 Engraving 模块（OpenCV/Engine3D），**裁决：在 Engine2D 新建 double 精度 `LeadGeometry`，只复用其直线切线策略，补圆弧/角度/碰撞/过切**（见 9.4 D-11 与 C6）；割缝只在 UI 预处理路由里做。

### 0.4 最该先做的三件

1. **把已有算法接进生产链**：排序（`PathOptimizerV2`）+ 割缝（`KerfCompensator`）+ 引线（Engine2D 新建 `LeadGeometry`，以 `Engraving::LeadInOut` 的直线切线为行为基线、不复用其 float 代码，**不引 Engraving**）+ 穿孔参数，统一由 `MotionPlanCompiler` 调用一次，不再在 UI 路由里各做一段。
2. **只读的加工前检查 + 刀路回放**：复用 `Hw::MotionPlanView` 做纯前端预览，不新增框架；先做四项检查。
3. **NC/G-code 导出 + 真实时间估算**：`ToolpathExporter` 提升到用户可见入口，加极薄方言模板；时间估算直接读 `MotionPlan` 分段速度/加速度，不维护第二套口径。

## 1. 现状盘点（按模块，带证据）

### 1.1 必须核实的三件事

**核实一：生产链路走 `MotionPlanCompiler`，不是 `Cam::compile`。**

- 生产调用点：`Main/Src/Hardware/ProcessingJobService.cpp:446` `MotionPlanCompiler::compile(scene, layers, spec, m_impl->builder)`，随后 `startPlan()`。
- `Cam::compile` 只被 `Main/Src/UI/Test/CamBridgeTests.cpp:103/140/171/214/287`、`Tools/PerfBenchmark/CamBench.cpp:217` 调用，**生产零调用**。
- `CamPlanEmitter`、`CamInputBridge` 同样零生产调用（`CamInputBridge.cpp:533` 的割缝只是测试覆盖）。
- 结论：CAM 模块目前是**与生产并行的孤岛**；生产 CAM 的真名是 `Main/Src/Hardware/MotionPlanCompiler.cpp`。

**核实二：旧硬件三件套零生产构造。**

- 声明仍在 HAL 公共头：`Hardware/Hardware/Include/Hardware/MaterialDatabase.h:22`（`HARDWARE_API MaterialDatabase : public QObject`）、`SafetyManager.h:28`、`ToolpathExecutor.h:26`。
- 实现被排除出应用本体、单独编成 `HardwareApp.dll`：`Main/CMakeLists.txt:94`、`:110`。
- 构造点只在测试：`Main/Src/Hardware/Test/MaterialDatabaseTests.cpp:42`、`SafetyManagerTests.cpp:26`。
- 结论：**保留 ABI 的僵尸接口，无生产消费方**。

**核实三：偏移实现同时"在跑"2 份，另有 2 份休眠。**

    {
        double totalSeconds = 0.0;
        double cutSeconds = 0.0;
        double rapidSeconds = 0.0;
        double dwellSeconds = 0.0;

- **算法**（写清口径，避免"拍脑袋"）：
  1. 逐指令累加：`RapidTo` 用 `SetRapidRate` 的当前值（未设置则用 `limits` 或默认 300 mm/s，并在结果里 `approximate=true`）。
  2. `LineTo/ArcTo` 用 `SetFeedRate` 当前值；圆弧长度用圆心半径与扫角（不按弦长）。
  3. 加减速：若 `limits.accelMmPerSec2 > 0`，每段按梯形/三角形速度曲线计时间（`t = 2d/(v0+v1)` 的简化版 + 拐点减速），否则按匀速并标 `approximate`。
  4. `Dwell` 直接累加 `durationUs`。
  5. `LaserOn` 之后的第一个 `LineTo` 计一次穿孔（`pierceCount++`）。
  6. 多遍（`BeginPass/EndPass` 或 `header.passCount`）按实际指令流累加，**不乘倍数**（避免与设备实际重复走位不一致）。

- **数据流**：`startJob` → `compile` 成功 → `estimateJob(view, limits)` → 存 `ProcessingJobService` → 发 `jobEstimated(double)` → UI 显示；`jobProgress` 用 `fraction × est` 显示剩余时间。

  1. commit：`JobEstimate` + `MachineLimits` + 匀速版估算 + 单测（直线/圆弧/停顿/空移四类）。
  2. commit：梯形加减速（`accel > 0` 时）+ 单测（短段减速到零）。
  3. commit：`ProcessingJobService` 接入并发信号；UI 显示。

- **不计算总分**。总分会把"仿真为 0"与"位图为 2"平均成一个没有决策意义的小数，掩盖"设备能切但不敢切"的真实风险。
- 每段按 0–3 级（定义见 0.1），判定问题只有一个：**该段"行业必备"功能中，有多少已经在生产链路（菜单 → 计划 → 设备）上真正跑通并有验证手段**。
- 三个反例说明口径：
  - `PathOptimizerV2` 有实现、有测试，但 `MotionPlanCompiler` 不调用 → **不算跑通**（第 5 段因此为 1，而不是 2）。
  - `KerfCompensator` 在 `ProcessRouteRegistry.cpp:380` 的 UI 预处理里跑，但生产编译链不调用 → **算"半跑通"**，只在"割缝"单项给 1.5，不给整段加分。
  - 6 家适配器能下发、能停止，但没有回读 → 第 9 段给 2，不给 3（"能切"不等于"可追溯"）。

## 7. 分期（P0 / P1 / P2）

> 分期口径：**P0 = 用户能真正切一个件且不出废件**；P1 = 能卖进产线；P2 = 差异化/规模化。每期只列"这一期结束时必须可验证"的功能。
> 本文档默认克制：需要新增整套框架的功能一律放 P2，并写清前置成本。

### 7.1 P0｜最小可用闭环（7 步 = 6 条 A 项 + 1 条前置分组；全部是"接已有实现"或"薄适配"）
