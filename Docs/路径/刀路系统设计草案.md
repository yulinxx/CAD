# 路径 / 刀路系统设计草案

## 1. 文档目的

本文用于定义工业激光加工软件中的路径 / 刀路系统设计方案，说明如何将几何图形、工艺参数和加工任务转换为可执行的加工路径。

本草案重点回答以下问题：

- 路径 / 刀路系统为什么必须独立于几何对象
- 路径系统需要哪些核心对象和字段
- 路径如何与工艺数据模型衔接
- 路径如何支持 2D / 3D 预览
- 如何为后续硬件层预留输出接口

---

## 2. 路径系统的定位

路径 / 刀路系统位于工艺数据模型与设备执行之间，负责把“图形”转换成“可加工轨迹”。

### 2.1 核心职责

- 从几何实体提取加工轮廓
- 根据工艺参数生成路径
- 对路径进行排序与优化
- 为仿真预览提供轨迹数据
- 为后续设备执行提供统一输出

### 2.2 不承担的职责

路径系统不直接负责：

- 几何绘制
- UI 交互
- 设备通讯
- 实时运动控制
- IO 与安全联锁

这些职责分别属于图形层、交互层和硬件层。

---

## 3. 路径系统的总体流程

```text
几何实体
    ↓
工艺映射
    ↓
路径生成
    ↓
路径优化
    ↓
路径校验
    ↓
仿真预览
    ↓
设备输出
```

### 3.1 典型处理链路

1. 用户在 2D/3D 视口中创建或导入几何
2. 工艺层为几何分配工艺参数
3. 路径系统提取轮廓、填充或扫描路径
4. 系统执行路径排序与最短行程优化
5. 系统进行几何和工艺校验
6. 仿真层使用路径数据进行预览
7. 后续设备层根据路径输出执行指令

---

## 4. 核心对象设计

### 4.1 PathJob（路径任务）

`PathJob` 表示一次路径生成任务，是路径系统的顶层对象。

#### 职责
- 聚合一个或多个工艺对象
- 组织路径生成流程
- 保存生成结果与校验状态
- 为仿真和输出提供入口

#### 建议字段
- `jobId`：任务唯一 ID
- `name`：任务名称
- `projectId`：所属项目 ID
- `materialId`：材料 ID
- `createdAt`：创建时间
- `updatedAt`：更新时间
- `status`：任务状态
- `items`：任务项列表
- `warnings`：警告列表
- `errors`：错误列表

---

### 4.2 PathItem（路径项）

`PathItem` 表示路径任务中的一个加工单元。

#### 职责
- 绑定一个几何对象或几何集合
- 绑定一组工艺参数
- 生成一组可执行路径

#### 建议字段
- `itemId`
- `entityIds`：关联实体 ID 列表
- `layerId`
- `processId`：工艺 ID
- `strategy`：路径策略
- `enabled`
- `selected`
- `pathSegments`
- `previewVisible`

---

### 4.3 PathSegment（路径段）

`PathSegment` 是最小的可执行路径单元。

#### 职责
- 表示一段连续运动轨迹
- 描述加工方式和运动参数
- 可用于仿真和输出

#### 建议字段
- `segmentId`
- `type`：线段、圆弧、样条近似段、跳转段、引线段、填充段等
- `startPoint`
- `endPoint`
- `centerPoint`：圆弧段时使用
- `radius`
- `startAngle`
- `sweepAngle`
- `feedRate`
- `laserPower`
- `laserEnabled`
- `direction`
- `isRapidMove`
- `isLeadIn`
- `isLeadOut`
- `sourceEntityId`

---

### 4.4 Toolpath（刀路）

`Toolpath` 表示一个完整的路径集合，可以理解为一个加工策略的最终结果。

#### 职责
- 汇总多个路径段
- 作为仿真和设备执行的输入
- 保存最终优化后的顺序

#### 建议字段
- `toolpathId`
- `ownerItemId`
- `segments`
- `totalLength`
- `estimatedTime`
- `boundingBox`
- `optimized`
- `valid`

---

### 4.5 PathPreview（路径预览）

`PathPreview` 用于 2D / 3D 可视化，不直接代表执行结果。

#### 职责
- 渲染路径轨迹
- 显示加工顺序
- 显示引线、跳刀、回退等辅助轨迹
- 与真实文档几何保持分离

#### 建议字段
- `previewId`
- `toolpathId`
- `visible`
- `colorMode`
- `showDirection`
- `showIndex`
- `showRapidMove`

---

## 5. 路径分类

### 5.1 按加工语义分类

| 类型 | 说明 |
|------|------|
| 轮廓路径 | 沿实体边界切割 |
| 偏置路径 | 在原轮廓外/内按偏移距离生成 |
| 引线路径 | 加工前引入的过渡轨迹 |
| 退刀路径 | 加工结束后的退出轨迹 |
| 填充路径 | 对区域进行扫描填充 |
| 扫描路径 | 对表面或区域进行规则扫描 |
| 跳转路径 | 非加工移动路径 |

### 5.2 按运动类型分类

| 类型 | 说明 |
|------|------|
| 直线段 | 两点间最短线性运动 |
| 圆弧段 | 通过圆弧进行运动 |
| 样条近似段 | 曲线近似得到的离散段 |
| 快速移动段 | 不加工的高速移动 |
| 加工移动段 | 启用激光的加工路径 |

---

## 6. 路径生成策略

### 6.1 轮廓切割

适用于线、圆、弧、多段线等封闭或半封闭图形。

#### 输出内容
- 外轮廓路径
- 内轮廓路径
- 起刀点
- 引线段
- 退刀段

### 6.2 偏置生成

通过设定偏移距离生成加工路径。

#### 适用场景
- 切割补偿
- 刀缝修正
- 内外轮廓补偿

### 6.3 填充生成

用于面域加工、打标、蚀刻、填充扫描等场景。

#### 常见策略
- 平行线扫描
- 斜线扫描
- 交叉扫描
- 区域分块扫描

### 6.4 扫描生成

适用于高密度区域、纹理、蚀刻或表面处理。

#### 常见策略
- 单向扫描
- 双向往返扫描
- 角度旋转扫描
- 自适应密度扫描

---

## 7. 路径优化

路径优化是工业加工中非常关键的一步，直接影响效率和质量。

### 7.1 优化目标

- 减少空走距离
- 减少起停次数
- 减少跳刀次数
- 保证工艺顺序合理
- 降低热影响
- 提高设备利用率

### 7.2 常见优化策略

#### 7.2.1 空间顺序优化
根据路径段空间位置，尽量减少移动距离。

#### 7.2.2 工艺优先级优化
先加工内孔，再加工外轮廓；先小件，再大件；先低热敏区域，再高热敏区域。

#### 7.2.3 方向优化
根据路径形状调整切割方向，降低变形风险。

#### 7.2.4 分组优化
将同类工艺、同参数路径聚合处理。

### 7.3 优化结果字段

建议为优化结果保存：

- `beforeLength`
- `afterLength`
- `beforeTime`
- `afterTime`
- `optimizationType`
- `changedSegments`

---

## 8. 路径校验

路径校验应在仿真和设备执行前完成。

### 8.1 几何校验

- 路径是否闭合
- 是否自交
- 是否存在零长度段
- 是否超出加工范围
- 是否重复段过多

### 8.2 工艺校验

- 工艺参数是否缺失
- 功率、速度、频率是否合理
- 路径类型是否与工艺匹配
- 引线/偏置/填充参数是否冲突

### 8.3 设备能力校验

虽然硬件最后做，但路径层应预留能力校验接口。

例如：
- 设备是否支持圆弧插补
- 设备是否支持样条近似
- 设备是否支持连续输出
- 设备是否支持分段加工

---

## 9. 与工艺数据模型的衔接

路径系统不应直接依赖 UI 控件，而应依赖工艺数据模型。

### 9.1 关系链路

```text
GeometryEntity
    ↓
ProcessDefinition
    ↓
PathItem
    ↓
PathSegment
    ↓
Toolpath
```

### 9.2 衔接原则

- 几何对象只负责表达形状
- 工艺对象负责表达加工语义
- 路径对象负责表达轨迹
- 仿真对象负责表达展示
- 硬件对象负责表达执行

### 9.3 重要要求

路径系统必须支持从工艺对象反查来源实体，以便：

- 高亮路径对应的几何
- 定位错误来源
- 回放加工顺序
- 做撤销/重做

---

## 10. 与 2D / 3D 框架的衔接

### 10.1 2D 视口衔接

2D 视口主要用于：

- 显示几何轮廓
- 显示路径预览
- 显示加工顺序
- 显示偏置、引线、跳刀
- 显示校验提示

#### 建议接口方向
- 由状态中心提供路径预览状态
- 由视口根据状态刷新预览层
- 不要让路径系统直接操作 QGraphicsItem

### 10.2 3D 视口衔接

3D 视口主要用于：

- 显示加工场景
- 显示刀路轨迹
- 显示扫描平面或体积关系
- 显示设备坐标参考

#### 建议接口方向
- 3D 渲染层从路径模型读取轨迹数据
- 3D 视口只负责展示，不参与路径计算

### 10.3 预览刷新原则

- 路径生成完成后，再刷新预览
- 路径优化不应直接改动几何实体
- 路径变化只影响预览层和工艺层状态
- 几何编辑完成后，可选择是否自动重算路径

---

## 11. 与命令系统的关系

路径生成和编辑不应直接写在视口里，而应由命令触发。

### 11.1 典型命令

- 生成刀路
- 重新生成路径
- 优化路径
- 校验路径
- 显示/隐藏路径预览
- 导出路径任务

### 11.2 命令职责

命令负责：

- 收集用户意图
- 选择工艺对象
- 触发路径计算
- 更新状态中心

命令不负责：

- 手工拼装设备输出格式
- 直接控制硬件
- 绘制具体轨迹图元

---

## 12. 与撤销重做的关系

路径系统同样应该支持撤销重做。

### 12.1 可撤销操作

- 新增路径
- 删除路径
- 修改工艺参数后重算路径
- 调整路径顺序
- 调整路径偏置

### 12.2 撤销对象建议

撤销对象应保存：

- 修改前的路径快照
- 修改后的路径快照
- 关联工艺参数
- 关联实体 ID

这样才能保证重做时能恢复完整路径结果。

---

## 13. 为硬件层预留的输出接口

虽然硬件最后再做，但路径系统必须提前预留输出格式。

### 13.1 建议输出内容

- 路径段列表
- 运动类型
- 激光开关状态
- 功率/速度/频率
- 执行顺序
- 分层信息
- 任务标识

### 13.2 输出原则

- 输出格式应独立于 UI
- 输出格式应独立于具体硬件厂商
- 设备层只做适配，不做路径重算

### 13.3 推荐结构

```text
PathJob
  └── PathItem
        └── Toolpath
              └── PathSegment
```

设备层拿到的是已经计算完成的路径结果，而不是几何原始数据。

---

## 14. 开发建议

### 14.1 第一阶段：路径数据结构

先建立基础类：

- 路径任务
- 路径项
- 路径段
- 刀路结果
- 预览对象

### 14.2 第二阶段：路径生成器

实现基础几何到路径的转换：

- 线段路径
- 圆路径
- 弧路径
- 多段线路径

### 14.3 第三阶段：优化与校验

加入：

- 顺序优化
- 偏置生成
- 引线生成
- 自交检查
- 越界检查

### 14.4 第四阶段：仿真接入

将路径结果接入 2D / 3D 仿真层。

### 14.5 第五阶段：设备输出预留

只定义输出接口，不实现具体硬件协议。

---

## 15. 推荐错误码

路径系统建议使用以下错误码前缀：

- `path.*`
- `toolpath.*`
- `preview.*`

### 示例

- `path.empty`
- `path.generate_failed`
- `path.invalid_geometry`
- `path.out_of_bounds`
- `toolpath.optimize_failed`
- `preview.update_failed`

---

## 16. 总结

路径 / 刀路系统是工业激光加工软件从“图形编辑”走向“加工准备”的核心中间层。

它需要做到：

- 与几何实体分离
- 与工艺数据模型对接
- 为仿真预览提供轨迹
- 为设备层预留统一输出
- 支持优化、校验和撤销

只要路径系统设计得稳定，后续无论接入哪类硬件，软件上层都可以保持相对稳定，不会被设备差异反向污染。
