## 1. 概念与术语对齐

### 1.1 术语与命名（对外统一）

- **唯一对外名称：同心环填充（Concentric Ring Fill）**。UI 样式列表、结果提示、文档、参数表
  一律使用该名称；历史文档里的旧对外名称已废弃并入本名称，代码标识符仍为 `ContourFill`。
- **同心圆填充**：是同心环填充的**另一种叫法**，**不是独立样式**。当源轮廓是圆（或近似圆）时，
  逐级内缩天然退化为同心圆，效果与"同心圆填充"一致；两者共用同一实现、同一参数、同一入口。
- **必须区分的另一种功能**：如果未来需要"无视源轮廓形状、按固定圆形步距铺满圆"的独立样式，
  那是另一种算法与独立样式，不能并入本轮同心环填充。本轮不实现。
- 螺旋填充是独立样式（`SpiralFill`），与同心环共用内缩内核与参数结构，但输出形态不同。

### 1.2 定义

**同心环填充（Concentric Ring Fill）**：从外轮廓向内按等间距连续内缩，每一级内缩产生
一条闭合填充环，直至剩余区域过小时停止；源轮廓是圆时自然形成同心圆。

**螺旋填充（Spiral Fill）**：复用同一套内缩结果，把相邻层的同绕向环按拓扑配对后连成一条开链；
每圈从接缝点绕行整圈，圈内在本层环与下一层环之间按参数线性插值，因此半径连续减小、形如蚊香；
当内缩产生拓扑分裂或跨孔洞时无法保持单链，降级为多条路径，路径之间的跳转在加工层体现为空移。

### 1.3 与其他填充方式的区别

| 填充方式 | 路径形态 | 典型用途 | 激光加工场景 |
|---------|---------|---------|-------------|
| **扫描线填充**（Scanline Hatch） | 等距平行直线，可 L2R/R2L/Bi | 通用 CAD 图案填充、快速大面积填充 | 大面积刻蚀、要求不高的粗加工；尖角处易过烧、有空程 |
| **弓形填充**（Bow Fill） | 扫描线 + 行间折返连接段 | 激光雕刻，连续不断笔 | 取代扫描线减少空程，但本质仍是扫描线族 |
| **同心环填充**（Concentric Ring Fill，本设计） | 同心闭合环，逐级内缩 | 薄壁件、精细凹槽、避免尖角过烧 | 激光切割薄壁结构的填充、精细内缩轮廓加工 |
| **螺旋填充**（Spiral Fill，本设计新增） | 由外向内逐圈推进的连续折线；拓扑分裂时降级为多条路径 + 空移 | 铣削口袋加工、激光焊接、需要少空移的场合 | 连续不断笔；分裂处无法保持单链，如实降级 |

### 1.4 在激光加工中的典型用途

- **薄壁件填充**：热影响均匀，避免扫描线在尖角处能量集中导致的过烧或断裂
- **精细内缩轮廓**：零件本身就是多环嵌套结构（如垫圈阵列），同心环填充直接命中加工意图
- **避免加工变形**：从外向内逐层收缩，加工过程中材料始终有刚性支撑
- **多遍加工**：每层环可独立走刀，适合功率递减的薄壁顺序加工

### 1.5 与现有填充类型的关系

现有代码中已有的填充体系：

```cpp
// FillParameters.h（当前实际形态）
enum class FillStyle : uint8_t
{
    LineFill = 0,  // 线填充（扫描线 / 弓形）
    ColorFill,     // 色块填充（三角剖分实心区域）
    ContourFill,   // 同心环填充（按轮廓逐级内缩）
    SpiralFill,    // 螺旋填充（连续路径，拓扑分裂时降级）

```

**结论**：在现有 `FillStyle` 的注释占位处新增 `ContourFill` 与 `SpiralFill` 两个值，
**不**另起独立枚举。两者复用同一个填充命令、同一个填充对话框、同一个 FillTaskHandler 分派点，
只在自己的参数页收集参数。

关键实现代码（已存在）：

```cpp
// PolygonOffset.cpp:101-163
std::vector<std::vector<Point3D>> inflateRegionToRings(
    const Clipper2Lib::Paths64& inputRegion,
    float offsetDistance,
    double scale)
{
    Clipper2Lib::Paths64 region = inputRegion;
    const int maxIterations = static_cast<int>(std::ceil(maxSpanMm / offsetDistance)) + 2;
    const double step = static_cast<double>(offsetDistance) * scale;

    for (int iteration = 0; iteration < maxIterations; ++iteration)
    {
        Clipper2Lib::Paths64 shrunk = Clipper2Lib::InflatePaths(region,
            -step,                                              // 负偏移 = 内缩
            Clipper2Lib::JoinType::Miter,                      // 当前硬编码 Miter
            Clipper2Lib::EndType::Polygon,
            2.0,                                                // miterLimit
            0.0);                                               // arcTolerance = 0

        if (shrunk.empty()) break;                              // 区域耗尽则终止

        // 每轮 Union 归一化（2026-11-03 补齐）：剔除自交/重叠脏环，统一绕向
        Clipper2Lib::Paths64 normalized =
            Clipper2Lib::Union(shrunk, Clipper2Lib::FillRule::EvenOdd);
        if (normalized.empty()) break;

        region = std::move(normalized);                         // 下一轮基于归一化后的结果
        // 收集当前环到 result
    }
    return result;
}
```

#### 2.1.5 偏移算法能力总结

- **算法类型**：Clipper2 `InflatePaths`（多边形膨胀/收缩），直线段离散化 + 圆弧近似
- **支持能力**：孔洞、多环、嵌套岛屿、自交自动裁剪（Clipper2 内置）
- **Join 策略**：Miter（斜角）硬编码，Round/Square 可通过 PolygonOffsetOptions 配置
- **精度容差**：scale=1000 定点精度（微米），arcTolerance 默认 0.25mm
- **拓扑重建**：✅ 每次 InflatePaths 返回的 Paths64 自动重建正确的环嵌套关系
- **多次内缩**：✅ Engraving `inflateRegionToRings`（每轮 Union 归一化，2026-11-03 补齐）与 Engine2D `Geo2DOffset::insetRingLayers`（Phase 1 新增）均已具备

## 3. 逻辑与流程设计

### 3.1 完整流程

```mermaid
flowchart TD
    A[输入: 选中图元或闭合轮廓] --> B[离散化: EntityDiscretizer 转为闭合折线]
    B --> C[拓扑归一化: Geo2DBoolean::uniteContours<br/>EvenOdd 规则 → 正确识别外环/孔洞/岛屿]
    C --> D{计算步距与层数}
    D --> D1[offsetDistance: 用户设置的环间距 mm]
    D --> D2[maxLayers: 用户设置的最大层数，或自动到底]
    D --> D3[minArea: 最小残余面积阈值 mm²]
    D --> D4[minWidth: 最小可加工宽度 mm<br/>（< 割缝宽度就停止）]
    D --> E[逐级内缩循环]
    E --> E1[InflatePaths(region, -step, joinType=Miter/Round/Square)]
    E1 --> E2{shrunk.empty?}
    E2 -- 是 --> F[循环结束]
    E2 -- 否 --> E3[region = shrunk]
    E3 --> E4{当前环有效?}
    E4 -- 否 --> E3
    E4 -- 是 --> E5[收集当前层所有环<br/>记录 layerIndex 和 拓扑关系]
    E5 --> E6{达到终止条件?}
    E6 -- 否 --> E1
    E6 -- 是 --> F
    F --> G[路径排序与衔接]
    G --> G1[按层序排列: 外层先/内层先<br/>用户参数控制]
    G1 --> G2[每层内: 所有同级环排序<br/>PathOptimizer nearest-neighbor]
    G2 --> G3[每层方向: CW/CCW<br/>保证切割负载一致]
    G3 --> G4{层间衔接?}
    G4 -- 是 --> G5[螺旋化: 相邻层的首尾连接段<br/>消除空程]
    G4 -- 否 --> H[保持独立层]
    G5 --> H
    H --> I[输出可加工路径: 每段为闭合折线]
    I --> J[writeToScene: 批量写回 SyPolygon<br/>继承 refEntity 图层]
```

### 3.2 终止条件（按优先级）

| 终止条件 | 说明 | 实现方式 |
|---------|------|---------|
| `shrunk.empty()` | Clipper2 InflatePaths 返回空：区域完全耗尽 | 循环内 break |
| `currentArea < minArea` | 当前层所有环的面积之和小于阈值 | `polygonArea()` 累加比较 |
| `maxLayers` 达到 | 用户设置的最大层数 | 计数器比较 |
| `minWidth` | 环的最小宽度小于割缝宽度 | BBox 短边或最窄处检测（⚠️ 实现成本高，可先跳过） |

### 3.3 难点与处理方式

#### 3.3.1 孔洞变大 / 岛屿收缩 / 细颈分裂

**现状**：Clipper2 的 `InflatePaths` 在每轮偏移时自动处理：
- 内缩时 **外轮廓向里缩**、**孔洞向外涨**、**独立岛屿各自缩**
- 细颈处宽度不足一次 step 时，**Clipper2 会把一分为多**（自交裁剪 → 分裂为多个独立子环）
- 岛屿和孔洞的角色在偏移过程中**不互换**：Clipper2 通过缠绕方向（Positive=外环=CCW，Negative=孔洞=CW）维持拓扑

**不需要自己维护拓扑**：Clipper2 每次 InflatePaths 返回的 Paths64 已经是正确归一化的环集合，
外层 CCW、孔洞 CW，直接作为下一轮的输入即可。

#### 3.3.2 尖角处过冲与自交

**Join 策略**：

| JoinType | 效果 | 适用场景 |
|---------|------|---------|
| **Miter（斜角）** | 尖角处向外延伸形成尖锐尖角，超过 miterLimit 自动退化为 Bevel | 锐利方形轮廓、追求几何忠实还原 |
| **Round（圆角）** | 尖角处用圆弧过渡，arcTolerance 控制圆弧精度 | 激光加工推荐，避免尖角过烧 |
| **Square（平头）** | 拐角处延伸形成方形 | 机械加工口袋 |

**Clipper2 自动裁剪自交**：`InflatePaths` 内部对结果做自交检测，自交段被裁掉，
最终输出的 Paths64 保证不自交。**不需要额外处理**。

#### 3.3.3 步距过小导致层数爆炸

现有 `inflateRegionToRings` 已做了 bounding box 估算 maxIterations：

```cpp
const int maxIterations = static_cast<int>(std::ceil(maxSpanMm / offsetDistance)) + 2;
```

**建议**：
- UI 层限制 offsetDistance 最小值（如 0.01mm）和 maxLayers 最大值（如 500）
- 实际运行中，如果当前层面积 < minArea 立即终止，而不是跑满 maxIterations
- Engraving 现有实现的 maxIterations 加了 +2 保险值，工程上够用

#### 3.3.4 精度：圆弧 vs 离散化误差

| 项目 | 现状 | 影响 |
|------|------|------|
| Clipper2 精度 | 定点 64 位整数域，scale=1000 对应微米级 | 足够精细 |
| 圆弧保持 | ❌ InflatePaths 输出纯折线，圆弧近似为多段直线 | 激光加工实际就是折线逼近圆弧，无实际影响 |
| arcTolerance | 控制 InflatePaths 内部的圆弧逼近精度，默认 0.25mm | 设小一点（0.05mm）可获得更光滑的转角 |
| 多级误差累积 | 每轮偏移都把 region 转为定点 → Inflate → 转回 mm，浮点往返 | 偏移 50 层后误差约 0.05mm 量级，可忽略 |

#### 3.3.5 首刀方向与边界保留

| 选项 | 说明 | 推荐 |
|------|------|------|
| 由外向内（Out→In） | 先加工最外层，逐层向内 | ✅ 推荐，热影响均匀，加工过程中材料始终有刚性支撑 |
| 由内向外（In→Out） | 先加工最内层，逐层向外 | 可能导致外层加工时内层已被切掉，结构变形 |
| 保留最外层边界 | 额外输出原始外轮廓作为单独切割路径 | 可选项，薄壁件加工常用 |
| 每层独立方向 | 每层环统一 CW 或 CCW | 影响切割负载方向和排渣路径，经验值：交替方向 |

### 3.4 与加工参数的衔接

| 衔接点 | 建议 | 备注 |
|--------|------|------|
| 每层共用工艺参数 | ✅ 默认所有层共用 | 最简单，用户预期内 |
| 按层递减功率 | ⚠️ 可选功能 | 薄壁顺序加工热累积场景，需要激光控制器支持功率渐变 |
| 每层独立图层 | ❌ 不推荐 | 层数多了图层爆炸，且没有实际工艺收益 |
| 层间跳刀优化 | ✅ 强烈推荐 | PathOptimizer nearest-neighbor 排序每层环的起终点 |

### 4.1 参数设计

#### 4.1.1 参数结构（已实施）

```cpp
// Engine/2D/Include/Engine2D/Algorithm/Fill/ContourFillParameters.h
namespace Eg
{
    // 纯 POD：只用项目自有枚举与基础标量，禁止出现任何第三方几何库类型
    struct ContourFillParameters
    {
        std::uint32_t structSize{ sizeof(ContourFillParameters) };  // 版本守卫
        double dOffsetDistance{ 1.0 };             // 环间距（mm）
        bool bAutoMaxLayers{ true };               // true=自动到底；false=手动指定层数
        std::uint32_t nMaxLayers{ 50 };            // 最大层数（bAutoMaxLayers=false 时生效）
        double dMinArea{ 0.05 };                   // 最小残余面积阈值（mm²）
        double dMinWidth{ 0.0 };                   // 最小可加工宽度（mm），本轮仅预留
        Geo2DJoinType eJoin{ Geo2DJoinType::Round };// 拐角处理：项目自有枚举 Round/Square/Miter
        double dMiterLimit{ 2.0 };                 // 斜角限制
        double dArcTolerance{ 0.25 };              // 圆弧近似容差（mm）
        bool bOuterToInner{ true };                // true=由外向内；false=由内向外
        bool bKeepOuterBoundary{ false };          // 是否额外保留原始外轮廓（仅同心环样式）
        bool bMergeToSpiral{ false };              // 历史预留字段，螺旋已由 SpiralFill 实现
        double dLinkTolerance{ 0.0 };              // 螺旋桥接容差（mm），0=按 2 倍间距自动
    };
}
```

同心环填充与螺旋填充**共用这一个结构**：`ContourFillParameters` 同时承载两种样式的参数，
`FillTaskParams` 里各自持有一个实例（`contourParams` / `spiralParams`），互不覆盖 UI 记忆值。
`dLinkTolerance` 只在螺旋样式生效，其余字段语义完全一致。

> **硬约束：公共接口零第三方类型。** 本结构只使用 `std::uint32_t`、`double`、`bool` 与项目自有
> `Geo2DJoinType`。端点处理（闭合多边形）由实现内部固定，不在公共参数暴露。
> `Clipper2Lib::JoinType` / `Clipper2Lib::EndType` / `Clipper2Lib::Paths` 等类型只允许出现在
> `Geo2DOffset.cpp` 的匿名命名空间适配函数里，公共头不得 include 任何 Clipper2 文件。
> 参数结构无堆指针、可直接 `memcpy`。`structSize` 为历史字段，现不参与校验，仅为维持布局保留（已标记 deprecated）。

### 5.3 降级策略

| 降级场景 | 处理方式 |
|---------|---------|
| offsetDistance > 轮廓最小宽度 | 内缩结果为空，任务失败并记录 warning（不弹 OK 置灰） |

| 跨图层多选 | 全部环/路径归属收集顺序第一个源图元图层；第二图层实体数不变 |

**核心思想**：把"单次偏移 + 多次内缩循环 + EvenOdd 归一化"全部收口到 `Geo2DOffset` 里，
让它成为唯一的偏移几何内核。上层两个业务（偏移命令、同心环填充）都只调它，不直接碰 Clipper2。
Engraving 的 `inflateRegionToRings` 实现逻辑**直接拷贝到 Geo2DOffset 的新函数中**，
循环部分变成公开可配置的 API，而不是私有硬编码函数。

#### 8.3.2 每层的职责与边界

| 层 | 归属 | 职责 | 依赖方向 |
|----|------|------|---------|
| **基础几何层** | Engine2D `Geo2DOffset` | 单次偏移、多次内缩循环、EvenOdd 归一化、精度/JoinType/miterLimit/arcTolerance 全参数可配置 | 只依赖 Clipper2 + Engine2D 自身几何类型（Ut::Vec2d） |
| **任务/服务层** | Engine2D | `EntityOffset`（偏移命令的实体层入口）、`EntityContourFiller`（同心环填充的实体层入口，已实施） | 依赖 Geo2DOffset；不直接碰 Clipper2 |
| **UI 层** | UI/2D | OffsetDialog、FillDialog（含同心环填充页面） | 依赖 Engine2D 任务层接口 + Engine2D 参数结构体 |
| **Clipper2** | External | InflatePaths、Union 等底层几何运算 | — |

**关键约束**：
- Engine2D 不反向依赖 Engraving
- Engraving（如果未来要接过来）可以调 Geo2DOffset，依赖方向正确
- UI 层只依赖任务层接口和参数结构体，不碰几何细节
- 任务层可以各自维护自己的业务参数（OffsetParameters / ContourFillParameters），但**几何参数**统一映射到 Geo2DOffsetParams

#### 8.3.3 偏移命令能否直接表达同心环填充？

**不能。** 理由：
1. OffsetDialog 没有次数/层数参数
2. 偏移命令的 `OffsetParameters` 结构体没有 `count` / `maxLayers` 字段
3. EntityOffset 的核心函数 `computeOffsetEntities` 里只调一次 `Geo2DOffset::offsetContours`，没有循环逻辑
4. 偏移命令的业务语义是"对轮廓做 N mm 的一次性偏移"，不是"持续缩到缩不动为止"

所以必须在 Geo2DOffset 里补一个**新的公开方法**，而不是在 EntityOffset 或 OffsetTaskHandler 里自己写循环。

### 8.4 低耦合接口设计

#### 8.4.1 Geo2DOffset 新增接口（已实施的最终形态）

> 本节为 Phase 1 实际落地的签名，与 [Geo2DOffset.h](file:///c:/Users/xx/Documents/Cpp/CAD/Engine/2D/Include/Engine2D/Geometry/Geo2DOffset.h)
> 逐字一致。与早期草案的差异：层元信息结构 `Geo2DRingLayer` 提到命名空间作用域（不再是类内嵌套），
> 字段名改为 `rings / nLayerIndex / dArea`，参数名改为 `dStep / params / nMaxLayers / dMinArea`。

```cpp
// Engine2D/Include/Engine2D/Geometry/Geo2DOffset.h（追加）

namespace Eg
{
    /// 内缩循环的保护上限：防止步距过小导致的层数爆炸
    constexpr int kInsetRingMaxLayers = 500;

    /// 单层内缩结果
    struct Geo2DRingLayer
    {
        std::vector<std::vector<Ut::Vec2d>> rings; ///< 该层所有闭合环（外环 CCW、孔洞 CW）
        int nLayerIndex{ 0 };                       ///< 层序号，0 为最外层（原始轮廓内缩一步后的位置）
        double dArea{ 0.0 };                        ///< 该层所有环的面积绝对值之和（mm²）
    };

    class ENGINE2D_API Geo2DOffset
    {
    public:
        // === 已有接口（签名与行为完全保持不动）===
        static std::vector<std::vector<Ut::Vec2d>> offsetContour(
            const std::vector<Ut::Vec2d>& contour,
            const Geo2DOffsetParams& params,
            const GeometryContext& ctx);

        static std::vector<std::vector<Ut::Vec2d>> offsetContours(
            const std::vector<std::vector<Ut::Vec2d>>& contours,
            const Geo2DOffsetParams& params,
            const GeometryContext& ctx);

        // === 新增：多次内缩循环 ===

        /// 连续内缩并逐层重建拓扑，返回从外到内的每一层环集合
        static std::vector<std::vector<std::vector<Ut::Vec2d>>> insetRings(
            const std::vector<std::vector<Ut::Vec2d>>& loops,
            double dStep,
            const Geo2DOffsetParams& params,
            const GeometryContext& ctx,
            int nMaxLayers = 0,
            double dMinArea = 0.0);

        /// 连续内缩并返回每层环集合、层序号与面积
        static std::vector<Geo2DRingLayer> insetRingLayers(
            const std::vector<std::vector<Ut::Vec2d>>& loops,
            double dStep,
            const Geo2DOffsetParams& params,
            const GeometryContext& ctx,
            int nMaxLayers = 0,
            double dMinArea = 0.0);

        /// 连续内缩后把各层环首尾桥接成螺旋折线（复用 insetRingLayers，不复制偏移逻辑）
        /// 每个元素是一条连续路径；拓扑分裂/跨孔洞时拆分为多条，路径之间由加工层作空移
        static std::vector<std::vector<Ut::Vec2d>> insetSpiralPaths(
            const std::vector<std::vector<Ut::Vec2d>>& loops,
            double dStep,
            const Geo2DOffsetParams& params,
            const GeometryContext& ctx,
            int nMaxLayers = 0,
            double dMinArea = 0.0,
            double dLinkTolerance = 0.0);
    };
}
```

**语义约定（已实现）**：

| 项 | 约定 |
|----|------|
| 输入 `loops` | 任意方向的闭合环集合，可以是外轮廓 + 孔洞、多岛屿、嵌套孔洞 |
| `dStep` | 内缩步距（mm），必须 > 0 且 > `ctx.toTolerance().dLinear`，否则直接返回空 |
| `params` | 只用作 `JoinType / miterLimit / arcTolerance` 的来源；`dOffset` 与 `bInset` 在内部被覆盖为 `dStep` / `true`，调用方传什么不影响结果 |
| `nMaxLayers` | `0` 表示自动缩到底，但仍受 `kInsetRingMaxLayers = 500` 硬上限保护；> 0 时取 `min(nMaxLayers, 500)` |
| `dMinArea` | 当**该层**的净材料面积 < 此值时，丢弃该层并终止（不是累加所有层后比较） |
| 返回顺序 | 从外到内，`nLayerIndex` 从 0 递增 |
| 环方向 | 每层外环 CCW（有符号面积为正）、孔洞 CW（为负）；`dArea = fabs(Σ 有符号面积)` |
| `dLinkTolerance`（螺旋） | 只在 `insetSpiralPaths` 生效；0 表示按 `2 × dStep` 自动，且不小于 `ctx` 线性容差 |
| 螺旋返回 | 每条路径是一条开放折线，首尾不自动闭合；每圈从接缝点出发绕行整圈，圈内在本层环与下一层环之间按参数线性插值，因此半径沿整圈连续减小，圈末落到下一圈接缝点。相邻层接缝取同一角度（离上一圈接缝最近的顶点），不存在固定角度的径向跳线 |
| 螺旋接续约束 | 只桥接「上一层 + 同绕向」的链：同层兄弟环（拓扑分裂产物）不桥接，孔洞与材料环不桥接 |

**为什么提供两个版本**：`insetRings` 返回纯环集合（Engraving 现有 `contourParallelFill*` 就是这个扁平返回值语义），
`insetRingLayers` 额外带层序号与净材料面积（同心环填充 UI 预览需要每层计数/面积）。`insetRings` 内部就是
调 `insetRingLayers` 再投影出 `rings`，不存在两套算法。

**公共接口零第三方类型**：以上三个签名与 `Geo2DRingLayer` 只出现 `std::vector`、`Ut::Vec2d`、
`Geo2DOffsetParams`、`GeometryContext` 与基础标量，**没有任何 Clipper2 类型或命名空间**。
`Clipper2Lib` 只出现在 [Geo2DOffset.cpp](file:///c:/Users/xx/Documents/Cpp/CAD/Engine/2D/Src/Geometry/Geo2DOffset.cpp)
的匿名命名空间适配函数（`toClipperJoin` / `toClipperPathOffset`）与实现体内。

量化级面积差（最大相对差 < 0.05%），因此它当前的作用是**防御性不变量**而不是已证实的 bug 修复。

### 8.5 复用边界与约束（风险 + 守护）

#### 8.5.1 共用内核时容易被破坏的点

| 风险点 | 具体表现 | 守护写法 |
|--------|---------|---------|
| **参数语义不一致** | Engine2D OffsetParameters 的 `dOffset` 语义是"偏移距离"（正），`OffsetType::Inset/Outset` 控制方向；Engraving 是"正数=外扩，负数=内缩" | Geo2DOffsetParams 内部统一为 `bInset + dOffset`，映射函数必须严格把两种表达收敛到同一种 |
| **精度容差不同** | Engine2D 用 double 域（`Clipper2Lib::PathD` + `GeometryContext` 容差），Engraving 用 scale=1000 定点域（1e-3 级别） | Phase 1 实际沿用 Engine2D 既有 double 域（`PathD`），容差来自 `ctx.toTolerance()`；**未**改成定点域。若后续要统一到定点，改动只在 `Geo2DOffset.cpp` 内部的 `toClipperPathOffset` 与 `InflatePaths` 调用处，公共签名不变 |
| **拓扑重建差异** | Engraving 的 inflateRegionToRings 循环里**没有在每次 InflatePaths 后重新 Union 归一化**，直接把 shrunk 当 region 继续；如果 InflatePaths 返回的是已归一化的（外环 CCW / 孔洞 CW），那没问题，但如果某轮 InflatePaths 因自交裁剪产生了方向混乱的子环，下一轮就会错 | **必须在每轮 InflatePaths 后追加一次 Union(EvenOdd)** 保证下一轮输入的拓扑正确。Engraving 现有实现缺这一步——是个潜在 bug |
| **InflatePaths 硬编码参数** | Engraving 的 inflateRegionToRings 里 JoinType 硬编码 Miter、miterLimit=2.0、arcTolerance=0.0 | Geo2DOffset::insetRings 必须从 Geo2DOffsetParams 读取，**不能硬编码** |
| **终止条件语义** | Engraving 用 BBox 估算 maxIterations 做硬上限，不看面积；同心环填充需要 minArea 语义 | 两种终止条件都要实现，且 minArea 语义优先级更高（小于 minArea 立即停止，不跑满 maxIterations） |
| **细颈分裂后空环过滤** | 细颈宽度不足一步距时，InflatePaths 可能返回空（整张图消失），也可能返回少量微环 | 空环必须过滤，不能直接返回给上层。Engraving 现有实现已经检查 `ring.size() >= 3`，保留这个逻辑。Phase 1 已实现：过滤后若该层无有效环，直接终止且不把该层入表 |
| **公共接口泄漏第三方类型** | 若把 `Clipper2Lib::JoinType / EndType / PathD` 写进参数结构或公共方法签名，则 UI 层、其他模块、二次开发都被迫看到 Clipper2 头，换后端等于全链接改一遍 | 见 8.5.3：公共头一律只用项目自有枚举 + 基础标量，Clipper2 只在 `.cpp` 内部出现 |
| **scale 转换精度** | Engraving 的 toClipperPath 用 `llround(pt.x * scale)`，从 mm 到微米放大 1000 倍；Engine2D 若也用定点必须共用同一份 scale | Phase 1 **未**引入定点常量：`Geo2DOffset` 用 `Clipper2Lib::PathD`（double 域），不存在 scale 常量，因此也没有两处 scale 不一致的风险 |
| **性能特征不同** | InflatePaths 单次调用约 O(N)，循环 K 次后整体 O(K×N)；同心环填充 K 可能达到上百层 | 必须提供 maxLayers 硬上限（UI 层限制 + Geo2DOffset 内部二次兜底），且 UI 层显示层数估算让用户知情 |
| **Engraving 外部 C API 签名** | Engraving::contourParallelFill 返回 `vector<vector<Point3D>>`（z 恒为 0），如果以后桥接到 Geo2DOffset，中间会多一次 double↔Point3D 转换 | 这层桥接放在 Engraving 内部，不改外部 API 签名 |

#### 8.5.2 具体守护代码约定

```cpp
// Geo2DOffset.h 模块级常量（Phase 1 实际只引入了一个）
namespace Eg {
    constexpr int kInsetRingMaxLayers = 500;   // 循环硬上限（防爆炸）
}
// 其余下限（步距下限、面积下限）不设模块级常量：
//   - 步距下限直接取 GeometryContext 的线性容差（ctx.toTolerance().dLinear）
//   - 面积下限由调用方 ContourFillParameters::dMinArea 传入，默认 0.05 mm²
```

```cpp
// Geo2DOffset::insetRingLayers 实际实现骨架（与源码一致的精简版）
std::vector<Geo2DRingLayer> Geo2DOffset::insetRingLayers(loops, dStep, params, ctx, nMaxLayers, dMinArea)
{
    // 1) 参数守卫：空输入 / 非有限值 / 步距 <= 0 / 步距 <= 线性容差 一律返回空
    if (loops.empty() || !std::isfinite(dStep) || dStep <= 0.0) return {};
    const Geo2DTolerance tol = ctx.toTolerance();
    if (dStep <= tol.dLinear) return {};

    // 2) EvenOdd 归一化：整理成"外轮廓 + 孔洞"的正确嵌套结构
    structure = Geo2DBoolean::uniteContours(loops, EFillRule::EvenOdd, ctx);
    region   = toClipperPathD(structure, tol);          // 丢弃顶点数 < 3 的环

    // 3) 层数上限：0 = 自动到底，同时受 500 硬上限保护
    nLayerCap = (nMaxLayers > 0) ? std::min(nMaxLayers, kInsetRingMaxLayers) : kInsetRingMaxLayers;

    for (int nLayer = 0; nLayer < nLayerCap; ++nLayer)
    {
        // 4) 整组外轮廓 + 孔洞一起内缩（EndType::Polygon 固定，JoinType/miterLimit/arcTolerance 来自 params）
        shrunk = Clipper2Lib::InflatePaths(region, -dStep, join, Clipper2Lib::EndType::Polygon,
                                           params.dMiterLimit, /*precision*/ 2, params.dArcTolerance);

        // 5) 每轮强制 EvenOdd Union 归一化（本实现新增；Engraving 侧 2026-11-03 已同步补齐）
        normalizer.AddSubject(shrunk);
        normalizer.Execute(Clipper2Lib::ClipType::Union, Clipper2Lib::FillRule::EvenOdd, normalized);
        if (normalized.empty()) break;

        // 6) 过滤顶点数 < 3 的环；有符号面积累加（孔洞为负）后取 fabs 才是净材料面积
        for (path : normalized) { if (path.size() < 3) continue; dSignedArea += signedArea(ring); ... }
        layer.dArea = std::fabs(dSignedArea);

        // 7) 该层无有效环 → 终止；该层面积 < dMinArea → 丢弃该层并终止
        if (layer.rings.empty()) break;
        if (dMinArea > 0.0 && layer.dArea < dMinArea) break;

        // 8) 推进：下一轮基于本轮归一化后的结果
        region = std::move(normalized);
        layers.push_back(std::move(layer));
    }
    return layers;
}
```

#### 8.5.3 公共接口零第三方类型（硬约束）

**约束原文**：公共参数结构不得出现第三方库类型，Clipper2 只允许出现在实现内部。

适用范围：任何会被 UI 层、其他模块或外部消费者看到的头文件，包括
`ContourFillParameters`、`Geo2DOffset::insetRings` / `insetRingLayers` / `insetSpiralPaths` 签名、
`FillStyle` 扩展的参数字段、`FillTaskParams` / `FillUIParams` 的 `contourParams` 与 `spiralParams`、
`FillDialogParams`、`UiEngineAccess` 门面头。

强制规则：

| 规则 | 内容 |
|------|------|
| R1 | 公共头只允许出现项目自有枚举（`Geo2DJoinType`、`FillStyle`、`FillStyle::SpiralFill` 等）、基础标量（`double` / `bool` / 定宽整型）与 `std::vector<Ut::Vec2d>` |
| R2 | 禁止出现 `Clipper2Lib::JoinType`、`Clipper2Lib::EndType`、`Clipper2Lib::PathD`、`Clipper2Lib::PathsD` 等任何 Clipper2 类型或命名空间 |
| R3 | 公共头**不得** `#include` 任何 Clipper2 头文件，也不得通过其他公共头间接引入（`Geo2DOffset.h`、`ContourFillParameters.h`、`EntityContourFiller.h`、`FillUIParams.h` 均须保持干净） |
| R4 | 端点处理（`EndType`）不进参数结构：同心环对外语义恒为"闭合多边形"，螺旋对外语义恒为"开放折线"，实现内部固定 `EndType::Polygon`；若未来需要更多端点语义，再新增自有 `enum class`，而不是暴露库枚举 |
| R5 | 参数结构保持纯 POD：可 `memcpy`、不持有堆指针、字段全部有默认值；`structSize` 位于 `ContourFillParameters` 首位，但已不再参与校验，仅为维持 ABI 布局保留（已标记 deprecated） |
| R6 | Clipper2 → 自有类型的映射只允许出现在 `.cpp` 的匿名命名空间（`toClipperJoin`、`toClipperPathOffset`、`insetRingSignedArea` 等），或仅 `.cpp` 可见的私有适配头 |
| R7 | 螺旋路径的桥接与断裂只使用自有类型：`insetSpiralPaths` 的入参/返回值不出现任何库路径类型；桥接容差为 `double` |

### 8.6 对 Q1 的修正结论

**上一轮 Q1 的结论**："方案 A：在 Engine2D 内基于 Geo2DOffset 单次偏移循环调用（推荐）"
——这个方向没错，但不够精确。当时的理解是"EntityOffset 里自己写循环"，现在确认**循环逻辑应该下沉到 Geo2DOffset 几何基础层**，而不是挂在 EntityOffset 任务层。

**修正后的 Q1 最终方案（无分支）**：

| 项 | 内容 |
|----|------|
| **结论** | 不需要在 EntityOffset / ConcentricFill 里写循环，在 Geo2DOffset 里新增一个 `insetRings` 公开方法，内部实现多次内缩循环 + 每轮 Union 归一化 + 可配置 JoinType/miterLimit/arcTolerance + 可配置终止条件 |
| **依赖方向** | Geo2DOffset（Engine2D 几何层）只依赖 Clipper2 + Ut::Vec2d，不依赖 Engraving，完全符合分层约束 |
| **复用效果** | 偏移命令和同心环填充都走 Geo2DOffset，共用同一份偏移内核；Engraving 后续可以桥接过来复用（非本轮） |
| **Engraving 现有代码** | inflateRegionToRings 曾缺每轮 Union 归一化，**2026-11-03 已在 Engraving 内补齐**；补测（第 9.6 节）未能复现脏环，故按防御性不变量保留；Geo2DOffset 新实现按同一规则实现 |
| **工作量** | Geo2DOffset::insetRings 约 80~120 行（从 Engraving inflateRegionToRings 拷贝 + 补 Union 归一化 + 改为可配置参数） |

**Engraving 现有代码能"跑起来"但不应该"直接用"**：
- 它是匿名命名空间私有函数（inflateRegionToRings），不对外暴露 JoinType/miterLimit/arcTolerance 配置
- 它曾缺每轮 InflatePaths 后的 Union 归一化，**2026-11-03 已补齐 EvenOdd Union 归一化**（补测证实当前后端下 InflatePaths 本身不产脏环，此归一化现为防御性不变量，见第 9.6 节）
- 它的 scale=1000 定点化与 Engine2D 的 double 域接口不衔接
- 它不支持 minArea 终止条件（只用 BBox 估算 maxIterations）

所以正确做法是：**把它的循环逻辑拷贝到 Geo2DOffset 里，补上 Union 归一化 + 参数化 + minArea 终止**；
Engraving 侧本轮只补归一化，不做参数化与桥接，避免改变 3D 分层/体积加工结果。

> 最小残余面积沿用文档量级 0.05 mm²。

#### 9.2.1 数据契约：层序稳定、同层环无序

`insetRings` / `insetRingLayers` / `insetSpiralPaths` 以及 `Geo2DRingLayer` 的输出遵循两条契约：

1. **跨层顺序稳定**：层的顺序即内缩顺序（`nLayerIndex` 从 0 递增），同一次调用的层数可比较。
2. **同层环顺序不稳定**：每轮 EvenOdd Union 归一化会按绕向重排同层环（实测哑铃用例第 6 层两个环的
   0/1 下标互换，点数多重集不变）。调用方**不得**按环下标把某一层的第 i 个环对应到另一层或上一次结果；
   需要跨层匹配时，只能按几何位置（质心、包围盒、包含关系）重新匹配。

螺旋路径由各层环顺序桥接而来，因此**同一输入重算得到的路径分段顺序也可能变化**，调用方不得依赖
“第 i 条路径”的跨次一致性；断点数、总长度等统计量不受影响。

#### 9.6.1 测量条件

| 项 | 条件 |

- **旧实现症状**：**未复现**。93/93 的旧实现输出均无自交、无环间相交、绕向与嵌套奇偶一致、面积逐层单调；

- **根因证据**：Clipper2 2.0.1 的 `ClipperOffset::ExecuteInternal` 内部已执行
  `c.Execute(ClipType::Union, FillRule::Negative / Positive, …)` 清理自交

  的前提在当前后端不成立。
- **如实结论**：**无法证明该修复修的是真 bug**。它的实际收益是被量化的：PathD 域面积量化误差、
  环顺序重排；Path64 域为无操作。保留它的理由是防御性不变量（后端更换或参数极端化时兜底），
  而不是已证实的缺陷修复。
- **测试固化的不变量**：`Geo2DOffsetNormalizationContrastTests.cpp` 断言——层数相等、每层环数相等、
  每层点数多重集相等、两条路径都无脏环、生产路径面积逐层单调、整件净面积相对差 < 5e-4
  （3/3 PASSED：2 mm 细颈哑铃、三层嵌套奇偶、1 mm 薄壁坍缩）。
- **对照代码保留与基线重定（2026-11-04 定案）**：对照实现保留在测试内（匿名命名空间，不进入生产路径），
  其定位是“当前 Clipper2 后端不变量”的回归哨兵，而不是对旧实现的永久承诺。更换偏移后端或升级
  Clipper2 版本后，必须重新测量并重定基线——旧实现可能开始产出脏环、也可能与生产路径不再等拓扑，
  此时应更新期望值并记录新基线，不能把断言失败直接当成产品回归。

#### 9.6.7 本节一句话结论

1. 单次 `Union(Path64 单环, EvenOdd)`：64/256/1024 点中位数 **0.0054 / 0.0176 / 0.111 ms**，P95 **0.0061 / 0.0299 / 0.146 ms**。
2. 多级内缩每轮归一化的增量：**+17% ~ +30%**，绝对值 +0.04 ~ +4.7 ms（Engraving）、+0.06 ~ +21.9 ms（Engine2D）。
3. 20 层 × 5 环的典型规模增量约 **+0.5 ms / +1.5 ms**（插值），**可接受**；实时预览场景需另做优化。
4. 点数/环数**完全不变**；仅同层环顺序可能重排、PathD 面积有量化级差异。
5. 下游**无填充环点数依赖**；渲染层 64 点简化阈值只影响 LOD，不影响正确性。
6. 93 个输入族**未复现脏环**：归一化在当前后端是幂等/防御性步骤，不能宣称"修复了真 bug"。
7. 已拍板并实施：`dMiterLimit` 补 UI（仅 Miter 可见，1.0~10.0，默认 2.0，Round 隐藏并回落默认值）；
   测试内旧实现对照代码保留，作为“当前后端不变量”的回归哨兵，换后端需重定基线。

### 10.2 调用链

```
UI 对话框 FillDialog
  → 用户点击 OK，收集 FillUIParams（style + line/color/contour/spiral 参数）
  → 填充命令（Fill2D / FillColor2D，OperationBus → AlgorithmApplicationService）

```

### 10.3 图层归属语义

| 规则 | 实现 |
|------|------|
| 结果不新建图层 | 只调用 `setLayer` / `setLayerId`，不调用 LayerManager 创建接口 |
| 结果不落当前活动图层 | 参考实体固定为 `m_entities.front()`，与活动图层无关 |

| 跨图层多选 | 全部结果归属第一个源图元图层；其余源图层实体数不变（已有单测覆盖） |

## 11. 螺旋填充设计

### 11.1 定位

螺旋填充（`SpiralFill`）不是独立偏移算法：它**复用** `Geo2DOffset::insetRingLayers` 的层结果，
只在几何层新增 `insetSpiralPaths` 做"环 → 连续折线"的桥接。因此：

- 参数结构与同心环完全共用（`ContourFillParameters`），仅多一个 `dLinkTolerance`；
- 终止条件（层数上限、最小残余面积）与同心环一致；
- 不复制任何 Clipper2 调用，换偏移后端时螺旋侧无需改。

### 11.2 算法步骤

1. 与同心环相同：图元离散化 → 只保留闭合轮廓 → 组合后 EvenOdd 归一化；
2. 调用 `insetRingLayers(loops, step, ...)` 得到由外到内的各层环；
3. 第一遍做拓扑配对：按层序、层内环序为每个环寻找可接续的链，条件是「上一层 + 同绕向 +
   两环曲线最小距离 ≤ `dLinkTolerance`（默认 `2 × step`）」；接缝点取环上离上一圈接缝最近的顶点，
   使相邻两圈接缝保持同一角度；
4. 第二遍生成点列：第 i 圈从接缝点出发绕行整圈，圈内参数 `t = j / n`，
   取「第 i 环第 j 个顶点」与「第 i+1 环同参数采样点」的线性插值作为输出点；
   于是圈内半径连续减小、圈末正好落到第 i+1 圈接缝点，**不存在离散跳线**；
   链的最后一圈没有下一层可过渡，按接缝点开链输出且不重复追加接缝点；
5. 输出所有链；每条链是开放折线，链之间是空移；
6. `bOuterToInner = false` 时，反转链顺序并对每条链反转顶点顺序，让加工从最内圈开始。

### 11.3 与"理想阿基米德螺旋"的区别（如实说明）

当前实现是**相邻等距内缩环之间的连续插值折线**，视觉上是蚊香状向内渐缩，但不是数学意义上的
阿基米德螺旋：

- 优点：与同心环共用同一份内缩内核；任意形状（含尖角、孔洞）都能给出单链或按拓扑降级；
  逐点到中心（首圈质心）的距离单调不增，实测最大正增量约 `0.02mm`（最内圈半径约 `1mm` 时环自身
  离散化带来的噪声，小于步距 5%）；
- 代价：插值把一圈的径向位移均摊到整圈，因此每一小段都略偏离"等距线"（单段偏差不超过一个步距），
  尖角处的过渡段方向不如圆弧插值自然；
- 折线近似：输出不含圆弧插值，圆形的螺旋仍由多段直线构成。若工艺要求真正的圆弧螺旋，
  需要另立"连续渐变偏移"算法，本轮不做。

### 11.4 降级策略

| 情形 | 表现 |
|------|------|
| 简单单连通区域 | 单条连续路径（`pathCount = 1`，`jumpCount = 0`） |
| 细颈在第 k 层分裂成两个子区域 | 一支沿原链继续，其余子环立即另起新链（同层兄弟环不桥接） |
| 外轮廓 + 孔洞（壁厚 > 桥接容差） | 外环族与孔洞族各成一条链（`pathCount = 2`） |
| 外轮廓与孔洞绕向相反 | 即使壁厚收窄到桥接容差内也不合并（只接续「上一层 + 同绕向」的链） |
| 多独立岛屿 | 相距超过桥接容差，每个岛屿各自成链 |
| 桥接容差被调得极小 | 每层都判为跳转，路径条数 ≈ 层数（用于验证降级开关） |

### 11.5 跳转在 CamPlan 中的体现

螺旋的每条连续链写成一个**开放 `SyPolygon`（`bClosed = false`）**，多条链是多个图元。
加工层 `MotionPlanCompiler` 对每个轮廓起点调用 `emitRapidTo(start)`（激光关闭的快速定位），
因此链与链之间的跳转**自然表现为空移**，不需要额外的跳转实体或专用字段。
结果提示里的 `jumpCount = pathCount - 1` 就是这次填充会产生的空移次数。

> 注意：这依赖"一个图元 = 一段连续出光路径"的既有加工约定；若后续加工层改为跨图元连续出光，
> 需要重新确认空移语义。
